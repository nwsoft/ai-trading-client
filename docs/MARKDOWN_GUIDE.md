# Markdown 작성 가이드 (NoahAI)

이 문서는 저장소 전반의 Markdown 문서 스타일을 통일하기 위한 가이드입니다. VS Code에서 Markdown All in One, markdownlint, Code Spell Checker 사용을 권장합니다.

## 헤더와 구조
- 문서 제목: `# 제목`으로 시작합니다. 파일당 제목은 1개.
- 섹션 깊이: 최대 3~4 레벨까지 사용 권장(`#`, `##`, `###`, `####`).
- 목차: 문서가 길다면 상단에 간단히 수동 목차를 두거나, VS Code Outline을 활용합니다.

## 본문 스타일
- 한글 띄어쓰기/맞춤법 준수. 너무 긴 문장은 2~3 문장으로 나눕니다.
- 줄바꿈: 자연스러운 문단 구분을 위해 빈 줄 1줄을 사용합니다.
- 강조: 굵게(`**굵게**`)는 핵심 용어에 한정해 과용하지 않습니다.
- 인라인 코드: 설정 키, 파일명, 심볼 등은 백틱(``)으로 감쌉니다. 예) `settings.json`, `ChartScreenshotWidget`.

## 코드 블록
- 언어 지정을 반드시 포함합니다.
  - Python: ```python
  - JSON: ```json
  - Bash/PowerShell: ```bash / ```powershell
- 긴 코드보다는 최소 예시 위주로, 실행/사용에 필요한 맥락을 문장으로 보충합니다.
- 명령 예시는 OS/셸을 고려합니다. 본 프로젝트 기본 셸: Windows PowerShell.

## 표, 리스트, 체크리스트
- 표는 파이프(`|`) 기반 기본 표를 사용합니다.
- 순서 없는 리스트(`-`), 순서 있는 리스트(`1.`)를 상황에 맞게 사용합니다.
- 태스크 진행 표시는 체크박스로 표현할 수 있습니다. 예) `- [x] 완료`, `- [ ] 진행중`.

## 링크와 이미지
- 내부 링크는 상대 경로를 사용합니다. 예) `docs/INSTALLATION.md`.
- 이미지: `docs/` 혹은 `docs/images/` 폴더에 저장하고 상대 경로로 참조합니다.
- 캡션이 필요한 경우 본문에서 이미지 윗줄 또는 아랫줄에 간단히 설명합니다.

## 파일 네이밍과 위치
- 파일명은 UPPER_SNAKE_CASE.md 또는 하이픈 케이스(`-`) 중 하나로 유지합니다. 현재는 UPPER_SNAKE_CASE를 우선.
- 제품/기능별 문서는 `docs/` 하위에 위치시키고, 상위 개요 문서에서 링크를 제공합니다.

## 줄바꿈과 줄 길이
- VS Code에서 Markdown은 자동 줄바꿈(wordWrap) 사용을 권장합니다.
- 물리적 줄 길이는 제한하지 않지만, 가독성을 위해 80–100자 내외를 권장합니다.

## 이모지와 아이콘
- 문서 스캔 가독성을 위해 섹션 제목에 가벼운 이모지를 사용할 수 있으나, 과도한 사용은 지양합니다.

## 품질 확인 체크
- 철자 검사: Code Spell Checker 결과를 확인합니다.
- markdownlint 경고: 저장 시 자동으로 확인되며, 경고가 지속되면 규칙에 맞게 수정하거나 합리적이면 예외를 추가합니다.
- 링크 유효성: 상대 경로가 맞는지, 삭제된 문서를 참조하지 않는지 확인합니다.

## 예시
```markdown
# EXCHANGE_SETUP

## 개요
- 이 문서는 거래소 연결 설정 절차를 설명합니다.

## 준비물
- API Key, Secret

## 설정 단계
1. `config/settings.json`에서 `exchange` 섹션을 엽니다.
2. 키 값을 입력하고 저장합니다.

## 문제 해결
- 연결 실패 시 네트워크 상태와 키 유효성을 먼저 확인합니다.
```

## 부록: VS Code 설정 요약
- Markdown: 자동 줄바꿈 켜기, 저장 시 포맷팅(On), 트레일링 공백 보존(두 칸 공백 줄바꿈).
- JSON/JSONC: 2칸 들여쓰기, 저장 시 포맷팅(On).
- Python: 4칸 들여쓰기, 저장 시 포맷은 수동(Black/autopep8 등은 팀 합의 후 적용).
