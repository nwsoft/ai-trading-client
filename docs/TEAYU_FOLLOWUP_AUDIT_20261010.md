## 앞선 결론의 정정

앞서 확인한 세 문제가 폴더 전체의 유일한 원인이라는 결론은 성립하지 않는다. OKX의 불필요한 인증 통화·타 상품 조회 의존성은 실제 설치 SDK로 재현한 소스 결함이다. 그러나 문의 요청의 정확한 원인 예외까지 확인한 것은 아니다. 요청 시각은 2026-10-10 **07:54:59 KST**이며 제공 운용 로그의 최종 시각 **07:38:31 KST** 이후다. 해당 409는 종목 목록을 확보하지 못했음을 뜻하며, 당시 원인이 인증·시간 초과·요청 제한 중 무엇인지는 미확정이다. 현재의 공개 조회 성공을 당시 원인 확정으로 사용하지 않는다.

이번 재점검은 `logs/`와 `log_archives/`의 **398개 파일, 96,893,772줄**을 스트리밍으로 읽었다. 읽기 실패는 없었다. ERROR/CRITICAL/FATAL 또는 Traceback 표시 줄은 6,084개다. 이는 고유 버그 수가 아니며 과거 로그·중복·이미 재처리된 사건을 포함한다. 학습 gzip 자료 전체의 의미 분석이나 모든 주문·손익의 전수 대조를 했다는 뜻도 아니다. 자동 범주에 들어가지 않은 오류는 해시와 파일 위치를 남겼고 주요 유형을 추가 검토했다. 따라서 ‘모든 오류 수정 완료’로 보고하지 않는다.

## 추가 오류와 처리 판단

- **DB 저장 대기 초과**: 최근 Bitget/Bithumb/Coinone/키움 로그와 압축 Upbit/Bithumb 로그에 존재한다. 현재 소스에는 별도 SQLite 재처리 큐와 중복 적용 방지 영수증이 이미 있다. 제공 `trading.pending_writes.sqlite3`를 읽기 전용으로 확인한 시점의 대기 행은 0개다. 격리 DB의 잠금·재시작·한 번만 재처리 검사를 재검증한다. 대기 0개만으로 과거 저장 누락이 전혀 없었다고 증명하지 않는다. 잠금을 강제로 무시하거나 원본 DB를 변경하지 않았다.
- **Coinone 잔고 조회 실패**: 현재 로그 1회, 압축 로그에도 1회 남아 있다. 현재 PAPER 자금은 가상 원장 기준으로 계산하므로 이것만으로 PAPER 무거래를 설명할 수 없다. 당시 외부 응답은 재현하지 않았으며 API 키를 사용한 재조회도 하지 않았다.
- **Upbit 시세 해석 실패**: 10/08 09:31~09:32 KST의 3.9.2.7 PAPER 로그에 종목 ID 중복 시 `safeMarket()`이 상품 구분을 요구하는 오류 9줄이 있다. 설치 SDK에 동일 중복 상태를 주입해 재현했다. 단건은 해당 예외 때 명시적 현물 종목으로 복구하고, 일괄 조회도 공개 KRW 시세와 현물 종목을 명시해 해석한다. 응답 종목 불일치는 거절한다. 원래 사용자의 중복 상태 생성 경위까지 확인한 것은 아니다.
- **KIS 연결 실패·포지션 상태 오류**: 증권 경로의 별도 문제다. 현 소스의 연결 실패 시 미확인을 유지하는 동작을 확인했으나 당시 계좌 API 응답 복구를 검증하지 않았다. 이를 코인 PAPER 무거래의 원인으로 합치지 않는다.
- **키움 세션 불확실·TimeoutError**: 최근 로그에도 자동 재로그인 차단 경고가 반복된다. 중복 로그인 방지를 위한 보호 동작이며 강제 자동 재로그인으로 해제하지 않는다. 사용자 Windows의 OCX·증권 세션 인수는 미실시다.
- **과거 `inserted_id` NameError·DB locked**: 압축 과거 로그에도 존재한다. 현 소스에서는 ID 할당 후 사용하는 경로와 재처리 테스트가 존재한다. 과거 손익·체결 이력까지 전부 복구됐다는 의미가 아니다.
- **Bitget 비암호화 상품 혼입**: NATGAS/XAG 같은 원자재 및 명시적 `isRwa=YES` 상품이 일반 USDT 무기한 상품으로 표시될 수 있었다. 후보 분류에서 제외하는 회귀를 추가했다. 이 문제를 장기 무거래의 직접 원인으로 단정하지 않는다.

## 이번 추가 수정

1. Bybit는 공개 linear 상품으로 제한하고 인증 통화·옵션 조회를 제거했다. Bitget는 공개 USDT-FUTURES 계약 목록만 조회하며 타 결제통화/모의상품 조회도 제거했다. 가격·수량 정밀도, 최소 주문, 계약 단위, 수수료, 거래 상태를 유지한다. 현재 820행 전부를 설치 CCXT 4.5.50의 정규화 결과와 대조해 차이가 없었다. Upbit는 단건·일괄 시세 해석에서 현물 상품을 명시했다. 필요한 공개 API 자체의 장애는 여전히 실패로 처리하며 과거 목록으로 우회하지 않는다.
2. 자금 부족, 다른 주문의 자금 예약, 이전 주문 대조 필요, 동시 운용 한도, 종목 거래 중단, 수익성 검증, 신뢰도 계산 오류 등을 일반 ‘진입 미실행’보다 구체적인 유한 코드·조치로 표시한다. 제공 근거에 구체적 원인이 없을 때는 확정 사유를 만들어 내지 않는다. Unified 경로의 실제 동적 신뢰도 보류도 적용 수치를 남긴다.
3. 7개 코인 기관의 실제 실행 주기에 관찰을 연결했다. **현재 실행 세션에서 30분 이상 신규 주문 처리 기록이 없고 실행 주기가 3회 이상 종료**되면 메인 거래 현황에 ‘거래 활동 확인 필요’를 표시한다. HOLD도 포함하므로 기술 오류라고 단정하지 않는다. **15분 이상 실행 주기 갱신이 없으면** 별도 갱신 확인 경고를 표시한다. 정지·LEARNING에서는 무거래 경고를 내지 않는다.
4. 기관 운용 요약에 관찰 시작, 경과 시간, 최근 주기, 최근 판단 최대 128건 중 상위 3개 사유와 횟수를 표시한다. 기술 차단은 기존 자금·위험·목록 근거와 함께 확인한다. 다른 기관·PAPER/LIVE·계정·초기화 세대로 근거가 섞이지 않도록 검사했다.

감시는 수익이나 체결 빈도 목표가 아니다. 앱 실행 세션 기준이며 재시작 이전 전체 기간 통계가 아니다. 주문 처리 기록은 체결 확인과 다르다. 화면을 닫아 놓은 사용자를 위한 OS 알림·메일·메신저 전달, 서버 중앙 장애 집계·자동 업데이트 보급률 측정은 이번 수정에 포함되지 않는다. 보호 조건을 자동으로 낮추거나 LIVE를 자동 재개하지 않는다.

## PAPER/LIVE 근거와 기존 사용자

문의 OKX 진단은 명시적으로 PAPER다. 제공 설정의 `paper_trading=true`와 현 실행 모드 해석 결과도 7기관 전부 PAPER이며 최근 세션 로그와 별도 PAPER 원장에 부합한다. 폴더에는 과거 LIVE/미분류 이력도 있으므로 폴더 전체를 PAPER 전용으로 취급하지 않는다. 최근 LIVE 실제 거래 중단 원인까지 이 자료로 확정하지 않는다.

기존 6기관의 미확정 원장 문제는 프로그램 패치만 설치해도 과거 결제통화가 생기는 문제가 아니다. 원본을 보존한 별도 PAPER 평가 준비가 필요하다. 실제 runtime action을 원장 복사본에서 재생하여 6기관의 새 자금 기준·예약 검사 통과, 반복 생성 금지, 주문·자동 시작 없음, 원장 보존을 재확인했다. 사용자 PC 원본에는 적용하지 않았다. 보유·미확정 주문이 있으면 우회하지 않고 거절한다.
