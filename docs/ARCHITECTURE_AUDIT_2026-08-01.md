# NoahAI v3.9.0.5 구조·연동 종합 감사

- 감사일: 2026-08-01
- 범위: 실행 진입점, 거래소·증권사 어댑터, 주문·잔고·포지션·통계, 대시보드·위젯, 설정 재주입, PyInstaller 포함 범위
- 판정 원칙: 소스 존재나 문자열 매트릭스 통과를 실연동 완료로 간주하지 않는다.

## 결론

Fix Patch 5 기준으로 소스 구조·계약·회귀·문서 정합 작업은 마감했다. 다만 자동 테스트를 Windows EXE, 실계정 체결, 24~72시간 지속성의 증거로 확대하지 않는다.

1. 비바이낸스 거래소가 `ExchangeManager`와 `UnifiedTradingManager`에서 별도 어댑터로 생성될 수 있어 잔고·포지션·주문 화면이 서로 다른 연결 상태를 볼 수 있었다. 이번 감사에서 공통 어댑터 재사용으로 수정했다.
2. Bithumb 주문내역 폴백은 정상적인 0건 응답도 세션 영구 `unsupported`로 고정했다. 거래 전 빈 응답 뒤 실제 거래가 생겨도 가져오기가 재시도되지 않는 원인이며 이번 감사에서 수정했다.
3. 계좌 표시를 `ui/controllers/account_state_controller.py`로 분리했고 현물 보유자산·선물 포지션·PAPER 가상 포지션·빈 상태·조회 실패를 계약으로 구분했다. PAPER에서는 LIVE 저장소와 실계정 API를 표시 정본으로 사용하지 않으며, 가상 원금 장부가 없어 잔고를 임의 추정하지 않는다. 핵심 주문 규격·TP/SL 경로의 무음 예외은 차단/경고로 보강했다.
4. 감사 당시 증권사 15개 모드 매트릭스는 등록 문자열 검증에 그쳤고 신한 `xingapi`, 미래에셋 `kis` 등 표기와 실행 경로가 불일치했다. Fix Patch 3에서 공식 계약 4개 경로로 재분류하고 설정 이전·어댑터·권한을 교정했다.
5. 사용하지 않는 변형 위젯·충돌/손상 소스·레거시 테마·대시보드 정의 전용 메서드를 활성 패키지 밖으로 격리했다. 16개 아티팩트는 SHA-256 매니페스트로 복구 가능하게 보존한다.
6. 2026-07-31 12:40의 Windows EXE는 2026-08-01 소스 변경보다 오래되어 이번 수정이 들어 있지 않다.
7. Fix Patch 4의 가시성 최적화는 숨김 판정 시 반복 예약 자체를 폐기했다. Windows/CTk에서 Map 이벤트가 누락되면 탭 전환으로 한 번만 갱신된 뒤 다시 멈출 수 있었다. Fix Patch 5는 갱신 생명주기를 독립 모듈로 분리하고 숨김 중 저빈도 생존 확인을 유지한다.
8. 공통 거래소 LIVE 경로는 `exchange_execution_log`만 기록하고 `trade_log` 진입 행을 만들지 않았다. 청산 시 UPDATE 대상이 없어 거래통계·거래소 대시보드 청산 성과·AI 리포트가 함께 누락됐다. Fix Patch 5는 체결 확정 시 두 원장의 생명주기를 함께 시작한다.
9. 공통 경로가 NEW/PENDING 주문도 성공으로 인정해 내부 포지션을 만들면서 실제 체결 원장에는 확인 대기로 남기는 모순이 있었다. Fix Patch 5는 접수 원장은 보존하되 양수 체결 확인 전 포지션·성과 기록 승격을 차단한다.
10. `data/260801_Teayu`의 실제 DB·로그를 대조해 시작 마이그레이션이 `trade_log`를 삭제하고 청산 완료 행만 복원한 뒤, `order_id` 등 신규 컬럼 없이 테이블을 남기는 결함을 확인했다. 그 결과 재시작 시 미청산 행이 사라지고 2026-07-31 실제 진입 기록 29건이 `table trade_log has no column named order_id`로 실패했다. Fix Patch 5는 DROP/복원을 제거하고 컬럼·인덱스만 증분 보강하며 전후 행 수를 검증한다.

증권사는 `SUPPORTED_API_VERSIONS`와 공식 계약명을 일치시켰다. v3.9.0.5에서 키움 `openapi_plus/pykiwoom`, 신한 `partner_rest/shinhan_openapi_v2`, 미래에셋 `partner_rest/mirae_partner_profile`, 한국투자 `rest/kis_openapi_v1`로 정본화했다. `kiwoom_api`는 pykiwoom으로 설정 이전하고, 신한에 잘못 섞였던 `xingapi`는 LS증권 API이므로 신한에서 분리한다. 과거 미래에셋 `kis` 경로도 한국투자 KIS와 분리했다.

실주문은 영구 검증 플래그로 일괄 차단하지 않는다. `NOT PAPER AND 전역 LIVE AND 증권사별 LIVE AND 어댑터 런타임 준비 AND 주문 가드레일`을 모두 만족할 때만 허용한다. 신한·미래에셋은 계약 프로필이 빠진 경우 잘못된 추정 URL로 전송하지 않고 구체적인 설정 미완료 사유를 반환한다. 상세 정본은 `STOCK_BROKER_CONTRACTS_v3.9.0.5.md`에 있다.

## 대시보드·위젯 감사

- 실제 대시보드에서 사용하는 주요 위젯: AI 학습·리포트·어시스턴트, 사용자 매뉴얼, 커스텀 전략, AlphaArena, 시장 트렌드, 금융 인텔리전스, 실시간 로그, 차트 분석.
- 고신뢰 미사용/손상 파일, 레거시 테마, 대시보드 정의 전용 메서드를 활성 패키지 밖의 복구 가능한 격리 폴더 `noahai_client_source_quarantine_20260801`로 이동했다. 총 16개 아티팩트이며 사용자 거래 데이터·로그·자격증명은 포함하지 않는다.
- `docs/TRADING_FLOW.md`와 위젯 변형 가이드는 현재 활성 `ai_learning_widget.py` 기준으로 교정했다.
- PyInstaller spec은 `build_safe.py` 단일 생성기로 통합했다. 폐기 테마 hidden import와 Python 소스 폴더의 `datas` 이중 번들을 제거했고, Windows 대상에서 `win32_setctime`을 잘못 제외하던 플랫폼 판정도 수정했다.
- 대시보드 정의 전용 메서드 23개를 외부 격리로 이동했고 클래스는 238개 메서드로 정리했다. 자동 감사 기준 정의 전용 메서드는 0개이다.
- `theme_system` 활성 Python 소스는 전부 격리했다. 현행 UI는 `utils.fixed_colors`와 `ui.visual_system`만 사용하며 남은 `__pycache__`는 생성 산출물이지 소스·빌드 입력이 아니다.

## 정리·개선 순서

1. P0: 거래소 클라이언트 단일 정본, Bithumb 빈 이력 재시도, Binance 포지션 정본을 유지하고 실제 계정으로 재검증한다.
2. P0: Windows EXE를 다시 빌드해 소스 시각·SHA·manifest를 일치시킨다.
3. P1 완료: 깨진 미사용 파일을 활성 소스에서 격리하고 위젯 변형 문서를 기본 파일 기준으로 통합했다.
4. P1 완료: 증권사 지원 목록을 공식 계약 4개로 정본화하고, 구현 경로의 임시 전면 차단 대신 전역·증권사·런타임 준비·가드레일 AND 게이트를 적용했다.
5. P1 일부 완료: 거래소 계좌 상태를 하위 컨트롤러로 분리했다. 대시보드 전체 모놀리스의 추가 분해는 기능 변경 시 진행할 장기 품질 개선이며 Fix Patch 5 배포 차단 조건은 아니다.
6. P2 지속: 광범위 `except Exception: pass`를 기능 변경 단위로 상태 객체와 오류 코드로 교체한다. 계좌 조회·최소 주문·TP/SL 핵심 경로는 우선 보강 완료했다.
7. P2 완료: PyInstaller spec을 생성 경로 하나로 통일하고 source data 전체 번들 대신 실제 import/필수 자산 allowlist를 사용한다.
