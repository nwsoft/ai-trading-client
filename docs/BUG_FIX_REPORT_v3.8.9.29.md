## 1. Binance `time` 예외

증상:

```text
UnboundLocalError: cannot access local variable 'time' where it is not associated with a value
```

정확한 원인:

- `trading/trader.py`의 `execute_trading_cycle()` 안쪽 조건문에 `import time`이 있었습니다.
- Python은 함수 안의 import 대상도 함수 전체에서 지역변수로 판단합니다.
- 조건문이 실행되기 전에 같은 함수의 `time.perf_counter()`가 호출되면 아직 값이 배정되지 않은 지역변수를 읽어 예외가 발생했습니다.

조치:

- 함수 내부 `import time`을 제거하고 모듈 전역 import만 사용합니다.
- AST 회귀 테스트로 거래 사이클 함수 안에 같은 지역 import가 다시 들어오지 못하게 했습니다.

## 2. OKX 분석 대상 0개

정확한 원인은 두 가지가 겹쳤습니다.

1. Evaluator의 fallback 후보가 문자열 심볼 목록으로 반환될 수 있는데 `UnifiedTrader._prefilter_supported_coins()`는 dict만 처리했습니다. OKX의 문자열 후보가 모두 버려져 10개 선택 후 0개 확정이 됐습니다.
2. Analyzer가 호출 시 거래소 이름을 받았지만 현재가와 캔들을 요청할 때 `exchange_name`을 ExchangeManager에 전달하지 않았습니다. 따라서 비바이낸스 심볼이 기본 선택 거래소 컨텍스트로 조회될 수 있었습니다.

조치:

- 문자열과 dict 후보를 모두 정규화해 전처리합니다.
- 현재가·캔들·캐시 키에 요청 거래소 이름을 끝까지 전달합니다.
- OKX 문자열 후보 2개가 2개 분석 대상으로 유지되는 회귀 테스트를 추가했습니다.

## 3. Bybit/Bitget 코인 선택 품질

증상:

- 후보 수는 존재하지만 EWY, SKHY, SNDK, SAMSUNG, IBM, INTC, MSTR 같은 토큰화 주식 선물이 암호화폐 후보에 포함됐습니다.
- 이런 종목은 암호화폐 학습/신호 조건과 데이터 특성이 달라 HOLD 또는 데이터 부족이 반복되어 사용자는 코인이 선택되지 않는 것으로 체감했습니다.

조치:

- 기본 토큰화 비암호화 기초자산 목록을 자동선정에서 제외했습니다.
- `futures_selection.<exchange>.excluded_bases` 설정으로 거래소별 추가 제외가 가능합니다.
- KRW 거래소 Upbit/Bithumb 경로는 이 USDT 필터 변경의 대상이 아닙니다.

## 4. 시작 버튼과 `시작 중…` 고착

정확한 원인:

- 대시보드 백그라운드 스레드가 `main.on_start_exchange()`를 호출했습니다.
- 실제 엔진 시작 뒤 main 코드가 Tk 위젯을 작업 스레드에서 직접 변경하는 경로가 있었습니다.
- Tk 스레드 예외가 발생하면 엔진은 이미 시작됐는데 호출 결과는 실패로 처리될 수 있어 버튼과 상태가 준비 상태에 남았습니다.

조치:

- 모든 UI 변경을 대시보드의 안전한 `after` 경로로 예약합니다.
- 콜백 반환값뿐 아니라 Binance 워커/UnifiedTrader monitoring thread의 실제 실행 상태를 재확인합니다.
- 실제 실행 확인 후 버튼은 `중지`, 상태는 `진행 중`으로 통일합니다.

## 5. 강제 종료 시 로그 유실

정확한 원인:

- v3.8.9.28은 파일 로그에 `enqueue=True` 비동기 기록을 적용했습니다.
- 프로세스를 강제 종료하거나 `os._exit()`로 즉시 끝내면 큐에 남은 마지막 로그가 디스크에 기록되기 전에 종료될 수 있습니다.
- 재시작이 과거 로그를 지우는 것이 아니라, 종료 직전 큐에 남은 꼬리 로그가 기록되지 않은 현상입니다.

조치:

- 대시보드 상단에 `⏻ 종료` 버튼을 추가했습니다.
- 종료 순서를 신규 진입 차단 → 거래 루프 중지 → DB flush → loguru complete/표준 로그 flush → 창 종료로 통일했습니다.
- 운영체제 강제 종료·전원 차단까지 완전 보장할 수는 없으므로 안전 종료 버튼 사용을 안내합니다.

## v3.8.9.28에서 발견되지 않은 이유

- 28의 코인 선택 테스트는 “목표 수 달성 후 불필요한 fallback 재진입 차단”을 검증했습니다.
- 실제 비바이낸스 Analyzer 호출에서 거래소 컨텍스트가 현재가/캔들까지 전달되는지, 그리고 fallback이 문자열일 때 Unified 전처리를 통과하는지는 검증하지 않았습니다.
- 29에서는 이 두 경계를 직접 검증하는 회귀 테스트를 추가했습니다.

## 남은 배포 게이트

- macOS 소스/정적/회귀 검증과 Windows EXE 배포는 별도 단계입니다.
- 자동업데이트 manifest에는 실제 Windows 빌드 파일의 URL, 크기, SHA-256이 필요하므로 28 EXE 값을 29로 가장해 재사용하지 않습니다.
