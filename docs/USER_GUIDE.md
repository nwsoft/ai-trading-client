## NoahAI는 당신을 위해 무엇을 할 수 있는가?

### NoahAI란 무엇인가?

**NoahAI**는 당신이 금융을 깊이 있게 배우지 않아도 **자신의 자산·상황·위험을 이해하고 올바른 선택을 할 수 있도록 돕는 AI 금융 동반자**입니다.

NoahAI의 핵심은 **자동으로 돈을 벌어주는 시스템이 아니라, 금융 의사결정을 투명하고 검증 가능하게 만드는 인프라**입니다.

## 업데이트 확인 방법 (사용자 필독)

신규 기능·실거래 조건은 클라이언트 안에서 아래 순서로 확인합니다.

1. 업데이트 후 최초 1회 표시되는 `실거래 시작 전 필수 안내`
2. 대시보드 하단 `실거래 필수 안내` 또는 상단 `메뉴얼 → 실거래 준비`
3. 설정창 상단의 설치 식별·LIVE 조건과 `실거래 필수 안내`
4. `메뉴얼 → 업데이트`에서 버전별 변경 상세 확인
5. 기능 적용 범위를 AI 어시스턴트에 질문해 현재 설정 기준으로 재확인

최초 안내에서 `내용을 확인했습니다`를 선택한 뒤에도 대시보드와 설정의 상시 버튼으로 같은 정본을 다시 열 수 있습니다. 안내에는 6개 거래소·4개 증권사, 회원등급, LEARNING/PAPER/LIVE, 현물 보유자산과 선물 포지션 차이, API·증권 계약·가드레일·실계정 검증 순서가 포함됩니다.

운영 원칙:
- 화면에 보이지 않는 기능은 아직 제공되지 않는 것으로 판단합니다.
- 문서 표현보다 현재 버전의 실제 UI 노출 상태를 우선합니다.
- 버전이 같아도(예: v3.8.9.20) 날짜 기준으로 추가 업데이트가 누적될 수 있습니다.
- 운용 리스크 대응은 상용화 이후가 아니라 테스트 단계에서 먼저 수행합니다.
- 점진적 적용은 지연이 아니라, 리스크를 통제하며 빠르게 검증하기 위한 표준 절차입니다.
- 사용자에게 보이는 기능 변경은 인앱 매뉴얼/가이드 안내가 함께 업데이트된 항목만 반영됩니다.
- 고정 큐레이션형 푸시 상품(예: 매일 n종목 푸시)은 기본 제공 범위가 아닙니다.
- 특정 확률 보장형 마케팅 문구(예: 상승확률 xx%)를 전제로 한 기능은 운영 기준에서 제외합니다.
- 유료 등급과 레퍼럴 무료등급은 권한이 다릅니다. 레퍼럴 등급은 관리자가 활성화한 해외 제휴 거래소만 사용할 수 있으며 수익을 보장하는 상품이 아닙니다.

### 거래소 계좌 화면 보는 법

- Upbit·Bithumb은 현물 거래소이므로 `보유자산`에 KRW와 양수 보유 코인이 나옵니다. `포지션 0개`를 현물 보유 0으로 이해하면 안 됩니다.
- Binance·Bybit·OKX·Bitget은 선물 `포지션`을 표시합니다. `실시간`은 현재 API 결과, `캐시 표시`는 최근 정상 결과, `조회 오류`는 API 실패입니다.
- PAPER에서는 포지션 제목과 건수에 `PAPER`가 표시되고 엔진의 가상 포지션·미실현 PnL을 보여 줍니다. 가상 계좌 카드의 `실잔고 미사용`은 오류가 아니라 실계정 잔고와 PAPER 성과를 섞지 않는 안전 표시입니다.
- 거래 통계의 `실제 체결`은 확정 체결 원장입니다. 승률·PnL은 NoahAI가 진입부터 청산까지 연결한 완료 거래만 계산하므로 건수가 다를 수 있습니다.
- Bithumb의 거래소 전체 과거 체결 API가 제한되어도 NoahAI가 제출해 주문 ID를 보존한 건은 개별 주문 재조회로 복구합니다. NoahAI 밖에서 직접 낸 수동 주문은 API 기능에 따라 자동 복구가 불가능할 수 있습니다.
- 구조·격리 판정은 `ARCHITECTURE_AUDIT_2026-08-01.md`와 `SOURCE_QUARANTINE_MANIFEST_20260801.md`를 정본으로 사용합니다.

- 화면의 `v3.9.0.5` 문자열만으로 Fix Patch 포함 여부를 판단하지 않습니다. 현재 공개 자산은 Fix Patch 1이고, Bybit 실행 모드·Bithumb 체결 기록·서비스 복귀 잔고·자동업데이트 보강은 Update Patch 1 Windows 재빌드 대상입니다.
- 자동업데이트는 초기 화면·거래소 연결이 끝날 시간을 두고 앱 실행 약 15초 뒤 한 번 확인합니다. 이후에는 `설정 → 업데이트`의 1~72시간 주기(기본 6시간) 또는 `업데이트 확인` 버튼을 사용합니다. 15초마다 검사하는 기능이 아닙니다.
- 버전 문자열이 같은 Fix Patch도 공개 manifest의 EXE SHA와 현재 설치 파일 SHA가 다르면 업데이트로 감지합니다. GitHub HTTPS와 manifest SHA-256이 일치해야 하며 인증서·Authenticode는 요구하지 않습니다. 무서명 EXE는 Windows SmartScreen/Defender가 평판 경고를 표시할 수 있습니다.
- Update Patch 1 배포 안내에는 빌드 시각·파일 크기·SHA-256을 함께 표시합니다.

## 처음 설정과 실행 모드

- 설정은 `일반 → 거래소 선택 → 거래소 API → AI 엔진/API → 고급 매매 계층 → AlphaArena → AI 시스템 상태 → 업데이트` 순서로 사용합니다.
- `일반` 상단에서 정본 v3.9.0.5, 현재 LEARNING/PAPER/LIVE 모드, 호환 보관 수와 설정 모순 수를 확인합니다.
- 위쪽 거래소 선택은 화면·시세·분석·학습 범위이고 아래쪽 실제 주문 실행 거래소는 신규 LIVE 주문 권한입니다.

## AI 커스텀과 코인·종목 선택은 이렇게 연결됩니다

### NoahAI의 대표 AI 전략 운영체제

> **NoahAI AI 커스텀 — 누구나 자신의 투자 지식을 AI와 함께 전략으로 만들고, 시장국면에 맞춰 검증·실행·개선하는 AI 전략 운영체제**

TradingView와 기존 자동매매에서 익숙한 LONG/SHORT, 진입·청산, TP/SL, 시간봉, PnL·MDD·Profit Factor와 월별·연별 표를 그대로 읽을 수 있도록 유지합니다. NoahAI는 사용자가 익힌 방식을 다시 버리게 하지 않고, 그 위에 원문 근거, 변환 차이, 미지원 차단, PAPER, 국면·위험·주문·체결 감사를 추가합니다.

외부에는 NoahAI를 `사용자의 금융 지식과 시장 데이터를 판단·검증·실행·기록으로 연결하는 AI 금융 의사결정 인프라`, AI 커스텀을 `책·영상·Pine·TradingView·사용자 대화의 투자 지식을 AI와 함께 전략으로 만들고 시장국면에 맞춰 검증·실행·개선하는 AI 전략 운영체제`로 설명합니다. TradingView의 차트·Pine·백테스트·알림 생태계를 복제하는 완전 대체재가 아니라, 해당 자료까지 받아 원문·누락·국면·위험·실행을 연결하는 상위 운영 계층입니다. 자세한 대외 설명과 사업 경계는 `docs/NOAHAI_EXTERNAL_POSITIONING_AND_BUSINESS_PLAN_20260804.md`를 확인하세요.

사용자 흐름은 `배우기 → 만들기 → 검증하기 → 실행하기 → 개선하기 → 공유하기`입니다. 현행 소스는 멀티모달 전략 입력, AI 멘토 인터뷰, 원문→규칙 근거·누락 확인, Noah Strategy IR v1, 안전 선언형 규칙, 버전 변경점, 검증 연구소, 일반/독립 역할, 전략 버전·승인·검증·적용, 국면·계좌·주문 안전과 LEARNING/PAPER/LIVE 분리를 구현했습니다.

분석 결과 상단의 보기 단계는 같은 전략을 다른 깊이로 보여 줍니다. `Level 1 이해·시험`은 요약·위험·누락·근거 연결을, `Level 2 핵심값`은 조건·위험·국면 값을, `Level 3 전체 IR`은 전체 노드·capability·원문 근거와 안전 DSL 편집기를 표시합니다. 단계를 바꿔도 전략이 자동 수정되거나 적용되지 않습니다. 버전 목록의 `IR v1.0`에서 저장된 실행 계약을 다시 확인할 수 있습니다.

`설정 → AI 엔진/API`에서 AI 커스텀 사용 난이도를 `초보자 / 일반 / 고급 / 실험실`로 선택할 수 있습니다. 이는 서로 다른 전략 엔진이 아니라 화면과 기능의 초기 노출값입니다. 과거 재생, 월·연도 표, Expression Graph, 제한형 사용자 지표 언어, 전략 패키지, 팀 권한 메타데이터, 품질 리포트, webhook, 감사 번들을 개별적으로 다시 켜거나 끌 수 있습니다.

고급 규칙의 부분청산·다단계 TP·추적손절·손익분기·재진입 계획은 허용 필드와 범위를 통과해야 저장됩니다. Binance·통합 선물 부분청산은 reduce-only 체결을 확인한 뒤에만 완료 처리하며, 재진입은 쿨다운이 지나도 새 진입 신호와 공통 가드레일을 다시 요구합니다. 중첩 Expression Graph와 제한형 사용자 지표 수식은 임의 Python/Pine을 실행하지 않습니다. 서명 webhook은 소스 검증 게이트만 구현되었고 서버 endpoint·영속 중복 방지·외부 E2E 전에는 운영 기능으로 보지 않습니다.

자동검증 결과에는 총 PnL·총 수익률·MDD·승률·Profit Factor와 데이터에 시간이 있으면 월별·연별 수익률 표가 표시됩니다. 이는 미래 수익 예측이 아니라 음수 PnL·과도한 낙폭·표본 부족을 거르는 최소 필터입니다. 백테스트만으로 전략을 자동 승격하지 않으며, 미사용 구간·비용 민감도·과최적화 경고와 PAPER 전진검증을 함께 확인해야 합니다.

전략 공유 형식은 `전략이름.noahstrategy`입니다. 이 패키지는 전략 규칙·출처·호환 버전·검증 조건을 담지만 API 키, 계좌번호, 잔고, 개인 주문·거래내역, 로컬 절대경로, 승인·활성 상태는 담지 않습니다. 가져온 전략은 항상 비활성 검토 버전에서 시작합니다. 로컬 전략 여권·패키지는 6A로 구현되었고 실제 회원/팀 서버 공유는 6B 외부 게이트, 결제·구독·정산·환불·분쟁이 필요한 마켓은 별도 7단계입니다. 자세한 계약은 `docs/AI_CUSTOM_STRATEGY_SHARING_AND_PASSPORT.md`를 확인하세요.

daltrading의 전략 허브는 하나의 전체 순위 대신 추세장, 횡보장, 저위험, 소액 계정, Binance 선물, Upbit/Bithumb 현물, 장기 PAPER, 실제 체결, 초보자 설명 우수로 나누어 보여 줍니다. 공개·권리·패키지·검증·가드레일 조건을 통과한 실제 전략만 표시하므로 빈 카테고리는 오류가 아닙니다. 승률·총수익률만으로 순위를 정하지 않으며, 이 화면은 유료 판매나 수익 보장이 아닙니다. 일반 이상 프로필에서는 저장 버전을 `.noahstrategy`로 내보내고 가져올 수 있습니다. 로컬 패키지는 SHA-256 변조와 민감정보를 검사하고 항상 비활성 검토 버전으로 가져옵니다. 회원 초대·철회·서버 다운로드를 포함한 실제 팀 공유는 후속 6B 단계입니다.

전략 허브는 먼저 기본 30일 무료 테스트로 운영합니다. 관리자는 충분한 실사용과 오류·장시간 안정성을 확인한 뒤 유료 전환을 검토하지만, 약관·환불·정산·가격·실제 결제/구매 권한 인프라가 모두 준비되기 전에는 서버가 유료 전환을 차단합니다. 현재는 결제 실행기가 없는 무료 테스트 단계입니다.

- 공통 첫 단계에서 각 거래소·증권사의 지원 종목, 거래 가능 상태, 유동성·거래대금, 스프레드와 데이터 품질을 검사합니다.
- 일반 역할은 `사용자 고정 + NoahAI 자동 선정 → 종목 분석 → 기본 AI 후보 → 커스텀 확인` 순서입니다.
- 고급 역할은 `사용자 고정 + 전략 UniversePolicy → 로컬 사전필터 → 전략 지표 → 사용자 전략 독립 평가` 순서입니다. 포함/제외 종목, 최소 거래대금, 최대 스프레드, 변동성 범위와 후보 수를 정할 수 있으며 종목선정 때문에 LLM을 추가 호출하지 않습니다.
- `코인 정보` 또는 `주식 정보`에서 추가한 종목은 평가 대상에 우선 포함되지만 진입을 강제하지 않습니다.
- 국면 기준은 전략별로 `전체 시장(권장)·종목·둘 다·사용 안 함` 중 고릅니다. 선택한 범위의 데이터가 없으면 다른 국면으로 몰래 대체하지 않고 HOLD 사유를 기록합니다.
- `BINANCE만`은 Binance 후보에만 적용됩니다. `모든 가상자산 거래소`는 각 거래소가 자기 지원 종목으로 후보를 따로 만든 뒤 같은 전략을 적용한다는 뜻입니다. Binance 코인 목록을 Upbit·Bithumb에 복사하지 않습니다.
- `모든 증권사`도 같은 원칙입니다. 각 증권사의 연결·시장목록·주문규격 안에서 주식/ETF 후보를 따로 만들고 전략을 적용합니다.
- 일반 방식은 기본 AI의 LONG/SHORT 후보를 커스텀 조건으로 재확인합니다. 고급 방식은 사용자 전략이 방향과 진입·청산값을 결정하지만 시장국면·계좌·주문 안전은 공통으로 검사합니다.
- Bitget과 OKX가 모두 실제 주문 대상이고 같은 BTC 기회가 안전검사를 통과하면 기본값에서는 양쪽 주문이 가능합니다. 동일 기회 ID로 통합 위험과 대상별 결과를 관리하며, 동일 대상·계좌·신호의 재제출만 중복 차단합니다.

### TP/SL 화면·로그의 세 값

- `저장된 기본 폴백`: 동적 계산이나 전략 청산값을 만들 수 없을 때만 쓰는 마지막 기준입니다.
- `현재 적용값`: 현재 종목·국면·변동성 또는 선택한 커스텀 전략에서 실제로 결정한 TP/SL과 근거입니다.
- `보험 제출값`: 진입가와 거래소 가격 단위를 적용해 실제 거래소에 제출·확인한 TP/SL 가격입니다.

세 값은 서로 다를 수 있으며 정상입니다. 고급 커스텀 전략의 현재 적용값은 NoahAI가 임의로 좁히지 않습니다. Binance·지원 선물 거래소는 보험 제출 상태를 표시하고, Upbit·Bithumb 현물 또는 서버 측 보험 주문을 사용하지 않는 증권 경로는 `모니터 청산·보험 주문 미제출`로 표시합니다. PAPER는 실제 제출 없이 가상 청산 상태로 기록합니다.

### AI 호출과 비용은 이렇게 제한됩니다

- 시장분석은 로컬 기술 신호를 먼저 계산합니다. 같은 시장상태는 30분 동안 모델 결과를 재사용하며 단순 새 캔들, 지속 중인 LONG/SHORT, 계속 과매수·과매도인 RSI만으로 반복 호출하지 않습니다. 후보 전환·RSI 임계 진입·MACD 교차·국면 전환은 즉시 반영하고 미세 변화는 최소 5분 간격을 둡니다.
- 기본 시장 호출예산은 전역 1일 240회, 거래소별 1일 40회, 월 6,000회입니다. 시장분석 밖 자동 AI 역할도 공통 원장에서 전역 1일 360회·월 9,000회와 역할별 상한을 적용합니다. 한도에 닿으면 모델 호출만 로컬 신호로 대체하며 거래 루프는 계속됩니다.
- 포지션 크기 AI는 같은 심볼·방향·상태를 15분 재사용합니다. 방향 변경, 1% 이상 가격 변화, 신뢰도 0.10 이상 변화가 있을 때만 다시 요청하고 실패 후 120초 동안 재시도하지 않습니다.
- 손실패턴 비교는 같은 신호와 같은 최근 손실 표본을 15분 재사용하고 실패 후 120초 동안 재시도하지 않습니다.
- 성과 기반 임계값 최적화는 최소 10개 완료 거래 후 새 거래 5개마다 최대 한 번입니다. 같은 실패 표본을 10초 거래 사이클마다 다시 요청하지 않습니다.
- 거래 후 손익 복기는 포지션 종료 이벤트에만, 전략 원문·차트 이미지·AI 어시스턴트는 사용자가 요청한 때만 호출합니다.
- `실제 주문 실행 거래소`가 0개여도 위쪽 `거래소 선택`에 포함된 LEARNING 거래소는 분석하므로 비용이 발생할 수 있습니다. 비용을 줄일 때는 사용하지 않는 관찰·학습 거래소를 끕니다.

재생하고 양쪽 수수료·슬리피지·스프레드를 반영한 PnL, Profit Factor, 기대값, MDD, 거래목록과 국면별 결과를 기록합니다.
코인 명시 청산은 실시간 모니터에 연결됩니다. 주식/ETF도 진입 전략 버전·명시 청산·TP/SL을 XAI 기록에서 복원해 클라이언트 자동 청산에서 평가하며, 증권사 서버 측 보험/브래킷 주문은 어댑터별 지원 범위입니다.

시장상황 선택:

- 영상·책·Pine·설명에 상승장·하락장·횡보장·고변동·저변동이 명시되면 해당 국면을 추천 선택합니다.

### v3.9.0.1 AI 커스텀 위험기반 전략 사용법 (2026-07-24)

AI 커스텀은 사용자가 정한 전략을 AI가 구조화하고 검증하는 기능입니다. 기본 모드는 계속 NoahAI가 자동 판단하며, AI 커스텀을 사용한다고 해서 시스템이 사용자 전략을 임의로 바꾸지는 않습니다.

가장 쉬운 순서:

1. `AI 커스텀`에서 전략 설명이나 Pine/문서/차트 자료를 넣고 `AI 분석 및 전략 초안 만들기`를 누릅니다.
2. AI가 보여주는 진입·청산·손절·익절·위험예산·시장상황 질문에 답합니다. 모르는 값은 임의 입력하지 말고 전략 의도를 문장으로 보완합니다.
3. `전략 위험예산`에서 거래당 허용손실, 최대 증거금 사용률, 레버리지 상한을 고릅니다.
4. `국면 이탈 시`에서 `기본 노아AI에 맡김` 또는 `커스텀 신규 진입 일시정지`를 선택합니다.
5. 실제 레버리지는 사용자가 목표 배수를 찍는 방식이 아니라 거래당 허용손실 ÷ 손절거리로 필요한 총 노출을 구한 뒤, 증거금 한도와 레버리지 상한 안에서 계산됩니다.
6. `검토 및 전략 버전 저장` → `내용 확인 후 승인` → `자동 검증 실행` → `최종 적용` 순서로 진행합니다.
7. 검증 후 전략 행의 `개선안 · …` 버튼에서 근거와 제안을 확인합니다. 현재 버전을 자동 변경하지 않으므로 반영하려면 사용자가 새 버전을 만들고 다시 승인합니다.

예시:

- 계좌 대비 거래당 허용손실 0.5%
- 손절거리 1%
- 최대 증거금 사용 10%
- 레버리지 상한 5배

이 경우 목표 총 노출은 계좌의 50%이고, 증거금 10%를 쓰려면 5배가 계산됩니다. 손절거리가 넓어지면 필요한 노출과 레버리지는 낮아집니다. `레버리지 상한`은 항상 목표값이 아니라 최대 허용값입니다.

주의:

- 자동검증 미통과 전략의 `검증미통과 안전 시험`만 1배·전략 비중 최대 1%를 강제합니다. 일반 운용 사용자 전체에 1배를 강제하지 않습니다.
- 고변동 시장도 기본적으로 일괄 차단하지 않고 합의 점수와 기존 가드레일로 평가합니다. 설정 경로는 `설정 → 고급 매매 계층 → 전략 엔진 세부 설정 → 고변동장 처리`이며, `항상 차단(block)`을 고른 경우에만 일괄 차단합니다. AI 어시스턴트에 현재값·위치를 묻거나, “high vol 차단을 해제해줘”라고 요청해 확인 후 변경할 수도 있습니다.
- 전략 엔진은 시장국면의 판단 시각·신뢰도·근거와 전환 후보를 함께 남깁니다. 오래된 시세 입력은 차단하고 일반 국면 전환은 연속 확인 후 반영해 한 번의 튐으로 전략이 왕복 변경되는 일을 줄입니다.
- “매수해줘”, “거래 시작/중지해줘”, “API 키 바꿔줘”, 출금·송금처럼 직접 실행을 뜻하는 요청은 현재 채팅에서 실행하지 않습니다. NoahAI는 미실행 상태와 필요한 안전 검증을 명확히 답하고, 분석·설정 위치 안내만 제공합니다.
- 가드레일은 API 장애·급변동·미체결·슬리피지·청산 가능성을 없애지 않습니다.

### AI 동반자가 할 수 있는 5가지

#### 1. **설명 (Explain)**
- 자산·거래·시장을 이해하기 쉬운 언어로 설명
- 기술적 용어를 평신도 수준으로 번역
- "왜 그런 신호가 나왔는가"를 구조적으로 제시

#### 2. **비교 (Compare)**
- 금융상품을 조건별로 비교 분석
- 대출, 보험, 예금 등 선택지 제시
- 당신의 상황에 맞는 추천안 제공

#### 3. **경고 (Warn)**
- 비정상 거래 자동 탐지
- 금융사기 위험도 평가
- 위험한 거래 조건 사전 경고

#### 4. **기록 (Record)**
- 모든 판단과 거래를 자동 기록
- 의사결정 근거를 일관되게 저장
- 사후 검증과 학습에 활용

#### 5. **검증 (Verify)**
- "내 결정이 맞았는가" 사후 검증
- AI 판단의 정확도 추적
- 시간 경과에 따른 성과 비교

### 기술 기초: 판단·설명·기록·검증·환류

NoahAI는 다음 5단계 파이프라인으로 운영됩니다:

1. **판단 (Decision)**: AI가 분석하여 신호/추천을 생성
2. **설명 (Explanation)**: 왜 그 판단을 했는지 구조적으로 설명
3. **기록 (Logging)**: 판단·근거·결과를 자동으로 저장
4. **검증 (Verification)**: 판단이 맞았는지 나중에 확인
5. **환류 (Feedback)**: 검증 결과를 다음 판단에 반영

이 구조를 통해 **신뢰할 수 있고 학습하는 AI 금융 동반자**가 가능해집니다.

### 2026-04-30 고도화 적용 상태 (운영 정책 ON 시)

- 적용 경로: 주식 자동매매 루프 + 통합 코인 주문 루프
- 바이낸스 경로: 바이낸스 전용 거래 루프에도 동일한 1~5 계층이 적용됩니다.
- 수익성 검증: 일반 KPI 미달은 최소 위험 회복 학습, Hard MDD 초과는 자동매매 진입 차단
- 포트폴리오 오케스트레이션: 자산군 리스크 버짓/상관관계 기반으로 주문 수량 자동 조정
- 실행 품질 최적화: 주문 타입 선택 + 재시도 + 타임아웃 + 슬리피지 상한 적용
- 전략 엔진: 레짐 필터/합의 점수/쿨다운으로 과매매 신호 차단
- 운영 자동화: 이상 징후 탐지, 롤백 액션 제안, 일일 브리핑 자동 생성

위 고도화는 정책값에서 활성화했을 때 적용됩니다.

전략 엔진은 매매전략을 새로 생성하는 기능이 아니라 AI·커스텀 전략이 만든 진입 후보를 후행 필터링합니다. 합의 임계값은 `0.10~0.95`이며 높을수록 보수적입니다. 예를 들어 `0.60`이면 합의 점수 0.60 이상만 다음 가드레일로 넘어갑니다. 심볼 쿨다운은 같은 종목의 재진입 최소 대기시간(`0~3600초`)입니다. 고변동장 기본값 `evaluate`는 무조건 진입이 아니라 나머지 계층으로 계속 평가한다는 뜻이며, `block`일 때만 고변동 후보를 즉시 차단합니다.

적용 범위는 표준 자동매매 경로인 Binance·Bybit·OKX·Bitget·Upbit·Bithumb·증권입니다. 학습 전용 모드에서는 주문 계층을 실행하지 않으며 AlphaArena는 별도 실행 체계입니다.

### 운영 정책 ON/OFF가 무엇인가

- 위치: settings의 `advanced_trading_layers` 각 항목의 `enabled`
- ON: 해당 계층이 실제 주문 판단에 개입합니다.
- OFF: 해당 계층은 우회되고 기존 로직으로 동작합니다.

사용자 관점에서 왜 필요한가:

- 장애 대응: 시장 급변/거래소 이슈 시 일부 계층만 임시 OFF 가능
- 단계적 적용: 신규 전략을 한 번에 전체 반영하지 않고 점진 적용 가능
- 원인 분석: 수익성/실행품질/전략엔진 중 어느 계층이 영향을 주는지 분리 확인 가능

계층별 기능 요약:

- `profitability_validation.enabled`: 극단적 MDD는 차단하고 일반 성과 미달은 최소 위험의 회복 학습으로 전환
- `portfolio_orchestration.enabled`: 종목별 위험도/상관관계 기반 수량 자동 보정
- `execution_optimizer.enabled`: 재시도/타임아웃/슬리피지 상한으로 체결 품질 관리
- `strategy_engine.enabled`: 레짐 필터와 쿨다운으로 과매매 억제
- `ops_automation.enabled`: 이상 징후 감지 및 롤백 액션/일일 브리핑 생성

초기 운영 권장:

- 실거래 초기는 `safe` 프리셋 기준으로 시작
- 전략 검증/디버깅은 `dev` 프리셋으로 계층 OFF 후 원인 분리
- 공격적 운용은 `aggressive` 프리셋을 쓰되 리스크 한도와 함께 사용

### 수익성 검증 차단이 발생했을 때(중요)

대표 차단 로그:

- `바이낸스 수익성 검증 차단: ['insufficient_trades', 'win_rate_below_threshold', 'sharpe_below_threshold', 'walkforward_below_threshold']`

의미:

- 시스템 오류가 아니라 안전 가드레일 발동입니다.
- 종료 거래 부족은 1포지션·1배 제한 학습, 일반 성과 미달은 위험배수 0.15 회복 학습으로 거래 표본을 계속 쌓습니다.
- Hard MDD를 넘는 심각한 손실 구간만 신규 진입을 차단합니다.

권장 대응 순서(운영 표준):

1. 게이트 임시 OFF(dev): 숙련된 개발·진단 담당자만 대시보드 환경설정 → 고급 매매 계층 → `전체 OFF (개발·진단)`를 임시 적용합니다. 신규 사용자는 `safe(신규 권장)`와 PAPER를 유지합니다. 목적은 "진짜 원인"이 전략/체결/시장인지 분리 진단입니다.
1. 기준 완화(점진 복구): `profitability_validation` 기준값을 완화합니다. 예: `min_trades`, `min_win_rate`, `min_sharpe`, `min_walkforward_pass_rate`.
1. 종료 거래 데이터 축적 후 재평가: 최소 표본이 쌓이기 전에는 차단이 반복될 수 있으므로, 표본 확보 후 `safe` 프리셋으로 복귀합니다.

AI 어시스턴트 요청 예시:

- "수익성 검증 차단 사유를 현재 로그 기준으로 요약해줘"
- "수익성 게이트를 임시 OFF(dev)로 전환해줘"

### 3가지 고도화 항목은 수동화인가?

아닙니다. 아래 3가지는 자동매매를 수동으로 되돌리는 항목이 아니라, 자동매매의 판단 품질과 설명 가능성을 강화하는 항목입니다.

- 철학 정합성:
  - 초보자/디지털약자도 "복잡한 파라미터 튜닝" 없이 START/STOP 중심으로 사용할 수 있어야 함
  - 3가지 고도화는 자동을 없애는 기능이 아니라, 자동의 근거를 쉽게 이해하게 만드는 기능
- 코인과의 관계:
  - 코인에는 일부 로직이 기존 파이프라인에 내장되어 있고, 주식/ETF는 시장구조 차이(섹터/유동성/거래시간)로 별도 레이어를 명시적으로 강화
  - 방향성은 동일: AI가 판단하고, 사용자는 최소한의 정책 의사결정만 수행

- 주식/ETF 유니버스 선정기:
  - 사용자가 종목을 지정하면 그 목록을 우선하고, 비어 있으면 증권사 제공 KOSPI·KOSDAQ·ETF 목록에서 분석 후보를 자동 선정
  - `주식만`은 주식, `ETF만`은 ETF, `통합`은 주식 4개·ETF 4개를 기본으로 거래대금 우선 선정
  - 거래정지 종목은 제외하며 이후 시장국면·기술신호·위험 검증에서 실제 진입 여부를 별도로 판단
  - 현재 단계는 수익 종목 예측이나 섹터 분산 보장이 아니라 거래 가능한 유동성 분석 유니버스 선정
- AI 명령 실행기:
  - 단축키 매크로가 아니라 자연어 의도를 정책으로 변환하는 계층
  - 예: "ETF만 운용" → 전략 정책 변경 후 기존 자동 루프가 그대로 실행
- 설정 UI 보강:
  - 자동을 수동으로 바꾸는 기능이 아니라, 현재 자동 정책을 사용자가 이해하고 통제할 수 있게 하는 가시화 도구
  - START/STOP 실행 스위치와 자동예약 옵션(auto_start), 실주문 허용을 명확히 분리

## AI 판단 알고리즘 — 사용자가 이해할 수 있는 수준의 설명

### 암호화폐: 어떻게 "매수/매도" 신호가 나오는가?

**Step 1: 현재 시장 상태 진단**
```
"BTC가 지난 14일 중 가장 낮은 가격대(RSI < 30)에 있고,
 거래량이 평소의 30% 이상 증가했습니다.
 이는 시장이 매도 과열(과매도) 상태임을 의미합니다."
```

**Step 2: 거래량 + 가격 추세 확인**
```
"같은 기간 동안 가격이 5% 이상 하락했지만,
 새로운 저점을 뚫고 내려가지는 않았습니다.
 이는 강한 '손절(저가 매도)'의 신호이며, 곧 회복할 가능성이 있습니다."
```

**Step 3: 최종 판단**
```
LONG 신호 생성 
신뢰도: 72%

근거: 과매도 상태(RSI < 30) + 거래량 증가 + 가격 저항선 유지
```

**Step 4: 리스크 평가**
```
손실 한도: -3% (이 수준에서 자동으로 청산 제안)
수익 목표: +5% (이 수준에서 자동으로 청산 가능)
```

### 이 신호는 언제 틀리는가?

- **시장이 급락하는 경우**: 추가 하락으로 RSI < 20까지 내려갈 수 있음
  → 미리 설정한 손실 한도(-3%)에서 자동 청산되어 손실 제한

- **뉴스/이슈로 급등하는 경우**: 예상보다 빨리 상승
  → 수익 목표(+5%)에 도달하면 자동으로 청산 가능

### 주식: 왜 암호화폐와 다른가?

**암호화폐 (24/7 시장)**
- 시간대 제약 없음
- 기술 지표만 사용 (RSI, MACD, 거래량)
- 1시간~1일 단위의 빠른 신호

**주식 (장시간만 거래)**
- 거래 시간: 09:00 ~ 15:30
- 기업 실적, 뉴스, 섹터 동향 추가 고려
- 1일 이상의 중기 신호 중심
- 거래량이 암호화폐보다 변동성 적음

**진행 중**: 주식별 알고리즘 최적화 및 ETF/주식 사용자 분리 운용

### ETF: 어떻게 다르게 관리하는가?

**ETF의 특성**
- 지수를 따라가는 상품 (예: KOSPI 지수를 따라가는 ETF)
- 개별 주식처럼 빠르게 변하지 않음
- 주기적으로 보유 종목을 "리밸런싱"(재조정)해야 함

**현재 상태**: ETF 전용 알고리즘 개발 중
- 추적오차(ETF 값과 지수의 차이) 분석
- 정기 리밸런싱 시점 제안
- 운용보수 효율성 분석

### 핵심 기술: 금융 특화 강화학습 기반 판단 엔진

NoahAI의 차별화 요소는 **DAL의 AI 디지털케어로그 기반 구조를 금융 의사결정에 맞게 재설계·구현한 판단 엔진**(개발·운영: Noah AI Labs)입니다.
핵심은 수익 약속이 아니라, **설명 가능하고 검증 가능한 판단 구조**를 운영에 고정하는 데 있습니다.

#### 기술 특징 (이미 구현 완료):
- **멀티모달 금융 데이터 분석**: 차트 이미지, 수치 데이터(가격/거래량/변동성), 시장 심리 지수(공포/탐욕, 펀딩비) 등을 통합 분석
- **성과·로그 기반 적응**: 거래 이력·리스크 데이터로 임계값·파라미터를 조정하는 루프(`unified_trader`, `AIAutoOptimizer`, `ExchangeLearningManager` 등, 설정·AI 활성 조건에 따름). 엄밀한 RL 정책 네트워크가 항상 전 구간에 걸쳐 학습한다는 뜻은 아님.
- **실시간 적응형 시스템**: 시장 변화에 즉시 반응하여 전략을 자동 조정하는 동적 적응 메커니즘
  - **동적 적응형 임계값 시스템**: 시장 상황, 변동성, 거래 이력에 따라 실시간으로 진입/청산 기준 자동 조정
  - **실시간 시장 국면 감지**: LOW/NORMAL/HIGH 변동성에 따라 전략 강도 자동 조절
  - **점진적 학습**: 거래 이력이 쌓일수록 점진적으로 정상 임계값으로 전환 (첫 거래 → 초기 → 중기 → 정상)
  - **승률 기반 자동 조정**: 거래 성과에 따라 자동으로 더 공격적 또는 보수적으로 전환
- **DAL 기록·환류 철학의 금융 적용**: 의료·돌봄 맥락의 기록·분석·환류 개념을 금융 판단·로그 구조로 재구현한 축(의료 진단·허가 수준의 정확도를 금융에 보장한다는 뜻 아님)
- **셀프 호스팅 가능**: 자체 AI 엔진 기반으로 데이터 보안과 비용 효율성 극대화 (운영 비용 최적화 중심)
- **금융 도메인 특화 학습**: 암호화폐 시장의 고유한 특성(24/7 거래, 고변동성, 다중 거래소)에 최적화된 학습 데이터 기반

### 2단계: 코인 선정 (Coin Selection)

**evaluator.py - AI 코인 선택의 핵심 엔진**

NoahAI의 코인 선정은 `evaluator.py`라는 **과학적 평가 시스템**을 통해 이루어집니다. 이는 단순한 랜덤 선택이 아닌, **5가지 차원의 종합 점수**를 기반으로 최적의 거래 코인을 선별하는 고도화된 시스템입니다.

#### evaluator.py의 주요 기능
```
코인 선택 시스템:
├── 코인 후보군 수집 (거래소별 특화)
├── 다차원 점수 계산 (5가지 평가 기준)
├── 메이저/알트코인 비율 동적 조정
├── 시장 상황별 자동 선택 전략
└── 하이브리드 접근법 (캐싱 + 백업)
```

#### 5가지 평가 기준
```
종합 점수 계산:
├── 기술적 점수 (RSI, MACD, 볼린저밴드)
├── 변동성 점수 (스캘핑 최적화)
├── 거래량 점수 (유동성 보장)
├── 트렌드 점수 (시장 방향성)
└── 리스크 점수 (안정성 평가)
```

#### 하이브리드 접근법 (성능 최적화)
```
3단계 백업 시스템:
├── 1단계: 캐시된 API 데이터 (1시간 이내) → 가장 정확
├── 2단계: 백업 심볼 파일 (API 실패 시) → 안정적
└── 3단계: 하드코딩된 주요 심볼 (최종 백업) → 확실함
```

#### 거래소별 최적화 전략
```
시장 상황에 따른 자동 조정:
├── 상승장: 메이저 20% + 알트코인 80% (공격적)
├── 하락장: 메이저 50% + 알트코인 50% (보수적)
├── 횡보장: 메이저 30% + 알트코인 70% (균형)
└── 거래소별 특화 (바이낸스/업비트/바이비트 등)
```

#### 거래소별 코인 선택 방식

| 거래소 | 방식 | 특징 | 장점 | 단점 |
|--------|------|------|------|------|
| **바이낸스** | `_analyze_candidate_coins()` | API 직접 호출 + 캐싱 | 정확한 실시간 데이터 | API 제한, 느린 초기 로딩 |
| **업비트/빗썸** | `_analyze_candidate_coins_spot()` | KRW 페어 + 거래량 정렬 | 국내 시장 특화 | 제한된 코인 수 |
| **바이비트/OKX/비트겟** | `_analyze_candidate_coins_ccxt_futures()` | CCXT + 선물 마켓 | 다중 거래소 통합 | CCXT 의존성 |

#### 성능 최적화 결과

| 항목 | 이전 | 현재 | 개선율 |
|------|------|------|--------|
| **초기 로딩** | 4분 | 즉시 | **99%** |
| **데이터 정확성** | 100% | 99% | -1% |
| **안정성** | 70% | 99% | **29%** |
| **API 의존성** | 100% | 30% | **70%** |

## 거래 과정의 상세 흐름

### 시작 과정
1. **앱 실행** → ⏰ **자동 시간 동기화** → 로그인 → 거래소 선택
2. **API 키 설정** → 거래소 연결 확인
3. **코인 선정** → AI가 시장 분석하여 최적 코인 선택
4. **거래 시작** → 거래소 카드의 "시작" 버튼으로 자동거래 활성화

#### ⏰ 자동 시간 동기화 (v3.8.8.8 신규)
```
시작 시 자동 수행:
├── Windows 시스템 시간 확인
├── 바이낸스 서버 시간과 비교
├── 차이가 5초 이상이면 자동 동기화 실행
└── NTP 서버(time.windows.com)와 강제 동기화

목적: 바이낸스 API는 타임스탬프가 5초 이상 차이나면 거래 거부
효과: API 오류 완화, 주문 지연 감소, 거래 안정성 개선
```

### AI의 구체적인 역할

#### 분석 단계 (실제 AI 호출 패턴)

**실제 코드 분석 결과 (정정):**

**거래 사이클 (10초마다 반복)**
```python
# trading/unified_trader.py - monitoring_interval = 10초
self.monitoring_interval = int(self.settings.get("auto_trade_interval", 10))
```

**현재 AI 호출 시나리오 (2026-07-24 코드·사용량 정정):**

1. `TradingWorker`는 `auto_trade_interval`에 따라 거래 사이클을 반복합니다.
2. AI가 켜져 있으면 `Analyzer.generate_trading_signal()`이 최종 LONG/SHORT/HOLD 판정 전에 심볼별 시장 분석을 모델에 요청합니다.
3. 따라서 실제 주문이나 체결이 없어도 분석 대상 심볼과 거래소가 많으면 OpenAI 비용이 발생합니다.
4. LONG/SHORT 후보에는 최근 손실표본이 있을 때만 패턴 유사성 호출이 붙을 수 있으며 같은 신호·표본은 5분 재사용합니다.
5. 포지션 크기는 같은 상태를 15분 재사용하고, 실패 재시도는 120초 제한합니다.
6. 역할별 저가 모델과 함께 동일 시장상태 캐시·시장 이벤트 재호출·일일 예산 폴백을 적용합니다. 다심볼 단일 요청은 품질 A/B 후 적용합니다.

**실사용 점검값**

| 기간 | OpenAI 비용 | 모델 요청 | 판정 |
|---|---:|---:|---|
| 2026-05 | $62.05 | 230,596회 | 높은 반복 호출 |
| 2026-06-01~07-01 | $51.73 | 190,435회 | 전월 대비 비용 16.6% 감소 |
| 2026-07-21~07-23 | $9.08 | 27,879회 | 같은 속도면 30일 약 $90.82 |

- 점검 계정은 선택 거래소가 Binance였지만 활성 거래소 6개가 모두 켜져 있었고 6개 거래소 로그가 생성되었습니다.
- 비용 CSV는 OpenAI 프로젝트 합계이므로 거래소별 정확한 비용은 분리되지 않습니다.
- 전체 점검 비용 중 출력 토큰 비중은 67.5%였고 캐시 입력 비중은 약 0.001%였습니다.
- “2주가 지나면 자동으로 일 20~170원으로 하락”하거나 “99% 절감이 완료됐다”는 고정 보장은 현재 코드·실측과 맞지 않습니다.

**비용을 줄이는 사용 방법**

1. 사용하지 않는 거래소를 비활성화합니다.
2. `설정 → AI 엔진/API → 작업별 모델 배치`에서 빈번 호출은 계정에서 확인된 절약형 모델로 둡니다.
3. OpenAI Billing에서 Soft/Hard Limit를 낮게 설정합니다.
4. AI API 키를 연결하지 않으면 기본 기술지표 분석은 사용할 수 있지만 모델 기반 분석·복기는 제한됩니다.
5. 전 거래소 학습은 호출량이 합산되므로 실제 주문 범위와 별개로 사용하지 않는 관찰·학습 거래소를 끕니다.
6. 오픈소스·호환 모델은 `base_url` 구조로 연결할 수 있지만 품질·지연·운영비 검증 없이 외부 비용이 0원이 된다고 단정하지 않습니다.

```
AI 신뢰도 측정 방법
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AI 신뢰도는 0~1 사이 값으로 계산되며, 여러 요소를 종합하여 결정됩니다:

1. **기본 신뢰도**: 0.7 (시작점)

2. **패턴 분석 기반 조정** (과거 거래 이력이 있을 때만):
   - 손실률 > 30%: 신뢰도 -0.2 (신뢰도 하락)
   - 손실률 < 20%: 신뢰도 +0.1 (신뢰도 상승)
   - 과거 성과가 없으면: 기본값 0.7 유지

3. **시장 조건 기반 조정**:
   - 변동성 부적절: 신뢰도 -0.3
   - 변동성 적절: 조정 없음

4. **신호 강도 기반 조정**:
   - 신호 신뢰도 > 0.8: 신뢰도 +0.1 (강한 신호)
   - 신호 신뢰도 < 0.5: 신뢰도 -0.1 (약한 신호)

5. **최종 신뢰도 범위**: 0.0 ~ 1.0

동적 임계값 계산 (거래 허용 기준)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

거래를 허용할지 결정하는 "임계값"도 동적으로 계산됩니다:

1. **기본 임계값**: user_signal_threshold / 100
   - 예: 설정값 68 → 임계값 0.68
   - 기본값: 0.65 (설정값이 없을 때)

2. **시장 상황 조정**:
   - 고변동성: +0.02 (더 보수적)
   - 저변동성: -0.02 (약간 완화)

3. **연속 성과 조정**:
   - 연속 승리 ≥ 2회: -0.03 (더 공격적)
   - 연속 손실 ≥ 2회: +0.03 (더 보수적)

4. **승률 기반 자동 조정** (과거 성과가 있을 때만):
   - 거래 이력 10회 이상 필요
   - 승률 > 70%: 임계값 -0.05 (더 공격적)
   - 승률 < 30%: 임계값 +0.05 (더 보수적)
   - 승률 30-70%: 비례 조정
   - 과거 성과가 없으면: 승률 기반 조정 없음 (기본값 사용)

5. **안전 범위**: 0.30 ~ 0.95

최종 거래 허용 조건
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

거래가 허용되려면: **AI 신뢰도 >= 동적 임계값**

예시:
- AI 신뢰도: 0.75
- 동적 임계값: 0.68
- 결과: 0.75 >= 0.68 → 거래 허용 

신규 거래자 / 첫 거래인 경우
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

과거 성과가 없을 때 (첫 거래 또는 신규 코인):

1. **AI 신뢰도**:
   - 기본값 0.7 사용
   - 패턴 분석 조정 없음 (과거 이력 없음)
   - 시장 조건과 신호 강도만 반영
   - 약한 시그널이라도 AI가 시장 조건을 종합 분석하여 높은 신뢰도를 줄 수 있음

2. **동적 임계값 (점진적 학습 시스템)**:
   - **전체 첫 거래 (0회)**: 임계값 -0.15 (최소 0.55)
   - **코인별 첫 거래 (전체 10회 이하)**: 임계값 -0.12 (최소 0.58)
   - **초기 거래 (2-5회)**: 임계값 -0.10 (최소 0.60)
   - **중기 거래 (6-10회)**: 임계값 -0.05 (최소 0.65)
   - **정상 거래 (11회 이상)**: 정상 임계값 사용

3. **거래 허용 조건**:
   - 변동성 적합 + AI 신뢰도 >= 동적 임계값
   - 손실률 체크 없음 (과거 이력 없으므로)
   - AI가 이미 시그널 강도를 반영했으므로 AI 판단을 신뢰
   - 약한 시그널이라도 AI가 시장 조건을 종합 분석하여 높은 신뢰도를 주면 거래 허용

스마트한 점진적 학습 시스템
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**AI가 시그널 강도를 자동으로 반영**:
- 매우 강한 시그널 (0.8 이상): AI 신뢰도 +0.15
- 강한 시그널 (0.7-0.8): AI 신뢰도 +0.10
- 중간 이상 시그널 (0.6-0.7): AI 신뢰도 +0.05

- 약한 시그널 (0.5 미만): AI 신뢰도 -0.15

**따라서 약한 시그널이라도**:
- 시장 조건이 매우 좋으면 → AI 신뢰도 상승 → 거래 허용 가능
- 시장 조건이 나쁘면 → AI 신뢰도 하락 → 거래 거부

**코인별 첫 거래 처리**:
- BTC는 거래했지만 ETH는 안 거래한 경우
- ETH 첫 거래 시에도 완화된 임계값 적용
- 새로운 코인 거래 가능

실제 작동 예시:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**시나리오 1: 전체 첫 거래 (user_signal_threshold = 83)**
- 시그널 신뢰도: 0.60 (중간)
- 시장 조건: 매우 좋음
- AI 신뢰도: 0.7(기본) + 0.05(중간 시그널) + 0.2(좋은 시장) = 0.95
- 동적 임계값: 0.83 (기본)
- 첫 거래 임계값: 0.83 - 0.15 = 0.68
- 조건: 0.95 >= 0.68 → 거래 허용 

**시나리오 2: 약한 시그널이지만 좋은 시장 조건**
- 시그널 신뢰도: 0.45 (약함)
- 시장 조건: 매우 좋음
- AI 신뢰도: 0.7(기본) - 0.15(약한 시그널) + 0.2(좋은 시장) = 0.75
- 첫 거래 임계값: 0.68
- 조건: 0.75 >= 0.68 → 거래 허용 (AI 종합 판단)

**시나리오 3: 코인별 첫 거래 (BTC는 거래했지만 ETH는 첫 거래)**
- 전체 거래: 5회 (BTC만 거래)
- ETH 거래: 0회 (첫 거래)
- AI 신뢰도: 0.7 + 0.1(강한 시그널) = 0.8
- 코인별 첫 거래 임계값: 0.83 - 0.12 = 0.71
- 조건: 0.8 >= 0.71 → 거래 허용 

**시나리오 4: 약한 시그널 + 나쁜 시장 조건**
- 시그널 신뢰도: 0.45 (약함)
- 시장 조건: 나쁨
- AI 신뢰도: 0.7(기본) - 0.15(약한 시그널) - 0.3(나쁜 시장) = 0.25
- 첫 거래 임계값: 0.68
- 조건: 0.25 < 0.68 → 거래 거부 (AI 종합 판단)
```

## 일반 자동매매 앱과의 차이점

### 왜 대부분의 자동매매/AI 봇은 이런 구조가 불가능한가?

NoahAI는 단순한 "조건매매 프로그램"이 아닌 **AI 자율 판단 시스템**입니다.  
현재 시중에 있는 수많은 "AI 자동매매" 혹은 "AI 트레이딩"이라고 홍보되는 제품들은 다음 이유로 동일한 기술을 구현할 수 없습니다.

#### 1. **AI 학습 구조 자체가 없음**
```
대부분의 프로그램은 미리 정해진 규칙(if-then)만 수행합니다.
거래 결과를 학습하거나 강화학습 데이터로 재활용하지 못합니다.
AI 모델이 존재하지 않거나, 단순 API 호출로 'AI처럼 보이게'만 구성됩니다.
NoahAI는 거래 결과를 실시간으로 기록·분석하여 패턴을 학습하고 다음 판단에 반영합니다.
```

#### 2. **시장 실시간 분석이 불가능**
```
기존 봇들은 1분~5분 단위의 단순 신호만 처리합니다.
초 단위(5~10초)의 실시간 데이터 처리, 변동성 감지, 거래소별 슬리피지 계산은 기술적으로 구현이 어렵습니다.
NoahAI는 초 단위로 6개 거래소 데이터를 수집·분석하여 시장 급변에도 즉시 대응합니다.
```

#### 3. **멀티모달 분석 불가능**
```
대부분은 차트 숫자 데이터만 사용합니다.
뉴스·거래심리·거래량 패턴·시장 국면 등을 통합적으로 분석할 수 없습니다.
NoahAI는 AI 디지털케어로그(DAL)에서 이어지는 멀티모달 분석 관점을 바탕으로, Noah AI Labs 구현을 통해 텍스트·숫자·패턴 데이터를 통합 처리합니다.
```

#### 4. **실시간 강화학습 엔진 부재**
```
대부분의 서비스는 '백테스트' 데이터에만 의존합니다.
실시간 강화학습이나 거래 후 피드백 학습은 구현되어 있지 않습니다.
NoahAI는 거래 후 성과 데이터를 자동 저장하고, 실패 패턴은 패널티로 학습시켜 즉시 개선합니다.
```

#### 5. **데이터 인프라 및 처리 한계**
```
단일 거래소, 단일 계정, 단일 전략 기반의 구조.
초당 수천 건의 데이터 처리 불가능.
NoahAI는 DAL에서 축적한 의료·돌봄 AI 데이터 인프라 경험을 바탕으로, Noah AI Labs가 금융용 실시간 데이터 파이프라인으로 구현합니다.
```

#### 6. **기술 검증 불가 또는 비공개 구조**
```
많은 프로그램이 'AI'라는 표현만 쓰고, 실제 코드·로그·AI 호출 내역을 공개하지 않습니다.
외부 검증 불가능, 결과를 조작하거나 미리 저장된 데이터를 출력하는 경우도 존재합니다.
NoahAI는 실제 AI 호출 로그, 학습 데이터, 신호 분석 기록이 모두 로컬에 저장되어 검증 가능합니다.
사용자는 언제든지 로그를 확인하여 "AI가 어떤 판단을 내렸는지" 직접 볼 수 있습니다.
```

#### 7. **개발 리소스 및 기술 장벽**
```
실시간 트레이딩 AI를 만들려면 금융 데이터 엔지니어링 + 강화학습 + 마이크로서비스 구조를 모두 다뤄야 합니다.
중소 개발팀은 이 기술 조합을 구현하기 어렵습니다.
NoahAI는 DAL에서 축적된 의료·금융 융합 알고리즘과 인프라 경험을 바탕으로, Noah AI Labs가 제품화한 시스템입니다.
```

## 실제 사용법 및 설정 가이드

### 첫 시작하기

#### 1단계: 앱 실행 및 로그인
```
1. AITrading.exe 실행
2. 사용자 계정 정보 입력 (사용자명/비밀번호)
3. 로그인 성공 시 대시보드 표시
```

#### 2단계: 거래소 설정
```
1. 설정 탭 → 거래소 선택
   ├── 원하는 거래소들 체크박스로 다중 선택
   ├── 바이낸스, 바이비트, OKX, 비트겟, 업비트, 빗썸 중 선택
   └── 동시에 여러 거래소 선택 가능

2. API 키 입력
   ├── 바이낸스: API Key + Secret Key
   ├── 업비트/빗썸: Access Key + Secret Key  
   ├── 바이비트/비트겟: API Key + Secret Key
   └── OKX: API Key + Secret Key + Passphrase

2-1. 입력 직후 "검증" 실행 (권장)
  ├── 실패하면 원인/조치 팝업 내용부터 반영
  ├── Bitget은 공인 IP를 확인해 화이트리스트와 대조
  ├── Bybit은 Unmatched IP/권한/키 만료 여부 우선 확인
  └── OKX는 Passphrase/계정모드(선물/스왑) 일치 여부 우선 확인

3. OpenAI API 키 입력 (AI 기능 사용 시)
   OpenAI Billing에서 Soft/Hard Limit를 먼저 설정
   빈번 호출 역할에는 가장 저렴한 모델을 선택
   사용하지 않는 거래소는 비활성화
   비용은 앱 사용 기간이 아니라 실제 호출 수와 토큰량으로 결정
   향후 전망: 오픈소스 LLM 기반 비용 최적화 고도화
   - 알리바바 Qwen 오픈소스 모델 (후속 실행 경로 준비 중)
   - 오픈소스 LLM 연동 구조 이미 구현 완료
   권장: 먼저 AI 기능 없이 기본 자동매매 체험 후 AI 기능 활성화
```

#### 3단계: 거래 시작
```
1. 거래소 카드에서 시작 버튼 클릭
  → 선택한 거래소만 시작

2. 각 거래소를 필요 시 개별 시작/정지
  → 거래소별 상태를 분리해 운영

3. AI가 자동으로:
   ├── 시장 분석 시작
   ├── 최적 코인 선정
   ├── 거래 신호 생성
   └── 자동 거래 실행
```

### v3.8.9.11 (2026-01-25)

#### TP/SL -2021 오류 근본 수정: GALA/JASMY 등 저가 알트코인 완전 지원

**배경**:
- GALA, JASMY 등 저가 알트코인에서 TP 주문이 반복적으로 실패 (`-2021: Order would immediately trigger`)
- TP와 SL이 모두 0.01로 동일하게 설정되어 전달됨
- SHORT 포지션에서 TP만 실패, SL만 성공하는 패턴 반복
- **이전 수정(v3.8.9.8, v3.8.9.9)으로도 해결되지 않은 이유**:
  - 이전 수정은 **SL 검증**과 **TP 거리 검증**만 추가했음
  - **TP 방향 검증**이 없어서 SHORT 포지션에서 TP > 현재가인 경우를 감지하지 못함
  - **trader 쪽에서 TP/SL 가격을 계산할 때** `price_precision` 키 이름 불일치로 항상 2자리로 고정되어 0.006xx가 0.01로 반올림됨

**근본 원인**:
1. **trader.py - 키 이름 불일치**:
   - `get_symbol_info_direct()`는 `pricePrecision`, `tickSize` (camelCase)를 반환
   - trader는 `price_precision`, `tick_size` (snake_case)로 찾음
   - 결과: `price_prec`가 항상 2로 고정 → `format(0.00657, '.2f')` = `0.01`로 반올림
   - GALA (진입가 0.0067): TP=0.0066, SL=0.0068이 0.01, 0.01로 변환됨
2. **binance_client.py - TP 방향 검증 누락**:
   - SHORT 포지션에서 TP는 현재가보다 **낮아야** 함
   - TP=0.01, 현재가=0.0067인 경우: 0.01 > 0.0067 → "가격이 0.01 이하로 떨어질 때" 조건이 **이미 충족** → 즉시 트리거 → -2021
   - 이전 수정은 **거리만** 검증하고 **방향**은 검증하지 않음

**주요 개선사항**:
- **trader.py - 키 이름 수정 및 저가 코인 보호**:
  - `info.get('price_precision', 2)` → `info.get('pricePrecision') or info.get('price_precision') or 2`
  - `info.get('tick_size', ...)` → `info.get('tickSize') or info.get('tick_size', ...)`
  - **저가 코인 자동 감지**: 진입가 0.001~0.02 범위면 `price_prec`를 최소 4~5로 강제
  - 예외 처리에서도 `round(., 2)` → `round(., price_prec)` 사용
- **binance_client.py - TP 방향 검증 추가**:
  - SHORT: `tp_price >= current_price` 감지 시 자동 재계산
  - LONG: `tp_price <= current_price` 감지 시 자동 재계산
  - 방향 검증 후 거리 검증 수행 (기존 로직 유지)

**주요 효과**:
- GALA (진입가 0.0067): `price_prec` 2 → 4로 조정 → TP=0.0066, SL=0.0068 (정확)
- JASMY (진입가 0.0081): `price_prec` 2 → 4로 조정 → 정확한 가격 유지
- 모든 저가 알트코인 (0.001~0.02 범위) 자동 보호
- TP 방향 오류 자동 감지 및 재계산
- 예외 처리 강화로 어떤 상황에서도 정확한 정밀도 유지

## Alpha Arena 모드 사용 가이드

### Alpha Arena 모드란?

**Alpha Arena 모드**는 nof1.ai의 Alpha Arena 벤치마크 운영 방식을 참고한 독립 LLM 거래 실험 모드입니다. 과거 벤치마크 결과가 사용자 계정의 수익이나 승률을 보장하지 않습니다.

#### 핵심 특징
- **LLM 기반 자율 거래**: AI가 직접 거래 결정을 내리고 실행
- **벤치마크 참고 구조**: 공개 실험의 프롬프트·결정 형식을 참고하되 사용자 계정 성과는 별도 검증
- **독립 모드**: 기존 자동매매 파이프라인과 완전 분리
- **Binance Futures 전용**: 바이낸스 선물 거래소만 사용

### 시작하기

#### 1단계: 설정 활성화
```
1. 설정 탭 → "AlphaArena" 선택
2. "Alpha Arena 모드 활성화" 스위치 켜기
3. AI 엔진 확인:
  - DeepSeek V4 Flash (현재 AlphaArena 단일 실행 기준)
  - Qwen 3 Max (구형 설정 호환 항목, 현재 실행 미지원)
4. API 키 입력:
  - DeepSeek API Key (현재 실행 기준)
  - Qwen3 (Alibaba) API Key (후속 지원 대비 저장 가능)
```

#### 2단계: 대시보드에서 사용
```
1. 대시보드 → "AlphaArena" 탭 선택
2. 첫 진입 시 안내 모달 확인
3. "시작" 버튼 클릭하여 거래 시작
```

### Alpha Arena 모드 작동 방식

#### 거래 프로세스
```
1. 시장 데이터 수집
   ├── 6개 코인 시세/지표 (BTC, ETH, SOL, XRP, DOGE, BNB)
   ├── 계좌 정보
   ├── 현재 포지션
   └── 직전 주문 결과

2. LLM 프롬프트 생성
   ├── 시장 상태 요약
   ├── 각 코인별 기술적 지표
   └── 거래 가능 여부

3. LLM 응답
   ├── MODEL_CHAT (사람이 읽는 설명)
   └── TRADING_DECISIONS (실행 가능한 JSON)

4. 주문 실행
   ├── TRADING_DECISIONS 파싱
   ├── 검증 및 가드레일 적용
   └── Binance Futures API로 직접 주문
```

#### 거래 신호 타입
- **ENTER_LONG**: 롱 포지션 진입
- **ENTER_SHORT**: 숏 포지션 진입
- **HOLD**: 기존 포지션 유지
- **CLOSE**: 포지션 청산

#### 가드레일 (자동 적용)
- **레버리지 범위**: 10-20x 자동 클램핑
- **TP/SL 필수**: 진입 시 반드시 TP/SL 지정 필요
- **쿨다운**: 동일 코인 재진입 최소 30초 간격
- **리스크 캡**: 틱당 최대 리스크 제한
- **최대 동시 포지션**: 6개 코인 (심볼당 1개)

### 설정 가이드

#### 필수 설정
- **엔진 선택**: 현재 AlphaArena 실행은 DeepSeek V4 Flash 단일 기준이며 Qwen 3 Max는 실행 미지원 호환 항목
- **API 키 입력**: 현재 실행 기준은 DeepSeek API 키

#### 자동 설정 (사용자 조절 불필요)
다음 설정들은 Alpha Arena 벤치마크와 동일하게 내부 가드레일로만 사용되며, 사용자가 조절할 필요가 없습니다:
- 틱 주기 (기본 60초, 최소 30초 가드레일)
- 레버리지 범위 (기본 10-20x)
- 틱당 최대 리스크 (기본 1500 USDT)
- 심볼별 쿨다운 (기본 30초)
- 최대 동시 포지션 (기본 6개)

### 주의사항

#### Alpha Arena 모드의 특징
- **기존 TP/SL 보험 미작동**: NoahAI의 기존 TP/SL 보험과 워치독은 동작하지 않습니다
- **LLM 직접 제어**: 모든 거래 결정은 LLM이 직접 내리며, TP/SL도 LLM이 지정합니다
- **TP/SL 필수**: LLM이 TP/SL을 지정하지 않으면 주문이 실행되지 않습니다
- **피드백 루프**: 주문 실패 시 다음 프롬프트에 실패 사유가 전달되어 LLM이 재조정합니다

- 모든 거래 결과는 사용자 본인의 책임입니다
- 처음 사용 시 모의 거래(테스트넷)로 먼저 테스트하시기 바랍니다
- 자세한 내용은 대시보드 사용자메뉴얼에서 AlphaArena 섹션을 참고하세요

- **테스터 지위**: 현재 일부 기능은 베타/테스트 성격을 포함할 수 있으며, 사용자는 테스터 지위로 사용합니다.

### v3.9.0.1 코인·종목 정보 화면 사용법 (2026-07-24)

- `코인 정보`와 `종목 정보`는 탭 바깥쪽 전체 화면을 마우스 휠 또는 트랙패드로 세로 스크롤할 수 있습니다.

- 같은 종목이 보유와 최근 체결에 모두 있으면 현재 판단에 유용한 보유 상태를 먼저 표시합니다.
- `시장 종목 미리보기 · 검색용`은 증권사가 제공하는 검색 후보이며 사용자가 실제 거래한 종목이라는 뜻이 아닙니다.
- 새 체결·보유 상태를 확인하려면 `종목 정보 새로고침`을 누릅니다. 증권사 미연결 또는 내역 없음은 빈 상태 안내로 표시됩니다.

### v3.9.0.1 TP/SL 설정 보호 (2026-07-24)

- TP/SL은 주문 엔진에서 fraction으로 사용합니다. 예: `0.0018 = 0.18%`, `0.01 = 1%`.
- 퍼센트로 입력한 AI 커스텀 값은 주문 직전에 fraction으로 변환됩니다.
- 자동 최적화의 변경안은 제안일 뿐이며 사용자가 승인하기 전에는 현재 설정을 바꾸지 않습니다.
- 허용 범위를 벗어난 TP/SL이 최종 주문에 도달하면 해당 거래를 실행하지 않고 오류 로그를 남깁니다.
