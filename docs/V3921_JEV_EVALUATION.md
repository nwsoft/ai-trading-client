# 3.9.2.1 — TypeSafe JEV 자료 검증과 도입 판단

> 2026-10-04 후속: v3.9.2.4는 생활금융의 짧은 목적 분류를 기존 지원 모델로 선택·실행하는 기능을 구현했다. Jev 자체의 직접 연동이나 동등 성능 검증은 아니다. [사용 이유·모델 선택 안내](LIFE_FINANCE_GUIDE.md#빠른-질문-분류는-왜-쓰나요), [구현·검증 범위](V3924_FINANCE_DECISION_UPDATE_PLAN.md). 아래 미구현 연구 계획과 판단은 2026-10-01 Jev 직접 도입 검토 당시 기록이다.

확인일: 2026-10-01. 상태: **외부 자료 검토·오프라인 산술 재현 완료, 실행 Provider 미통합**. 사용자 키·유료 API·실주문을 사용하지 않았다. 이 문서는 JEV 도입 완료나 성능 인증서가 아니다.

## 결론

정해진 범주로 질문·문서를 분류하는 보조 수단으로 연구 가치는 있다. 그러나 기존 로컬 규칙으로 해결되는 오류 분류에 유료 모델을 붙이거나, 어시스턴트·전략 컴파일러·손절·보호주문·승인 체계를 대체할 근거는 없다. **3.9.2.1에는 정확한 어시스턴트 안내와 검증 문서를 반영한다. JEV 런타임은 배포 필수 항목이 아니라 아래 평가를 통과해야 승인할 별도 제안이다.**

사용자 효용 가설은 모호한 한국어 질문의 적절한 도움말 연결, 자료 분류·보완 질문 선택의 비용/응답시간 개선이다. 매매 수익 향상은 확인되지 않았다. 확률 숫자가 기존 전략 조건과 다른 판단을 대신 결정해서는 안 된다.

## 3. 공식 자료 대조

TypeSafe는 텍스트 상태와 정해진 질문에 typed decision을 반환한다. 자유문장 설명·전사 모델이 아니다. 현재 공식 native 모델 ID는 `jev-1.13.0`, 별칭은 `jev-latest`이며 입력 $0.042/백만, 출력 무료로 안내한다. 별칭은 이동할 수 있고 한국어는 자체 평가가 필요하다. [공식 모델 문서](https://docs.typesafe.ai/models)

Native API는 `POST /v1/systemone`의 state/questions 계약이다. 기존 chat/completions에 모델명만 추가하는 변경으로 호환되지 않는다. [공식 API](https://docs.typesafe.ai/api), [OpenRouter 사용 가이드](https://openrouter.ai/blog/tutorials/how-to-use-jev/)

Choice/Score의 confidence는 확률 분포를 요약한 값이고, Noul은 별도 참/거짓 질문의 응답이다. confidence 0.99를 해당 금융 판단 정답률 99% 또는 상승 확률로 바꿔 표시하면 안 된다. [공식 confidence 설명](https://docs.typesafe.ai/confidence)

OpenRouter 자체 Banking77 평가(3,080건)에서 JEV 정확도 81.0%, Opus 84.4%; 두 모델 모두 형식 오류는 0건이었다. **형식 오류 0 ≠ 의미 오류 0**을 직접 보여준다. 해당 실험의 JEV P50 175ms도 NoahAI 고객 PC RTT 보장은 아니며 금융 수익 실험도 아니다. [공식 비교 실험·한계](https://openrouter.ai/blog/insights/jev-vs-claude-opus-5-classification/)

보고서의 단일 O(1) 구조·항상 70ms·일반 LLM 대비 1,000배 절감·환각/오판 0%를 NoahAI의 검증 사실로 채택하지 않는다. 비자기회귀 설계와 특정 벤치마크 이점이 모든 입력·네트워크·금융 과제로 일반화되지는 않는다. [제공사 제품 설명](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

## 5. NoahAI 코드와의 적합성

현행 `trading/ai/inference_policy.py`에는 캐시·변화 감지·기관별/전체/월별 예산이 있다. 기본 일 40회 기관 상한은 실제 존재하지만 거부 횟수만으로 'AI 99.54% 침묵, RSI만 거래'라고 계산할 수 없다. 호출 후보·캐시 재사용·기본 전략·사용자 전략·기간·설정을 함께 알아야 한다. 보고서가 지목한 고객 비용 파일은 첨부되지 않았으므로 해당 고객의 사용률을 재현하지 않았다.

UI polling 2초와 거래 엔진 의사결정 주기는 다르다. 싸다는 이유로 10초 주기 무제한 전송을 추가하면 전체 종목·기관·고객 수에 비례한 과호출과 자료 외부 전송이 생긴다. 기능 추가 전 호출 단위와 개인정보 경계를 먼저 정해야 한다.

| 용도 | 판정 |
|---|---|
| 정확한 오류 코드 → 도움말 | 로컬 결정형 매핑으로 충분. JEV 불필요 |
| 한국어 자유 질문/자료 분류 → 도움말 후보 | 선택적 실험 가치. 기존 로컬 매핑·저비용 LLM과 비교 |
| 근거를 읽고 자세한 설명·전략 초안 생성 | 기존 어시스턴트 역할. JEV 대체 불가 |
| 손절·위험 한도·주문 가능 여부·원장 복구 | 결정형 보호/증거 대조 유지. JEV 확률로 승인 금지 |
| 시장 상태 보조 분류 | 시점 고정·정의·사후 정답·미확인 처리 갖춘 shadow 연구만 |

## 6. 조건부 개발 계획 (아직 미구현)

1. **평가 데이터부터**: 한국어 질문·오타·다중 오류·unknown·오래된 버전·프롬프트 주입 사례를 비식별화한다. 코드·문서 정본으로 사람 2명이 독립 정답을 정하고 불일치를 조정한다. 개발/검증 분리, 중복 제거, 정답을 암시하는 제목 제거. 처음 목표 500건 이상은 연구 설계 목표이지 정확도 보증이 아니다.
2. **동일 과제 비교**: 로컬 규칙, 현재 저비용 LLM, JEV의 동일 분류 체계/시점/문맥으로 비교한다. 한국어 원문과 번역 경유는 따로 측정한다. 정확도·macro-F1·위험 안내 오류·unknown 보류율·coverage·confidence calibration, P50/P95/P99·timeout·429/5xx·총 USD/건을 기록한다. 설명 생성 전체 시간/비용도 포함한다.
3. **별도 어댑터**: `TypedDecisionProvider` 계약을 chat provider와 분리한다. 모델/스키마/질문 버전, 허용 enum, 유한 숫자·범위·확률 합, 누락 질문, 응답 actual model을 검증한다. 응답 confidence/noul을 금융 성공 확률로 재해석하지 않는다. SDK가 자동 재시도해도 명시 예산·timeout·취소를 넘지 못하게 한다.
4. **기본 OFF·동의·최소 전송**: 기능별 동의와 별도 키/예산. 비밀키·계좌번호·원문 전략·전체 잔고를 자동 전송하지 않는다. Native/OpenRouter 각각 보관·학습·subprocessor·지역·삭제 조건 확인. 일반 계정이 enterprise ZDR라고 가정하지 않는다. [제공사 데이터 처리 안내](https://docs.typesafe.ai/models), [계약](https://typesafe.ai/legal/mca)
5. **shadow만**: 이벤트/완료 봉 기반 bounded queue, 요청 dedup, 계정·기관·모드·봉 시각·원문/질문/모델 버전 별 캐시, TTL·단일 in-flight·일/월 비용 상한·회로 차단. 한 판단 실패는 unknown으로 기록한다. UI·거래 스레드를 기다리게 하지 않고 기존 결정·포지션 보호를 그대로 유지한다. 기록 크기·보존 기간 제한과 키/원문 마스킹 필요.
6. **통과/기각 기준을 사전 고정**: 기존 로컬 규칙으로 확정되는 오류의 오안내 0, 미확인→안전 승인 승격 0, 계정/모드 혼합 0, 외부 장애로 거래/보호 지연 0은 필수 회귀 조건. 실제 정확도·비용 개선 목표는 평가 설계 시 정하고 테스트 결과를 보고 유리하게 바꾸지 않는다. 거래 성능을 주장하려면 별도의 시점외 PAPER 비교·비용/슬리피지·국면별 표본이 필요하다.
7. **채택 여부**: 효용이 없으면 도입하지 않는다. 통과해도 우선 도움말 후보/자료 분류의 선택 기능만 승인한다. LIVE 판단 기능은 이번 계획 범위가 아니며 별도 사용자 승인·위험 검토·배포 절차가 필요하다.

## 7. 완료와 미완료를 구분

- 이번 완료 대상: 첨부 자료 대조, 공식 계약 확인, 오프라인 재계산 도구, 지원 안내의 오해 방지, 이 개발 계획.
- 미실행: 유료 JEV 호출, receipt 인증, 독립 금융 벤치마크, typed-provider 구현, JEV 사용자 설정/UI, shadow 운영, 실제 주문.
- 위 연구 미실행은 기존 어시스턴트 안내 수정의 배포를 막는 누락 구현이 아니다. JEV를 지원 완료라고 홍보하거나 목록에 가짜 호환 모델을 추가하지 않는다.
