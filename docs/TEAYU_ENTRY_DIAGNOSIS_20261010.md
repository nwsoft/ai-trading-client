## 근본 원인과 과거 수정의 누락

1. **OKX 공개 선물 목록이 불필요한 다른 API에 종속됐다.** defaultType='swap'만 지정한 CCXT load_markets(reload=True)는 실제로 현물·만기 선물·SWAP·옵션 전체를 조회하고, 인증 키가 있으면 먼저 private currencies API도 호출한다. 선물 시세가 정상이어도 인증 통화 또는 옵션 등 다른 요청의 실패로 전체 목록 갱신이 실패할 수 있다. 기존 패치는 목록 이후의 일괄 티커/단일 티커 폴백과 에러 코드 분류에 집중해 이 앞단의 의존성을 제거하지 못했다. 설치된 CCXT 4.5.50의 실제 load_markets 경로에 private 조회 실패를 주입하여 기존 실패와 수정 후 성공을 재현했다. 당일 요청이 어떤 하위 API에서 실패했는지는 원본 예외가 없어 특정하지 않는다.

2. **PAPER 가용자금 검증이 과거 미확정 원장에서 계속 멈춘다.** Coinone 외 6기관의 옛 청산 기록에는 결제통화가 없고, 일부 해외 선물 기록에는 계약 단위·손익 계산 근거도 없다. 전체 누적 원장에서 첫 미확정 기록을 만나면 신규 가상 진입을 막는다. PnL·승률 하락만으로 모든 기관이 정지한 것으로 해석할 수 없다. 최근 원장 계산이나 청산 저장 코드의 수정은 이미 저장된 과거 기록의 누락 근거를 만들어 주지 않는다. 기록 삭제, 손익 0 치환, 오늘의 계약 단위 소급 적용으로 해제하면 안 된다.

3. **자금 차단의 해결 안내가 앞단에서 가려졌다.** 기존 새 PAPER 평가 기능은 있었으나, 자금 근거가 후보·신뢰도 검사를 통과한 뒤에만 채워지는 경로가 있었다. 이 경우 신뢰도에서 계속 멈추는 사용자는 자금 차단과 새 평가 준비 버튼을 발견하기 어렵다. 대시보드 역시 위험 평가만 주요 차단으로 읽고, 후보 단계 통과와 이후 실제 실행 미실행을 분리해 연결하지 않았다.

4. **진입 판단의 일부 이력·사유 계약이 달랐다.** Binance 신뢰도 임계값의 DB 보완 경로가 미확정/다른 모드 성과를 필터링하지 않아 과거 미확정 손실로 기준을 높일 수 있었다. 실제 손실률 상한이 60%인 상황에도 사유 문구는 50%를 고정 기준으로 사용해 신뢰도 실패를 '높은 손실률'로 안내할 수 있었다. Unified 기본값 손실률 50%를 실측 손실로 사용하면 이력이 없는 계정도 max_loss_rate=50에서 시작 학습이 차단됐다. 이때도 실제 측정된 소표본 손실은 기존 가드레일을 유지해야 한다.

5. **.10의 변경 범위와 사용자 설치 상태가 다르다.** 기존 .10 릴리스 노트는 전략 스튜디오 작업/학습 안내 정리가 중심이고 매매 엔진·PAPER 계산을 변경하지 않는다고 명시한다. 그 버전 번호만으로 위 엔진 경로가 수정됐다고 볼 수 없다. 자료에 남은 .8 세션, 문의의 .9 진단, 현재 .10 소스, 후속 로컬 패치와 새 Windows 설치본의 식별·검증은 각각 필요하다.

## 반영한 수정

- OKX 연결에서 markets 종류를 swap으로 제한하고, 목록 로딩의 private currencies 조회를 제거했다. 이후 현재 목록 검증은 공개 fetch_markets_by_type('swap')와 실제 CCXT 정규화로 수행한다. 과거 시장 캐시나 티커 가격으로 종목을 만들어 넣지 않는다.
- 현재 목록의 일시적 통신 오류는 최대 2회 시도한다. 인증·응답 형식 오류를 무한 재시도하지 않는다. 실패 후 15초 실패 캐시가 만료되면 새 조회가 가능하며, 실행 엔진은 다음 선정 주기에 다시 평가한다. 세부 원인은 유한 코드(network_timeout 등)·시도 횟수로 기록하고 원본 인증/쿼리 문자열은 노출하지 않는다.
- PAPER 사이클에서 신호 조건과 별개로 자금을 진단해 읽기 전용 메모리에 제공한다. 화면 폴링은 DB·외부 API를 조회하거나 세션을 만들지 않는다. 초기 시작의 실패 단계 분류도 유지한다.
- 기관/모드/실행 세션별 최종 실행 판단을 후보·시장국면 기록과 별도로 제공한다. 시장 관찰 heartbeat가 직전 자금/신뢰도 차단 사유를 덮어쓰지 않는다. 같은 판단의 연속 횟수·관찰 시작·최근 처리 기록은 해당 실행 세션 범위로 표시한다.
- 대시보드의 경고, 기관별 표, 선택 기관의 전략 카드, 거래소 운용 요약에 이유와 확인 경로를 연결했다. 실제 신뢰도/적용 기준, 목록 조회 오류 종류·시도 횟수, 자금 대조와 새 PAPER 평가 준비를 함께 보여준다.
- 설정된 실제 손실률·표본·변동성·신뢰도 조건 중 실패한 것을 안내한다. 미확정 이력은 신뢰도 자동 조정에 쓰지 않고, 중립 기본 손실률은 실측으로 취급하지 않는다. 실제 측정된 소표본 손실 및 사용자 요구 표본은 계속 검사한다. 신뢰도 기준 자체를 거래 횟수를 늘리기 위해 낮추지 않았다.
- 이전 공개 .9 롤백 설치기가 이 Mac의 deploy 폴더에서 빠져 있던 기존 환경 문제는 이미 보관된 동일 파일의 pinned SHA-256·크기를 확인해 복원했다. 새 설치기 제작이나 게시가 아니다.

## 기존 사용자의 재개 경로

새 패치를 포함한 설치 환경에서 각 기관의 **거래 정지 → 운용 요약 → 보유 PAPER 포지션·주문 예약 확인 → 별도 새 평가임을 확인 → 과거 기록 보존하고 새 PAPER 평가 준비** 순서로 진행한다. 실행 중·잔여 보유·미확정 예약·계정/모드 불일치 때는 작업을 거절한다. 같은 기관/통화의 새 기준을 반복 초기화하지 않으며 손실 후 자금을 계속 리셋하는 기능이 아니다. 과거 기록·전체 기간 통계·LIVE 한도·전략 승인도 유지된다. 새 평가는 과거 PnL 복구 완료가 아니며 실제 시작은 사용자가 시작 버튼으로 요청해야 한다.

사용자 원장 복사본에서 Binance/Bybit/OKX/Bitget/Upbit/Bithumb 6기관의 실제 runtime action을 재생했다. 모두 미확정 자금 차단에서 paper_reconciled_funds로 바뀌고, 해당 모드의 가상 자금 예약 검사도 통과했다. 재실행은 created=false다. 복사 원장 해시는 동일했고 실제 사용자 폴더에는 세션 파일을 만들지 않았다. Coinone의 운용 기준은 변경하지 않았다. 신호·전략·위험 조건이 충족되지 않으면 이 절차 이후에도 거래를 기다리는 것이 올바른 동작이다.

## 검증 근거와 남은 범위

- 사용자 원본 DB·설정·청산 원장·보유 파일: 작업 전후 SHA-256 동일. 전체 제공 파일의 크기/mtime도 전후 대조한다.
- 공개 OKX 현재 목록: 인증 키/주문 없이 SWAP 500개, 현재 조회 1회 성공. 당시 사용자 네트워크의 재현이나 계좌 주문 인수를 뜻하지 않는다.
- 전체 Python **5,607 passed / 11 skipped / 3 subtests passed**, Node **73 passed**, 렌더러 TypeScript 검사·production build 통과. Python의 2개 경고는 기존 Starlette/httpx 및 utcnow deprecation이다. 신설 회귀는 실제 CCXT 의존성, 일시 오류/실패 캐시 회복, 정확한 실패 기준, 기본값과 실제 손실의 구분, 기관·모드·세션 격리 및 읽기 전용 화면 투영을 포함한다.
- 실제 빌드된 React 화면: 신설 6개 시나리오 및 기존 PAPER 세션·코인/증권 운용 화면 41개 검사, 합계 47개를 통과했다. 실행 중 새 평가 금지, 별도 확인 후 준비, 중복 초기화 금지, 화면 오류/불필요한 주문·설정 변경 없음을 확인했다.
- 이 패치의 Windows 설치기 빌드·설치 업데이트/롤백·사용자 PC에서의 OKX 실제 시작·거래 지속·24/72시간 운용은 수행하지 않았다. 설치된 공개 .10을 이번 로컬 패치와 혼동하지 않아야 한다. 후속 배포는 새 제품/updater 버전과 공개 .10 기준을 맞춘 다음 전체 Windows 빌드·설치 인수를 수행해야 하며, 동일 .10 설치기를 패치됐다고 재사용하면 안 된다. 이 자료만으로 '모든 사용자에게 완벽히 재발하지 않음'이나 수익 회복을 보장하지 않는다.
