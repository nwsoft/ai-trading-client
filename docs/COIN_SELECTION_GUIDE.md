# NoahAI 코인·종목 선택 가이드

> 기준: 2026-09-11 · v3.9.1.27 공개판  
> 이 문서는 암호화폐와 국내 주식·ETF의 자동 후보 선정 계약 정본입니다. 후보 선정은 주문·수익 추천이 아닙니다. v3.9.1.18의 OKX 후보 복구와 이후 기관별 소유권·실행 계약은 현행 코드에 누적됐으며, 현재 공개 자산과 실제 계정·시장·장시간 결과는 별도 증거로 판단합니다.

## 1. 한눈에 보는 실행 흐름

```text
거래소·증권사 지원 종목 확인
  → 전체 시세 스냅샷 1회 수집
  → 거래정지·상품유형·유동성 1차 필터
  → 유동성 상위 후보의 스냅샷 점수 계산
  → 선정 종목만 상세 캔들·지표·전략 재검증
  → 시장국면에 맞춘 수량·메이저/알트 비율 조정
  → 후보 목록 원자 교체
  → 심볼별 최신 신호와 AI 커스텀 조건 재평가
  → 계좌·비용·손실·포지션·주문 가드레일
  → PAPER 또는 LIVE 주문
```

후보 선정은 “지금 더 자세히 분석할 종목”을 줄이는 단계입니다. 정상 후보로 뽑혀도 실시간 신호가 `HOLD`이거나 전략·위험·주문 조건 중 하나가 차단하면 주문하지 않습니다. 시장의 다른 참여자가 거래 중이라는 사실도 NoahAI의 진입 조건 통과를 뜻하지 않습니다.

Binance의 `선택된 코인 수: 10`은 건강 상태를 뜻하지 않습니다. 10개가 모두 `fallback_unscored`·`미산출`이면 화면용 진단 목록일 뿐 실행 가능한 후보는 0개입니다. v3.9.1.15는 이 목록을 성공 캐시나 완료된 재선정으로 취급하지 않고 현재 계정 캐시를 새로 평가합니다. 회복 전에는 기존 포지션 보호만 계속하며, 같은 경고를 거래 사이클마다 출력하지 않습니다.

후보 캐시는 계정별 `Documents/NoahAI/<계정>/cache`에 저장됩니다. 앱 설치 폴더나 고정 `nwsoft` 계정의 캐시를 공유하지 않으며, 계정·API 런타임을 바꾸면 후보 평가기도 같은 최신 연결로 갱신됩니다.

현물 거래소는 LONG 매수·NoahAI 관리 수량 청산만 허용합니다. 파생 거래소는 지원 마켓과 전략 조건에 따라 LONG/SHORT를 평가합니다. 토큰화 주식·지수·원자재처럼 암호화폐 선물로 볼 수 없는 상품은 파생 후보에서 제외합니다.

주식·ETF 후보는 증권사마다 따로 보관합니다. 사용자가 지정한 종목을 우선하고, 자동 후보는 기본 8개까지 선택합니다. `all` 모드는 주식과 ETF가 한 종류에 치우치지 않도록 조합하며, 거래정지·상장폐지 상태는 제외합니다.

## 3. 점수의 의미

암호화폐 종합점수는 다음 값을 정규화해 상대 비교합니다.

- 변동성: 너무 낮아 기회가 부족하거나 지나치게 높아 위험한 구간을 구분합니다.
- 거래량 안정성: 실제 체결 가능성과 급격한 유동성 저하 위험을 봅니다.
- 추세: 후보 단계에서는 24시간 가격 변화 방향을 반영하고, 선정 뒤 실시간 분석에서 다중 시간봉 방향과 강도를 다시 확인합니다.
- 거래 빈도: 시장 활동성이 충분한지 확인합니다.
- Binance 보조값: 5분 캐시에 펀딩비와 미결제약정(OI)이 있으면 보조 반영합니다. 없으면 50점으로 꾸미지 않고 그 항목의 가중치를 제외해 나머지 실제 값만 다시 정규화합니다.
- 기술·리스크 열: 설명을 위한 세부값입니다. 후보 단계에서 기술 캔들을 아직 읽지 않았으면 기술점수는 `—`이며, 화면의 모든 열을 단순 평균한 값이 종합점수와 같아야 하는 구조는 아닙니다.

주식 점수는 가격 모멘텀, 거래량, MA5/MA20, RSI, 외국인·기관 수급, 최근 NoahAI 거래 피드백을 사용합니다. ETF는 NAV 괴리, 추적오차, 거래대금, 운용보수와 최근 거래 피드백을 별도 모델로 평가합니다. 점수는 미래 수익률 인증이 아닙니다.

## 4. 시장국면과 재선정

### 암호화폐

- Binance는 BTC 70%·ETH 30%의 15분봉 지표를 사용합니다.
- Upbit·Bithumb·Bybit·OKX·Bitget은 각 거래소의 BTC 시장 15분봉을 따로 사용합니다. 다른 거래소의 국면을 복사하지 않습니다.
- 첫 관찰은 즉시 현재 국면으로 사용합니다.
- 이후 기본 5분마다 관찰하되, 서로 다른 국면이 2회 연속 확인되고 이전 확정 국면이 최소 10분 유지된 뒤에만 전환합니다.
- 확정 국면이 바뀌면 백그라운드에서 후보를 다시 평가합니다. 안정된 국면에서도 후보 선정 후 3시간이 지나면 재평가합니다.
- 기존 포지션 감시와 TP/SL은 재선정을 기다리지 않습니다. 포지션이 많은 경우 후보 교체를 연기하고 다음 사이클에서 재시도합니다.

기본 비율은 상승장 메이저 20%/알트 80%, 하락장 60%/40%, 고변동장 40%/60%, 정상·횡보장 30%/70%입니다. 실제 수량은 `min_total_coins`, `max_total_coins`와 현재 확보된 정상 후보 수를 함께 따릅니다. 한 분류가 부족하면 다른 분류의 고득점 후보로 빈자리를 채우지만 메이저/알트 분류 자체는 바꾸지 않습니다.

### 국내 주식·ETF

- 지원 증권사는 KOSPI 최근 6개 종가로 5거래일 수익률과 일간 절대변동 평균을 계산합니다.
- 5일 수익률이 +1.5% 이상이면 `bull`, -1.5% 이하이면 `bear`, 일간 절대변동 평균이 2% 이상이면 `volatile`, 나머지는 `range`입니다.
- 지수 이력 API가 없는 증권사는 현재 KOSPI 등락률을 명시적 대체값으로 사용합니다. 지수도 없으면 대표 종목 변화로 제한적으로 추정합니다.
- 동일 증권사 분석 서비스와 유니버스는 기본 5분 재사용하므로 60초 거래 주기마다 전체 목록과 국면을 다시 받지 않습니다.

## 5. AI 커스텀과의 관계

- 일반 `confirm`: NoahAI 기본 후보와 기본 신호를 사용자 전략 조건이 추가 확인합니다.
- 고급 `independent`: 전략의 UniversePolicy가 포함·제외 종목, 최소 거래대금, 스프레드, 변동성, 데이터 길이와 정렬 기준으로 별도 후보를 만들 수 있습니다.
- 고정 심볼: 평가 대상에는 반드시 포함하지만 주문을 강제하지 않습니다.
- 공통 불변 경계: 거래소 미지원, 데이터 부족, 오래된 스냅샷, PAPER/LIVE 권한, 계좌·손실·포지션·주문 가드레일은 어떤 AI 커스텀도 우회하지 못합니다.
- 적용된 전략이 심볼 범위를 명시하지 않으면 기본 후보군을 사용합니다. 전략이 종목별 조건을 명시하면 각 종목의 실제 데이터로 다시 판정합니다.

## 6. 상태 표시와 실패 처리

| 상태 | 의미 | 신규 진입 |
|---|---|---|
| `scored` | 목표 수량만큼 정상 평가 | 후속 게이트 통과 시 가능 |
| `scored_partial` | 정상 후보가 목표보다 적음 | 확보된 후보만 후속 평가 |
| `fallback_unscored` | 거래소 상품·전체 티커 또는 필수 스냅샷 계산 실패로 정상 후보 0개 | 차단 |
| `stale_unscored` | 스냅샷 또는 선정 소요시간이 허용 범위를 초과 | 차단 |

평가 실패 때 표시되는 주요 심볼 목록은 연결 복구용 참조 목록이지 시장 순위가 아닙니다. `0.00점`이나 임의의 30·50점으로 정상 후보처럼 만들지 않습니다. 신규 진입은 차단하지만 기존 포지션의 감시·보호주문·청산은 계속합니다.

새 결과가 120초보다 오래되면 최근 정상 후보가 있는 경우 그 목록을 유지합니다. 정상 후보가 전혀 없다면 `stale_unscored`로 표시하고 주문하지 않습니다.

현재 목록 전체가 `fallback_unscored` 또는 다른 비실행 상태이면 다음처럼 처리합니다.

- 후보 상세 캔들·AI 신호 분석과 신규 진입을 생략해 장애 중 API 호출과 화면 부하를 늘리지 않습니다.
- 기존 포지션 감시·TP/SL·청산은 계속합니다.
- 3시간 정기 주기를 기다리지 않고 즉시 한 번 복구를 요청한 뒤 60초→120초→240초처럼 재시도 간격을 늘리며 최대 15분에서 제한합니다. 회복하면 다시 초기값으로 돌아갑니다.
- 같은 거래소의 UI·자동 재시도는 기존 single-flight에 합쳐집니다.
- 같은 거래소·상태·이유·심볼의 동일 실패 원장은 최초 즉시 저장한 뒤 기본 15분에 한 번만 감사 기록을 남깁니다. 재평가는 계속하되 1분마다 성공처럼 보이는 새 세션을 만들지 않습니다.
- 재선정이 다시 미산출이어도 이전 정상 점수 후보가 있으면 그 목록을 보존합니다.
- Binance·Upbit·Bithumb·Bybit·Bitget·OKX의 재시도 시각과 실행 중 작업은 거래소별로 분리됩니다.

## 7. 실사용 성능 구조

- 거래소가 일괄 티커를 지원하면 전체 심볼 시세를 한 요청으로 받습니다.
- 일괄 API가 없을 때만 최대 8개 제한 병렬 호출을 사용하며 단계별 기본 제한시간은 10초입니다.
- 유동성으로 먼저 줄인 상위 30개만 네트워크 호출 없는 스냅샷 점수를 계산합니다. AI 커스텀 고급 필터용 원본 시장 목록은 별도로 유지합니다.
- 같은 거래소에서 버튼·자동 루프가 동시에 요청하면 `single-flight`로 한 작업만 실행하고 결과를 공유합니다.
- 전체 티커·완료 후보는 기본 30초, Binance 펀딩비·OI는 기본 5분, 주식 유니버스는 기본 5분 재사용합니다.
- 상세 캔들은 선정된 종목의 후속 신호·전략 검증에서만 읽고 거래소·심볼·시간봉별로 기본 60초 재사용합니다. 후보 점수 worker는 종목별 네트워크 호출을 하지 않습니다.
- 자동 재선정은 거래·포지션 감시 루프 밖에서 실행하고, 완료된 새 목록만 한 번에 교체합니다. 중간 목록을 화면이나 주문 경로에 노출하지 않습니다.
- 여섯 거래소의 캐시·실행 중 요청·선정 결과는 거래소 키로 분리합니다.

### 성능 검증 목표

아래는 설계 목표이며 인터넷·거래소 장애에서도 보장되는 수치가 아닙니다.

- 버튼 접수·로딩 표시: 200ms 이내
- 최근 캐시 결과: 2초 이내
- 단일 거래소 초기 선정 p95: 10초 이내
- 6개 거래소 병렬 초기 선정 p95: 15초 이내
- 거래·포지션·설정·AI 커스텀 요청: 후보 재선정 때문에 대기하지 않음
- 120초 초과 결과: 런타임 후보 교체 금지

소스 단위 테스트만으로 위 p95를 확정할 수 없습니다. Windows 배포 후보에서 Binance·Upbit·Bithumb·Bybit·Bitget·OKX와 연결 증권사별 콜드/웜 실행시간, API 제한, 종료 복구를 측정해야 합니다.

## 9. 사용자가 확인하는 방법

1. 코인 정보에서 현재 거래소를 확인한 뒤 `코인 선정 실행`을 누릅니다.
2. 숫자 점수와 상태가 `scored` 또는 `scored_partial`인지 확인합니다.
3. `미산출`이면 시장이 나쁜 것으로 해석하지 말고 해당 거래소의 상품 목록·전체 티커·필수 스냅샷 로그를 확인합니다. 기술점수만 `—`인 것은 후속 캔들 검증 전 상태일 수 있습니다.
4. 같은 참조 목록이 반복되면 시장 순위 갱신으로 보지 말고 연결·티커 단위·유동성 필터를 확인합니다. 자동 복구는 점진적으로 간격을 늘리며, 동일 실패 저장 로그는 기본 15분보다 자주 나오지 않아야 합니다.
5. 정상 후보인데 주문이 없으면 거래 로그에서 `HOLD`, AI 커스텀 조건, 비용·손실·포지션·주문 차단 사유를 확인합니다.
6. 자동 운용 중 재선정은 기존 포지션을 자동 청산하지 않으며, 새 후보는 다음 신규 진입 평가부터 사용됩니다.

## 10. 배포 전 필수 확인

- 6개 거래소 각각에서 일괄 티커가 한 번만 호출되는지
- 후보 점수 worker가 종목별 캔들·펀딩비·OI 네트워크 호출을 만들지 않는지
- 거래소별 심볼·점수·로그가 다른 거래소에 섞이지 않는지
- 데이터 일부 실패가 `scored_partial`, 전체 실패가 `fallback_unscored`인지
- 전체 실패 시 상세 분석을 반복하지 않고 60초부터 최대 15분까지 점진 재시도하는지
- OKX 파생 ticker에 `quoteVolume`이 없어도 원문 `volCcy24h`(기초자산 수량)와 현재가로 USDT 거래대금을 환산하고, `vol24h`/CCXT `baseVolume`의 계약 수를 기초자산 수량으로 오인하지 않는지
- 동일 `fallback_unscored`가 1분마다 새 DB 세션으로 저장되지 않고 기본 15분 감사 주기를 지키는지
- 재선정 실패가 이전 정상 후보를 덮지 않는지
- 120초 초과 결과가 기존 정상 후보를 덮지 않는지
- 재선정 중 포지션 감시·TP/SL·설정·AI 커스텀이 응답하는지
- 국면 한 번의 튐으로 후보가 왕복 교체되지 않는지
- 주식·ETF 목록과 국면 API가 매 60초 중복 호출되지 않는지
- Windows 설치본의 콜드/웜 p95와 6개 거래소 12시간 운용 메모리·요청량
- 거래 시작 전 잔고·종목 조회만 한 키움·신한·미래에셋·KIS 어댑터도 안전 종료 때 남지 않는지

공개 v3.9.1.17 설치본은 변경하지 않습니다. v3.9.1.18 새 Windows 설치본·업데이트 메타데이터·OKX 콜드/웜 선정과 장시간 PAPER를 확인하기 전에는 사용자 해결 완료로 간주하지 않습니다.
