## 2026-09-25 현행 보강과 재설계안

2026-09-26 최종 구현 연결: 중첩 기간식·latched와 별도로 STATE/UPDATE의 명시적 숫자 상태를 공통 IR·Level 1~5·진입/청산·재생에 연결했다. 제한 문법과 완료 봉·계정/기관/종목/버전/모드 격리를 유지한다. 원문 보완은 고객별 DB 수정이 아니라 앱의 질의→답변→재분석→새 버전→승인/PAPER 경로로 제공한다. 정의 없는 원문 자동 완성이나 모든 기존 성과 승계는 하지 않는다. 현재 완료/실환경 게이트는 47 실행 원장, 시험은 TEST_STATUS를 따른다.

v47 후보는 기존 전략 호환성을 우선한다. 기존 beginner/standard/advanced/lab=1~4를 유지하고 research=5를 추가했다. 5는 같은 거래의 비용 민감도와 저장된 검증 근거를 비교하는 읽기 전용 연구 기능이다. Level 5를 만든다는 사용자 결정으로 과거 미도입 방침을 변경했다. 향후 Level 6 이상도 추가할 수 있으며 Level 5를 영구 상한으로 두지 않는다. 새 Level은 기존 전략/설정 호환과 공통 실행 계약을 보존해야 하며 추가 Level의 현재 구현 완료를 뜻하지 않는다. 아래 이전 버전 절의 기능 범위는 당시 기록이다.

세 계약을 분리한다: (1) 실행 의미·자료·단위의 유효성, (2) 표본·순손익·낙폭 등 성과 평가, (3) PAPER/LIVE 실행 권한과 계좌 위험. 성과 기준 미달을 안전 위반으로 기록하지 않는다. 유효한 승인 전략은 과거 재생 합격 없이 PAPER를 선택할 수 있다. 기존 46 차단에 대한 공통 전환은 원문·버전·기존 성과 보존을 전제로 하며, 빈 실행식을 기본 AI로 대체하는 방식으로 호환성을 가장하지 않는다.

2026-09-26 코드 보강: 중첩 기간 조건과 이름 붙인 유한 latched 상태(설정/해제/만료, 합성 이력 최대 300봉)를 공통 IR로 지원한다. Drive 공개 공유 자료는 사용자 로그인 없이 앱 API 키로, 제한 자료는 기본 브라우저 PKCE 승인과 메모리 토큰 갱신으로 연결한다. NoahAI 회원 로그인은 변경하지 않는다. 운영자 Google 앱 등록과 실제 권한 승인은 별도 게이트다. PAPER 진행과 선택형 백테스트는 분리하며 기존 원문·성과·실주문 권한을 자동 변경하지 않는다.

| 장기 제품 비전 | NoahAI Strategy OS | 현재 완성 기능명이 아니라 지향점으로만 사용 |
| 무료 공유 서비스 | NoahAI 검증 전략 허브 | 한국 사용자 주명칭. `Verified Strategy Hub`는 영문·검색·기술 문서의 보조명 |
| 향후 유료 서비스 | NoahAI Strategy Marketplace | 포인트 구매·영구 실행 라이선스·제작자 수익 원장이 검증된 뒤 사용 |
| 파일 형식 | `.noahstrategy` | 변경하지 않음 |
| 내부 호환 식별자 | `ai_custom`, `StrategyStudio`, 기존 설정 키 | 사용자 데이터 호환을 위해 변경하지 않음 |

`전략 스튜디오`와 `검증 전략 허브`는 이름이 다른 중복 서비스가 아니다. 전자는 클라이언트 안에서 전략을 입력·구조화·검증·PAPER·적용하는 **제작·운용 작업 공간**, 후자는 daltrading에서 회원이 패키지를 제출하고 E0 공개·검증 여권을 확인하며 전략을 찾고 내려받는 **공유·탐색 서비스**다. NoahAI Labs는 두 기능을 함께 설명할 때 `전략 스튜디오 → 검증 전략 허브` 관계를 먼저 보여 주고, 한국어 화면에서 영문 이름만 단독 사용하지 않는다.

### Level 명칭

Strategy Studio의 Level 1~5는 **현재 구현된 화면 깊이와 편집·운용 정책 범위**다. 전략 성과 등급이나 LIVE 권한 등급이 아니다. 기존 1~4 식별자는 유지하고 research=5를 추가한다. **향후 Level 6 이상도 추가할 수 있다.** Level 5는 영구 상한이 아니며 추가 단계의 기능·호환·사용법을 함께 정의한다. 현재 UI/엔진이 미구현 Level을 임의로 허용한다는 뜻은 아니다.

- Level 1: 이해·시험
- Level 2: 핵심값·적용 범위
- Level 3: 원문-규칙 추적·전체 IR·안전 선언형 규칙 편집
- Level 4: 전문가 운용 정책·전체 IR·안전 DSL. 안정형·표준형·적극형의 3단계로 위험예산, 최대 비중, 레버리지·동시 포지션 요청과 국면 이탈 대응을 조절. 최종값은 계좌 마스터 상한을 넘지 않음
- Level 5: 연구 비교. Level 4 범위에 읽기 전용 비용 민감도·저장 근거 비교를 추가하며 주문 권한은 늘리지 않음

| Level | 권장 사용자 | 이용 범위 | 대표 시나리오 |
|---|---|---|---|
| 1 이해·시험 | 처음 전략을 가져오는 초보자 | 자료 범위·요약·원문 근거·누락·위험 확인 | 이동평균 아이디어·책·영상의 의미와 빠진 조건을 저장 전에 확인 |
| 2 핵심값 | 일반 사용자, TradingView·Pine 경험자 | 진입·청산·TP/SL·국면·거래소 적용값, 표준 위험정책, 저장·승인·자동검증·PAPER | Pine 원문과 실제 엔진 적용값·미지원 조건을 대조하고 PAPER 근거 축적 |
| 3 전체 근거 | 규칙을 직접 설계·수정한 고급 사용자 | 원문-규칙 추적, 전체 IR, 안전 선언형 규칙, 독립 후보·다중 시간대·국면 범위 | 상승·하락·횡보 전략을 분리하고 우선순위·포함 종목·조건을 근거와 함께 관리 |
| 4 전문가 운용 | 계정 위험 정책을 비교하는 전문가·실험실 사용자 | Level 3 + 위험·레버리지·동시 포지션의 제한된 전략 요청 | 같은 승인 전략을 계좌 마스터 한도 안에서 운용하되 하드 가드레일은 유지 |
| 5 연구 비교 | 검증 가정을 비교하는 사용자 | Level 4 + 같은 거래의 비용 민감도·저장 근거 비교 | 연구 결과를 확인하되 승인·PAPER·LIVE를 자동 승격하지 않음 |

TradingView·Pine 경험자는 Level 2에서 원문과 실제 적용값을 먼저 대조하고, 직접 규칙을 수정할 때만 Level 3으로 올리는 것을 기본 흐름으로 한다. Level이 높을수록 수익률이나 전략 품질이 높다는 뜻은 아니다.

처음 사용자의 제작 흐름은 별도 실행 엔진이나 위험 권한을 만들지 않는다. 모든 Level에서 `처음 사용 · 5분 따라 만들기`를 열어 `기본 NoahAI / 관리형 예제 / 내 전략 가져오기` 중 하나를 고르고 쉬운 질문 → 실행 설명 → 규칙 유효성 확인·버전·승인 → PAPER로 진행한다. 과거 백테스트는 별도의 선택 평가다. 안내는 현재 Level과 설정을 바꾸지 않으며, 관리형 예제는 검증된 선언 규칙 정본을 사용한다. 안내 초기화는 전략·검증·거래 원장을 삭제하지 않는다. Level 5 연구 비교는 초보자 우회 단계가 아니다.

Level 4는 가드레일 해제 권한이 아니다. 사용자 승인·LIVE 명시 허용·일일 손실 중단·포지션/집중도 상한·거래소 최소주문/정밀도·TP/SL 보호·중복 주문 방지·포지션 대조·긴급 정지는 조절하거나 끌 수 없다.

현재 Level 5는 기존 Level 4의 운용 정책에 읽기 전용 연구 비교를 더한다. 손실 권한을 확대하지 않는다. Level 4·5 전략은 위험·레버리지·동시 포지션을 요청할 수 있지만 최종 실행은 `min(계좌 마스터, 전략 요청, 시장 제한, 성과 제한)` 계약을 따른다. 계좌 상한을 5~10개로 올리는 일은 전략 편집과 별도의 명시적 사용자 승인이고, 상관 노출·총 위험·증거금·보호주문/API 호출량을 PAPER와 소액 LIVE에서 확인해야 한다.

검증 증거는 `E0~E5`를 사용해 화면 깊이 Level 1~5와 구별한다.

## 2. 제품 정의

> NoahAI Strategy Studio는 자연어·Pine·문서·영상 등 사용자가 보유한 전략 지식을 근거가 추적되는 안전한 전략 버전으로 구조화하고, 과거 재생·PAPER·실체결 증거와 위험 가드레일을 거쳐 사용자가 직접 승인·운용하도록 돕는 전략 작업 공간이다.

NoahAI는 TradingView를 대체하는 차트 플랫폼을 만들지 않는다. TradingView와 기존 전략 자산을 입력으로 받아 다음 공백을 해결한다.

1. 사람이 설명한 전략을 실행 가능한 규칙으로 옮길 때 생기는 누락과 오역
2. 백테스트와 실제 시장의 비용·지연·체결 차이
3. 시장국면과 계좌 위험을 무시한 일괄 실행
4. 전략 버전·승인·체결·성과가 서로 연결되지 않는 문제
5. 검증 근거 없이 전략이 홍보·공유되는 문제

## 3. 하나의 사용자 흐름

```text
자료 입력
→ 근거 추출
→ Noah Strategy IR 초안
→ 미지원·모호 조건 확인
→ XAI 검토
→ 새 버전 저장
→ 사용자 승인
→ 과거 재생·OOS·워크포워드 (보조 평가 선택, PAPER 시작의 성과 합격 조건 아님)
→ PAPER 전진검증
→ 사용자 최종 적용
→ LEARNING/PAPER/LIVE 실행 게이트
→ 버전별 판단·주문·체결·성과 기록
→ 공유 패키지 내보내기 또는 개선 버전 제안
```

저장, 검증, 적용과 실행은 서로 다른 상태다. 어느 단계도 사용자 승인 없이 다음 단계로 자동 승격하지 않는다.

PAPER 전진검증 후보와 최종 적용 전략은 실행 권한도 다르다.

- PAPER 후보 불일치: 해당 후보만 표본을 만들지 않고 기본 NoahAI 후보로 위임한다.
- 최종 적용 전략 불일치: 사용자가 선택한 운용 조건이므로 신규 진입을 fail-closed로 차단할 수 있다.
- 독립 PAPER 후보: LONG/SHORT 한 방향, 선언형 진입조건, 단위가 명확한 TP/SL이 모두 있어야 시작할 수 있다.
- 원문·IR 보존 성공은 실행 가능 판정이 아니다. 실행 노드가 비어 있으면 `실행 규칙 미구조화`로 분리한다.
- 기존 미구조화 관찰 버전은 삭제·자동변환하지 않으며 기본 NoahAI 거래를 막지 않는다.
- PAPER 일시정지는 실행 권한 삭제이며, 늦은 결과는 일시정지 전 열린 포지션의 근거만 갱신할 뿐 실행 권한을 다시 만들지 않는다. 재개는 같은 attempt의 다음 활성 구간을 열고, 새 시도는 이전 attempt 전체를 보관한 뒤에만 만든다.
- 같은 strategy key의 여러 버전은 한 번에 하나만 PAPER 실행 권한을 가진다. v1 검증 중 v2를 시작하면 v1을 자동 초기화하거나 상태만 바꾸지 않고, v1의 명시적 일시정지를 먼저 요구한다.
- 여러 PAPER 전략이 동시에 일치하면 동일 거래소·종목의 공유 가상 실행 슬롯을 round-robin으로 배정한다. 독립 동시계좌 검증이 필요하면 별도 포트폴리오 격리 기능이 구현되기 전에는 제공됐다고 표시하지 않는다.

전략 정의와 실행 근거 내보내기도 분리한다.

- `.noahstrategy`: 전략 규칙·IR·집계 여권·이용 정책. 공유·다운로드 정본이며 개인 체결 상세를 담지 않는다.
- `strategy_execution_evidence`: 해당 계정과 strategy key/version의 PAPER 세부 거래. 사용자가 로컬에서 명시적으로 내보낼 때만 생성한다.
- 허브 증거: 서버가 확인할 수 있는 서명된 집계·체결 증명만 E2~E5 승격에 사용한다. 사용자 로컬 JSON을 자동 업로드하거나 신뢰 점수로 즉시 전환하지 않는다.
- 세부 거래에는 종목·방향·시각·가격·보유시간·수량·Notional·레버리지·gross/net PnL·비용·진입/청산 사유·적용 TP/SL·Smart Exit를 기록하되, API 키·잔고·외부 주문 ID·원문 파일·AI 내부 추론은 제외한다.
- 이전 버전이 기록하지 않은 상세값은 0으로 생성하지 않고 `not_recorded`로 표시한다.

## 5.1 v3.9.1.17 전략 의미 보존 계약

v3.9.1.17 소스 후보는 전략 원문을 실행 규칙으로 바꾸는 단계에서 다음을 필수 계약으로 둔다.

1. `confirm` 전략도 원문에 LONG 또는 SHORT가 명시되면 반대 방향 NoahAI 후보를 승인하지 않는다.
2. 양방향 전략은 LONG/SHORT 조건을 각각 구조화한다. 둘을 분리하지 못하면 한 방향으로 축소하지 않고 사용자 확인 상태로 둔다.
3. Pine 변수·별칭의 데이터 흐름을 지원 범위에서 해석한다. 진입 조건 별칭을 해석하지 못하면 방향만 남겨 실행 가능으로 표시하지 않는다.
4. TP/SL은 `%` 또는 명시된 fraction 단위가 있어야 한다. `손절 30`처럼 단위가 없는 숫자는 가격·ATR 배수·비율 중 무엇인지 추측하지 않는다.
5. TP 0.05~5%, SL 0.05~3%, 포지션 비중 1~50%, 레버리지 1~10배, 신호 임계값 0~1의 저장·PAPER·주문 경계를 하나로 사용한다. 범위 밖 값은 조용히 보정하지 않는다.
6. Level 3 JSON이나 범위·국면·역할을 편집한 뒤에는 저장 직전 서버가 최종 규칙을 다시 검사한다. 이전 분석 결과의 준비 상태를 재사용하지 않는다.
7. 과거검증은 Upbit/Bithumb KRW 현물, Binance/Bybit/OKX/Bitget USDT 선물 데이터를 각각 조회한다. Bithumb는 공개 API가 지원하는 30분봉, 나머지는 15분봉을 사용하고 화면·결과에 출처와 시장 유형을 남긴다.
8. 외부 LLM은 이름·요약·위험·확인 질문을 보조할 수 있지만 주문 조건·방향·TP/SL·비중·레버리지를 실행 정본으로 확정하지 않는다. 실행 정본은 로컬 결정형 컴파일러가 원문에서 증명한 규칙만 사용한다.
9. 원문 분석 뒤 실행 조건이나 TP/SL을 편집하면 source-grounding 해시가 달라지므로 저장 직전 재검증에서 차단한다. 변경한 내용을 원문에 반영하고 다시 분석하거나, Level 3·4에서 `사용자 선언 실행 규칙` 확인을 선택해 원문 자동 변환과 구분된 새 해시·새 버전으로 저장해야 한다.
10. AI 멘토의 관리 프리셋은 모호한 자연어가 아니라 선언형 LONG/SHORT 조건, 고정 단위 TP/SL, 위험예산·최대 비중·레버리지 상한을 가진 검토 초안이다. 불러오기는 자동 저장·승인·PAPER·LIVE가 아니다.

이 계약은 단순하고 지원되는 전략의 의미 보존을 강화한 소스 상태다. `request.security`, 동적 `input.*`, 사용자 함수, 배열·맵, rolling state, `strategy.position_avg_price` 기반 동적 청산처럼 아직 지원하지 않는 Pine은 구체적인 사유와 함께 실행 불가로 둔다. 임의의 모든 Pine·외부 데이터·복합 주문 상태의 완전한 의미 동등성을 보장하지 않는다.

### 현재 서비스로 약속하지 않는 범위

- 모든 Pine 완전 호환
- AI가 수익 전략을 자동 창조하거나 몰래 수정
- 백테스트·PAPER만으로 수익 인증
- 자동 전략 구매·자동 적용·자동 LIVE
- 성과 기반 과금
- 실제 Noah Point 충전·전략 구매·제작자 지급·코인 결제
- 클라이언트 파일의 완전한 복제 방지
- 사용자 동의 없는 거래 데이터 학습
- 블록체인을 이용한 불법 유통 자동 적발

## 6. 단계별 개발·서비스 계획

### 주문 금액 3계약

Strategy Studio와 기본 NoahAI 전략은 주문 금액을 다음처럼 분리한다.

1. `configured_target_notional`: 사용자가 정한 목표 주문금액. 위험·초기학습·손실회복 정책으로 줄어들 수 있다.
2. `authorized_quantity_cap`: 다중 거래소·계좌·집중도 정책이 허용한 수량 상한. 최소 주문을 맞추기 위해 이 상한을 넘겨 억지로 늘리지 않는다.
3. `exchange_min_notional`: 거래소가 반환한 실제 최소 주문규격. 정밀도·step size·minQty와 함께 주문 직전 재검증한다.

`5.10 USDT < 20 USDT`는 거래소 최소 주문을 맞춘 위험 축소 주문을 사용자 목표 금액과 다시 비교한 구형 계약 오류였다. 신규 계약은 상한 안에서 거래소 최소 규격을 만족하면 진행하고, 만족하지 못하면 실패 폐쇄하며 차단 사유를 XAI와 로그에 남긴다.

### Phase 0 — 신뢰성 기준선

목표: Strategy Studio가 거래·설정·종료·업데이트 안정성을 해치지 않도록 한다.

- Windows 설치·업데이트·롤백 검증
- 설정 저장·복구·기존 계정 호환
- PAPER 원장·TP/SL·손익·통화 정합성
- 다중 거래소·증권사 생명주기와 안전 종료
- 전략 버전·실행 모드·거래소 상태의 분리 표시

완료 기준: 공개 설치본에서 동일 계정 재시작, PAPER 장시간 실행, 안전 종료와 업데이트가 모두 통과한다.

### Phase 1 — Strategy Studio Level 1~4 완성

목표: 사용자가 전략을 이해하고 안전한 버전으로 만들 수 있게 한다.

- Level 1 이해·시험
- Level 2 핵심값·위험·적용 범위
- Level 3 원문 추적·전체 IR·안전 규칙 편집
- Level 4 안정형·표준형·적극형 운용 정책과 조절 가능/불가 가드레일 XAI
- 미지원 조건 차단과 누락 질문
- 버전 diff·승인·롤백·삭제 감사
- 고정 TP/SL과 동적 ExitPolicy의 명시적 구분

완료 기준: 대표 자연어·Pine·PDF 전략이 원문 근거와 함께 재현되고, 미지원 조건은 조용히 제거되지 않으며, Level 4는 하드 가드레일 해제 필드를 저장·실행하지 않는다.

### Phase 2 — 검증 증거 체계

목표: 수익률 하나가 아니라 재현 가능한 증거 묶음을 만든다.

- 과거 재생·비용·슬리피지
- OOS·워크포워드·파라미터 민감도
- 국면별 성과와 부적합 HOLD
- PAPER 전진검증
- 실제 체결 ID·수수료·부분체결·청산 사유 귀속
- 전략 여권과 검증 실행 ID

완료 기준: 같은 전략 버전·데이터 스냅샷·비용 조건으로 검증을 재실행할 수 있고 PAPER와 LIVE를 혼합하지 않는다.

### Phase 3 — Verified Strategy Hub 무료 베타

목표: 판매보다 신뢰 가능한 낮은 장벽의 제출·증거 단계·다운로드 흐름을 안정화한다.

```text
클라이언트 패키지 내보내기
→ 회원이 daltrading에서 직접 제출
→ 제작자 권리 자기선언 + 패키지·IR 구조 검사
→ E0 공개·무료 다운로드
→ OOS·PAPER·확인 체결 증거 단계 승격
→ 신고 기반 운영자 검토·격리
→ 목적별 무료 탐색·다운로드
→ 비활성 가져오기
→ 다운로드 사용자 재검증·PAPER·최종 승인
```

- 자동 외부 제출 금지
- 자기 신고 수익률 랭킹 금지
- 결제·성과 기반 과금 없음
- E0 공개와 검증 근거 승격의 명확한 분리
- 신고·공개 중지·철회·감사 기록
- 원저작자와 파생 전략 권리 구분
- 신규 무료 다운로드도 `가격 0인 취득 거래`와 계정별 영구 실행 라이선스로 기록할 수 있는 원장 계약

완료 기준: 제출자·다운로더·운영자 전체 흐름과 공개 중지 후 신규 취득 차단을 실서비스에서 검증한다. 계정별 라이선스 원장이 도입되면 기존 합법 취득자의 재다운로드와 신규 취득 차단을 구분한다.

### Phase 4 — 전략 여권·탐색·추천 고도화

목표: 인기순이 아니라 사용자 목적과 근거에 맞는 전략을 찾게 한다.

- 최소 표본과 신뢰구간
- 최근성 감쇠와 버전 변경 시 성과 분리
- 국면·거래소·자산·계좌 규모·위험별 탐색
- 상관·집중 위험과 동시 손실 시나리오
- 추천 이유와 사용 금지 조건 설명

추천은 기본적으로 의사결정 보조다. 사용자 승인 없이 전략을 구매·적용·LIVE 실행하지 않는다.

### Phase 5 — 유료 Marketplace 준비

진입 조건: 무료 테스트 기간 동안 상품·판매자 자율 가격 스냅샷, 테스트/유상 포인트 원장, 계정별 구매 권한, 영구 실행 라이선스, 제작자 수익·월 정산 원장, daltrading 관리자 콘솔과 클라이언트 재다운로드 E2E를 완성한 뒤 테스트 종료일에 개방한다.

권장 거래 흐름:

1. 외부 카드·계좌 결제로 Noah Point 충전
2. 전략 버전의 영구·비독점 NoahAI 실행 라이선스 구매
3. 구매 시점 가격·버전·패키지 해시 고정
4. 공급가 기준 플랫폼 20%·제작자 80%를 복식 원장에 적립
5. 14일 보류, 월 마감, T+30 원화 지급과 최소 지급액 50,000원 적용
6. 테스트 포인트는 적립 전부터 유료 오픈일 `1P=1원 구매가치`로 1:1 전환되고 모든 전략에 잔액 범위에서 100% 사용된다고 고지
7. 로그인 1일 1회 10P·그날 최초 유효 PAPER 60분 100P, 30일 최대 3,000P·테스트 누적 최대 30,000P로 제한
8. 후속으로 외부 코인 결제 사업자를 통한 Noah Point 충전

유상 포인트, 테스트·적립 포인트, 제작자 수익을 분리한다. 구매자 포인트는 사용자 간 양도·현금/코인 환전을 허용하지 않는다. 플랫폼 부담 적립 포인트 사용액과 일반 PG 비용은 플랫폼 몫에서 부담하며 세금·원천징수·환불·차지백은 별도 원장 항목으로 기록한다. 판매자는 증거 단계별 허용범위에서 가격을 직접 정하고 10,000,000P 이상은 개별계약형 심사로 판매할 수 있다. 초기 제작자 지급은 원화만 지원한다.

보너스는 안전한 활성화와 첫 결제 마찰을 낮추기 위한 수단이다. 앱 실행 시간을 매시간 누적해 주거나 LIVE 실행·거래 횟수·거래금액·레버리지·PnL을 보상하지 않는다. 이는 장시간 켜 두기·다계정 파밍·과도한 거래를 유도하고 PAPER/LIVE 안전 경계를 훼손하기 때문이다.

전략 다운로드는 저작권·소유권 이전이 아니라 해당 전략 버전의 영구·비독점 실행 라이선스 발급이다. 다운로드 또는 라이선스 발급 후 단순 변심 환불은 제공하지 않되 중복 결제·미발급·손상·비정상 결제 등은 관리자 예외 처리한다.

현재 범위에서 제외:

- 성과 기반 과금
- 광고비로 랭킹 상승
- 검증되지 않은 예상수익 판매
- 자동 구매·자동 실거래
- 사용자 간 포인트 송금·환전
- NoahAI의 직접 코인 보관·교환

상세 거래·포인트·코인 결제 계약은 `STRATEGY_MARKETPLACE_POINTS_AND_LICENSE_PLAN.md`를 따른다.

### Phase 6 — 보호형 실행과 선택적 블록체인

클라이언트에 전체 전략을 전달하는 방식만으로 완전한 복제 방지는 불가능하다. 사업성이 확인되면 서버 사이드 평가·라이선스 토큰·철회 가능한 실행 권한을 별도 설계한다.

블록체인은 필수 기반이 아니다. 적용하더라도 다음 정보만 선택적으로 앵커링한다.

- 패키지 해시
- 전략 버전
- 공개·철회 시각
- 서버 서명 상태

원문, 개인정보, 거래내역, API 키와 삭제가 필요한 데이터는 온체인에 기록하지 않는다.

## 7. 검증 증거 등급

`E`는 Evidence의 약자다. 회원등급·가격등급·수익등급이 아니며 화면에는 한국어 검증명을 먼저 표시한다.

| 등급 | 의미 | 자동 실행 권한 |
|---|---|---|
| E0 신규 공개·구조 확인 | 권리 자기선언·패키지·IR 구조 확인, 성과 점수 없음 | 없음 |
| E1 과거 재생 확인 | 비용 포함 과거 재생 | 없음 |
| E2 외부구간·강건성 확인 | OOS·워크포워드·민감도 근거 | 없음 |
| E3 실시간 PAPER 검증 | 실시간 PAPER 전진검증 | 없음 |
| E4 제한 LIVE 관찰 | 가드레일 안의 제한 실행 관찰 | 없음 |
| E5 실체결 출처 확인 | 출처가 확인된 체결·비용·버전 귀속 근거 | 없음 |

증거 등급은 수익 보증·추천 등급·자동 적용 권한이 아니다. 표본 수, 기간, 데이터 출처, 거래소, 비용, 통화, 전략 버전과 확인 시각을 함께 표시한다.

## 8. 전략 여권과 랭킹 원칙

전략 여권에는 다음을 포함한다.

- 제작자와 권리 근거
- 전략 ID·버전·부모 버전·패키지/IR 해시
- 자산·거래소·현물/선물·시간봉
- 허용·금지 국면
- 진입·청산·TP/SL·포지션 크기·중단 조건
- 데이터 기간·OOS·워크포워드·PAPER·LIVE 구분
- 수수료·슬리피지·통화·MDD·연속 손실
- 실제 체결 증거와 마지막 검증 시각
- 신고·철회·지원 상태

랭킹은 최소 표본, 신뢰구간 또는 보수적 축소, 최근성, 강건성, 위험 효율, 실행 품질, 증거 품질과 운영 품질을 사용한다. 원시 승률·총수익률·다운로드 수만으로 정렬하지 않으며 KRW와 USDT PnL을 환산 근거 없이 합치지 않는다.

## 9. 데이터와 권리 원칙

- 사용자가 입력한 Pine·책·영상·문서의 소유권을 NoahAI가 자동 취득하지 않는다.
- 사용자는 제출 전에 공개·배포·파생 권리를 확인한다.
- 다운로드 사용자는 전략의 저작권·소유권이 아니라 표시된 버전의 NoahAI 실행 라이선스를 취득한다.
- `fork/clone`은 원제작자가 허용한 라이선스에서만 제공한다.
- 검증 데이터와 사용자 거래 데이터는 목적, 동의, 보존기간, 삭제와 비식별 정책을 분리한다.
- 서버는 패키지가 자기 신고한 성과를 신뢰하지 않고 검증 실행 또는 서명된 증거로 확인한다.
- 철회·분쟁·호환 중단이 발생하면 신규 다운로드와 신규 실행 권한을 차단하되 감사 이력은 정책 범위에서 보존한다.

## 10. 핵심 KPI

현재 단계 KPI:

- 원문→IR 변환 성공률
- 사용자 확인 필요 비율과 확인 완료율
- 미지원 조건 실패 폐쇄율
- 버전 저장→승인→검증→PAPER 전환율
- PAPER 7일·30일 유지율
- 버전별 손익·통화·체결 귀속 정합률
- 제출→승인 소요시간
- 다운로드→재검증 완료율
- 무료·유료 취득 거래→라이선스 발급 정합률과 중복 발급 차단률
- 철회·신고·가드레일 위반 건수
- 전략 여권 근거 완성도

유료 Marketplace가 시작되기 전에는 GMV와 성과 기반 수수료를 핵심 KPI로 사용하지 않는다.
