## 1. 최종 권고안

NoahAI는 무료 테스트 기간에 유료 운영 기반을 함께 완성하고, 테스트 종료일에 daltrading 관리자가 유료 모드를 개방할 수 있게 한다. 전환 구조는 `무료 허브·테스트 포인트 적립 → 테스트 포인트의 구매가치 전환 → 원화 Noah Point 충전 → 전략 버전 라이선스 구매 → 제작자 월 정산`이다.

```text
무료 탐색·E0 공개와 테스트 포인트 적립
→ 내 환경 PAPER 재검증
→ 유료 오픈일에 테스트 포인트를 1:1 구매가치로 전환
→ 카드·간편결제·계좌 기반 Noah Point 충전
→ 정확한 전략 버전의 실행 라이선스 구매
→ 14일 판매 보류 원장
→ 월 마감 후 T+30 이내 원화 정산
→ 거래량·규제·보안 조건 충족 뒤 외부 코인 결제 추가
```

핵심 정책은 다음과 같다.

- `E`는 가격등급이 아니라 **Evidence(검증 증거) 단계**다. 화면에는 `E3`보다 `실시간 PAPER 검증` 같은 한국어를 먼저 표시한다.
- E0 전략은 계속 무료다. 성과 근거가 없는 전략을 유료 상품으로 바꾸지 않는다.
- 판매자는 허용 구간 안에서 정확한 가격을 직접 정한다. 저가·박리다매 상품과 100만원·1,000만원 이상 전문 전략을 모두 허용하되, 고가일수록 증거·계약·지원 조건을 강화한다.
- 초기 유료 상품은 구독이나 수익배분이 아니라 **전략 버전의 영구·비독점 NoahAI 실행 라이선스**다.
- 플랫폼 기본 수수료는 부가세를 제외한 판매 공급가의 **20%**, 제작자 몫은 **80%**로 시작한다.
- 일반 카드·간편결제 PG 비용은 플랫폼 20% 몫에서 부담한다. 구매자나 제작자에게 사후 별도 공제하지 않는다.
- 제작자 정산은 원화 계좌 지급이 기본이다. 구매자가 코인으로 결제했더라도 제작자에게 코인을 그대로 전달하지 않는다.
- 사용자끼리 Noah Point를 송금·판매·현금화하지 못하게 한다.
- 테스트 기간에 적립한 포인트는 유료 오픈일부터 `1 Noah Point = 1원 구매가치`로 전환한다. 현금·코인으로 환전되지는 않지만 전략 구매에 실제 사용할 수 있고, 전환일·사용 범위·상한을 적립 전에 공개한다.
- 로그인·PAPER 보상은 **무상 적립 포인트**로 지급하며 유상 충전 포인트와 원장을 분리한다. 플랫폼 부담 적립 포인트 사용 때문에 제작자 정산액을 깎지 않는다.
- LIVE 실행, 거래 횟수, 거래대금, 수익률에는 포인트를 주지 않는다. 보상이 과도한 거래나 손실 감수를 유도해서는 안 된다.
- 앱 실행 또는 PAPER를 매시간 계속 켜 두는 방식의 무제한 보상은 도입하지 않는다. 하루 첫 유효 PAPER 60분만 보상한다.
- 현재 출시 채널은 자체 웹 Marketplace와 NoahAI Windows 클라이언트다. Apple·Google 스토어 정책은 현재 유료 출시 게이트가 아니며, 실제 모바일 스토어 배포를 결정할 때 별도 검토한다.
- 코인 결제·코인 정산은 원화 PG와 월 정산 안정화 뒤의 선택 기능이다. 관리자의 수동 코인 매수·해외 거래소 전송은 핵심 정산 흐름으로 사용하지 않는다.

따라서 NoahAI의 초기 모델은 복잡한 구독·성과수수료·토큰 경제가 아니라 **단건 디지털 라이선스 마켓**으로 한다. 무료 베타에서 공급·재검증·재다운로드 습관을 만든 뒤, 이미 익숙한 라이선스 흐름에 가격만 추가하는 방식이 전환 마찰이 가장 낮다.

## 3. 상품·가격 정책

### 3.0 E0~E5의 뜻

`E`는 Evidence의 약자이며 전략의 **검증 근거가 어디까지 확인되었는지** 보여 주는 단계다. 수익률 순위, 회원등급, 가격표가 아니다.

| 코드 | 사용자 표시명 | 확인 범위 |
|---|---|---|
| E0 | 신규 공개·구조 확인 | 제작자 권리 자기선언, 패키지·IR 구조와 무결성 확인. 성과 근거 없음 |
| E1 | 과거 재생 확인 | 과거 데이터 재생·백테스트 근거가 있으나 미래 구간 검증 아님 |
| E2 | 외부구간·강건성 확인 | OOS, 워크포워드, 비용·민감도 스트레스 근거 |
| E3 | 실시간 PAPER 검증 | 실제 주문 없이 실시간 시장에서 전진 검증한 근거 |
| E4 | 제한 LIVE 관찰 | 사전 안전한도 안에서 관찰한 LIVE 실행 근거 |
| E5 | 실체결 출처 확인 | 거래소·증권사 출처로 체결을 확인한 LIVE 근거 |

E4·E5도 미래 수익을 보증하지 않는다. PAPER와 LIVE 표본은 합산하지 않고 전략 버전·기관·시장·통화별로 분리한다.

### 3.1 유료 판매 자격

| 증거 단계 | 판매·가격 자격 |
|---|---|
| E0 신규 공개·구조 확인 | 무료만 허용, 성과 점수·추천 랭킹 제외 |
| E1 과거 재생 확인 | 무료 또는 10,000~99,000P 입문 구간. `백테스트만 확인`을 가격 옆에 표시 |
| E2 외부구간·강건성 확인 | 10,000~999,000P 판매 후보 |
| E3 실시간 PAPER 검증 | 10,000~9,999,000P 전문 판매 후보 |
| E4 제한 LIVE 관찰 | 일반 가격구간 전체와 10,000,000P 이상 프리미엄 심사 신청 가능 |
| E5 실체결 출처 확인 | 일반 가격구간 전체와 10,000,000P 이상 프리미엄 심사 신청 가능 |

증거 단계는 판매 가능한 범위의 최소 조건일 뿐 전략의 가치를 자동 결정하지 않는다. E3 이상이라는 이유만으로 판매를 자동 승인하지 않으며 권리, 패키지 무결성, 최소 표본, 최대낙폭, 비용 반영, 설명 품질, 지원기관 범위, 중단 조건을 함께 확인한다. 독창적 IP·지속 지원 등 별도 가치가 있는 E3 전략의 프리미엄 신청도 관리자가 개별 계약으로 검토할 수 있지만, 수익률 주장으로 가격을 정당화하려면 E4·E5 출처 근거가 필요하다.

### 3.2 판매자 자율 가격과 판매 구간

1 Noah Point는 결제 화면에서 **1원의 구매가치**로 표시한다. 현금·예금·코인이 아니며 사용자 간 양도나 환전은 할 수 없다.

| 판매 구간 | 가격 | 결정·심사 방식 |
|---|---:|---|
| 무료·체험 | 0P | E0 공개본, 기능 제한 샘플, 제작자 선택 |
| 입문형 | 10,000~99,000P | 판매자가 1,000P 단위로 직접 결정. E1 이상 |
| 표준형 | 100,000~999,000P | 판매자가 직접 결정. E2 이상과 상품 설명 검토 |
| 전문형 | 1,000,000~9,999,000P | 판매자가 직접 결정. E3 이상, 실명/KYC·지원·업데이트·환불 고지와 관리자 승인 |
| 프리미엄·기관형 | 10,000,000P 이상 | 최대가격을 일률 제한하지 않음. E4·E5 원칙, 개별 견적·계약·구매자 확인·분쟁/지급 보류·관리자 승인 |

판매자가 최종 소비자 가격을 정하고 daltrading 관리자는 증거 단계별 허용 범위, 허위·과장 표시, 권리, 지원 가능성, 비정상 가격을 심사한다. 관리자는 특정 수익률을 근거로 가격을 대신 보장하지 않는다. 일반 즉시결제와 고가 개별계약을 분리해 저가 박리다매와 고가 전문 전략이 동시에 존재할 수 있게 한다.

10,000,000P 이상은 단순 클릭 한 번으로 결제하지 않는다. 구매 전 적합성·지원범위 확인, 계약서, 결제 한도와 사기 방지, 분쟁·환불 조건을 별도 확인하고 필요하면 PG 결제·에스크로·계좌결제 중 승인된 수단을 쓴다. 구독은 지속 업데이트·데이터·지원이 실제 제공되는 상품에 한해 후속 허용하고, 수익배분·성과보수 가격은 별도 금융규제 검토 전 금지한다.

### 3.3 버전과 업데이트

- 구매 대상은 `strategy_id + strategy_version + package_hash`로 고정한다.
- 구매 후 같은 버전은 같은 계정에서 계속 재다운로드할 수 있다.
- 버그 수정처럼 실행 의미가 바뀌지 않는 패키지는 무상 교체 후보지만 해시와 사유를 남긴다.
- 진입·청산·위험·지원범위가 바뀌는 새 버전은 새 상품이다.
- 제작자는 `기존 구매자 무료`, `할인 업그레이드`, `별도 구매` 중 하나를 새 버전 공개 전에 고른다.
- 정기 신호·데이터·지속 지원이 실제로 제공되기 전에는 전략 파일에 구독을 붙이지 않는다.

## 4. 수수료와 실제 정산 공식

### 4.1 기본 수수료

- 플랫폼 수수료: 공급가의 20%
- 제작자 적립: 공급가의 80%
- 부가가치세: 소비자 표시가격에 포함하고 플랫폼/계약 구조에 따라 별도 세금 원장에 기록
- 일반 PG 비용: 플랫폼 수수료에서 부담
- 환불·차지백: 확정 전이면 판매 취소, 정산 후이면 다음 정산에서 상계
- 원천징수·세금계산서: 제작자 사업자 유형과 국가에 따라 실제 법정 처리

예시:

```text
구매자 표시가격            11,000P
부가가치세                  1,000원
정산 기준 공급가           10,000원
플랫폼 수수료 20%           2,000원
제작자 세전 적립 80%         8,000원
일반 PG 비용              플랫폼 2,000원 몫에서 부담
최종 지급액               8,000원 - 법정 원천징수/조정액
```

플랫폼이 부담한 쿠폰은 제작자 정산 기준을 줄이지 않는다. 제작자가 선택한 할인은 할인 후 공급가를 정산 기준으로 한다. 각 거래에는 원가격, 쿠폰 부담 주체, 세금, 플랫폼 수수료, PG 비용, 제작자 적립, 환불·상계액을 따로 저장한다.

### 4.2 지급 주기

- 판매 발생 후 14일: 환불·부정결제 대응을 위한 `pending` 보류
- 매월 말: 확정 판매 마감
- 다음 달 말까지: T+30 이내 원화 계좌 지급
- 최소 지급액: 50,000원, 미달액은 다음 달로 이월
- 신규·고위험 제작자: 위험평가에 따라 최대 10%를 60일 한시 보류할 수 있으나 사유와 해제일을 명시
- 판매자 화면: 거래별 총액·세금·수수료·보류·환불·지급액과 CSV/PDF 명세 제공

제작자는 실명/사업자 확인, 지급계좌, 거주국, 세금정보, 이용약관·권리보증 동의를 완료해야 유료 판매와 지급을 받을 수 있다. 익명 판매자는 무료 E0 공개까지만 허용한다.

## 5. 포인트 정책

### 5.1 유상 포인트와 테스트·적립 포인트

| 구분 | 유상 Noah Point | 테스트·적립 Noah Point |
|---|---|---|
| 취득 | 카드·간편결제·계좌 등 승인된 PG 결제 | 테스트 기간 로그인·학습·유효 PAPER 미션 |
| 구매가치 | 1P = 1원, 전략 구매에 100% 사용 | 유료 오픈일에 1P = 1원 구매가치로 1:1 전환 |
| 환불 | 약관·법령·미사용 범위에 따라 원결제수단 환급 | 무상 지급분은 환불·현금화 불가 |
| 양도 | 금지 | 금지 |
| 현금·코인 전환 | 금지 | 금지 |
| 사용 | 모든 전략 라이선스 | 모든 전략 라이선스에 잔액 범위 안에서 100% 사용. 고가 개별계약도 계약서에 포인트 사용액 표시 |
| 만료 | 법률·PG 심사로 확정, 임의 단기 소멸 금지 | 유료 오픈 전 소멸 금지, 전환 후 최소 12개월 보장 |
| 원장 | `paid_point_ledger` | `earned_point_ledger` |

테스트 시작 전에 `유료 오픈 예정일`, `1P=1원 구매가치`, `현금화 불가`, `모든 전략에 잔액 범위 100% 사용`, `계정별 적립 상한`을 화면과 약관에 표시한다. 약속한 전환율과 사용범위를 이미 적립된 포인트에 불리하게 소급 변경하지 않는다. 유료 오픈이 연기되면 포인트도 소멸시키지 않고 새 날짜를 공지한다.

플랫폼이 지급한 적립 포인트가 사용되면 그 금액은 플랫폼의 마케팅 비용으로 부담해 제작자의 정산 기준을 낮추지 않는다. 제작자가 별도 쿠폰을 발행한 경우에만 계약에 정한 제작자 부담분을 반영한다. 화면에는 유상·적립 잔액, 사용 가능액, 만료 예정액을 분리한다.

### 5.2 유료화 전 초기 보상안

| 행동 | 보상 | 제한 | 이유 |
|---|---:|---|---|
| 하루 첫 로그인 | 10P | 계정당 하루 1회 | 가벼운 재방문 습관 |
| 하루 첫 유효 PAPER 60분 | 100P | 계정당 하루 1회 | 실제 제품 가치 경험 |
| 7일 연속 로그인 | 100P | 7일 주기 1회 | 단기 유지율 실험 |
| 첫 전략 가져오기·검토 완료 | 500P | 계정 생애 1회 | 핵심 활성화 유도 |
| 첫 PAPER 검증 리포트 확인 | 500P | 계정 생애 1회 | 검증 가치 학습 |
| 신고가 권리·무결성 문제로 확정 | 1,000P | 운영자 확정 건만 | 마켓 신뢰 기여 |

기본 상한은 30일 3,000P, 테스트 기간 누적 상한은 계정당 30,000P다. 이는 가장 낮은 유료 구간에서 실제 구매 또는 의미 있는 할인이 가능하면서도 플랫폼의 출시 부채를 통제하기 위한 시작값이다. 변경은 새 정책 버전의 미래 적립분에만 적용하며 운영자가 DB 잔액을 직접 수정하지 않는다.

### 5.3 왜 매시간 계속 지급하지 않는가

앱을 켜 둔 매시간 포인트를 주면 실제 학습보다 백그라운드 켜두기, 가상머신, 다계정, 네트워크 반복 호출을 보상하게 된다. 특히 거래모드 보상은 불필요한 거래나 LIVE 위험 감수를 유도할 수 있다.

따라서 `유효 PAPER 60분`은 다음 조건을 모두 만족한 하루 첫 세션만 인정한다.

- PAPER 모드이며 LIVE 주문이 한 건도 없음
- 같은 계정에서 동시에 하나의 보상 세션만 활성
- 시장 데이터 heartbeat와 전략 평가가 정상
- 일시정지·네트워크 단절·오류 시간 제외
- 최소 3개의 유효 평가 주기 또는 정책이 정한 최소 데이터 이벤트 충족
- 서버가 시작·중간·종료 증거를 확인한 뒤 한 번만 원장 기록

거래 횟수·거래대금·수익·레버리지에는 추가 보상을 주지 않는다. 장시간 검증은 배지와 전략 여권의 증거를 높이되 포인트 농장으로 만들지 않는다.

## 6. 구매 흐름

```text
전략 상세에서 증거·위험·호환기관·가격 확인
→ 무료 샘플 또는 내 환경 PAPER 미리보기
→ 보유 유상/적립 포인트와 상품별 최대 사용 가능 적립액 확인
→ 가격·세금·환불 제한 재확인
→ 포인트 부족 시 외부 결제
→ 결제 webhook 검증
→ 포인트 충전 원장
→ 구매 차감 원장과 상품 스냅샷 원자 처리
→ 라이선스 발급
→ 다운로드는 비활성 상태로 가져오기
→ 사용자 재검토·PAPER·별도 LIVE 승인
```

구매 완료는 수익성, 특정 거래소 작동, LIVE 적합성 보증이 아니다. 상품 페이지에는 최근 검증 시각, E 단계, 표본, 비용 포함 여부, MDD, 중단 조건, 지원/미지원 기관, 제작자 자기설명과 서버 확인 근거를 분리한다.

## 7. 환불·취소·권리침해

- 결제 중복, 포인트 미충전, 라이선스 미발급, 손상·변조 패키지, 표시와 다른 상품은 전액 복구한다.
- 다운로드·라이선스 활성화 전에는 적용 법령과 약관이 허용하는 청약철회 경로를 제공한다.
- 다운로드 또는 이용을 시작해 청약철회가 제한될 수 있는 디지털 콘텐츠는 구매 전에 제한 사실, 무료 샘플/미리보기, 즉시 이용 동의를 명확히 제공한다.
- 수익이 나지 않았다는 이유만으로 자동 환불하지 않는다. 허위 성과·중요 위험 누락은 일반 변심이 아니라 표시·품질 분쟁으로 조사한다.
- 제작자의 일반 공개 중지는 신규 판매만 막고 정상 발급된 기존 라이선스는 유지한다.
- 결제 무효, 악성·변조 패키지, 권리 침해 확정, 법령·기관 명령은 사유·처리자·시각을 기록하고 라이선스를 중지할 수 있다.
- 환불은 원거래를 수정·삭제하지 않고 역분개 이벤트로 처리한다.

## 8. 기술 원장과 서비스 경계

무료 베타에 구현된 `strategy_offer_snapshots`, `strategy_acquisitions`, `strategy_licenses`, `strategy_download_audit`를 유상 거래의 기반으로 유지한다. 다음 원장을 별도로 추가한다.

### 8.1 필수 원장

- `payment_orders`: 결제 주문, 제공자, 원화/코인 원금, 만료, 상태
- `payment_receipts`: 외부 주문 ID, webhook ID, 승인 시각, 영수증, 환율·세금 스냅샷
- `paid_point_ledger`: 충전·구매·환불·만료·조정의 불변 이벤트
- `earned_point_ledger`: 테스트·보상 정책 ID, 근거 이벤트, 지급·전환·사용·만료
- `creator_earnings_ledger`: 판매 적립·보류·환불·차지백·지급 상계
- `settlement_batches`: 월 마감, 지급 대상, 원천징수, 지급 결과
- `payout_accounts`: 암호화된 지급 참조와 본인확인 상태
- `reward_events`: 로그인/PAPER 미션 멱등 키와 부정사용 판정
- `refund_cases`, `disputes`: 요청, 증거, 판정, 역분개 연결

잔액 컬럼을 직접 고치는 방식은 금지한다. 잔액은 원장 이벤트 합계와 일치해야 하고, 정기 대사 작업이 불일치를 발견하면 신규 결제·정산만 실패 폐쇄한다. 보유 전략 실행과 PAPER는 계속 작동해야 한다.

### 8.2 원자성과 멱등성

- 결제 provider webhook ID는 전역 unique
- 충전은 한 결제 영수증당 한 번
- 구매는 `buyer + offer + request_id` 기준 멱등
- 포인트 차감과 라이선스 발급은 하나의 DB transaction/outbox 계약
- 지급은 `settlement_batch + creator + payout_attempt` 기준 멱등
- 재시도는 새 잔액 이벤트를 만들지 않고 같은 상태 머신을 이어감
- 관리자 조정은 원거래를 수정하지 않고 사유·승인자·상대 계정이 있는 조정 이벤트로 기록

### 8.3 장애 격리

결제·포인트·정산은 거래 실행 프로세스와 DB 잠금·큐·재시작 경계를 분리한다. 마켓 장애로 Strategy Studio, 보유 전략 로컬 실행, PAPER 또는 사용자가 이미 승인한 LIVE가 멈추면 안 된다. 단, 신규 구매와 라이선스 서버 확인이 필요한 다운로드만 안전하게 지연할 수 있다.

### 8.4 daltrading 관리자 운영 콘솔

테스트 기간이 끝난 뒤 별도 수작업 배포 없이 관리자가 유료 마켓을 열 수 있도록 다음 기능을 daltrading에 구현한다.

- `테스트 운영`: 시작·종료일, 적립 정책 버전, 계정별 한도, 부정사용 검토
- `유료 전환`: 테스트 포인트 1:1 전환 대상·총부채 미리보기, PG·약관·정산 E2E 체크, 이중 승인형 유료 모드 개방
- `판매자`: 실명/KYC·사업자·세금·계좌·계약·권리보증 승인과 정지
- `상품`: E 단계 근거, 판매 가격, 지원·업데이트·환불 조건, 고가 개별계약·포인트 사용액 심사
- `결제·라이선스`: 주문·영수증·webhook·충전·차감·라이선스 발급·재다운로드·환불 추적
- `정산`: 거래별 공급가·세금·20% 수수료·80% 제작자 적립·보류·상계·월 지급 batch와 명세
- `감사·분쟁`: 관리자 조정 이중 승인, 권리침해·차지백·부정사용 사건, 원장 대사와 내보내기

관리자가 데이터베이스 숫자를 직접 바꾸는 화면은 만들지 않는다. 정책 변경과 조정은 모두 새 정책 버전 또는 역분개 이벤트로 남기고, 테스트 포인트 전환·유료 모드 개방·정산 지급은 이중 승인과 감사 로그를 요구한다.

### 8.5 사용자 마이페이지와 클라이언트 조회

2026-09-12 daltrading `/auth/dashboard#marketplace`에 현재 무료 취득·활성 라이선스·최근 주문·내 전략·순취득자/전체 다운로드 집계를 연결했고, `/strategies/api/account-summary`를 추가했다. 포인트와 판매정산 원장이 없는 동안에는 0P·0원으로 오인시키지 않고 `준비 중`으로 표시한다. 공개 상품에는 동일 사용자의 재다운로드를 합산한 횟수가 아니라 확정 취득 원장의 순취득자를 표시하고, 제작자 화면에서만 순취득자와 전체 다운로드를 나란히 제공한다.

유료 원장이 구현되면 같은 마이페이지에 유상/적립 잔액·만료, 충전/적립/사용/환불 내역, 구매가격·주문·영수증, 업데이트·지원·분쟁, 판매액·수수료·보류·상계·지급명세를 추가한다. API와 화면은 로그인 계정 범위만 반환하고 다른 구매자의 식별정보를 공개하지 않는다.

## 9. 결제수단 출시 순서

### 9.1 1차: 원화 결제

- 국내 PG의 카드·간편결제부터 시작
- 1차에는 PG 한 곳 또는 PG 연동·파트너 정산 자동화 서비스 한 곳만 채택해 결제 승인, 취소, webhook, 판매자별 정산 명세를 표준 API로 연결한다.
- daltrading은 상품·포인트·라이선스·수수료 원장의 정본을 유지하고, 외부 서비스는 돈의 수납·취소·지급 실행을 맡긴다. 외부 서비스의 숫자를 그대로 신뢰하지 않고 일일 대사한다.
- 계좌이체/가상계좌는 환불·입금 대사 E2E 뒤 추가
- 구매 장소는 daltrading 자체 웹 Marketplace다. Windows 클라이언트는 브라우저에서 구매를 완료한 뒤 서버 라이선스를 동기화한다.
- PG 충전은 큰 잔액을 오래 쌓게 하기보다 구매 시 부족액을 즉시 충전하는 흐름을 기본으로 하되, 적립·환불·재구매에 필요한 포인트 잔액은 원장으로 관리한다.
- 카드정보는 NoahAI 서버에 저장하지 않고 PG 토큰과 영수증 ID만 보관

### 9.2 모바일 앱스토어는 현재 범위가 아님

현재 유료 출시에는 Apple App Store·Google Play 출시나 인앱 구매를 포함하지 않는다. 자체 웹 Marketplace에서 전략을 사고 NoahAI 클라이언트가 보유 라이선스만 동기화하는 것이 현재 계약이다.

향후 모바일 스토어 배포를 실제 결정하면 그 시점의 정책을 다시 검토한다. Google Play의 소비 전용 앱은 앱 안에서 구매·외부 결제 유도를 하지 않고 다른 곳에서 산 콘텐츠를 로그인 후 이용하는 형태가 가능할 수 있다. 반면 iOS에서 NoahAI 전략은 일반적인 책·음악·영상형 Reader 앱 예외라고 단정할 수 없고, 멀티플랫폼 디지털 상품 접근 규칙이 적용될 수 있으므로 별도 심사가 필요하다. 이 조건부 검토는 현재 웹 Marketplace 출시를 막지 않는다.

### 9.3 2차: 코인 결제

코인 결제는 `코인 → 결제 사업자 확정 → 원화 기준 영수증 → Noah Point` 흐름만 허용한다.

- 초기 지원은 한 개 결제 사업자, 한 개 안정적 토큰, 한 개 네트워크로 제한
- 주문별 고유 invoice·15분 환율 스냅샷·만료 시각
- 과소·과다 입금, 중복 tx, 잘못된 체인, 확인 수, 체인 재구성 정책
- 서명 webhook과 원장 대사 전에는 포인트·라이선스 발급 금지
- NoahAI는 사용자의 코인을 보관·교환·송금하지 않음
- 제작자에게 코인으로 지급하지 않고 원화 정산
- 외부 사업자가 규제·KYC/AML·제재국·Travel Rule 책임을 어디까지 맡는지 계약서로 확인

직접 지갑·노드·핫월렛을 운영하거나 제작자 코인 지급을 추가하는 것은 별도 사업이다. 가상자산의 매매·교환·이전·보관·중개를 영업으로 하면 가상자산사업자 범위 검토가 필요하므로 초기 범위에서 제외한다.

## 10. 유료 오픈에 꼭 필요한 게이트와 조건부 게이트

모든 가능한 규제를 한꺼번에 해결하는 것이 아니다. 자체 웹 Marketplace·국내 원화 PG·국내 제작자 원화 정산의 첫 출시에는 아래 네 묶음만 완료한다.

1. **PG·포인트**: PG 가맹 심사, 선불전자지급수단 해당/등록 면제 여부와 선불충전금 관리·환급·만료에 대한 1회 서면 검토
2. **구매자 보호**: 판매자/중개자 지위, 가격·세금 표시, 디지털 콘텐츠 미리보기·즉시 이용 동의·청약철회 제한·분쟁 절차
3. **판매자 정산**: 국내 개인/사업자 KYC, 권리보증 계약, 지급계좌, 부가세·원천징수·지급명세 책임
4. **운영 증거**: 결제→포인트→구매→라이선스→환불→14일 보류→월 정산의 sandbox·대사·감사 E2E

투자 수익 보장·자동 수익 표현은 차단하고 전략 파일 라이선스 판매와 투자자문·일임을 분리한다. PG와 계약할 때 NoahAI 상품·환불·성과표시 구조를 숨기지 않고 금융 관련 디지털 콘텐츠 취급 가능 여부를 확인한다.

아래는 해당 기능을 실제 추가할 때만 여는 **조건부 게이트**다.

- Apple·Google: 모바일 스토어 배포 또는 앱 안 구매를 실제 결정할 때
- 코인 결제·코인 지급: 국내외 가상자산사업자, AML·Travel Rule·외국환·회계 구조를 실제 도입할 때
- 해외 제작자: 조세조약·국외송금·제재·현지 소비세 처리가 필요할 때
- 성과보수·복사매매·주문 대행: 투자자문·일임 등 금융규제 검토가 필요한 상품을 도입할 때

국내 개정 선불 규제는 소규모 또는 단일 가맹점 면제 가능성을 두지만, 면제 추정만으로 개발·판매를 시작하지 않는다. 발행잔액·연간 발행액·사용처 구조가 바뀌면 등록·보호 의무도 달라질 수 있으므로 월별 모니터링과 사전 재검토가 필요하다.

## 11. 부정사용과 안전 정책

- 보상 기준일은 UTC 또는 KST 중 하나로 정책 버전에 고정하고 화면에 표시
- 이메일만 다른 다계정이 아니라 기기·결제·행동·네트워크 신호를 조합하되 자동 영구차단은 금지
- CAPTCHA·속도 제한·동일 기기 동시 세션 제한·위험 이벤트 수동검토
- PAPER 보상은 서버 확인 이벤트만 인정하고 클라이언트 시계·로컬 DB만 신뢰하지 않음
- 자기 전략 구매, 순환 구매, 쿠폰 세탁, 허위 환불, 다운로드 후 반복 차지백 탐지
- 보상·랭킹·판매량을 거래 수익성 증거로 사용하지 않음
- 포인트 구매가 전략 추천 순위를 올리지 않음
- 개인정보·전략 원문·계좌·API 키는 결제 provider와 보상 판정에 전달하지 않음

## 12. 유료화 전 실험 KPI

### 무료 베타 공급과 신뢰

- 주간 신규 E0 제출 수와 승인/격리율
- 첫 전략 가져오기 성공률
- 다운로드 후 7일 내 내 환경 PAPER 시작률
- PAPER 시작 후 검증 리포트 확인률
- 신고율·권리 문제 확정률·재다운로드 성공률

### 포인트 보상 실험

- D1/D7/D30 재방문율
- 로그인 적립 수령자 대비 PAPER 60분 완료율
- 보너스 수령 후 30일 내 상품 상세·구매 화면 진입률
- 계정당 보상 비용, 다계정/비정상 세션 비율
- 보상 중단 시 유지율 변화

### 유료 전환

- 무료 상세 → 결제 시작 → 결제 성공 → 라이선스 발급 전환율
- 첫 결제까지 걸린 일수
- 입문형/표준형/전문형/프리미엄 가격구간별 전환·환불·지원 티켓
- 판매자가 선택한 가격 분포와 가격 변경 후 전환율, 제작자 유지율
- 구매 후 7일 내 가져오기·PAPER 재검증률
- 제작자별 순매출 집중도와 상위 판매자 의존도
- 플랫폼 20%에서 PG·지원·환불·부정결제 비용을 뺀 실제 기여이익

출시 판단은 단순 가입자 수가 아니라 `다운로드 → 가져오기 → PAPER → 검증 확인 → 재방문 → 첫 결제` 퍼널로 한다.

## 13. 단계별 개발·운영 게이트

### M0 — 현재 무료 베타: 구현됨/운영 검증 중

- 무료 상품 스냅샷, `FREE` 취득, 영구 비독점 실행 라이선스, 재다운로드
- 패키지 해시·전략 버전·구매자 계정 고정
- 제작자 공개 중지와 권리·무결성 신고
- 남은 게이트: 실서비스 제출→다운로드→가져오기→PAPER 재검증, 장시간 운영, CS 절차

### M0.5 — 테스트 기간 중 유료화 완성: 다음 개발 순서

1. 국내 원화 PG·포인트 서면 검토, 구매자 약관, 국내 판매자·정산 계약 확정
2. 유상/적립 포인트·보상 이벤트·1:1 전환·잔액 대사 원장
3. 결제 주문·영수증·webhook·환불 상태 머신
4. 상품 가격·쿠폰·세금·수수료 스냅샷
5. 제작자 KYC·지급계좌·수익 원장·월 정산 명세
6. daltrading 관리자 판매자·상품·가격·정책·조정·분쟁·차지백·감사·정산 화면
7. Windows 외부 브라우저 결제와 클라이언트 라이선스 동기화 E2E
8. 합성 결제/PG sandbox/장애·중복 webhook/복구/회계 대사 테스트

### M1 — 구매가치가 고지된 테스트 포인트

- 로그인·첫 PAPER 60분·온보딩 미션 보상
- 30일 최대 3,000P, 테스트 기간 누적 최대 30,000P
- 적립 전부터 `유료 오픈일 1P=1원 구매가치 전환`, 현금화 불가, 모든 전략에 잔액 범위 100% 사용을 명시
- 부정사용률·재방문·PAPER 전환과 총 포인트 부채를 daltrading 관리자가 확인

### M2 — 테스트 종료일 원화 유료 오픈

- 테스트 포인트를 1:1 적립 Noah Point로 전환하고 즉시 구매 허용
- E1 입문형부터 E3 전문형, E4·E5 프리미엄까지 판매자 자율 가격 카탈로그
- 10,000~9,999,000P 일반 구간과 10,000,000P 이상 개별계약형 구간
- 20% 플랫폼 수수료, 14일 보류, 월 마감 T+30 원화 정산
- daltrading 관리자 개방 스위치는 PG·세금·환불·라이선스·클라이언트·정산 E2E가 모두 PASS일 때만 활성

### M3 — 일반 유료 마켓 확대

- 판매자 셀프 온보딩과 운영자 위험 검토
- 가격/쿠폰 실험, 제작자 대시보드, 적립 포인트 플랫폼 부담과 정산 명세 자동화
- 고객지원 SLA와 권리침해 대응 운영
- 구매·랭킹·PAPER 검증의 독립성 검증

### M4 — 선택형 코인 결제

- 외부 결제 provider 한 곳으로 제한 운영
- NoahAI 비수탁, 원화 기준 영수증, 제작자 원화 지급
- 규제·AML·세무·환율·오입금·중복 tx·환불 E2E PASS
- 거래량과 고객 수요가 운영비보다 충분할 때만 확대
