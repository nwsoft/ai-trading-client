## 실제 앱에서 발견한 추가 결함

실제 Electron 앱의 네이티브 저장 확인 창에서 ‘확인’을 누르면 창 초점 복귀와 저장 요청이 겹친다. 보험 보관함 `summary`는 mutex 처리 중 정상적으로 `state=busy`를 반환하는데, 기존 화면은 `state != unlocked`를 모두 잠금으로 취급해 입력·계산 결과를 지웠다. 저장 파일은 생겼어도 사용자는 저장이 실패하거나 입력이 사라진 것으로 보게 된다. 기존 headless dialog 수락 검사에는 네이티브 초점 경합이 없어 놓쳤다.

`WealthWorkspace`와 같은 조회를 사용하는 `ProductIntelligenceWorkspace`에서 **busy와 locked를 구분**했다. busy는 다음 상태 확인을 기다리고, 실제 locked·만료·연결 실패의 개인정보 정리와 서버 쓰기 권한 재검사는 유지한다. 보관함 처리 중 뮤텍스를 실제로 점유하고 초점 이벤트를 보내는 회귀를 추가한다. 계산·저장 안내도 보관함을 열어야 하는 이유를 설명하도록 고친다.
