## 모델 선택과 사용 방법

**설정 → AI 엔진/API**에서 API 키를 저장하고 생활금융 빠른 판단 제공사·모델을 선택·저장한다. 키가 등록된 제공사만 새로 선택할 수 있고 모델 목록은 해당 제공사의 JSON 호환 목록으로 제한한다. 키 없는 기존 선택은 삭제하지 않고 비활성 상태로 표시한다. 생활금융 → 금융상품의 **내 말을 AI로 이해하기**는 저장된 AI·키 등록 상태와 설정 이동 버튼만 표시한다. 키가 없으면 요청을 막고 상황 버튼을 계속 제공한다. Jev 및 모델 선택 기준 설명도 AI 엔진/API에 둔다. 키 등록과 실제 연결 성공은 구분하며 ‘생활금융 선택 모델 연결 점검’은 선택 모델을 JSON으로 명시적으로 1회 시험한다.

질문 분류 미리보기는 외부 호출이 없다. 질문·수신 모델·비용 가능성에 동의하고 실행하면 `InteractiveAIService.ask_decision`이 실제 선택 Provider의 `chat_json`으로 요청한다. 사용량/추정 비용/실제 응답 모델/경과 시간을 표시한다. 가입 상태와 목적은 **‘이 해석이 맞아요’ 확인 후에만** 기존 탐색에 적용한다. 판단 결과로 금리·보험료·개인 가입 적합도·거래 승인·보호 해제를 만들지 않는다.

## 판단 계약·비용·개인정보

- 계약 `finance-intent-1`: 목적 enum, 보험 상태 enum, 질문의 정확한 근거 부분 문자열 2개, 추가 확인 boolean. 여분 필드·명령·확률·승인 값을 거절한다. 분류 범위는 현재 선택한 금융 종류 안이다.
- 근거 문자열 존재는 의미적 정답을 보증하지 않는다. 항상 사용자가 해석을 확인한다. 불확실/다중 목적은 적용 버튼 대신 재질문 안내.
- 일반 선택 버튼과 로컬 명시적 파서는 외부 호출 0회. AI 분류는 별도 명시 요청. 질문·모델·기능 계약 변경 시 기존 전송 동의 무효화.
- API 입력은 해당 질문과 정해진 선택지/스키마만. 기존 보험 원문·계좌·거래·건강정보 자동 첨부 없음. 사용자가 질문에 적은 내용은 미리보기에서 확인하고 삭제할 수 있다.
- 공통 interactive 호출·비용 제한 재사용. 분류 최대 출력 400, 요청 timeout 15초 설정, OpenAI 호환 SDK 자동 재시도 0회. 네트워크 timeout은 절대적인 전체 벽시계 지연 보증이 아니다. 기타 대화 요청의 기존 timeout은 유지한다.
- 캐시는 사용하지 않는다. 운영 기록에는 질문/분류 원문을 남기지 않으며 제공사가 알려준 token usage를 비용 기록에 반영한다. JSON 형식 오류도 제공된 usage를 기록한다. usage 미확인은 무료 0으로 바꾸지 않는다.
- 모델 변경은 설정 화면에서 생활금융 프로필에만 저장한다. 실행 API는 저장된 경로만 읽고 요청 본문의 다른 모델로 덮어쓸 수 없다. 저장 모델 변경 후에는 기존 미리보기 동의를 사용할 수 없다. 키 등록과 해당 API 계정의 호출 권한은 구분한다.

- 공개 안내와 권리 검토 피드/개인 견적은 분리한다. 탐색 자료는 보험료·가입 승인·자동 추천 순위·외부 AI 근거로 승격하지 않는다. 확인일/재확인 기한/판매 종료 상태를 유지하며 오래된 자료는 선택을 막는다.
- 관심 상품 ID를 서버의 현재 자료로 다시 해석하여 상담 확인 질문 및 사용자가 선택한 비교 공유 범위에 담는다. 기존 수신처·동의·접수/철회 계약을 유지한다.
- [자료 운영 명세](INSURANCE_REFERENCE_DIRECTORY.md): SQLite 저장, 개별 검토 갱신/철회용 CLI를 제공하여 자료 수정만으로 앱 패치를 기다리지 않게 한다.

### 실제 서비스 확대를 위해 남은 연결

보험다모아 전체 기능과 동등한 서비스를 완성했다고 표시하지 않는다. 전 보험회사 상품 범위, 이용권한이 확인된 자동 상품 피드, 개인별 보험료 산출 API, 본인 인증·심사·청약/전자서명, 실제 기관·지정 상담사 접수는 계약·자격·수신처 인수가 필요하다. 현재는 내부 탐색·조건 비교·상담 준비와 기존 연결 인터페이스까지다. 대출/예적금의 공식 실데이터 공급도 별도다. 신규 3.9.2.4 공개 설치본은 게시 전이다.
