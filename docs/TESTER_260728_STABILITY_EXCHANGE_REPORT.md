# 2026-07-28 Teayu 테스터 안정성·다중 거래소 진단

기준 데이터: `data/260728_Teayu`  
판정 범위: 로컬 사용자 데이터·로그·SQLite·현재 소스 비교  
주의: API 비밀값은 확인·기록하지 않았으며 실제 주문을 발생시키지 않았다.

## 결론

1. Binance는 2026-07-28 실제 주문이 발생했다. `trade_log`의 Binance 72건에 진입 주문 ID가 존재한다.
2. 나머지 거래소가 주문하지 않은 직접 원인은 연결 실패가 아니라 주문 허용 범위다. 화면·학습 범위에는 6개 거래소가 있었지만 `trade_enabled_exchanges`는 빈 목록이었고, 구 런타임이 이를 선택 거래소 Binance 한 곳으로 되돌렸다.
3. 갑작스러운 종료의 단일 원인을 기존 로그만으로 확정할 수는 없다. 다만 숨겨진 AI 학습 탭이 1.2초마다 무한 재예약되면서 `ui_perf_metrics.jsonl`에 1,374,298줄·약 164MB를 기록한 명백한 수명주기·자원 누수가 확인됐다.
4. 업데이트 설치 대상이 정식 EXE가 아니라 `cache/auto_updater/.../AITrading.new.exe`로 저장돼 있었다. 이 때문에 테스터가 최신 정식 설치본이 아닌 스테이징 EXE에서 반복 실행됐고, 이후 수정이 안정적으로 교체되지 않았을 가능성이 높다.
5. Binance 모니터에는 UTC aware 진입시각과 naive 현재시각을 빼는 예외가 1,172회 기록됐다. 프로세스 종료의 직접 증거는 아니지만 해당 포지션 모니터 판단을 반복 중단시키므로 수정이 필수다.

## 적용한 수정

- 숨은 AI 학습 탭은 더 이상 폴링하지 않고 화면 표시 이벤트에서 한 번 갱신한다.
- 탭 재생성·종료 시 위젯이 소유한 모든 Tk callback을 취소한다.
- UI 성능 JSONL을 20MB, 백업 3개로 회전해 무한 성장을 막는다.
- 어떤 위치의 `auto_updater` 하위 경로나 `AITrading.new.exe`도 정식 설치 대상으로 저장·적용하지 않는다.
- 잘못된 업데이트 대상이 있으면 과거 적용 스크립트에서 존재하는 정상 EXE를 복구한다.
- 포지션 보유시간 계산을 UTC aware로 정규화하고 구형 naive 저장 시각은 UTC로 안전 해석한다.
- `trade_enabled_exchanges` 키가 명시적으로 빈 목록이면 실제 주문 0개로 해석한다. 키 자체가 없는 구버전 프로필만 선택 거래소 1곳 호환을 유지한다.
- 설정에 `활성 거래소를 주문 대상으로 선택` 버튼을 추가했다. 이는 체크만 복사하며 설정 저장 전에는 적용되지 않는다.

## 테스터 재검증 절차

1. 새 Windows EXE를 기존 정상 설치 위치에 설치한다. 캐시의 `AITrading.new.exe`를 직접 실행하지 않는다.
2. 설정 → 거래소 선택에서 6개 연결·학습 대상과 `실제 주문 실행 거래소`를 각각 확인한다.
3. 실제 주문을 원하는 거래소만 명시적으로 선택하고 저장한다.
4. 최소 주문·최소 위험으로 거래소별 1건씩 주문 제출/체결/취소·청산을 확인한다.
5. 24~72시간 실행 후 다음 파일을 함께 회수한다.
   - `logs/runtime_stability.jsonl`
   - `logs/runtime_faulthandler.log`
   - `logs/ui_perf_metrics.jsonl*`
   - 거래소별 로그와 `trading.db`

소스 수정 완료는 Windows 배포·실계좌 E2E 완료를 뜻하지 않는다.
