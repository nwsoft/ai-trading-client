# NoahAI AI 어시스턴트 가이드 (대시보드)

기준 버전: NoahAI Client v3.9.0.8 AI Custom Update Fix 2 (2026-08-10)

이 문서는 **공개 저장소 기준**으로 `ui/widgets/ai_assistant_widget.py`의 실제 동작과 맞추었습니다. 설치 후 바로 확인할 수 있도록 **전제 조건 → UI 위치 → 대화로 되는 일/안 되는 일 → 확인 기반 설정 반영 규칙 → 트러블슈팅 → 음성(STT/TTS) 로드맵** 순으로 읽으면 됩니다.

상위 원칙·책임 경계는 `docs/ARCHITECTURE.md`, 문서 간 우선순위는 `docs/DOCUMENTATION_POLICY.md`를 참고하세요.

## 1. 이 앱에서 AI 어시스턴트가 하는 일

NoahAI 클라이언트는 사용자가 연결한 거래소 API와 설정 범위 안에서 **판단·설명·일부 설정 변경**을 돕습니다. **체결·잔고 확정**은 거래소 쪽 책임이며, 어시스턴트는 브로커가 아닙니다.

AI 어시스턴트 탭은 대략 다음을 수행합니다.

- **일반 질문**: 대시보드에서 수집한 **거래·계정 컨텍스트 문자열**과 함께 LLM에 질의하여 분석·조언 텍스트를 표시합니다.
- **설정 변경으로 분류되는 질문**: 모델이 특정 **JSON 형식**으로 답하면 허용 키·범위를 검증하고, 채팅의 적용 버튼과 최종 확인을 거친 뒤 `settings.json`에 저장합니다.
- **제품 사용법 질문**: AI 커스텀·XAI·고변동장 처리처럼 제품 내부 경로가 정해진 질문은 실제 현재값과 설정 위치를 우선 안내합니다.
- **금융 인텔리전스 사용법**: 시장·섹터, 코인/종목 탐색, 지표 탐색, 전략 검증, 이벤트·속보, 기업·가치·기관 메뉴는 API 키가 없어도 로컬 제품 지식으로 입력 순서와 결과 해석을 답합니다. 각 화면의 `AI에게 사용법 묻기`가 현재 기능을 질문에 포함합니다.
- **화면 역할 구분**: `코인 정보`는 내 계좌·선택 코인의 운용 상태이고, 금융 인텔리전스의 `코인 탐색`은 여러 코인의 시장 조건 비교입니다. 금융 인텔리전스 `전략 검증`은 간단 이동평균 비교이고, 승인된 외부 전략은 `AI 커스텀`에서 검증·적용합니다.
- **AI 커스텀 결과 설명**: SMA/EMA 20·50·200, ADX, ATR, MACD 세부값, 볼린저, 거래량·시간 조건, Pine 실제 교차 조건과 미지원 조건 차단 여부를 설명합니다. 자동검증의 양쪽 수수료·슬리피지·스프레드, PF·기대값·MDD·국면 결과도 현재 결과 기준으로 설명합니다.
- **v3.9.0.8 기능 가이드**: 현재 초보자·일반·고급·실험실 프로필과 개별 기능 상태를 읽고, Level 1·2·3, 백테스트/PAPER, Expression Graph·사용자 지표 언어, `.noahstrategy`, 서명 webhook의 사용법과 미완료 운영 게이트를 질문별로 구분해 설명합니다.

AI 커스텀 질문 예시:

- `AI 커스텀 초보자와 고급 프로필 차이는 무엇인가요?`
- `백테스트의 PnL·MDD와 PAPER 결과를 어떻게 봐야 하나요?`
- `XAI에서 원본 근거와 Noah Strategy IR은 어떻게 연결되나요?`
- `.noahstrategy를 가져오면 바로 실행되나요?`
- `TradingView webhook이 들어오면 바로 주문하나요?`
- **차트 이미지 분석**: `ChartScreenshotWidget` 모듈이 로드되는 빌드에서만 **「📊 차트 이미지 분석」** 버튼이 동작합니다. 임포트 실패 시 경고만 표시됩니다.

**대화만으로 할 수 없는 것(현재 코드 기준)**

- 거래 **시작/중지**, 주문 직접 하기, 다른 탭으로 전환, API 키 입력 등 **전체 앱 조작**은 채팅으로 연결되어 있지 않습니다.
- 설정 변경 이력 되돌리기와 기본값 복구는 지원하지만, 거래소가 이미 처리한 주문·체결까지 되돌리는 기능은 아닙니다.

### 안전한 대화형 변경 계약

NoahAI는 “사용자가 바꾸라고 했으니 무조건 변경”하지 않습니다.

1. 현재 시장·계좌·포지션·최근 성과·로그·설정을 수집합니다.
2. 사용자의 목표, 변경 대상, 방향이 불명확하면 한 번에 답하기 쉬운 질문으로 재확인합니다.
3. 손실 중 레버리지 확대처럼 위험한 요청은 위험 근거와 더 안전한 대안을 먼저 제시합니다.
4. 허용된 설정 키와 범위만 정규화하고 변경 전/후를 표시합니다.
5. 적용 버튼과 최종 확인 후 저장하고 대시보드 런타임을 갱신합니다.
6. 변경 이력으로 설정을 되돌릴 수 있지만 이미 발생한 체결은 취소하지 않습니다.
7. 과거 `ai_auto` 값이 있어도 최종 확인을 생략하지 않습니다.
8. 시장·성과·포지션이 부족하거나 최근 손실·열린 포지션 상태이면 위험 확대형 변경을 적용 단계에서 차단합니다.
9. 모든 허용 설정은 `SETTINGS_ACTION_REGISTRY`의 `user_confirm` 권한을 사용합니다. 예전 AI 권장안 적용도 같은 정규화·위험검증·최종확인 경로를 통과합니다.
10. 저장 직후 설정 파일을 다시 읽어 제안값과 비교하고, 다르면 이전 전체 설정으로 자동 롤백합니다.
11. 사용자별 앱 데이터의 `assistant/settings_change_history.json`에는 허용 작업 키의 변경 전/후만 저장합니다. API 키·전체 설정은 기록하지 않으며 앱 재시작 후에도 마지막 변경을 병합 방식으로 되돌릴 수 있습니다.

주문 시작·중지·임의 주문·API 키 입력은 현재 채팅 자동 실행 대상이 아닙니다. 향후 거래 액션은 별도 권한,
시세·잔고 재조회, 주문 미리보기, 강한 확인, 거래소 응답 검증, 감사 로그를 모두 갖춘 액션만 추가해야 합니다.

직접 실행형 문장이 들어오면 보호 작업 레지스트리가 주문, 거래 시작·중지, API 자격증명, 출금·송금을 먼저 분류합니다.
현재 버전은 실행된 것처럼 답하지 않고 `실행하지 않았습니다`와 미충족 안전 게이트를 명시합니다. 분석·위치 질문은
계속 일반 도움말로 답합니다.

## 2. 시작하기 전에 (필수)

### 2.1 설치·실행

1. `docs/INSTALLATION.md` — Python 버전, `pip install -r requirements.txt`(또는 Windows용 파일), `python3 main.py` 실행.
2. 문제 발생 시 `docs/TROUBLESHOOTING.md`.

### 2.2 AI API 설정

설정(`settings.json` 또는 앱 내 설정 UI)에 다음이 필요합니다.

| 키 | 설명 |
|----|------|
| `openai_api_key` | OpenAI 호환 API 키. 비어 있으면 `ai_assistant_widget`에서 AI 기능이 비활성화됩니다. |
| `assistant_ai_model` | 어시스턴트 전용 모델명(미설정 시 위젯에서 정규화 후 기본값 사용). |
| `openai_model` / `openai_base_url` | 트레이딩용 AI와 공통 `AIManager` 구성에 사용. **다른 벤더(DeepSeek, OpenRouter, 로컬 OpenAI 호환 서버)** 는 `docs/AI_API_ARCHITECTURE.md` 참고. |

앱 실행 후 대시보드에서 **「AI 어시스턴트」**(또는 제품 버전에 따른 동일 탭)을 엽니다. 질문 입력창과 자주 묻는 질문, `전체 복사`·`TXT 저장` 도구가 보이면 위젯이 정상 로드된 것입니다. 내부 모델명은 대화 화면에 상시 표시하지 않으며 모델 설정·실행 기능은 그대로 유지됩니다.

## 3. 어시스턴트가 참고하는 «현재 상황» 컨텍스트

`parent_dashboard`와 거래소 매니저가 연결되어 있으면, 매 질의마다 `_get_current_trading_context()`가 대략 다음 정보를 **한 덩어리 텍스트**로 만듭니다(일부는 거래소/API 상태에 따라 «조회 실패» 등으로 끊길 수 있음).

- 선택 거래소, 연결 상태(참고용 — **설정 파일 저장과는 독립**이라는 규칙이 설정 변경 프롬프트에 명시됨)
- 잔고·USDT 환산 등
- `default_leverage`, `default_tp`, `default_sl`, `min_trade_amount`, RSI·변동성·`ai_trading_preferences`·`ai_exit_settings` 등 **현재 설정 스냅샷**
- 거래 통계 요약, 활성 포지션 요약, 시장 데이터 일부, 선택 코인·분석 요약, AI 학습 패턴 수, CPU/메모리 등

따라서 **같은 질문이라도 시점·연결 상태에 따라 답이 달라지는 것이 정상**입니다. 컨텍스트가 비어 있거나 오류 문자열만 있으면 LLM 품질이 떨어질 수 있으므로, 먼저 거래소 연결·API 키·대시보드 탭에서 선택한 거래소를 확인하세요.

## 4. 대화 흐름 두 가지

### 4.1 일반 질문

설정 변경으로 분류되지 않으면, 시스템 프롬프트는 **제품 사용법·시장·거래 조언** 위주입니다. 최근 대화 일부와 현재 상태를 함께 전달하므로 후속 질문을 이어갈 수 있습니다. 목표·변경 대상·방향이 불명확하면 값을 추정하지 않고 재질문합니다.

### 4.2 설정 변경으로 분류되는 질문

메시지에 아래 **키워드 중 하나라도** 포함되면(대소문자 무시) 설정 변경 모드로 들어갑니다.

`레버리지`, `leverage`, `tp`, `sl`, `손절`, `익절`, `설정`, `변경`, `바꿔`, `조정`, `수정`, `설정해`, `내려`, `높여`, `줄여`, `낮춰`, `증가`, `감소`, `보수`, `적극`, `conservative`, `aggressive`, `moderate`, `리스크`, `risk`, `거래 성향`

위치·방법을 묻는 질문은 설명으로 답하고 즉시 변경하지 않습니다. 모호한 변경은 재질문합니다. **구체적으로** «레버리지를 3으로», «high vol 차단을 해제해줘»처럼 쓰면 변경 전/후를 확인할 수 있습니다.

이 모드에서는 모델에게 **반드시 JSON**으로 답하라고 요청합니다. 앱이 파싱하는 형식은 다음과 같습니다.

- 우선 마크다운 코드 펜스로 감싼 JSON 블록(펜스 첫 줄이 json 언어 태그인 형태)을 파싱합니다.
- 실패 시 `"action"`·`"settings"`가 포함된 `{...}` 패턴을 정규식으로 찾습니다.

**성공 시** `action`이 `"settings_change"`이고 `settings`에 허용된 키가 있어야 적용 제안을 표시합니다. 저장은 사용자 적용 버튼과 최종 확인 뒤에만 수행됩니다.

**확인 후 실제로 갱신되는 키 예시** (`_apply_settings_automatically` 내부 저장 함수 기준)

- 최상위: `default_leverage`, `default_tp`, `default_sl` 등 일반 설정 키.
- `risk_tolerance`, `balance_utilization_limit`는 **`ai_trading_preferences` 내부**로 넣어 저장합니다.
- `strategy_engine_high_vol_action`, `strategy_engine_consensus_threshold`, `strategy_engine_cooldown_sec`는 검증 후 **`advanced_trading_layers.strategy_engine` 내부**로 넣어 저장합니다.

모델이 JSON을 어기면 텍스트만 표시되고, 키워드 기반 **fallback 권장 설정**으로 넘어갈 수 있습니다.

위험을 낮추는 변경은 시장 데이터가 일부 없더라도 제안할 수 있습니다. 반대로 레버리지·잔고 활용 확대,
적극 성향 전환, 고변동장 차단 해제, 합의 임계값 하향, 쿨다운 축소, 손절 폭 확대는 현재 시장·성과·포지션
데이터가 충분해야 합니다. 최근 총손익이 음수이거나 레버리지 확대 중 열린 포지션이 있으면 대화 적용을 차단합니다.

### 4.3 high vol 차단 질문의 정확한 답

설정 위치는 **대시보드 상단 설정 → 고급 매매 계층 → 전략 엔진 세부 설정 → 고변동장 처리**입니다.

- `평가 계속(evaluate)`: 고변동장을 일괄 차단하지 않지만 합의 임계값·수익성 검증·AI 커스텀 조건·리스크·주문 가드레일은 유지합니다.
- `항상 차단(block)`: 고변동장 신규 진입 후보를 전략 엔진에서 차단합니다.
- 최신 OpenAI 모델 선택은 분석 품질·비용 선택입니다. 모델 변경만으로 수익성 검증을 통과하거나 거래 기회가 늘어난다고 보장하지 않습니다.

예: “OpenAI 최신 모델을 쓰면서 high vol 차단을 해제하고 싶은데 어디서 설정하나요?”라고 물으면 현재값과 경로를 설명합니다. “high vol 차단을 해제해줘”라고 명확히 요청하면 변경안과 위험 설명을 보여 주고, 사용자 확인 후 저장합니다.

## 5. 설정 변경 JSON 예시 (복사해 참고용)

아래는 모델 응답 예시입니다. 실제 숫자는 현재 전략에 맞게 조정해야 합니다.

```json
{
  "action": "settings_change",
  "message": "보수적으로 조정했습니다.",
  "settings": {
    "default_leverage": 3,
    "default_tp": 0.015,
    "default_sl": 0.012
  },
  "reason": "변동성 완화"
}
```

리스크 성향만 바꿀 때 예시:

```json
{
  "action": "settings_change",
  "message": "거래 성향을 보수적으로 변경합니다.",
  "settings": {
    "risk_tolerance": "CONSERVATIVE",
    "balance_utilization_limit": 0.15
  },
  "reason": "사용자 요청"
}
```

적용 후에는 `save_settings`가 성공해야 하며, 대시보드에 `on_settings_changed`가 있으면 호출됩니다. **가드레일**(레버리지 상한, 최소 노셔널 등)은 트레이딩 경로에서 별도로 적용되므로, 대화에서 나온 수치와 최종 주문이 다를 수 있습니다. 개요는 기존 가이드 문단과 동일합니다.

- 레버리지 clamp, 마진 타입, 최소 노셔널 등: `README.md` 및 `docs/ARCHITECTURE.md`의 가드레일 설명 참고.

## 8. 음성 STT / TTS (현재 구현 + 운영 주의)

현재 저장소 기준으로 AI 어시스턴트 음성 기능은 다음 범위까지 구현되어 있습니다.

- STT 입력: `ui/widgets/ai_assistant_widget.py`의 `🎤 음성입력` 버튼으로 마이크 음성을 텍스트로 변환하여 입력창에 주입
- TTS 출력: `assistant_voice.auto_tts=true`일 때 AI 답변을 OS 기본 엔진으로 읽기
- 음성 모듈: `ui/widgets/ai_voice_module.py`
  - macOS TTS: `say`
  - Windows TTS: PowerShell SpeechSynthesizer
  - STT: `SpeechRecognition` 사용 (`transcribe_microphone`)

의존성/배포 주의

- STT는 선택 의존성입니다. 미설치 시 `not_available`로 폴백됩니다.
- 배포 환경에서는 아래 패키지 포함 여부를 반드시 확인하세요.
  - `SpeechRecognition>=3.10.0`
  - `pyaudio>=0.2.14`
- macOS는 PortAudio 선설치가 필요할 수 있습니다.

제약 사항

- 현재 구현은 **음성 입력 보조 + 음성 읽기** 중심입니다.
- 사용자가 음성만으로 앱의 모든 기능을 직접 제어하는 전면 음성 UI(권한·화이트리스트 기반 명령 실행)는 별도 단계입니다.

권장 운영 흐름

1. 설정에서 `assistant_voice.enabled=true` 후 마이크 권한 확인
2. `🎤 음성입력`으로 질문 입력 → AI 분석/설정 제안 확인
3. 설정 변경은 AI 제안(JSON)을 검토 후 사용자 확인 기반으로 적용
