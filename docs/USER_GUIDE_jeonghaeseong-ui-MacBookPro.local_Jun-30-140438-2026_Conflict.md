## 📖 NoahAI는 당신을 위해 무엇을 할 수 있는가?

### 🎯 NoahAI란 무엇인가?

**NoahAI**는 당신이 금융을 깊이 있게 배우지 않아도 **자신의 자산·상황·위험을 이해하고 올바른 선택을 할 수 있도록 돕는 AI 금융 동반자**입니다.

NoahAI의 핵심은 **자동으로 돈을 벌어주는 시스템이 아니라, 금융 의사결정을 투명하고 검증 가능하게 만드는 인프라**입니다.

## 📣 업데이트 확인 방법 (사용자 필독)

신규 기능/변경사항은 아래 순서로 확인하는 것이 가장 정확합니다.

1. 대시보드 `사용자 매뉴얼` → `📅 업데이트` 탭
2. 변경 직후 안전 안내(제한/주의/준비 상태) 확인
3. 기능 적용 범위를 AI 어시스턴트에 질문해 개인 상황으로 재확인

운영 원칙:
- 화면에 보이지 않는 기능은 아직 제공되지 않는 것으로 판단합니다.
- 문서 표현보다 현재 버전의 실제 UI 노출 상태를 우선합니다.
- 버전이 같아도(예: v3.8.9.20) 날짜 기준으로 추가 업데이트가 누적될 수 있습니다.
- 운용 리스크 대응은 상용화 이후가 아니라 테스트 단계에서 먼저 수행합니다.
- 점진적 적용은 지연이 아니라, 리스크를 통제하며 빠르게 검증하기 위한 표준 절차입니다.
- 사용자에게 보이는 기능 변경은 인앱 매뉴얼/가이드 안내가 함께 업데이트된 항목만 반영됩니다.

#### 학습 데이터 10,000 상한 관련 FAQ

- Q. "모든 학습 로그가 1만개까지만 남는 건가요?"
  - A. 거래소별 학습 파일은 최신 N개만 유지합니다(예: 바이낸스 10,000).
  - A. 별도 호환 집계 파일(`ai_learning_data.json`)은 최근 5,000개를 유지합니다.
- Q. "그럼 KPI/통계 서버 전송도 줄어드나요?"
  - A. 아닙니다. 학습 이벤트는 기록 시점마다 KPI 이벤트 전송 경로를 그대로 탑니다.
  - A. 네트워크 실패 시 전송 실패만 기록되고, 학습 저장 정책과는 분리되어 동작합니다.
- Q. "거래 통계(승률/손익) 신뢰도는 유지되나요?"
  - A. 유지됩니다. 거래 통계는 학습 JSON이 아니라 거래 기록 DB/리포트 경로를 기준으로 계산됩니다.

### 💪 AI 동반자가 할 수 있는 5가지

#### 1. **설명 (Explain)**
- 자산·거래·시장을 이해하기 쉬운 언어로 설명
- 기술적 용어를 평신도 수준으로 번역
- "왜 그런 신호가 나왔는가"를 구조적으로 제시

#### 2. **비교 (Compare)**
- 금융상품을 조건별로 비교 분석
- 대출, 보험, 예금 등 선택지 제시
- 당신의 상황에 맞는 추천안 제공

#### 3. **경고 (Warn)**
- 비정상 거래 자동 탐지
- 금융사기 위험도 평가
- 위험한 거래 조건 사전 경고

#### 4. **기록 (Record)**
- 모든 판단과 거래를 자동 기록
- 의사결정 근거를 일관되게 저장
- 사후 검증과 학습에 활용

#### 5. **검증 (Verify)**
- "내 결정이 맞았는가" 사후 검증
- AI 판단의 정확도 추적
- 시간 경과에 따른 성과 비교

### 🏗️ 기술 기초: 판단·설명·기록·검증·환류

NoahAI는 다음 5단계 파이프라인으로 운영됩니다:

1. **판단 (Decision)**: AI가 분석하여 신호/추천을 생성
2. **설명 (Explanation)**: 왜 그 판단을 했는지 구조적으로 설명
3. **기록 (Logging)**: 판단·근거·결과를 자동으로 저장
4. **검증 (Verification)**: 판단이 맞았는지 나중에 확인
5. **환류 (Feedback)**: 검증 결과를 다음 판단에 반영

이 구조를 통해 **신뢰할 수 있고 학습하는 AI 금융 동반자**가 가능해집니다.

### 운영 정책 ON/OFF가 무엇인가

- 위치: settings의 `advanced_trading_layers` 각 항목의 `enabled`
- ON: 해당 계층이 실제 주문 판단에 개입합니다.
- OFF: 해당 계층은 우회되고 기존 로직으로 동작합니다.

사용자 관점에서 왜 필요한가:

- 장애 대응: 시장 급변/거래소 이슈 시 일부 계층만 임시 OFF 가능
- 단계적 적용: 신규 전략을 한 번에 전체 반영하지 않고 점진 적용 가능
- 원인 분석: 수익성/실행품질/전략엔진 중 어느 계층이 영향을 주는지 분리 확인 가능

계층별 기능 요약:

- `profitability_validation.enabled`: 최근 성과가 기준 미달이면 신규 진입 차단
- `portfolio_orchestration.enabled`: 종목별 위험도/상관관계 기반 수량 자동 보정
- `execution_optimizer.enabled`: 재시도/타임아웃/슬리피지 상한으로 체결 품질 관리
- `strategy_engine.enabled`: 레짐 필터와 쿨다운으로 과매매 억제
- `ops_automation.enabled`: 이상 징후 감지 및 롤백 액션/일일 브리핑 생성

초기 운영 권장:

- 실거래 초기는 `safe` 프리셋 기준으로 시작
- 전략 검증/디버깅은 `dev` 프리셋으로 계층 OFF 후 원인 분리
- 공격적 운용은 `aggressive` 프리셋을 쓰되 리스크 한도와 함께 사용

## 🧠 AI 판단 알고리즘 — 사용자가 이해할 수 있는 수준의 설명

### 암호화폐: 어떻게 "매수/매도" 신호가 나오는가?

**Step 1: 현재 시장 상태 진단**
```
"BTC가 지난 14일 중 가장 낮은 가격대(RSI < 30)에 있고,
 거래량이 평소의 30% 이상 증가했습니다.
 이는 시장이 매도 과열(과매도) 상태임을 의미합니다."
```

**Step 2: 거래량 + 가격 추세 확인**
```
"같은 기간 동안 가격이 5% 이상 하락했지만,
 새로운 저점을 뚫고 내려가지는 않았습니다.
 이는 강한 '손절(저가 매도)'의 신호이며, 곧 회복할 가능성이 있습니다."
```

**Step 3: 최종 판단**
```
LONG 신호 생성 ✅
신뢰도: 72%

근거: 과매도 상태(RSI < 30) + 거래량 증가 + 가격 저항선 유지
```

**Step 4: 리스크 평가**
```
손실 한도: -3% (이 수준에서 자동으로 청산 제안)
수익 목표: +5% (이 수준에서 자동으로 청산 가능)
```

### 이 신호는 언제 틀리는가?

- **시장이 급락하는 경우**: 추가 하락으로 RSI < 20까지 내려갈 수 있음
  → 미리 설정한 손실 한도(-3%)에서 자동 청산되어 손실 제한

- **뉴스/이슈로 급등하는 경우**: 예상보다 빨리 상승
  → 수익 목표(+5%)에 도달하면 자동으로 청산 가능

### 주식: 왜 암호화폐와 다른가?

**암호화폐 (24/7 시장)**

### 🧠 핵심 기술: 금융 특화 강화학습 기반 판단 엔진

NoahAI의 차별화 요소는 **DAL의 AI 디지털케어로그 기반 구조를 금융 의사결정에 맞게 재설계·구현한 판단 엔진**(개발·운영: Noah AI Labs)입니다.
핵심은 수익 약속이 아니라, **설명 가능하고 검증 가능한 판단 구조**를 운영에 고정하는 데 있습니다.

#### 기술 특징 (이미 구현 완료):
- **멀티모달 금융 데이터 분석**: 차트 이미지, 수치 데이터(가격/거래량/변동성), 시장 심리 지수(공포/탐욕, 펀딩비) 등을 통합 분석
- **성과·로그 기반 적응**: 거래 이력·리스크 데이터로 임계값·파라미터를 조정하는 루프(`unified_trader`, `AIAutoOptimizer`, `ExchangeLearningManager` 등, 설정·AI 활성 조건에 따름). 엄밀한 RL 정책 네트워크가 항상 전 구간에 걸쳐 학습한다는 뜻은 아님.
- **실시간 적응형 시스템**: 시장 변화에 즉시 반응하여 전략을 자동 조정하는 동적 적응 메커니즘
  - **동적 적응형 임계값 시스템**: 시장 상황, 변동성, 거래 이력에 따라 실시간으로 진입/청산 기준 자동 조정
  - **실시간 시장 국면 감지**: LOW/NORMAL/HIGH 변동성에 따라 전략 강도 자동 조절
  - **점진적 학습**: 거래 이력이 쌓일수록 점진적으로 정상 임계값으로 전환 (첫 거래 → 초기 → 중기 → 정상)
  - **승률 기반 자동 조정**: 거래 성과에 따라 자동으로 더 공격적 또는 보수적으로 전환
- **DAL 기록·환류 철학의 금융 적용**: 의료·돌봄 맥락의 기록·분석·환류 개념을 금융 판단·로그 구조로 재구현한 축(의료 진단·허가 수준의 정확도를 금융에 보장한다는 뜻 아님)
- **셀프 호스팅 가능**: 자체 AI 엔진 기반으로 데이터 보안과 비용 효율성 극대화 (현재 일일 20-170원, 향후 오픈소스 LLM 전환으로 무료화 예정)

### 🎯 2단계: 코인 선정 (Coin Selection)

**evaluator.py - AI 코인 선택의 핵심 엔진**

NoahAI의 코인 선정은 `evaluator.py`라는 **과학적 평가 시스템**을 통해 이루어집니다. 이는 단순한 랜덤 선택이 아닌, **5가지 차원의 종합 점수**를 기반으로 최적의 거래 코인을 선별하는 고도화된 시스템입니다.

#### 🔍 evaluator.py의 주요 기능
```
코인 선택 시스템:
├── 코인 후보군 수집 (거래소별 특화)
├── 다차원 점수 계산 (5가지 평가 기준)
├── 메이저/알트코인 비율 동적 조정
├── 시장 상황별 자동 선택 전략
└── 하이브리드 접근법 (캐싱 + 백업)
```

#### 📊 5가지 평가 기준
```
종합 점수 계산:
├── 기술적 점수 (RSI, MACD, 볼린저밴드)
├── 변동성 점수 (스캘핑 최적화)
├── 거래량 점수 (유동성 보장)
├── 트렌드 점수 (시장 방향성)
└── 리스크 점수 (안정성 평가)
```

#### 🚀 하이브리드 접근법 (성능 최적화)
```
3단계 백업 시스템:
├── 1단계: 캐시된 API 데이터 (1시간 이내) → 가장 정확
├── 2단계: 백업 심볼 파일 (API 실패 시) → 안정적
└── 3단계: 하드코딩된 주요 심볼 (최종 백업) → 확실함
```

#### 📈 거래소별 최적화 전략

```
🤖 AI 신뢰도 측정 방법
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AI 신뢰도는 0~1 사이 값으로 계산되며, 여러 요소를 종합하여 결정됩니다:

1. **기본 신뢰도**: 0.7 (시작점)

2. **패턴 분석 기반 조정** (과거 거래 이력이 있을 때만):
   - 손실률 > 30%: 신뢰도 -0.2 (신뢰도 하락)
   - 손실률 < 20%: 신뢰도 +0.1 (신뢰도 상승)

3. **시장 조건 기반 조정**:
   - 변동성 부적절: 신뢰도 -0.3
   - 변동성 적절: 조정 없음

4. **신호 강도 기반 조정**:
   - 신호 신뢰도 > 0.8: 신뢰도 +0.1 (강한 신호)
   - 신호 신뢰도 < 0.5: 신뢰도 -0.1 (약한 신호)

5. **최종 신뢰도 범위**: 0.0 ~ 1.0

🎯 동적 임계값 계산 (거래 허용 기준)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

거래를 허용할지 결정하는 "임계값"도 동적으로 계산됩니다:

1. **기본 임계값**: user_signal_threshold / 100
   - 예: 설정값 68 → 임계값 0.68
   - 기본값: 0.65 (설정값이 없을 때)

2. **시장 상황 조정**:
   - 고변동성: +0.02 (더 보수적)
   - 저변동성: -0.02 (약간 완화)

3. **연속 성과 조정**:
   - 연속 승리 ≥ 2회: -0.03 (더 공격적)
   - 연속 손실 ≥ 2회: +0.03 (더 보수적)

4. **🔥 승률 기반 자동 조정** (과거 성과가 있을 때만):
   - 거래 이력 10회 이상 필요
   - 승률 > 70%: 임계값 -0.05 (더 공격적)
   - 승률 < 30%: 임계값 +0.05 (더 보수적)
   - 승률 30-70%: 비례 조정
   - 과거 성과가 없으면: 승률 기반 조정 없음 (기본값 사용)

5. **안전 범위**: 0.30 ~ 0.95

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 🆚 일반 자동매매 앱과의 차이점

### ⚙️ 왜 대부분의 자동매매/AI 봇은 이런 구조가 불가능한가?

NoahAI는 단순한 "조건매매 프로그램"이 아닌 **AI 자율 판단 시스템**입니다.  
현재 시중에 있는 수많은 "AI 자동매매" 혹은 "AI 트레이딩"이라고 홍보되는 제품들은 다음 이유로 동일한 기술을 구현할 수 없습니다.

#### 1. **AI 학습 구조 자체가 없음**
```
❌ 대부분의 프로그램은 미리 정해진 규칙(if-then)만 수행합니다.
❌ 거래 결과를 학습하거나 강화학습 데이터로 재활용하지 못합니다.
❌ AI 모델이 존재하지 않거나, 단순 API 호출로 'AI처럼 보이게'만 구성됩니다.
✅ NoahAI는 거래 결과를 실시간으로 기록·분석하여 패턴을 학습하고 다음 판단에 반영합니다.
```

#### 2. **시장 실시간 분석이 불가능**
```
❌ 기존 봇들은 1분~5분 단위의 단순 신호만 처리합니다.
❌ 초 단위(5~10초)의 실시간 데이터 처리, 변동성 감지, 거래소별 슬리피지 계산은 기술적으로 구현이 어렵습니다.
✅ NoahAI는 초 단위로 6개 거래소 데이터를 수집·분석하여 시장 급변에도 즉시 대응합니다.
```

#### 3. **멀티모달 분석 불가능**
```
❌ 대부분은 차트 숫자 데이터만 사용합니다.
❌ 뉴스·거래심리·거래량 패턴·시장 국면 등을 통합적으로 분석할 수 없습니다.
✅ NoahAI는 AI 디지털케어로그(DAL)에서 이어지는 멀티모달 분석 관점을 바탕으로, Noah AI Labs 구현을 통해 텍스트·숫자·패턴 데이터를 통합 처리합니다.
```

#### 4. **실시간 강화학습 엔진 부재**
```
❌ 대부분의 서비스는 '백테스트' 데이터에만 의존합니다.
❌ 실시간 강화학습이나 거래 후 피드백 학습은 구현되어 있지 않습니다.
✅ NoahAI는 거래 후 성과 데이터를 자동 저장하고, 실패 패턴은 패널티로 학습시켜 즉시 개선합니다.
```

#### 5. **데이터 인프라 및 처리 한계**
```
❌ 단일 거래소, 단일 계정, 단일 전략 기반의 구조.
❌ 초당 수천 건의 데이터 처리 불가능.
✅ NoahAI는 DAL에서 축적한 의료·돌봄 AI 데이터 인프라 경험을 바탕으로, Noah AI Labs가 금융용 실시간 데이터 파이프라인으로 구현합니다.
```

#### 6. **기술 검증 불가 또는 비공개 구조**
```
❌ 많은 프로그램이 'AI'라는 표현만 쓰고, 실제 코드·로그·AI 호출 내역을 공개하지 않습니다.

✅ 사용자는 언제든지 로그를 확인하여 "AI가 어떤 판단을 내렸는지" 직접 볼 수 있습니다.
```

#### 7. **개발 리소스 및 기술 장벽**
```
❌ 실시간 트레이딩 AI를 만들려면 금융 데이터 엔지니어링 + 강화학습 + 마이크로서비스 구조를 모두 다뤄야 합니다.
```

### 🆕 v3.8.9.11 (2026-01-25)

#### 🔥 TP/SL -2021 오류 근본 수정: GALA/JASMY 등 저가 알트코인 완전 지원

**배경**:
- GALA, JASMY 등 저가 알트코인에서 TP 주문이 반복적으로 실패 (`-2021: Order would immediately trigger`)
- TP와 SL이 모두 0.01로 동일하게 설정되어 전달됨
- SHORT 포지션에서 TP만 실패, SL만 성공하는 패턴 반복
- **이전 수정(v3.8.9.8, v3.8.9.9)으로도 해결되지 않은 이유**:
  - 이전 수정은 **SL 검증**과 **TP 거리 검증**만 추가했음
  - **TP 방향 검증**이 없어서 SHORT 포지션에서 TP > 현재가인 경우를 감지하지 못함
  - **trader 쪽에서 TP/SL 가격을 계산할 때** `price_precision` 키 이름 불일치로 항상 2자리로 고정되어 0.006xx가 0.01로 반올림됨

**근본 원인**:
1. **trader.py - 키 이름 불일치**:
   - `get_symbol_info_direct()`는 `pricePrecision`, `tickSize` (camelCase)를 반환
   - trader는 `price_precision`, `tick_size` (snake_case)로 찾음
   - 결과: `price_prec`가 항상 2로 고정 → `format(0.00657, '.2f')` = `0.01`로 반올림
   - GALA (진입가 0.0067): TP=0.0066, SL=0.0068이 0.01, 0.01로 변환됨
2. **binance_client.py - TP 방향 검증 누락**:
   - SHORT 포지션에서 TP는 현재가보다 **낮아야** 함
   - TP=0.01, 현재가=0.0067인 경우: 0.01 > 0.0067 → "가격이 0.01 이하로 떨어질 때" 조건이 **이미 충족** → 즉시 트리거 → -2021
   - 이전 수정은 **거리만** 검증하고 **방향**은 검증하지 않음

**주요 개선사항**:
- **trader.py - 키 이름 수정 및 저가 코인 보호**:
  - `info.get('price_precision', 2)` → `info.get('pricePrecision') or info.get('price_precision') or 2`
  - `info.get('tick_size', ...)` → `info.get('tickSize') or info.get('tick_size', ...)`
  - **저가 코인 자동 감지**: 진입가 0.001~0.02 범위면 `price_prec`를 최소 4~5로 강제
  - 예외 처리에서도 `round(., 2)` → `round(., price_prec)` 사용
- **binance_client.py - TP 방향 검증 추가**:
  - SHORT: `tp_price >= current_price` 감지 시 자동 재계산
  - LONG: `tp_price <= current_price` 감지 시 자동 재계산
  - 방향 검증 후 거리 검증 수행 (기존 로직 유지)

**주요 효과**:
- ✅ GALA (진입가 0.0067): `price_prec` 2 → 4로 조정 → TP=0.0066, SL=0.0068 (정확)
- ✅ JASMY (진입가 0.0081): `price_prec` 2 → 4로 조정 → 정확한 가격 유지
- ✅ 모든 저가 알트코인 (0.001~0.02 범위) 자동 보호
- ✅ TP 방향 오류 자동 감지 및 재계산
- ✅ 예외 처리 강화로 어떤 상황에서도 정확한 정밀도 유지
- ✅ **다른 알트코인에서도 동일 문제 재발 방지** (범용적 해결)

**이전 수정이 "완전"하지 않았던 이유**:
- v3.8.9.8, v3.8.9.9에서 **SL 검증**과 **TP 거리 검증**만 추가
- **TP 방향 검증**이 없어서 SHORT에서 TP > 현재가인 경우를 감지하지 못함
- **trader 쪽 키 이름 불일치**를 다루지 않아서 잘못된 0.01이 계속 생성됨
- 결과: GALA/JASMY 같은 저가 코인에서 계속 같은 -2021 오류 발생

**참고 문서**:
- `docs/TP_SL_GALA_JASMY_ROOT_CAUSE_ANALYSIS_20260125.md`: 상세 원인 분석
- `docs/TP_SL_FIX_V3.8.9.11_20260125.md`: 수정 상세 내역

## ⚔️ Alpha Arena 모드 사용 가이드

### 🎯 Alpha Arena 모드란?

**Alpha Arena 모드**는 nof1.ai의 Alpha Arena 벤치마크에서 검증된 **승리 알고리즘**을 NoahAI에 적용한 독립 거래 모드입니다.

#### 핵심 특징
- **LLM 기반 자율 거래**: AI가 직접 거래 결정을 내리고 실행
- **검증된 전략**: Alpha Arena 벤치마크에서 수익을 낸 엔진 사용
- **독립 모드**: 기존 자동매매 파이프라인과 완전 분리
- **Binance Futures 전용**: 바이낸스 선물 거래소만 사용

### 🚀 시작하기

#### 1단계: 설정 활성화
```
1. 설정 탭 → "⚔️ AlphaArena" 선택
2. "Alpha Arena 모드 활성화" 스위치 켜기
3. AI 엔진 선택:
  - DeepSeek 3.1 (현재 대시보드 실행 기준)
  - Qwen 3 Max (설정 항목 존재, 현재 실행 경로 미완료)
4. API 키 입력:
  - DeepSeek API Key (현재 실행 기준)
  - Qwen3 (Alibaba) API Key (후속 지원 대비 저장 가능)
```

#### 2단계: 대시보드에서 사용
```
1. 대시보드 → "AlphaArena" 탭 선택
2. 첫 진입 시 안내 모달 확인
3. "시작" 버튼 클릭하여 거래 시작
```

### 📋 Alpha Arena 모드 작동 방식

#### 거래 프로세스
```
1. 시장 데이터 수집
   ├── 6개 코인 시세/지표 (BTC, ETH, SOL, XRP, DOGE, BNB)
   ├── 계좌 정보
   ├── 현재 포지션
   └── 직전 주문 결과

2. LLM 프롬프트 생성
   ├── 시장 상태 요약
   ├── 각 코인별 기술적 지표
   └── 거래 가능 여부

3. LLM 응답
   ├── MODEL_CHAT (사람이 읽는 설명)
   └── TRADING_DECISIONS (실행 가능한 JSON)

4. 주문 실행
   ├── TRADING_DECISIONS 파싱
   ├── 검증 및 가드레일 적용
   └── Binance Futures API로 직접 주문
```

#### 거래 신호 타입
- **ENTER_LONG**: 롱 포지션 진입
- **ENTER_SHORT**: 숏 포지션 진입
- **HOLD**: 기존 포지션 유지
- **CLOSE**: 포지션 청산

#### 가드레일 (자동 적용)
- **레버리지 범위**: 10-20x 자동 클램핑
- **TP/SL 필수**: 진입 시 반드시 TP/SL 지정 필요
- **쿨다운**: 동일 코인 재진입 최소 30초 간격
- **리스크 캡**: 틱당 최대 리스크 제한
- **최대 동시 포지션**: 6개 코인 (심볼당 1개)

- **엔진 선택**: 현재 대시보드 실행은 DeepSeek 3.1 기준, Qwen 3 Max는 준비 상태
