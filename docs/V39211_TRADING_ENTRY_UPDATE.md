## 사용자가 거래 보류를 확인하는 방법

1. 메인 **거래 현황**에서 대상 기관을 확인하고 해당 거래소의 **운용 요약**을 연다.
2. 목록 조회 실패라면 연결·공개 시세 접근과 초기화 로그를 확인한다. 과거 목록으로 시작하지 않는다. 신뢰도·합의·변동성·HOLD라면 실제 기준과 최근 판단 분포를 확인한다. 대기 자체가 오류를 뜻하지 않는다.
3. 과거 PAPER 자금 근거 누락이면 기록을 보존한다. 화면에 새 평가 준비가 안내되고 정지·보유/예약 없음 등 보호 조건을 충족할 때 직접 확인해 새 평가를 준비한다. 준비 완료와 거래 시작은 별도다. DB 저장 장애 등 다른 차단은 해당 조치를 먼저 따른다.
4. 주기 갱신 지연이면 앱 실행·기관 연결·로그 최신성을 확인한다. 진단 자료 조회 실패 때 마지막 표시를 현재 정상 상태로 해석하지 않는다. PAPER와 LIVE, 기관별 결과를 구분한다.

## 장시간 무거래 감시의 정확한 범위

- 현재 실행 세션에서 **30분 이상 신규 주문 처리 기록 없음 + 3회 이상 주기 반환**이면 무거래 안내와 최근 판단 분포를 표시한다. 주문 처리는 체결 완료와 동일하지 않다.
- **15분 이상 실행 주기 갱신 근거가 없으면** 갱신 지연을 별도로 표시한다. 최근 128개 판단에서 상위 3개 사유와 횟수를 제한된 범위로 보여준다.
- 7개 암호화폐 기관의 실행 중 PAPER/LIVE를 대상으로 한다. 정지·학습은 제외하며 증권에 동일 감시가 구현됐다고 표시하지 않는다. 정상 HOLD도 안내 조건에 포함된다.
- 앱 재시작 시 관찰 세션이 새로 시작된다. 4일 전체를 영속 집계하거나 앱 밖 OS·메일·Slack·중앙 서비스 알림을 보내는 기능은 이번 범위에 없다. 재시작을 넘는 감시와 외부 알림은 후속 과제다.

## 확인한 증거와 남은 한계

피드백의 시작 오류 본문은 `mode: paper`이고 제공 운용 자료도 PAPER 장애를 뒷받침한다. 실제 LIVE 장애·주문 성공을 이 자료로 증명하지 않는다. 해당 409 요청 시각은 제공 운용 로그의 마지막 시각 이후이므로 정확히 어떤 하위 API가 실패했는지는 미확정이다. 공개 조회 성공을 당시 요청의 원인 확정으로 사용하지 않는다.

버전 분리 전 최종 엔진 검증은 Python **5,635 passed / 11 skipped / 3 subtests**, Node **73**, 합성 응답을 사용하는 실제 빌드 React **49검사**다. 7기관 공개 목록 조회, Upbit SDK 실패 재현·시세 복구, Bitget 메타데이터 정규화 비교, 6기관 복사 원장 새 평가 재생을 확인했다. [당시 증거](../reports/teayu-20261010-followup/validation.json)와 [추가 감사](TEAYU_FOLLOWUP_AUDIT_20261010.md)는 변경하지 않는다. 버전 정렬 후 결과는 [새 검증 기록](../reports/v39211-version-alignment-20261010/validation.json)과 [TEST_STATUS](TEST_STATUS.md)에 따로 남긴다.

398개 로그의 96,893,772줄에서 발견한 오류 표시 6,084줄은 고유 버그 수가 아니다. DB 저장 대기 초과, Coinone 잔고 조회 실패, KIS 통신 지연, 키움 세션 문제 등도 있었다. 모든 과거 오류의 원인 재현·수정 완료나 모든 사용자 환경의 재발 방지를 선언하지 않는다. 거래 빈도·수익·승률을 보장하지 않는다.

## 빌드·업데이트·롤백 인계

`config/app_version.py`가 버전 정본이다. 매뉴얼은 `ui/widgets/user_manual_widget.py`에서 `scripts/export_legacy_manual_sections.py`로 11탭 JSON을 생성한다. `deploy/release_notes.md`는 .11 다음 빌드용 초안이다. 기존 `deploy/release-manifest.json`·`latest.yml`·.10 설치기와 자산 해시는 공개 이력으로 유지하며 .11로 재명명하지 않는다. .10 manifest와 릴리즈 노트 사본은 `config/published_release_manifests/`에 보존한다.

Mac 동기화 폴더에는 Git이 없다. `SOURCE_IDENTITY.json`의 현재 소스 지문은 실제 Windows Git 커밋을 대신하지 않는다. Windows 담당자는 수정 파일을 정확한 깨끗한 작업트리에 반영하고 커밋·입력 지문·제품/PE·updater·renderer를 대조한 뒤 새 설치기를 빌드한다. 빌드 결과의 새 manifest·latest.yml·해시와 원격 게시 결과를 별도 기록한다.

실제 .10→.11 설치·수동/자동 업데이트, 새 안내 화면, 기관별 PAPER 재개, .10 롤백과 24/72시간 운용은 [현재 패치 체크리스트](DEPLOY_CHECKLIST.md)의 미완료 항목이다. 롤백 전 앱·기관을 정지하고 .11에서 생긴 기록까지 최신 백업에 보존한다. 업데이트 전 백업만 복원해 최근 기록을 잃지 않도록 한다. 실제 LIVE 주문·체결 대조는 별도 인수다.
