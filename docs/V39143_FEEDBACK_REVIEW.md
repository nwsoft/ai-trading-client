# v3.9.1.43 피드백 검토 및 빌드 인계

2026-09-20. 공개 v3.9.1.42 이후 소스 후보이며 설치기 빌드·배포는 사용자가 수행한다.

후속 구현: [거래 기록 유지관리 계획 및 남은 조건](V39143_RECORD_RECOVERY_PLAN.md). 로컬 청산 ID가 없어도 Binance 과거 API 원장을 수집하여 포지션 구간과 정산 근거로 복구하는 경로를 추가했다. 고객 DB 40건 모두 새 조회 경로 진입을 확인했고 API 응답 계약으로 실제 행/체결/손익 복구를 시험했다. 아래 기존 DB의 40건은 고객 API 응답 없이 그대로 보존했다. 해당 계정의 복구 성공, 전체 계좌 일별 대조·조건부 재개 완료를 뜻하지 않는다. 배포 전 실제 연결/설치본 검증은 남아 있다.

## PnL 차단: 해결 완료로 안내하지 않는다

공유 DB를 `scripts/audit_pnl_ledger.py`로 읽기 전용 재감사했다. SHA-256은 `5a337529f46076843c6872e6482d1007b5976f25949c3746ff088433d416ab0a`로 원본 불변. 최근 300건 중 미대조 40건 모두 LIVE이며 청산 주문 ID가 없다. 33건 pending, 7건 candidate, 37건 TP/SL 사유다.

41의 전진 수정은 진입 주문→제출한 보호 주문→실제 청산 주문→fill의 소유 근거를 저장·조회한다. 근거가 없는 과거 기록을 시간·가격·수량 유사성만으로 확정하지 않는다. 따라서 과거 40건이 남은 계정은 정상적인 안전장치에 의해 기본/confirm 신규 후보가 계속 차단될 수 있다. 경고 자체는 안전장치이고, 그 원인이 된 기록 결함은 실제 문제다. 사용자 착오나 문구만의 문제가 아니다.

이번 자료는 기존 DB와 41 화면이다. 42 설치 후 새 거래에서도 누락이 재발했는지는 이 자료로 증명할 수 없다. 업데이트 후 동일 40/300이라는 사실만으로 전진 수정 실패 또는 성공을 단정하지 않는다. 자동 체결 동기화로 소유 근거가 확보되는 건만 확정한다. 증거 없는 과거 건은 초기화·제외·전략 변경으로 우회하지 않는다. 기존 40건의 계좌 원본 대조/복구는 미완료이며 완전 해결로 배포 문구에 쓰지 않는다.

사용자 안내: “청산 손익의 주문 근거가 미확정인 40건이 남아 잘못된 손익으로 다음 거래를 판단하지 않도록 보호 중입니다. 41은 이후 기록 연결을 보강했지만 과거 누락 40건의 복구까지 완료한 것은 아닙니다. 사용 실수는 아니며 기록을 초기화하거나 전략을 바꿔 우회하지 마세요. 체결 동기화 결과의 미대조 사유를 확인해 주문 근거를 대조해야 합니다.”

## 전략 스튜디오

- 영상에서 난이도 버튼이 일반 탭으로 열리는 동선을 확인했다.
- `사용 난이도 설정` → AI 엔진/API → 해당 선택기 자동 스크롤·키보드 포커스.
- Level 1 (초보자), Level 2 (일반), Level 3 (고급), Level 4 (실험실) 공통 표기. 영어도 같은 매핑.
- 변경 후 `현재 설정 저장` 또는 `전체 설정 저장`을 눌러야 적용된다. 저장하지 않고 닫으면 기존 변경 확인 동작을 유지한다.
- 저장 후 코인/주식의 열린 Strategy Studio 설정을 다시 읽는다. 전략 입력을 지우거나 컴포넌트를 재마운트하지 않는다.
- 프로필은 화면 복잡도이며 수익등급·LIVE 권한·검증/여권 우회가 아니다.
