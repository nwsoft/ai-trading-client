# AI 접근성 모드 실행 계획 (2026-05-07)

## 목적
- 고령층, 디지털 취약계층, 초보 사용자도 버튼 1회 또는 음성 1회로 NoahAI 핵심 기능을 안전하게 사용할 수 있게 한다.
- 기존 `모두시작` 버튼을 단순 일괄 실행이 아닌, 사용자 상태와 설정 완성도를 반영한 `AI 실행` 버튼으로 전환한다.
- 거래소/증권사 OpenAPI 키 발급과 설정 과정을 `AI 상담`으로 안내해 초기 이탈을 줄인다.

## 철학/비전 정합성
- NoahAI의 원칙(판단/설명/기록/검증 중심, 실행 책임 분리)과 일치한다.
- "자동 투자 대행"이 아니라 "이해 가능한 실행 보조"로 설계해야 한다.
- 접근성 도메인(Accessibility Domain)을 제품 핵심 경험으로 끌어올리는 확장이다.

## 핵심 제안

### 1) 대시보드 버튼 재정의: 모두시작 -> AI 실행
- 시작 전 자동 진단
  - 네트워크, API 키 존재, 브로커 조합(api_type/api_version), 실주문 플래그 상태, 필수 설정 누락 여부
- 실행 계획 제시
  - "지금 가능한 작업"과 "막힌 작업"을 분리해 3줄 요약으로 표시
- 단계별 실행
  - 안전한 조회/분석/동기화 작업부터 수행
  - 실패 시 자동 재시도 1회 + 사용자 안내
- 실행 결과 요약
  - 수행 항목, 실패 항목, 다음 행동 버튼(재시도/설정 열기/AI 상담 연결)

### 2) 접근성 모드
- 큰 글씨/큰 버튼/고대비/쉬운 문장 템플릿
- 음성 입력(STT) + 음성 안내(TTS)
- 초보 용어 치환
  - 예: API 키 -> 연결 비밀번호
  - 예: 레버리지 -> 배율
- 실수 방지 UX
  - 숫자/계좌/키 관련 변경은 반드시 텍스트 재확인

### 3) AI 상담 설정 도우미
- 대화형 키 발급 가이드
  - 거래소/증권사별 단계 체크리스트
  - OS별 안내 분기(Windows/macOS)
- 설정 후보 자동 생성
  - 사용자 목표/경험 수준/브로커 상태 기준의 기본값 추천
- 승인 기반 반영
  - 변경 diff, 영향 범위, 되돌리기 방법 표시 후 승인 시 저장

## 맹점과 리스크

### A. 과신(Overtrust) 리스크
- 문제: 사용자가 AI를 "자동 실행 권한자"로 오해할 수 있다.
- 대응:
  - 모든 핵심 화면에 책임 경계 문구 고정
  - 고위험 조작은 반드시 사용자 확인

### B. 음성 인식 오동작
- 문제: 숫자/종목/파라미터를 잘못 인식할 가능성
- 대응:
  - 핵심 값은 음성 인식 후 텍스트 확인 단계 강제
  - 확정 전 최종 요약 읽기 + 취소 버튼 제공

### C. 브로커 정책/절차 변동
- 문제: OpenAPI 발급 절차가 자주 변한다.
- 대응:
  - 브로커별 절차 템플릿 버전 관리
  - 실패 시 최신 공식 링크/점검 절차 자동 제시

### D. 접근성 기능 자체가 복잡도 증가
- 문제: 초보 모드 추가가 코드 복잡도를 높일 수 있다.
- 대응:
  - 공통 오케스트레이션 레이어 도입
  - UI 스킨 분기 대신 텍스트/컴포넌트 속성 기반 모드 전환

### E. 보안/개인정보
- 문제: 키/계좌 정보를 음성이나 로그로 노출할 수 있다.
- 대응:
  - 마스킹 기본값, 민감정보 음성 읽기 금지
  - 로그 저장 전 redaction 필수

## 실제 구현 난이도 평가
- 기술적으로 구현 가능: 높음
- 운영적으로 중요한 난점: 사용자 신뢰/오해 방지, 브로커 절차 업데이트 유지
- 권장 판단: "가능"이며, 안전 가드를 전제로 단계적 도입이 적합

## 단계별 실행 계획 (기존 1,2,3 완료 후)

### Phase G1 (1주)
- `AI 실행` 버튼 POC
- 실행 계획 미리보기, 실패 원인 카드, 재시도 버튼
- 비파괴 작업 중심(조회/점검/요약)

### Phase G2 (1~2주)
- 접근성 모드 UI
- 음성 입력/출력 안정화
- 초보자 용어 레이어와 쉬운 문장 템플릿 적용

### Phase G3 (1~2주)
- AI 상담 설정 도우미
- OpenAPI 발급 가이드 플로우
- 설정 diff 승인/롤백 기능

### Phase G4 (지속)
- 회귀 테스트 자동화
- 장애/오인식 로그 분석
- 브로커별 가이드 최신화

## 수용 기준 (Definition of Done)
- 초보 사용자가 "AI 실행" 버튼으로 진단-실행-결과 이해를 3분 내 완료
- 음성 모드에서 핵심 5개 시나리오 성공률 95% 이상
- 고위험 설정 변경은 100% 승인 게이트를 통과해야만 반영
- 설정 오류로 인한 치명 장애(앱 멈춤/설정 파손) 0건

## 초기 연동 대상 파일
- `ui/dashboard_modern.py` (버튼/오케스트레이션 진입점)
- `ui/widgets/ai_assistant_widget.py` (AI 상담 흐름)
- `ui/widgets/ai_voice_module.py` (STT/TTS)
- `ui/settings_modern.py` (설정 diff/승인/저장)
- `config/settings.py` (검증/기본값/마이그레이션)

## 비목표(초기 범위 제외)
- 완전 자동 투자 실행
- 사용자가 모르는 상태의 실주문 허용 전환
- 법적/세무 집행 자동화
