# AI 커스텀 전략 아키텍처 및 사용자 흐름

기준 버전: NoahAI Client 3.9.0.2  
기준 일자: 2026-07-26

> 버전이 파일명에 고정되지 않는 현행 정본이다. 과거 v3.9.0.0 구현 기록은 `V3900_IMPLEMENTATION_RECORD_20260722.md`에서 확인한다.

> “NoahAI는 TradingView를 없애는 제품이 아니라, TradingView·영상·문서·Pine 전략을 AI가 이해하고 검증하여 시장국면에 맞게 안전하게 운용하는 상위 전략 운영 계층입니다.”

## 실사용 제품 원칙

- 외부 전략이 바뀌면 사용자가 자료를 다시 입력하고 기존 전략을 저장 대상으로 선택해 다음 버전을 만든다.
- 이전 버전은 덮어쓰지 않으며, XAI와 자동검증 결과를 본 사용자가 적용 버전을 결정한다.
- 사용자에게 보이는 검증은 현재의 `사용자 승인 → 자동검증 1회 → 최종 적용 또는 안전 시험` 흐름을 유지한다. 워크포워드·모의운용 같은 연구 검증을 필수 승인 단계로 연쇄 추가하지 않는다.
- 자동검증은 판단 자료이지 수익 보증이나 사용자의 결정을 대체하지 않는다.
- 적용된 전략도 실제 주문 직전에 NoahAI의 시장국면 판단, 수익성·리스크·주문 가드레일을 다시 통과한다.

## v3.9.0.2 초보자 안내·시장국면 추천·어시스턴트 안전 계약

- 화면 상단 `처음 사용법 AI에게 묻기`는 NoahAI 어시스턴트를 열고 입력 종류, 초보자 권장값, 분석·검토 순서를 현재 화면 맥락과 함께 질문한다.
- 분석 뒤 `이 결과 AI에게 묻기`는 전략명, 출처 종류, 추천 시장국면, 누락 조건을 어시스턴트에 전달해 사용자가 XAI 결과를 다시 설명받게 한다.
- 소스가 `상승장`, `하락장`, `횡보장`, `고변동`, `저변동`을 명시하면 해당 국면을 추천하고 선택값에 반영한다.
- `고변동에서는 진입하지 않는다`처럼 제외 문맥이 있으면 추천 범위에서 제외하고 XAI에 근거 문장을 표시한다.
- LONG/SHORT, RSI 같은 신호만으로 시장국면을 추정하지 않는다. 국면 근거가 없으면 `전체/사용자 확인`을 유지한다.
- AI 어시스턴트는 설정을 바로 덮어쓰지 않는다. 현재값과 변경안을 설명하고, 모호하면 재질문하며, 허용 목록의 설정만 적용 버튼과 최종 확인 뒤 저장한다. 과거 `ai_auto` 값이 남아 있어도 확인을 생략하지 않는다.
- 레버리지·잔고 활용·위험 성향·고변동장·합의 임계값·쿨다운처럼 위험을 높일 수 있는 변경은 현재 시장·거래 성과·포지션 상태가 부족하거나 손실 구간이면 대화 적용 단계에서 차단한다.
- 주문·거래 시작/정지·API 키 변경은 v3.9.0.2 대화 실행 범위가 아니다. 향후 거래 작업도 실시간 시장·계좌·포지션 확인, 위험 검증, 변경 미리보기, 강화 확인, 실행 결과 검증, 감사기록을 모두 통과해야 한다.

## v3.9.0.1 핵심 보강

- AI는 누락 조건을 추정하지 않고 필드별 질문과 입력 예시를 반환한다.
- 사용자는 `risk_per_trade_percent`, `max_margin_usage_percent`, `max_leverage`를 정한다. `max_leverage`는 목표 배수가 아니라 상한이다.
- 런타임은 `거래당 위험예산 ÷ 전략 손절거리`로 목표 노출을 구하고 증거금 한도·레버리지 상한 안에서 실제 레버리지와 포지션 비율을 계산한다.
- 시장국면이 전략 범위를 벗어나면 `delegate_to_noah` 또는 `pause`를 사용자 선택대로 적용한다.
- 시장·성과 기반 동적 조절은 사용자 전략의 `regime_parameters`/`performance_adjustments`에 명시된 값만 실행한다.
- 실행검증 뒤 개선안은 다음 버전 후보로만 제공하며 현재 버전을 자동 변경하지 않는다.

## 현재 제공 입력

| 입력 | 실제 처리 | 조건/한계 |
|---|---|---|
| 텍스트·메모 | 전략 조건 문장 추출 후 AI 구조화 | 누락 조건은 사용자 재확인 |
| Pine Script·`.pine` | `strategy.entry/exit`, 지표, 손절·익절·포지션 값을 추출 | TradingView 비공개 원문은 사용자가 내보내기/붙여넣기 |
| TradingView 공개 링크 | 제목·설명·공개 Pine 근거를 추출 | 로그인/구독으로 보호된 원문을 우회하지 않음 |
| PDF | `pypdf`로 앞 100쪽까지 텍스트 추출, AI에는 앞 60,000자 전달 | 100쪽 초과는 분할 입력, 스캔 PDF는 페이지 이미지/OCR 입력 권장 |
| 차트 이미지 | RapidOCR/PaddleOCR 텍스트와 비전 AI의 지표·선·영역·매매 마커 해석을 결합 | 비전 실패 시 OCR 폴백, 불명확한 값은 재확인 |
| 로컬 영상 | 대표 시점 최대 9개 프레임을 접촉 시트로 만들어 OCR+비전 AI 분석 | 로컬 영상 음성 자동 전사는 미포함, 설명 텍스트 병행 |
| YouTube 링크 | 한국어/영어 자막, 메타데이터, 대표 프레임 최대 9개의 OCR+비전 AI를 결합 | 무자막 전사는 설정에서 모델·길이·용량을 직접 선택하며 자막·스트림·로그인 제한 시 일부 근거가 빠질 수 있음 |

사용자는 본인이 이용 권한을 가진 자료만 입력해야 한다. 회원 동의는 NoahAI 내부 처리의 근거이며, 외부 서비스의 접근통제나 저작권 제한을 우회하는 권한을 만들지는 않는다.

## 처리 흐름

1. 설정 `OpenAI API`에서 안전 기본값 OFF인 `AI 커스텀 전략을 실제 자동매매 엔진에서 사용`을 사용자가 내용을 이해한 뒤 켜고 저장한다.
2. 대시보드 `🧠 AI 커스텀`에서 입력 형식을 선택한다. 처음이라면 `처음 사용법 AI에게 묻기`로 현재 화면 기준 설명을 요청한다.
3. 파일/링크를 넣거나 텍스트·Pine Script를 붙여 넣고 `AI 분석 및 전략 초안 만들기`를 누른다.
4. 추출기가 출처 근거를 모으고 AI가 아래 필드로 구조화한다.
   - 진입, 청산, 손절, 익절, 포지션 크기, 시장 조건
   - 거래당 허용손실, 최대 증거금 사용률, 레버리지 상한
   - TP/SL, 포지션 비율, 신호 임계값 등 실행 엔진 설정
5. XAI 화면에서 근거, 추천·제외 시장국면, 변경값, 누락 조건, 위험을 확인한다. 이해되지 않으면 `이 결과 AI에게 묻기`로 현재 결과를 다시 설명받는다.
6. `검토 및 전략 버전 저장`으로 계정별 프라이빗 저장소에 보관한다. 이 단계는 검토 이력 저장이며 자동검증 통과나 활성화를 뜻하지 않는다.
7. 사용자 승인 후 거래소 15분봉 자동 재생으로 조건·수수료·PnL·MDD를 검증한다. 숫자 수기 입력은 허용하지 않는다.
8. 실행 검증 통과 전략은 `최종 적용`으로 일반 운용한다.
9. 실행 검증 미통과 전략은 사용자가 위험을 이해하고 설정에서 허용한 경우에만 `1% 제한운용`을 선택할 수 있다. 이때 레버리지 1배·전략 포지션 비중 최대 1%를 강제한다.
10. 적용 후 해당 거래소/증권사의 시작 버튼을 누르면 전략이 주문 직전에 평가된다. 최대손실, 포지션 수, 집중도, 시장위험 가드레일은 항상 우선한다.
11. 대상 시장국면이 끝나면 사용자가 고른 대로 기본 NoahAI에 위임하거나 커스텀 신규 진입만 일시정지한다.

전략 원본이 변경되면 3번부터 다시 진행하고 6번에서 기존 전략을 저장 대상으로 고른다. 별도의 외부 전략 동기화 기능이 없어도 새 버전으로 즉시 재분석할 수 있다.

## 한 줄 정의와 역할 경계

AI 커스텀은 단순 프롬프트가 아니라 사용자의 투자 지식을 실행 가능한 전략 규칙으로 변환하고 검증·승인·운용까지 연결하는 전략 생성 계층이다.

- AI 커스텀: 소스 수집, 전략 생성·정리, 버전·범위·국면·우선순위 관리
- 기존 NoahAI: 실시간 시장 분석, 전략 비교, 실행 승인·보류와 주문 실행
- 공통 가드레일: 레버리지, 손실한도, 포지션, 집중도, 시장위험을 최상위에서 강제
- 디지털케어로그: 선택·HOLD·차단·체결·비용·PnL 근거를 복기 가능한 기록으로 축적

따라서 사용자 전략은 실제 자동매매에 사용된다. 다만 임의 코드 자체를 실행하는 것이 아니라 허용된 선언형 규칙과 정규화된 setting으로 변환되어 기존 엔진에 안전하게 증설된다.

## 적용 범위와 다중 전략 풀

사용자는 저장 전에 적용 범위를 선택한다.

- 개별 코인 거래소: Binance, Bybit, OKX, Bitget, Upbit, Bithumb
- 모든 블록체인: 코인 전략 논리는 공유하지만 성과·PnL·임계값은 거래소별 분리
- 개별 증권사: 키움, 신한, 미래에셋, 한국투자증권
- 모든 주식/ETF
- 모든 자산: 코인·주식 공통으로 해석 가능한 선언형 필드만 사용

활성 전략 풀은 우선순위순 최대 10개다. 각 전략에는 `target_scope`, `market_regimes`, `priority`, `signal_mode`, `entry_signal`이 저장된다. 숫자 10이 가장 먼저 평가된다. 화면의 `기본 AI와 함께 사용 (권장)`은 내부 `confirm`으로 기존 AI LONG/SHORT를 확인·필터한다. `내 전략이 진입 신호 생성 (고급)`은 내부 `independent`로 명시된 LONG/SHORT 규칙이 진입 후보를 만든다. 고급 항목을 선택했을 때만 진입 방향 UI가 나타난다. 어느 방식이든 기존 전략 엔진과 수익성·리스크·주문 가드레일을 다시 통과한다. 여러 전략의 TP/SL이나 포지션 값을 임의 평균내지 않는다.

전략별 버전은 최대 10개를 보관한다. 따라서 “활성 전략 최대 10개”와 “각 전략 버전 최대 10개”는 서로 다른 제한이다.

## 대시보드 실제 조작 순서

1. `🧠 AI 커스텀` → 입력 형식과 자료를 선택한다.
2. `적용 범위`, `시장상황`, `우선순위`, `전략 역할`을 선택한다. 초보자는 권장값을 유지하며 고급 역할을 선택한 경우에만 진입 방향을 고른다.
3. `AI 분석 및 전략 초안 만들기`를 누른다.
4. XAI의 원문 근거, 규칙, 엔진 설정, 누락 조건을 검토한다.
5. `검토 및 전략 버전 저장`을 누른다. 필수 조건이 빠졌으면 `조건 재확인 필요` 검토 버전으로 저장되며 승인할 수 없다.
6. 버전 행의 `내용 확인 후 승인`을 누른다.
7. `자동 검증 실행`으로 실제 거래소 15분봉 500개를 재생한다.
8. 통과한 버전은 `최종 적용`, 미통과 버전은 위험을 이해하고 최소단위로 시험할 때만 `1% 제한운용`을 누른다.
9. 해당 거래소/증권사 `시작`을 누른다. 별도의 전략 시작 버튼은 없으며 활성 전략 풀이 거래 루프에 자동 연결된다.
10. 거래소 제어 카드와 로그에서 전략명·실행 방식·일반/제한운용·우선순위·현재 국면과 차단 사유를 확인한다.
11. 사용을 중단하려면 활성 버전의 `적용 해제`를 누르거나 설정의 AI 커스텀 런타임 스위치를 OFF로 저장한다.

텍스트는 링크/파일 입력줄 아래의 `전략 설명 / Pine Script 직접 입력` 칸에 작성한다. 화면 상단 `사용 AI`에는 실제 선택 모델 또는 API 미설정 상태가 표시된다. 구조화 모델은 `설정 → OpenAI API → 정밀 진단·최적화(고성능 모델)`, 무자막 전사는 같은 탭의 전사 설정에서 지정한다. 전사 모델은 영상 길이에 따라 자동 변경되지 않는다.

## 실행 규칙 변환

`trading/strategy_source_ingestor.py`는 입력을 `rules`, `rules.executable_entry`, 선택적 `rules.executable_exit`, `engine_settings`로 변환한다. `trading/declarative_strategy_engine.py`는 허용된 지표 필드와 비교연산만 평가하고 임의 코드 실행을 금지한다. 미지원 필드·연산자는 저장 단계에서 `unsupported_executable_conditions`로 승인 전 차단한다. `strategy_customizer.py`는 승인·실행검증된 조건과 설정만 Trader/UnifiedTrader/Analyzer에 전달한다. Trader/UnifiedTrader는 일반 전략엔진과 주문 직전에 커스텀 진입 게이트를 함께 통과시키고, 코인 포지션은 진입 당시 선택된 버전의 명시 청산 규칙을 실시간 모니터까지 보존한다. 자연어만 있고 실행 조건/엔진 설정이 없으면 활성화를 거부한다.

지원 선언형 필드는 다음과 같다.

- 가격·시간: `open`, `high`, `low`, `close`, `current_price`, `price`, UTC `hour`, `weekday`
- 추세: `ma20/50/200`, `sma20/50/200`, `ema20/50/200`, `adx`, `trend_strength`
- 모멘텀·변동성: `rsi`, `macd`, `macd_signal`, `macd_histogram`, `bb_position`, `bb_width`, `atr`, `atr_percent`, `market_volatility`
- 거래량·신호: `volume`, `volume_sma20`, `volume_ratio`, `signal`, `confidence`
- 비교: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`, `not_in`, `gt_field`, `lt_field`, `crosses_above`, `crosses_below`
- Pine `ta.crossover`/`ta.crossunder`는 단순 현재값 대소 비교가 아니라 직전 캔들과 현재 캔들을 함께 확인한다.

안전 범위와 사용자 통제는 다음처럼 적용한다.

- 일반 운용 레버리지: 전략 위험예산·손절거리에서 거래별 계산, 사용자 상한 1~10배
- 포지션 비율: 1~50%
- 자동검증 미통과 제한운용: 레버리지 1배·포지션 비율 최대 1%
- 저장/XAI의 TP 2.0·SL 1.0은 주문 직전 각각 fraction 0.02·0.01로 단일 변환
- 신호 임계값: 0~1
- 출금·외부송금 지시: 거부
- 전략 버전: 전략별 최대 10개

전략의 setting 값이 바뀌는 것은 전략 적용의 한 부분이다. 진입/청산 논리와 적용 시장조건도 함께 보존되어야 하며, 단순히 TP/SL만 바꾼 것을 완전한 신규 전략으로 오인하지 않는다.

## 위험기반 레버리지 계산

계좌 대비 거래당 위험예산을 `R`, 손절거리 fraction을 `S`, 최대 증거금 비율을 `M`이라 하면 목표 총 노출은 `min(max_notional, R / S)`다. 필요한 레버리지는 `ceil(목표 총 노출 / M)`이며 사용자 `max_leverage`를 넘지 않는다. 실제 포지션은 상한을 적용한 레버리지에 맞춰 다시 줄인다.

예: `R=0.5%`, `S=1%`, `M=10%`, `max_leverage=5`이면 목표 노출은 50%, 실제 레버리지는 5배, 증거금 사용은 10%다. 이는 5배를 언제나 쓰겠다는 뜻이 아니다. 손절거리·변동성·위험예산이 달라지면 매 거래 계산값도 달라진다.

## 실행 검증과 PnL 학습

대시보드의 현재 자동 검증은 `historical_replay`다. 저장 자체에는 통과/미통과 판정이 없다. 필수 조건이 채워진 `XAI 완료 · 승인 대기` 버전을 사용자가 승인하면 `자동 검증 실행` 버튼이 나타난다. 코인은 대상 거래소의 15분봉 500개, 주식/ETF는 활성 증권사의 가격 이력 최대 500개를 조회한다. 겹치지 않는 단일 포지션 방식으로 선언형 진입·명시 청산·TP/SL을 재생하며, 같은 봉에서 TP와 SL이 함께 닿으면 보수적으로 SL을 먼저 적용한다.

비용은 진입·청산 양쪽 수수료, 양방향 슬리피지, 왕복 스프레드를 각각 기록한다. 기본 가정은 한쪽 수수료 0.10%, 한쪽 슬리피지 2bp, 왕복 스프레드 1bp이며 `ai_custom_validation_costs`와 거래소별 override로 바꿀 수 있다. 결과에는 비용 전/후 PnL, 총비용, Profit Factor, 거래당 기대값, MDD, 자산·낙폭 곡선, 거래목록, 상승·하락·횡보·고변동 결과가 포함된다. 펀딩비·시장충격·부분체결은 아직 모델링하지 않으므로 실제 체결을 보장하지 않는다.

가격 이력 80개 미만, 전략 지표의 워밍업 표본 부족, 미지원 조건 또는 미지원 증권사 어댑터는 통과시키지 않는다. 조건 일치 3회 이상, 총비용 반영 순PnL 양수, MDD 10% 이하를 모두 만족해야 `자동검증 통과`가 되며 하나라도 실패하면 `자동검증 미통과`가 된다. 이는 실행 가능성 보조 검증이지 판매·수익 보장 근거가 아니다.

## 신규 사용자·데이터 부족

데이터가 없다고 영구 HOLD하지 않는다.

1. 거래소별 현재가·캔들·심볼 호환성을 먼저 확인한다.
2. 분석 데이터가 없으면 주문하지 않고 수집 원인을 표시한다.
3. 분석 데이터는 있지만 종료 거래가 기준 미만이면 `limited_live_learning` 단계로 전환한다.
4. 최대 포지션 1개, 최대 레버리지 1배, 초기 위험배수 0.10으로 시작한다.
5. 종료 거래가 쌓일수록 위험배수를 최대 0.50까지 점진적으로 올린다.
6. 최소 표본 도달 후 승률, 순PnL, 샤프, MDD, 기대값, 워크포워드와 실행품질을 거래소별로 재평가한다.

거래소별 신호 임계값은 `analyzer_settings.exchange_signal_thresholds`에 저장된다. OKX의 PnL 학습이 Bybit/Bitget/Binance 임계값을 덮어쓰지 않는다.

## AI 모델 역할과 비용

설정은 API의 `/v1/models` 목록을 조회해 사용자 계정에서 실제 사용 가능한 텍스트 모델을 갱신한다. 기본 선택 목록은 GPT-5.6 Sol/Terra/Luna를 포함한다.

- `AI 애널리스트 모델` (`openai_model` 호환 키): 시장 분석과 신호 후보의 기본 모델
- `AI 어시스턴트 모델` (`assistant_ai_model`): 사용자 대화·질의응답·설명의 기본 모델
- `작업별 모델 배치` (`ai_model_roles`): 빈번 신호, 손익/리포트, 정밀 진단처럼 역할이 명확한 호출만 다른 모델로 보내는 선택형 override

세 설정은 화면상 겹쳐 보일 수 있지만 호출 목적이 다르다. 작업별 값이 없는 분석 호출은 AI 애널리스트 모델로 돌아가며, 비용 정책상 같은 모델을 여러 역할에 지정해도 정상이다.

- 빈번 호출: GPT-4o mini 또는 GPT-5.6 Luna
- 표준 분석: GPT-5.6 Luna/Terra
- 복잡한 전략 추출·정밀 진단: GPT-5.6 Terra/Sol

AI 커스텀은 역할별 배치 중 `premium` 모델을 우선 사용하고, 값이 없으면 AI 애널리스트 모델을 사용한다. API 키가 없으면 Pine/RSI/EMA/TP/SL 등을 규칙 기반으로 1차 추출할 수 있지만 문서·영상의 의도 및 시각적 차트 구조 해석은 제한된다.

## 현재 정확도 경계

- 영상 전체를 프레임 단위로 연속 시청하는 방식이 아니라 최대 9개 대표 장면과 자막을 결합한다.
- 자막이 없고 중요한 조건이 대표 장면 사이에만 나오면 누락될 수 있으므로 해당 장면 스크린샷이나 조건 텍스트를 함께 넣는다.
- TradingView 보호 스크립트는 접근통제를 우회하지 않는다. 사용자가 볼 권한이 있는 Pine 원문을 붙여 넣어야 정확한 AND/OR 규칙과 setting을 만들 수 있다.
- 차트 전략은 위 선언형 허용 필드만 실행한다. 임의 Python/Pine 코드는 실행하지 않으며 미지원 조건을 조용히 버리지 않는다.
- 코인 명시 청산은 Binance와 UnifiedTrader 포지션 모니터에 연결된다. 주식/ETF는 현재 선언형 진입·신호 임계값까지만 공통 지원하며 증권사별 명시 청산은 후속 운영검증 범위다.
- 코인 경로는 선택 전략의 레버리지·TP/SL·포지션 비율·신호 임계값을 주문 파라미터에 반영한다. 주식/ETF는 현재 선언형 진입조건과 신호 임계값을 실행 게이트로 사용하며 코인 선물 설정을 그대로 혼합하지 않는다.

## AI 어시스턴트 작업 실행 계약

대화형 변경은 생성형 답변과 실제 작업 실행을 분리한다. 어시스턴트가 사용자의 문장을 이해했다고 해서 곧바로 거래나 설정 변경 권한을 얻는 것은 아니다.

1. 현재 설정과 필요한 경우 시장·계좌·잔고·포지션·열린 주문을 새로 조회한다.
2. 의도를 `설명`, `진단`, `설정 변경`, `거래 작업`으로 분류하고 대상이나 범위가 모호하면 재질문한다.
3. 정책·권한·손실 가능성·시장 상태·가드레일 영향을 평가한다.
4. 현재값과 변경값, 기대효과, 위험, 되돌리는 방법을 미리 보여준다.
5. 설정은 사용자 확인, 거래 작업은 더 강한 별도 확인을 받아야 한다.
6. 자유형 Python이나 LLM 생성 코드를 실행하지 않고 타입이 정해진 허용 작업만 호출한다.
7. 외부 API 응답뿐 아니라 실제 설정 재조회, 주문 상태, 체결·잔고 상태를 검증한다.
8. 요청·판단 근거·확인·실행 결과를 감사로그로 남기고 가능한 작업은 롤백을 제공한다.

v3.9.0.2는 이 계약 중 설명·재질문·일부 허용 설정의 제안/2단계 확인/저장을 제공한다. 위험 확대형 변경에는 현재 시장·성과·포지션 데이터의 결정적 차단 규칙을 적용한다. 모든 설정, 거래 시작·정지, 주문 실행까지의 일반화된 작업 레지스트리와 실거래 E2E는 후속 검증 범위다.

## v3.9.0+ 영상 전체 맥락·브라우저 연결 설계

현재 기능은 클라이언트 `AI 커스텀`에 URL을 입력하는 독립형 수집 방식이므로 내장 브라우저가 없어도 동작한다. 다음 고도화는 완전한 브라우저 내장보다 아래 순서를 우선한다.

1. 자막 타임스탬프 보존, 장면/차트 변화 기반 적응형 프레임 추출, 선택형 음성 전사로 URL 분석 정확도를 높인다.
2. Chrome/Edge 확장 또는 로컬 브리지를 선택 기능으로 제공해 사용자가 현재 보고 있는 탭을 `NoahAI로 분석`에 명시적으로 전달할 수 있게 한다.
3. 내장 WebView는 확장 설치가 불가능한 환경의 미리보기·현재 장면 캡처 용도로만 후순위 검토한다.

브라우저 브리지는 현재 탭의 URL과 사용자가 선택한 자막/화면 근거만 전달한다. 브라우저 기록·쿠키·비밀번호·인증 토큰을 수집하지 않으며 보호 콘텐츠의 접근통제를 우회하지 않는다. 분석 결과는 타임코드 근거와 함께 규칙 후보로 생성하고 기존 누락 재확인, XAI, 승인, 실행 검증, 가드레일 상태머신을 그대로 통과해야 한다. 상세 단계와 완료 기준은 `docs/UPDATE_PLAN.md`의 `YouTube 전체 맥락 분석·브라우저 연결 고도화 계획`을 정본으로 사용한다.

균형형 프리셋은 빈번 호출에 저비용 모델, 표준 분석에 Luna, 복잡한 작업에 Terra를 사용한다. 모델 가용성과 비용은 계정/시점에 따라 달라지므로 설정의 `사용 가능 모델 새로고침`으로 확인한다.
