## Windows에서 실행

동기화 폴더의 변경 내용이 정확한 Git 커밋에 포함됐는지 먼저 확인한다. 이 Mac 인계 폴더에는 Git 메타데이터가 없으므로 SOURCE_IDENTITY의 `commit: null`을 실제 Windows 커밋으로 간주하지 않는다. 기존 Windows 빌드 가이드의 Python·Node·x86 호스트 환경을 사용한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

검사 생략 없이 성공한 새 `deploy\web-release\NoahAI-3.9.2.11-Setup.exe`와 `deploy\release-manifest.json`을 확인한다. 이전 .10 설치기를 이름만 바꿔 전달하지 않는다. `Get-FileHash`로 SHA-256을 기록하고 기본 설치·기동을 확인한다. 필요하면 이 설치기를 먼저 테스터에게 전달해 검증을 시작할 수 있다.

```powershell
Get-FileHash .\deploy\web-release\NoahAI-3.9.2.11-Setup.exe -Algorithm SHA256
powershell -ExecutionPolicy Bypass -File .\scripts\release_windows.ps1
```

`release_windows.ps1`는 GitHub stable/latest 공개 게시다. 정확한 커밋·원격 ref·깨끗한 릴리즈 작업 폴더·기존 빌드 증거·같은 버전 자산과 원격 digest 검증을 따른다. `build_and_release_windows.ps1`는 빌드 후 게시까지 실행하는 명령이므로 설치기 생성만 필요할 때는 위 분리 명령을 쓴다. 태그를 이미 게시했다면 같은 버전 자산을 임의로 교체하지 않는다.

## 테스터에게 전달할 항목

- 설치기, 버전·SHA-256, 변경 요약, 기존 기록 보존·문제 발생 시 진단 복사 방법.
- PAPER부터 실행. 정상 HOLD·신뢰도 부족·목록/시세 장애·자금 대조 차단을 구분하고 메인 거래 현황과 해당 기관 운용 요약의 수치·기준·다음 조치를 확인.
- 과거 PAPER 기록은 삭제하지 않는다. 새 평가 준비는 엔진 정지·포지션/미결 주문 확인·사용자 확인을 거치는 기존 경로를 사용.
- 앱 종료·절전 시간은 정상 운용 시간에 합산하지 않는다. 실제 주문이 없어도 평가가 최신이고 보류 이유를 설명할 수 있는지 검사한다. 거래 횟수만으로 합격을 판단하지 않는다.

|테스터/설치 SHA|기관/모드|시작·종료 UTC/실행 시간|최신 후보 평가·사유/수치|장애·재시도·복구|다음 조치/결과|
|---|---|---|---|---|---|
|기록|기록|기록|기록|기록|기록|

API 키·계좌번호·잔고·원본 비밀 로그를 공개 보고서에 넣지 않는다. 실제 LIVE·OCX·마이크 검증은 해당 환경과 허가가 있는 담당자가 별도로 기록한다.

소스 환경을 가진 테스터는 다음 프로세스 감시를 보조 자료로 쓸 수 있다. `<엔진PID>`를 실행 중인 NoahAIEngine PID로 바꾼다.

```powershell
python .\scripts\runtime_soak_monitor.py --pid <엔진PID> --duration-min 1440 --interval-sec 60 --out .\data\reports\v39211-paper-24h.json
```

72시간은 `--duration-min 4320`을 사용한다. 이 기본 명령은 프로세스 자원 감시이며 PAPER 실행·보류 설명의 성공을 증명하지 않는다. 실제 gateway 점검을 추가하려면 실행 환경의 gateway URL과 토큰 환경변수를 안전하게 설정한 뒤 `--require-paper --sources <실제_실행_기관>`을 사용한다. gateway 없이 `--require-paper`를 쓰면 실패한다. 설치본만 받은 테스터에게 Python 준비를 필수로 요구하지 않으며 화면·지원 진단으로 결과를 기록할 수 있다.

## 문서·사이트 버전 전환

Windows .11 게시가 확인되기 전 공개 웹의 현재 배포판은 .10, 개발 후보는 .11이다. .11 게시 후 동일 manifest·설치기·태그를 확인하고 회사·정보·제품 사이트의 현재 버전을 함께 갱신한다. 클라이언트 릴리즈는 별도 서버의 웹 콘텐츠를 자동 배포하지 않는다. 사이트 정합성 패치는 별도 검토 경로로 전달한다.

현재 검증: [자산관리 추가 수정 후 소스 지문·검사](../reports/v39211-wealth-audit-20261011/validation.json). 배포 정책 정정: [기존 기록](../reports/v39211-tester-handoff-20261011/validation.json). 이전 로컬 회귀: [5,752 Python·73 Node 및 UI 증거](../reports/v39211-release-review-20261011/validation.json). 이번 문서 정정은 매매 엔진·진입 기준·게시 스크립트를 변경하지 않는다.
