# Teayu 거래소·통화 장애 분석과 v3.9.0.6 조치

> 기준일: 2026-08-03  
> 증거 폴더: `data/260802_Teayu`  
> 대상: Binance, Upbit, Bithumb, Bybit, OKX, Bitget

## 결론

거래가 적은 주된 이유를 단순한 “거래소별 학습 임계점 차이”로 설명할 수 없습니다. 사용자 데이터에는 6개 거래소 학습 자료가 모두 충분히 쌓였지만, 공통 거래 이력 조회가 KRW 현물과 CCXT 파생상품 심볼을 잘못 변환했습니다. 여기에 학습 데이터가 늘면 완료 거래 최소값이 3~5건으로 상승하는 정책이 결합되어, 완료 거래가 없는 종목이 첫 완료 거래를 만들 수 없는 순환 차단이 발생했습니다.

## 사용자 데이터에서 확인한 사실

- 학습 저장 건수: Binance 10,000, Upbit 6,000, Bithumb 6,000, Bybit 10,000, OKX 10,000, Bitget 10,000
- 청산 성과 원장: Binance 259건, Bithumb 1건, Upbit·Bybit·OKX·Bitget 0건
- Bithumb 실제 사례: `H/KRW` PnL `112.0228 KRW`, Fee `3.12105376 KRW`
- 같은 주간의 USDT 거래 PnL과 KRW 거래 PnL을 더해 `124.33 USDT`로 표시한 오류를 재현
- Binance 실제 체결 원장 200건은 200개 고유 키이며 중복 행이 아님. 다만 구형 Binance 전용 가져오기가 같은 개별 fill을 `reason=binance_import` 청산 성과로 다시 저장했습니다. 사용자 DB 전체에 4,800건, 최근 7일에 200건이 존재해 거래 수·승률·PnL 분모를 오염시켰습니다.
- 안정성 로그에는 clean shutdown 39회, 이전 비정상 종료 감지 17회, 비치명 예외 255회, fatal 예외 0회가 기록됨. 일부 비정상 종료 표시는 수 밀리초 간격의 서로 다른 PID 동시 실행으로 생긴 오탐

## 코드 원인

1. `symbol.replace('USDT', '')`가 `AVAX/USDT:USDT`를 손상시키고 `H/KRW`는 KRW인 채 다음 단계로 전달했습니다.
2. 거래 조회는 다시 `{coin}%USDT%`만 검색해 KRW 거래와 손상된 파생상품 심볼을 찾지 못했습니다.
3. 완료 거래가 0건인데 학습 자료가 많으면 `min_trades_history=3`이 되어, 거래하려면 기존 거래가 먼저 필요한 모순이 생겼습니다.
4. 무이력 기본값 `win_rate=0`, `loss_rate=0`을 실제 성과처럼 평가해 낮은 승률 감점과 낮은 손실률 가점을 동시에 적용했습니다.
5. AI 리포트와 챔피언–챌린저가 결제통화를 보존하지 않고 PnL·Fee를 단일 USDT 숫자로 합산했습니다.
6. Binance 가져오기가 공통 실제 체결 원장 저장 후 같은 fill을 완료 전략 거래인 `trade_log`에 한 번 더 기록했습니다.
7. 수익성 검증이 분석 주기마다 `force=True`로 거래소 최근 체결 최대 200건을 호출해 거래소별 30초 제한을 우회했습니다. 사용자 설정의 10초 분석 주기와 결합하면 거래소당 하루 최대 8,640회까지 개인 체결 조회가 가능했습니다.
8. 완료 거래 성과와 실제 체결 복구가 하나의 API 응답 목록을 공유해, 로컬에 이미 있는 성과 판단에도 계정 API가 필요했습니다.

## v3.9.0.6 수정

- `Recorder.get_recent_trades(symbol=...)` 정확 일치 조회 추가. 심볼이 없을 때만 거래소 전체를 조회하며 KRW도 포함
- UnifiedTrader의 진입 전 패턴, 성과 스냅샷, 최근 MDD가 거래소 원본 심볼 사용
- 완료 거래가 없으면 완료 거래 최소값 0 유지. 완료 이력이 있으면 요구값이 관찰된 완료 거래 수를 초과하지 않음
- 무이력은 “0% 저성과”나 진입 차단이 아니라 “완료 거래 없음·제한 학습 허용”으로 처리
- 시장 변동성이 커도 완료 이력 건수를 신규 심볼의 선행조건으로 만들지 않고 AI 신뢰도 기준을 강화
- 오늘·주간·월간·실시간 리포트와 챔피언–챌린저의 PnL·Fee를 결제통화별 분리
- Binance 가져오기는 API 조회 수·체결원장 신규 수·청산 성과 신규 수를 별도 표시
- Binance 개별 fill의 `trade_log` 신규 편입 중단. 기존 4,800행은 사용자 감사 이력으로 보존하되 성과·학습·리포트·챔피언–챌린저에서 제외
- 실행 중인 다른 PID는 `parallel_runtime_session_detected`로 기록하고 비정상 종료 통계에서 제외
- 수익성 검증은 로컬 `trade_log` 완료 거래를 우선하고, 없을 때만 로컬 `exchange_execution_log` 확정 체결을 보조 사용
- LIVE 체결 이력은 기본 5분 간격으로 마지막 체결 시각/ID 이후만 증분 조회. 전체 최근 이력은 시작·수동 가져오기·저빈도 복구에 한정
- 신규 NoahAI 주문은 계정 전체 체결목록 대신 로컬 주문 ID를 기본 10초 간격으로 최종 상태까지 확인
- PAPER·LEARNING은 미확정 실주문이 없으면 개인 체결 API를 호출하지 않음
- 인증 사용자 체결 스트림 어댑터가 존재하면 스트림을 우선하고 정상 상태에서는 주기 REST 이력 조회를 생략. 현재 공개 시세 WebSocket은 개인 체결 스트림으로 간주하지 않음
- 실제 체결 원장의 `realized_pnl`·로컬 최근 체결·증분 커서를 기존 행 삭제 없이 보강

이번 소스 수정은 거래가 반드시 발생한다는 보장이 아닙니다. 신호, 시장 적합성, 주문 최소규격, API 권한, 잔고, LIVE 권한은 계속 충족해야 합니다. 실제 거래소 작동 완료 판정은 새 Windows 빌드에서 거래소별 최소 주문과 장시간 E2E를 통과한 뒤 갱신합니다.
