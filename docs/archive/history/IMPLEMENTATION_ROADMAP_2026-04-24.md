## 현재 상태 정리 (솔직한 평가)

| 기능 | 현재 상태 | 사용자 입장에서의 경험 | 문제점 |
|------|---------|-----------------|------|
| **암호화폐 거래** | ✅ 운영 중 | "시작" 클릭 → 실제 거래 체결 | 없음 (정상) |
| **주식 검색/분석** | ✅ 기본 제공 | 종목코드 입력 → 분석 카드 표시 | 자동주문 아님 |
| **주식 거래** | 🚧 부분 | 연결/조회/분석 중심, 일부 실어댑터 존재 | 자동 실행 완성도 부족 |
| **ETF 거래** | 🚧 부분 | ETF 여부 판별 + NAV/추적오차 분석 | 사용자 전용 실행 모드 없음 |
| **주식 vs ETF 분리** | ❌ 미완료 | 단일 증권 서비스 안에서 함께 운영 | 사용자 선택권 부족 |
| **차액거래** | ❌ 안 됨 | 여러 거래소 가격 비교 불가 | 기능 자체 부재 |
| **AI 학습 강화** | 🚧 부분 | 과거 거래에서 학습하지만 실시간 강화 약함 | 지속적 개선 필요 |

#### 개발 계획 (단계별)

**Phase 1: 알고리즘 분리 구조 설계 (v3.9 이전, ~1주)**
```
파일: trading/evaluator.py

현재 (통합):
  def select_coins(candidates):
      for coin in candidates:
          score = calculate_technical_score(coin)  # RSI, MACD만
          select if score > threshold

변경 (분리):
  def select_stocks(candidates):
      for stock in candidates:
          # 주식 전용: 기술분석 + 펀더멘털
          technical_score = calculate_technical_score(stock)
          fundamental_score = calculate_fundamental_score(stock)
              # PER, PBR, ROE, 배당률 분석
          total_score = 0.6*technical + 0.4*fundamental
          select if total_score > threshold

  def select_etfs(candidates):
      for etf in candidates:
          # ETF 전용: 추적오차 + 비용 효율성
          tracking_error = calculate_tracking_error(etf)
          expense_ratio = get_expense_ratio(etf)
          nav_divergence = get_nav_divergence(etf)
          
          # 추적오차 낮은 순, 수수료 낮은 순으로 정렬
          score = 100 * (1 - tracking_error) * (1 - expense_ratio)
          select if score > threshold AND nav_divergence < 2%
```

### 3️⃣ 차액거래 (Arbitrage) 구현 (현재: ❌ 없음 → 목표: 자동화)

#### 사용자가 원하는 플로우
```
사용자:
"BTC가 바이낸스에서 $42,000인데 바이비트에서 $42,500이네.
 수수료를 빼도 $300 이익이잖아. 이걸 자동으로 해줄 수 있나?"

현재:
- "여러 거래소에서 거래 가능합니다" (설명)
- 하지만 각 거래소에서 "독립적으로" 거래만 가능
- 가격 비교는 사용자가 직접 해야 함
- 자동 거래 불가능

원하는 상황:
1. NoahAI가 실시간으로 6개 거래소 가격 모니터링
2. "차익이 있다"고 감지 (수수료 포함)
3. 자동으로 A 거래소에서 "매수" + B 거래소에서 "매도"
4. 이익 확정 및 기록
```

#### 개발 계획 (단계별)

**Phase 1: 가격 모니터링 시스템 (v3.9 이전, ~2주)**
```

기능:
- 6개 거래소 BTC 가격을 1분마다 수집
- 가격 차이 계산 (수수료 포함)
- 차익 기회 감지 시 로깅

예시:
시간        바이낸스    바이비트    OKX        차익(최고)  수익성
10:00      42,000     42,300      42,200     $250       차익 없음 (수수료 > 차익)
10:01      42,000     42,500      42,100     $400       ✅ 거래 가능 (+$200 순이익)
10:02      42,100     42,400      42,050     $300       ✅ 거래 가능 (+$100 순이익)
```

**Phase 2: 차액거래 엔진 (v3.9 이전, ~2주)**
```
파일: trading/arbitrage_executor.py (신규)

로직:
1. 차익 감지
   if (price_B - price_A) - (fee_B + fee_A) > MIN_PROFIT:
       trigger_arbitrage(A, B)

2. 동시 주문 실행
   # 1단계: A 거래소에서 매수
   order_A = exchange_A.buy(symbol='BTC', amount=amount)
   
   # 2단계: B 거래소에서 매도 (A가 체결될 때까지 대기)
   while order_A not filled:
       wait(1 second)
   
   order_B = exchange_B.sell(symbol='BTC', amount=amount)
   
   # 3단계: 결과 기록
   profit = (price_B - price_A) - fee_A - fee_B
   recorder.log_arbitrage(A, B, amount, profit)

3. 리스크 관리
   - 최대 거래액 제한 (사용자 설정)
   - 최소 수익 기준 (사용자 설정)
   - 동시 주문 실패 시 자동 롤백
```

- 차익거래는 "극소수만 성공" (경쟁이 심함)
- 설정한 수익 기준에 도달하는 기회는 드뭄
- 최소 수익을 낮출수록 기회 많아지지만 수익 감소
```

### 4️⃣ AI 학습/강화 고도화 (현재: 부분 → 목표: 완전 자동 진화)

#### 현재 상태
```

- 과거 거래 분석 (이미 했던 거래 검토)
- AI 어시스턴트가 사용자 의견 수집
- 신호 정확도 계산

❌ 부족한 것:
- 자동 강화 (사용자가 명시하지 않으면 학습 X)
- 실시간 피드백 (사람 개입 필요)
- 새로운 지표 자동 학습 (고정된 지표만 사용)
```

#### 개발 계획 (단계별)

**Phase 1: 자동 강화 루프 (v3.9 이전, ~2주)**
```

현재:
1. 신호 생성

5. 사용자가 답함
6. 학습 (사람 개입)

2. 사용자 거래 → 기록
3. 거래 완료 → 자동 분석
4. ✅ 신호가 맞았나? (수익/손실로 자동 판단)
5. ✅ 다음 신호에 반영
6. ✅ 학습 (자동)

로직:
if profit > 0:
    increase_signal_weight(correct_signal)

## ⚠️ 각 기능의 "실제 거래 품질 보증" 방법

### 주식 거래
```
테스트:
1. Mock → 실제 전환 시 동일한 신호 생성 (100% 일치)
2. 실제 거래 10회 → 모두 정상 체결 (성공률 90% 이상)
3. 기록 검증: 거래 기록 = 증권사 기록 (100% 일치)
4. 수익/손실 계산 검증: NoahAI = 증권사 (소수점 2자리까지 일치)

위험 관리:
- 1거래당 최대 손실 한도 설정 (예: -3%)
- 일일 최대 손실 한도 (예: -5%)
- 거래 중단 트리거 (손실 한도 도달 시 자동 중지)
```

### 차액거래
```
테스트:
1. 가격 모니터링 정확도 (99% 이상)
2. 수수료 포함 수익성 계산 (100% 정확)
3. 동시 주문 체결 성공률 (95% 이상)
4. 손실 방지 메커니즘 (롤백 성공률 100%)

위험 관리:
- 최소 수익 기준 설정 (수익 < 이 값이면 거래 X)
- 최대 거래액 제한
- 거래소 상태 모니터링 (한쪽이 다운되면 거래 중단)
- 24시간 거래 건수 제한 (과도한 매매 방지)
```

## 💡 핵심 원칙

1. **"Mock이 아니면 안 된다" 원칙**
   - 모든 기능은 Mock → 실제 거래로 명확히 전환
   - Mock 상태를 사용자가 항상 알 수 있도록 표시
   - 실제 거래 전 충분한 테스트

2. **"거래가 안 되면 손실" 원칙**
   - 모든 거래는 기록되어야 함
   - 기록과 실제 거래가 100% 일치
   - 손실 방지 메커니즘 필수

3. **"AI는 계속 진화" 원칙**
   - 매 거래마다 학습
   - 정확도가 떨어지면 자동 조정
   - 사용자가 학습 과정을 볼 수 있어야 함

4. **"사용자는 선택" 원칙**
   - 주식 vs ETF 선택 가능
   - 자동 거래 vs 수동 확인 선택 가능
   - 자동 학습 vs 수동 학습 선택 가능
