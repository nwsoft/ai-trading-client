다만 정상 연결에는 **API Key + Secret Key + Password(passphrase)** 3개가 모두 필요합니다.

- `trading/unified_trading_manager.py`
  - Bitget 초기화 시 password 필수

## 8) 2026-04-20 기준 문서-코드 정합 검토 결과

### A. 실제로 개발 완료되어 문서와 대체로 맞는 항목

1. 암호화폐 핵심 거래 인프라
- 바이낸스 전용 경로와 CCXT 다중 거래소 경로가 분리되어 있음
- Bybit, OKX, Bitget, Upbit, Bithumb 어댑터가 실제 존재함
- TP/SL, 포지션 동기화, 통계/로그 관련 패치 기록이 CHANGELOG와 USER_GUIDE에 반영되어 있음

2. AI 어시스턴트
- 실제 대시보드 위젯과 채팅 UI가 구현되어 있음
- 설정/컨텍스트 기반 응답 구조가 존재함
- 차트 분석 위젯과 연결되는 경로도 존재함

3. Alpha Arena
- 독립 러너, 프롬프트 빌더, 응답 파서, 주문 실행 모듈이 실제 존재함
- DeepSeek/Qwen 계열 엔진 사용 흔적도 코드에서 확인됨

4. 주식/ETF 준비 구조
- 설정 구조, 대시보드 전환 UI, StockExchange 인터페이스, Kiwoom 어댑터 골격은 존재함
- 따라서 “준비 중” 또는 “기본 구조 완료”라는 문구는 맞음

### B. 아직 개발 중이거나 준비만 된 항목

1. 키움증권 실제 연동
- Kiwoom 어댑터는 다수 메서드가 플레이스홀더 또는 not_implemented 상태임
- 즉, UI/구조는 준비되어 있으나 실거래/실조회는 아직 완성 단계로 보기 어려움

2. ETF/주식 실제 판단·집행 고도화
- 관련 UI와 인터페이스는 있으나, 암호화폐만큼 실동작 완성도가 높다고 보기는 어려움
- 문서의 “진행 중” 표현은 맞고, “완전 구현”으로 답변하면 안 됨

3. 음성 STT/TTS
- 현재 저장소 기준 전면 음성 UI와 라이브러리 통합은 확인되지 않음
- 문서상 로드맵/준비 단계로 쓰는 것은 맞지만, 이미 공개 기능처럼 설명하면 안 됨

### C. 문서상 주의해서 봐야 하는 항목

- UPDATE_PLAN, BUSINESS_PROPOSAL, WHITEPAPER 계열은 현재 배포 기능 목록이라기보다
  비전·확장 계획·기술 방향을 함께 담고 있음
- 따라서 “실제 구현 증빙” 용도로는 아래 문서가 우선임:
  1) CHANGELOG
  2) USER_GUIDE
  3) ARCHITECTURE
  4) 실제 코드 파일

### D. 최종 판단

- 현재 문서와 실제 코드의 큰 방향은 **대체로 일치**함
- 다만 **암호화폐 영역은 실동작 중심**, **주식/ETF·음성 영역은 준비/진행 중**으로 구분해서 읽어야 함
- 즉, “모든 문서 내용이 이미 완전 제품화됨”은 아니고,
  “핵심 거래 인프라는 구현 완료, 확장 영역은 부분 구현 또는 로드맵”이 가장 정확한 판단임

## 9) 추가 질의에 대한 실행 결론

### A. 주식/ETF는 이제 무엇을 개발해야 하는가

현재 상태가 구조/UI 준비 수준이라면, 다음은 **반드시 실제 구현**이 필요함.

1. 실계좌 연결
- 로그인
- 계좌조회
- 잔고조회
- 보유종목 조회
- 주문/정정/취소

2. 실시간 데이터
- 종목 현재가
- 호가
- 거래량
- 장 상태
- 체결 이벤트 반영

3. 전략 엔진 분리
- 코인용 전략을 그대로 쓰지 말고
- 주식/ETF 전용 진입 기준, 장 마감 처리, 거래 시간 제한, 변동성/유동성 기준을 따로 둬야 함

4. 검증 체계
- 모의투자
- 실거래 전 체크리스트
- 주문 실패/재시도/장중 예외 처리
- 로그 및 리포트 정합성 검증

### B. 키움 외 다른 증권사도 가능한가

**가능은 함.**
현재 구조는 증권 브로커를 어댑터 방식으로 추가할 수 있게 되어 있음.
다만 **지금 코드상 실제로 연결된 것은 키움 어댑터 골격뿐**이며,
코인처럼 여러 증권사를 이미 완성 지원하는 상태는 아님.

즉 방향은 아래와 같음.
- 코인: 이미 다중 거래소 구조 완성
- 주식/ETF: 다중 증권사로 확장 가능한 구조만 준비됨
- 다음 후보: 한국투자증권, 미래에셋, NH, 대신, 이베스트, 인터랙티브 브로커스 등은 API 조건이 맞으면 추가 가능

### C. 주식과 ETF는 별개인가

법적 상품 성격은 다르지만, **앱 구조상은 같은 증권 계열 거래군**으로 보는 것이 맞음.

- 주식: 개별 기업 종목 매매
- ETF: 여러 종목이나 지수를 묶은 상품 매매

앱 내부에서는 둘 다 **stock 계열**로 처리하고,
ETF는 주식 계좌 안에서 함께 거래되는 **하위 상품군**으로 다루는 방향이 적절함.
즉 완전히 다른 시스템으로 쪼개기보다,
하나의 주식/ETF 엔진 안에서 종목 속성에 따라 구분하는 구조가 맞음.

### D. 어떻게 거래할 것인가 / 어떤 기준인가

비전상 코인과 동일하게 “AI 기반 자동 보조 판단”을 지향하되,
실제 기준은 자산군별로 분리해야 함.

#### 코인 기준
- 24시간 시장
- 변동성 큼
- 선물/현물 분리
- 레버리지/포지션 리스크 관리 중요

#### 주식/ETF 기준
- 장 시간 제약 존재
- 갭 상승/하락, 장 시작/종료 리스크 존재
- ETF는 추종 지수/유동성/괴리율 고려 필요
- 주식은 실적, 뉴스, 업종, 수급, 거래대금이 중요

따라서 앱 비전은 **하나의 AI 자산관리 플랫폼**으로 통일하되,
실행 엔진과 리스크 규칙은 코인과 주식/ETF를 분리하는 것이 맞음.

### E. 웹사이트/앱 비전과의 정합성

현재 가장 자연스러운 비전 문구는 다음과 같음.

- NoahAI는 코인과 전통자산을 함께 다루는 **AI 기반 투자 보조 플랫폼**
- 사용자는 대시보드에서 현재 상황을 보고,
  AI와 대화하며,
  설정을 조정하고,
  자동화 수준을 단계적으로 높여 갈 수 있음
- 단, 자산별 실행 규칙은 다르므로
  “같은 철학, 다른 실행 엔진” 구조가 적절함

즉 웹사이트와 앱 비전은 **동일 방향으로 유지 가능**하지만,
실제 구현 문구는 코인과 주식/ETF의 성숙도를 구분해서 표현해야 함.

### F. 음성 기능은 무엇을 설치하고 어떻게 붙일 것인가

현재 저장소에는 전면 음성 기능이 고정 탑재되어 있지 않음.
향후 구현 시 권장 순서는 아래와 같음.

1. STT
- 로컬 우선: Whisper 또는 faster-whisper
- 클라우드 대안: Google Speech-to-Text
- 흐름: 마이크 입력 → 텍스트 변환 → 기존 AI 채팅 입력창 경로로 전달

2. TTS
- 로컬 우선: pyttsx3
- 경량 대안: gTTS
- 흐름: AI 답변 텍스트 → 요약 → 음성 재생

3. OS 권한
- macOS 마이크 권한 허용
- 장치 선택
- 실패 시 텍스트 입력으로 자동 폴백

즉 음성은 **새로운 두뇌**가 아니라,
이미 있는 AI 어시스턴트에 붙는 **입력/출력 인터페이스 층**으로 보는 것이 맞음.

### G. 음성 전에 AI 어시스턴트를 먼저 완성·검증해야 하는가

**그렇다. 우선순위는 AI 어시스턴트 텍스트 경로 검증이 먼저다.**
이유는 음성이 붙어도 결국 내부 판단은 같은 AI 어시스턴트 경로를 타기 때문임.

권장 순서:
1. AI 채팅 정상 동작 확인
2. 현재 거래 컨텍스트 수집 정확도 확인
3. 설정 변경 JSON 적용 확인
4. 예외 상황/오답/연결 실패 처리 보강
5. 이후 음성 STT/TTS 연결

### H. 현재 AI 어시스턴트는 어느 정도 가능한가

**현재 코드 기준으로는 “질문답변 + 일부 설정 조정”은 가능하나, 앱 전체를 완전 제어하는 단계는 아님.”**

실제 가능한 것:
- 사용자 질문에 답변
- 현재 거래소, 잔고, 포지션, 시장 데이터, 거래 통계 등 컨텍스트를 모아서 답변 품질 향상
- 특정 표현이 들어오면 settings.json 기반 설정값 조정

아직 제한적인 것:
- 채팅만으로 거래 시작/중지 전체 제어
- 탭 이동, 계정 등록, 모든 기능 직접 실행
- 완전한 음성 비서형 앱 조작

### I. AI가 사용자의 실제 거래상황을 알고 답변할 수 있는가

**부분적으로는 가능하다.**
현재 위젯은 아래 정보를 수집하도록 구현되어 있음.
- 선택 거래소
- 거래소 연결 상태
- 잔고
- 활성 포지션
- 일부 시장 데이터
- 선택 코인 및 분석 요약
- 거래 통계
- AI 설정 상태

따라서 연결이 정상일 때는 **상당히 문맥 있는 답변**이 가능함.
하지만 아래 한계는 분명함.
- 거래소 API 연결이 끊기면 정보가 부정확해질 수 있음
- 조회 실패 시 일반 조언 위주 답변으로 바뀔 수 있음
- “완벽한 실시간 브로커급 인지”라고 표현하면 과장임

### J. 최종 우선순위 제안

1. AI 어시스턴트 텍스트 기능 실사용 테스트 완료
2. 주식/ETF 실계좌·실시간 시세·주문 엔진 구현
3. 키움 외 추가 증권사 어댑터 확장
4. 음성 STT/TTS 연결
5. 이후 웹사이트/앱 홍보 문구 최종 통합

## 10) 실제 코드 교차검증 기반 구조 가이드라인

이 절은 문서가 아니라 **실제 코드 파일 기준**으로 정리한 개발 가이드다.
추가 기능 업데이트 시 아래 구조를 기준으로 움직여야 안전하다.

### A. 앱의 실제 큰 구조

1. 진입점
- `main.py`
- 로그인 → API 설정 확인 → 거래 컴포넌트 초기화 → 대시보드 표시 순서로 진행됨
- `TradingStateManager`가 IDLE / STARTING / RUNNING / STOP_PENDING / STOPPED 상태를 관리함

2. 메인 UI
- `ui/dashboard_modern.py`
- 실제 메인 창 클래스는 `ModernDashboard`
- 설정, 거래 상태, 서비스 전환, 각 탭/위젯 연결의 허브 역할을 담당함

3. 위젯 계층
- `ui/widgets/` 아래에 AI 어시스턴트, AI 리포트, AI 학습, 실시간 로그, Alpha Arena, 차트 분석, 사용자 메뉴얼 위젯이 존재함
- 대시보드는 이 위젯들을 탭으로 붙여서 사용함

4. 거래 계층
- 바이낸스 전용 경로: `api/binance_client.py` + `trading/trader.py`
- 다중 거래소 경로: `trading/exchange_manager.py` + `trading/unified_trading_manager.py` + `trading/unified_trader.py`
- 실제 다중 거래소 어댑터는 `trading/exchanges/adapters/` 아래에 있음

5. 설정/저장 계층
- 설정: `config/settings.py`
- 사용자 데이터/로그/리포트: `data/` 및 recorder 기반 저장 구조

### B. 대시보드와 위젯 구조에서 확인된 사실

실제 코드상 대시보드에는 아래 축이 확인됨.

- 실시간 거래 로그
- 코인 정보 / 종목 정보
- 거래 통계
- 시장 트렌드
- AI 학습
- AI 어시스턴트
- AI 리포트
- Alpha Arena (설정 활성화 시)
- 차트 스크린샷 분석 연결 경로

즉 현재 앱은 단순 거래창이 아니라,
**거래 + 모니터링 + AI 설명 + 리포트 + 실험 기능**이 함께 붙은 통합 대시보드 구조임.

### C. 실제로 잘 되어 있는 부분

1. 구조 분리가 어느 정도 되어 있음
- 거래소 라우팅, 대시보드 UI, AI 모듈, 어댑터 계층이 분리되어 있어 확장 방향은 좋음

2. AI 탭 연결은 실제 동작 경로가 있음
- AI 어시스턴트는 현재 거래 컨텍스트를 모아서 답변하는 구조가 있음
- AI 리포트, AI 학습 탭도 별도 위젯으로 분리되어 있음

3. 다중 거래소 확장 방향이 명확함
- futures / spot / stock 인터페이스가 분리되어 있어 추가 어댑터 연결이 가능함

4. 주식/ETF도 완전 무(無) 상태는 아님
- 대시보드 전환 UI, stock용 탭, 인터페이스, 키움 골격은 이미 있음
- 따라서 “새로 바닥부터 만드는 것”이 아니라 “골격에 실제 엔진을 채우는 작업”으로 봐야 함

### D. 잘못되었거나 주의가 필요한 부분

1. `main.py` 의존도가 높음
- 여러 컴포넌트 초기화가 한곳에 몰려 있어 무리한 수정 시 전체 영향 범위가 커짐
- 따라서 신규 기능을 넣더라도 `main.py` 직접 대수술은 최대한 피해야 함

2. `ui/dashboard_modern.py`가 허브 역할을 많이 담당함
- UI 표시와 일부 상태 연결 책임이 집중되어 있어,
  여기에 비즈니스 로직까지 더 얹으면 유지보수가 급격히 어려워질 수 있음

3. 주식/ETF 실거래는 아직 미완성
- stock 탭은 있으나 데이터·주문 엔진은 아직 placeholder 성격이 강함

4. 음성 기능은 아직 본체가 아님
- 현재는 텍스트 AI 어시스턴트가 본 경로이고,
  STT/TTS는 이후 입출력 레이어로 붙여야 함

### E. 추가 기능 개발 시 안전한 원칙

1. UI 추가는 `ui/widgets/`에서 먼저 분리 구현
- 새 기능을 바로 `dashboard_modern.py`에 길게 넣지 말고
- 독립 위젯으로 만든 후 탭에 연결하는 방식이 가장 안전함

2. 거래소 확장은 어댑터 방식 유지
- 새 거래소/증권사를 붙일 때는
  `trading/exchanges/adapters/`에 새 어댑터를 만들고
  `exchange_factory.py`에 등록하는 방식으로 가야 함

3. 설정은 `settings.json`/`config/settings.py` 경로를 존중
- 임시 하드코딩보다 설정 기반 확장이 유지보수에 유리함

4. AI 기능은 텍스트 경로를 기준으로 먼저 검증
- 질문답변 → 컨텍스트 수집 → 설정 변경 → 로그 검증 순으로 안정화한 뒤,
  그 다음 음성을 붙여야 함

5. 주식/ETF는 코인 로직 복붙 금지
- 거래 시간, 주문 체결 구조, 장중/장후 규칙, ETF 특성을 따로 반영해야 함

### F. 기능 추가 시 권장 개발 순서

#### 1단계: 안전성 확보
- AI 어시스턴트 실사용 테스트
- 대시보드 상태 반영 검증
- 설정 변경 저장 흐름 검증

#### 2단계: 주식/ETF 완성
- 키움 실계좌 로그인
- 잔고/보유종목/시세 조회
- 주문/정정/취소
- 장 상태 반영
- 주식/ETF 전용 전략 기준 도입

#### 3단계: 증권사 확장
- 키움 안정화 후 다른 증권사 어댑터 추가
- 각 브로커별 인증/주문 규격 차이를 어댑터에서 흡수

#### 4단계: 음성 기능 연결
- STT: 마이크 → 텍스트 → AI 어시스턴트 입력
- TTS: AI 응답 → 요약 → 음성 출력
- 실패 시 텍스트 입력으로 폴백

### G. 실제 수정 시 권장 파일 우선순위

#### 상대적으로 안전한 확장 지점

- `ui/widgets/realtime_log_widget.py`

#### 수정 시 특히 주의할 파일
- `main.py`
- `ui/dashboard_modern.py`
- `trading/unified_trader.py`
- `trading/trading_worker.py`

### H. 최종 개발 운영 원칙

앞으로의 업데이트는 아래 기준을 지켜야 함.

- 사용자용 문서와 내부용 문서 분리
- 코드에 없는 기능은 “로드맵/준비 중”으로만 표기
- 새 기능은 위젯/어댑터 단위로 분리 구현
- 대시보드는 연결만 담당하고, 핵심 로직은 외부 모듈에 배치
- 코인/주식/ETF/음성은 같은 비전 아래 두되, 실행 엔진은 자산군별로 분리

이 원칙대로 가면, 현재 구조를 크게 깨지 않고도 기능 확장이 가능하다.

## 11) 2026-04-21 기준 최종 우선순위 판단

### A. 지금 가장 먼저 해야 할 것

결론부터 말하면,
**전면적인 대시보드 재작성보다 “핵심 경계만 먼저 분리”하고, 그 다음 AI 어시스턴트 마무리를 우선하는 순서가 가장 적절하다.**

즉 순서는 아래가 맞다.

1. `main.py` / `dashboard_modern.py`에 더 이상 기능을 직접 덕지덕지 붙이지 않도록 경계 고정
2. AI 어시스턴트 텍스트 경로와 설정 반영 흐름을 먼저 실사용 기준으로 마무리
3. 위젯 잔여 정리 및 레거시 참조 제거
4. 그 다음 주식/ETF 실연동 확장
5. 마지막으로 음성 STT/TTS 연결

### B. 왜 이 순서가 맞는가

- 현재 위젯 분리 작업은 이미 상당 부분 진행되어 있음
- AI 어시스턴트는 실제 사용자 체감 기능이고, 현재 제품 비전과 가장 가까운 모듈임
- 반면 주식/ETF, 음성은 아직 구조/로드맵 단계 요소가 더 많음
- 따라서 “분리 작업을 끝없이 먼저”가 아니라,
  **회귀를 막을 만큼만 구조 경계를 먼저 잡고, 그 다음 AI 어시스턴트를 제품 단위로 마무리**하는 것이 맞음

### C. 현재 기존 기능에 큰 문제는 없는가

**치명적인 방향 오류는 없음.**
다만 아래는 계속 주의해야 함.

1. 허브 파일 집중
- `main.py`와 `ui/dashboard_modern.py`에 상태 연결 책임이 많아
  신규 기능을 직접 계속 추가하면 다시 복잡도가 올라감

2. 문서 일부 과장/선행 표현
- 정책/비전 문서 대부분은 정합함
- 하지만 사업 제안 성격 문서 일부는 현재 구현보다 앞서 있는 표현이 있음

3. 위젯 변형 문서의 레거시 잔존

## 12) AI 어시스턴트 마무리 체크리스트

### A. 기능 동작 점검
- [ ] 대시보드에서 `💬 AI 어시스턴트` 탭이 항상 정상 생성되는지 확인
- [ ] `openai_api_key` 미설정 시 비활성 UI가 올바르게 보이는지 확인
- [ ] API 키 설정 시 실제 질문/응답이 정상 동작하는지 확인
- [ ] 응답 지연/실패 시 사용자에게 오류 메시지가 과하지 않게 표시되는지 확인

### B. 컨텍스트 정확도 점검
- [x] 현재 선택 거래소가 답변 컨텍스트에 반영되는지 확인
- [x] 잔고 조회 성공/실패 상태가 올바르게 반영되는지 확인
- [x] 활성 포지션 정보가 실제 상태와 맞는지 확인
- [x] 시장 데이터/선택 코인/거래 통계가 질문 응답에 반영되는지 확인
- [x] 연결 실패 시 허위 정보 대신 “조회 실패/확인 불가”로 안전하게 답하는지 확인

### C. 설정 변경 흐름 점검
- [x] “레버리지 낮춰줘”, “보수적으로 바꿔줘” 같은 문구가 설정 변경 모드로 분류되는지 확인
- [ ] 모델 응답 JSON이 정상 파싱되는지 확인
- [ ] `settings.json` 저장이 실제 반영되는지 확인
- [ ] 대시보드의 설정 반영 콜백이 정상 동작하는지 확인
- [x] 잘못된 JSON 응답일 때 앱이 죽지 않고 텍스트 응답으로 폴백하는지 확인

### D. 안전성/정책 점검
- [ ] 채팅만으로 거래 시작/중지/직접 주문 같은 과도한 제어가 되지 않는지 확인
- [ ] AI의 역할이 “판단·설명·일부 설정 조정”으로 제한되어 있는지 확인
- [ ] 책임 경계 고지(주문·체결·법적 책임은 사용자/외부기관)가 문서와 동일한지 확인
- [ ] 과장 표현 없이 실제 구현 범위 안에서만 안내되는지 확인

### E. UI/사용성 점검
- [x] 자주 하는 질문 버튼 실패 시에도 로컬 폴백 안내가 가능하도록 보강
- [ ] 채팅창 스크롤, 전송, Enter 입력이 자연스럽게 동작하는지 확인
- [ ] 차트 분석 버튼은 모듈이 있을 때만 노출/동작하는지 확인
- [x] 위젯 단독 테스트 시 `parent_dashboard` 미연결 경고가 이해 가능하게 보이는지 확인
