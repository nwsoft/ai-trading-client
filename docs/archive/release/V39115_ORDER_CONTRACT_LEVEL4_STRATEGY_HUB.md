# v3.9.1.15 주문규격·Level 4·전략 허브 검증 원장

기준일: 2026-08-28  
상태: 소스 후보, Windows 재빌드 전  
배포 판정: `pending_windows_rebuild`, `publish_ready=false`

## 1. 사용자 오류 판정

v3.9.1.14 사용자 로그의 `최종 검증 실패: 5.10 USDT < 20 USDT`는 정상적인 시장 HOLD가 아니다. 설정의 목표 주문금액 20 USDT에 초기·회복 위험배수 0.10이 적용되면 목표는 2 USDT로 축소된다. 수량 계산기가 Binance 최소 주문 5 USDT와 2% 버퍼를 맞춰 5.10 USDT로 보정했지만, 구형 최종 검사가 이를 다시 원래 목표 20 USDT와 비교해 신규 진입을 차단했다.

이 오류가 반복되면 신호 생성과 후보 선정이 정상이어도 실제 주문 제출 단계로 넘어가지 않는다. 사용자 설정을 낮추는 것은 해결책이 아니며 위험 정책을 왜곡할 수 있다.

## 2. 주문금액의 세 계약

| 계약 | 의미 | 처리 원칙 |
|---|---|---|
| 사용자 목표 주문금액 | 정상 조건에서 원하는 sizing 목표 | 위험배수·계좌 정책으로 축소 가능 |
| 승인 수량 상한 | 다중 거래소·계좌·집중도 정책이 허용한 최대 수량 | 후단에서 다시 비율을 곱하지 않고 절대 초과하지 않음 |
| 거래소 주문규격 | `MIN_NOTIONAL`, `minQty`, `stepSize`, precision | 주문 유효성을 위한 하드 조건, 확인 불가 시 실패 폐쇄 |

승인 상한 안에서 거래소 최소 규격을 만족하면 목표금액보다 작아도 주문 검증을 통과할 수 있다. 승인 상한이 최소 규격보다 작으면 위험을 늘려 주문하지 않고 명시적인 가드레일 사유로 차단한다.

## 3. Strategy Studio Level 4 계약

Level 4는 새로운 무제한 전략 엔진이 아니라 Level 3의 동일한 전략 ID·버전·IR에 전문가 운용 정책을 저장하는 화면이다.

| 정책 | 거래당 위험 | 최대 비중·증거금 | 레버리지 상한 | 국면 이탈 |
|---|---:|---:|---:|---|
| 안정형 | 0.25% | 5% | 1x | 커스텀 신규 진입 일시정지 |
| 표준형 | 0.50% | 10% | 3x | NoahAI 기본 판단에 위임 |
| 적극형 | 1.00% | 20% | 5x | NoahAI 기본 판단에 위임 |

조절 가능한 값은 거래당 위험예산, 최대 비중, 레버리지 상한, 국면 이탈 대응이다. 다음 하드 가드레일은 어느 Level에서도 해제하지 않는다.

- 사용자 승인과 LIVE 명시 허용
- 일일 손실 중단
- 포지션 수와 집중도 제한
- 거래소 최소 주문·수량·정밀도
- TP/SL 보호
- 중복 주문 방지와 포지션 대조
- 긴급 중지

해제 필드와 허용 범위 밖 값은 저장 단계에서 거부한다. 구형 Web UI의 `risk_budget`은 새 버전 저장 시 실제 런타임 정본 `risk_model`로 변환한다. 이미 저장·승인된 버전은 자동 수정하지 않으며 새 버전으로 저장하고 XAI 검토·승인·PAPER를 다시 수행한다.

## 4. 자동 검증

- `min_trade_amount=20`, 위험배수 `0.10`, Binance 최소 주문 `5`에서 5.10 USDT 허용
- 승인 상한이 최소 주문 미만이면 수량 상향 없이 차단
- SPLIT 승인 비율 이중 적용 금지
- Binance camelCase·snake_case 심볼 규격 호환
- 거래소 규격 누락 시 추정 주문 금지
- Level 4 IR 투영과 `risk_model` 저장
- 하드 가드레일 해제 필드 거부

집중 명령:

```bash
PYTHONPATH=. pytest -q \
  tests/test_v39115_order_contract_and_level4.py \
  tests/test_noah_strategy_ir_v1.py \
  tests/test_ai_custom_p1_p3_features.py
```

현재 집중 결과는 `26 passed`다. 전체 Python 회귀는 `1,898 passed, 8 skipped`, Web production build는 49 modules를 통과했다. 이는 Windows 설치본과 실제 거래소 주문을 증명하지 않는다.

## 6. AI 커스텀·Marketplace 다음 개발 범위

무료 공개 베타의 우선순위는 다음과 같다.

1. 원문 → IR → 전략 요청 → Level 4 조정 → 하드 가드레일 → 거래소 제출 → 청산 사유를 하나의 XAI trace로 연결
2. 자연어·Pine·TradingView·PDF 대표 전략의 의미 동등성 코퍼스와 실제 webhook 수신 E2E
3. 전략 키·버전별 PAPER/LIVE 판단·주문·체결·손익·중단 귀속 완결
4. daltrading 회원 제출→운영자 검토→공개→무료 취득·영구 실행 라이선스→다운로드→비활성 가져오기→재검증→공개 중지 E2E. 소스에는 첫 취득 원장, 중복 방지, 내 라이선스 재다운로드, 제작자 요청 즉시 신규 취득 차단과 기존 취득자 권리 유지가 구현되었으며 운영 URL E2E는 별도 게이트다.
5. 검증 여권의 미사용 구간·워크포워드·비용 스트레스·MDD·PAPER·실체결·가드레일 증거 분리

성과 기반 과금은 현재 범위에서 제외한다. 무료 취득 원장은 향후 Noah Point 단건 구매의 계약 기반이지만 포인트 충전·차감·제작자 지급은 아직 활성화하지 않는다. 블록체인·NFT·완전 복제 방지는 선행 조건이 아니며, 필요하면 후속 단계에서 패키지 해시·버전·공개/철회 상태의 선택적 증명만 평가한다.
