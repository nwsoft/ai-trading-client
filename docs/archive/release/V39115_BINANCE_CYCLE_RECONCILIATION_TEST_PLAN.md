# v3.9.1.15 Binance 후보 선정 복구·사이클 정합성 검증 원장

> 이 파일은 v3.9.1.15의 단일 배포 승인 원장입니다. 주문규격·Strategy Studio Level 4·무료 허브 세부 계약과 Windows 시나리오는 [주문규격·Level 4 보조 검증](V39115_ORDER_CONTRACT_LEVEL4_STRATEGY_HUB.md)을 함께 확인하며, 해당 필수 게이트가 남아 있으면 이 원장도 완료할 수 없습니다.

> 기준일: 2026-08-28  
> 제품 버전: `3.9.1.15` · updater SemVer: `3.9.115`  
> 직전 공개본: `3.9.1.14`  
> 목적: Binance 계정별 후보 선정 복구, 거래 시작 1회당 분석 사이클 1회, 포지션 조회 실패 시 상태 보존, 조회 성공 시에만 정합화

## 1. 원인과 수정 계약

- 기존 Binance 평가기는 후보 캐시를 `data/nwsoft/cache` 상대경로에 고정했습니다. Windows 패키지의 작업 디렉터리에 따라 설치 폴더 또는 다른 계정으로 해석돼, 정상 공개 시세가 있어도 후보가 모두 미산출될 수 있었습니다.
- 미산출 폴백 10개도 30초 single-flight 성공 캐시와 재선정 완료로 취급될 수 있어, 거래 사이클마다 실행 불가 목록만 확인하고 실제 후보로 회복하지 못했습니다.
- 설정·자격증명 갱신은 Trader 연결은 바꿨지만 Evaluator의 Binance 클라이언트를 누락해 오래된 연결이 후보 선정에 남을 수 있었습니다.
- v3.9.1.15는 현재 계정의 쓰기 가능한 캐시 경로를 사용하고 실패 결과를 즉시 캐시에서 제거합니다. 재선정 실패는 완료로 기록하지 않으며 기본 60초 쿨다운과 single-flight로 다시 시도합니다.
- 미산출 후보만 있는 동안 시장국면과 상세 종목 분석은 반복하지 않습니다. 기존 포지션 정합화·보호는 계속하고, 숫자 점수와 `execution_eligible=true`인 후보가 회복된 뒤에만 신규 분석·진입을 재개합니다.
- 런타임 연결 갱신 시 Evaluator도 Trader와 동일한 최신 Binance 클라이언트를 공유합니다.
- 기존 worker는 즉시 첫 사이클을 실행한 뒤 대기 없이 정기 루프 본문을 한 번 더 실행할 수 있었다.
- 기존 좀비 플래그 정리는 `get_positions()`의 빈 목록만 보고 실제 무포지션과 API·시간·네트워크 실패를 구분하지 못했다.
- 같은 LIVE 사이클 안에서 좀비 정리와 포지션 동기화가 각각 계정 API를 호출해 스냅샷 시각과 결과가 달라질 수 있었다.
- v3.9.1.15는 첫 사이클 뒤 설정 간격을 기다리고, 한 사이클의 상태형 포지션 스냅샷을 정리와 동기화가 공유한다.
- `status=success`인 빈 포지션만 무포지션 확정으로 사용한다. `error`, `no_api_keys`, `unavailable`이면 메모리 포지션·거래 플래그·모니터 핸들을 보존하고 신규 주문을 보류한다.
- PAPER·LEARNING은 실계정 포지션 스냅샷을 호출하지 않는 기존 계약을 유지한다.
