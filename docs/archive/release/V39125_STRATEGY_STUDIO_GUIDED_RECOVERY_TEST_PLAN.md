# v3.9.1.25 Strategy Studio Guided Recovery 검증 원장

기준 일자: 2026-09-09  
소스 후보: v3.9.1.25 / updater 3.9.125  
직전 공개 자산: v3.9.1.24  
상태: `pending_windows_rebuild`, `publish_ready=false`

## 사용자 피드백과 근본 원인

v3.9.1.24 화면 녹화와 스크린샷에서 다음을 확인했다.

1. Strategy Studio의 `AI에게 묻기`가 자산 서비스명으로 질문을 전달해 AI 어시스턴트가 전략 차단 대신 Binance 포지션 상태를 답했다.
2. Provider가 성공 상태와 빈 본문을 반환해도 화면과 캐시에 빈 답변이 남을 수 있었다.
3. 탭 이동 시 Strategy Studio React 컴포넌트가 언마운트되어 입력 원문·브라우저 File 객체·분석 결과·5분 안내 단계가 모두 소멸했다.
4. `기본 NoahAI에 맡기기`가 방향·진입·TP/SL·위험 규칙이 없는 문장을 커스텀 전략 원문으로 만들어, 올바른 실패 폐쇄 검증과 초보자 안내가 충돌했다.
5. 5분 안내는 `보완할 조건 N개`만 표시하고 실제 조건·수정 방법·예시·재분석 동작을 모달 안에서 제공하지 않았다.
6. 승인된 confirm 전략 중 `NoahAI 기본 진입 + 사용자 위험·청산` 유형은 독립 실행 진입조건이 없어 과거재생 대상이 아닌데, 안내와 카드가 모든 승인 전략에 자동검증을 강제했다. 서버의 올바른 실패 폐쇄 뒤 확인 버튼만 계속 남아 PAPER 단계로 이동할 수 없었다.
7. 관리형 `추세 따라가기`는 LONG/SHORT 조건을 `independent_entries`에 보유하지만 과거재생기의 선행 검사가 단일 `executable_entry`만 읽었다. 실행 준비 검사와 재생기의 지원 범위가 달라 정상 양방향 전략도 `실행 가능한 진입 조건 없음`으로 오판했다.
8. 같은 재생 엔진을 쓰는 주식·ETF 경로는 한국투자증권 한 곳만 명시적으로 회귀 검증했고, 통합 저장소의 암호화폐 전략을 주식 시세로 요청하거나 주식 전략을 암호화폐 시세로 요청하는 범위 불일치를 자동검증 시작 전에 차단하지 않았다.

## 수정 계약

- 전략 질문은 `service=ai_custom`으로 보내고 실제 차단 코드를 포함한다.
- Provider의 공백 응답은 실패이며 캐시에 저장하지 않는다. 심층분석 실패는 현재 버전의 로컬 제품 지식으로 대체한다.
- 블록체인·주식 Strategy Studio는 방문 뒤 별도 keep-alive 인스턴스로 유지한다. 다른 서비스의 초안과 파일을 공유하지 않는다.
- AI 어시스턴트에서 `전략 스튜디오로 돌아가기 · 입력 유지`를 제공하며 일반 탭 버튼으로 돌아와도 같은 상태를 복원한다.
- 기본 NoahAI 경로는 커스텀 전략이 필요 없음을 확인하고 안내를 완료한다. 전략 생성은 관리형 예제·사용자 원문 가져오기에서만 시작한다.
- 분석 차단은 조건별 제목·이유·고치는 방법·입력 예시를 안내창 안에 표시한다. 텍스트 원문은 그 자리에서 수정하고 다시 분석하며, 파일 원문은 변경된 원본을 사용자가 다시 선택한다.
- 실행 준비 계약에 `historical_validation_applicable`을 기록한다. 자체 실행 진입조건이 있는 `custom_entry_logic`만 과거재생하며, `noah_base_with_custom_risk_exit`는 `과거재생 비대상`을 설명하고 PAPER 단계로 이동한다.
- 비대상 전략을 자동검증 통과로 기록하거나 가짜 진입조건을 만들지 않는다. PAPER는 NoahAI 실제 후보와 사용자 위험·청산 규칙의 결합을 전진검증하며, 일반 LIVE 적용은 계속 별도 검증·승인을 요구한다.
- 독립 양방향 전략은 LONG/SHORT `independent_entries`를 각각 평가하고 정확히 한 방향만 성립할 때 재생한다. 양쪽이 동시에 성립하면 임의 방향을 선택하지 않고 `direction_conflicts`로 기록해 HOLD한다.
- 자동검증은 저장된 `target_scope`와 요청 자산군을 먼저 대조한다. `asset:crypto` 전략을 주식·ETF 시세로, `asset:stock`/`broker:connected` 전략을 암호화폐 시세로 바꾸어 검증 근거를 만들 수 없다.
- 키움·신한·미래에셋·한국투자는 동일한 주식·ETF 현물 계약을 사용한다. 관리형 초보자 후보는 LONG·1배로 생성하며, 가져온 전략에 신규 SHORT가 남아 있으면 보유 수량 청산으로 추정하지 않고 과거재생 전에 차단한다.
- 주식과 ETF의 과거재생은 선택 증권사의 일봉·KRW 기준으로 실행 규칙을 검사한다. 종목별 세금·정수 수량·주문 가능성·실제 체결은 증권사별 PAPER 및 실환경 게이트에서 별도로 검증하며 과거재생만으로 증명했다고 표시하지 않는다.
- Level 1~4, 저장 버전, 사용자 승인, 자동검증, PAPER, 명시적 LIVE 적용, 하드 가드레일은 변경하지 않는다.
