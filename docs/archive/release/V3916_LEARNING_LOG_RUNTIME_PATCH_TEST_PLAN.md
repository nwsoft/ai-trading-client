# v3.9.1.6 학습 데이터·거래소 로그·런타임 안정화 검증 계획

`v3.9.1.5` 공개 설치본 이후 반영한 학습 데이터 초기 로딩, 대용량 파일 계수, 메인·거래소별 실시간 로그, 거래소 독립 실행, 대시보드 런타임 집계와 로그 설정 반영 수정의 Windows 배포 게이트입니다. 소스 회귀와 macOS Web 빌드는 실제 Windows 설치·업데이트·외부 거래소 실행을 대신하지 않습니다.

- [ ] `WIN-BUILD` — 현재 소스 fingerprint로 `NoahAI-3.9.1.6-Setup.exe`, `NoahAIEngine.exe`, blockmap, `latest.yml(3.9.106)`를 새로 생성하고 SHA-256을 확정한다.
- [ ] `UPGRADE-3915-3916` — 공개 v3.9.1.5에서 인앱 업데이트 후 v3.9.1.6이 실행되고 동일 계정의 설정·거래소/AI 자격증명·학습 데이터·로그가 유지되는지 확인한다.
- [ ] `LEARNING-PAGING` — AI 학습 화면이 처음 최근 50개만 표시하고 더보기마다 50개씩 추가하며, 화면의 전체 학습 수가 현재 운영 파일의 정확한 총 레코드 수와 일치하는지 확인한다.
- [ ] `LEARNING-LARGE-FILE` — 사용자별 100MB 이상 학습 파일에서 첫 페이지가 전체 파일 JSON 역직렬화 없이 자연스럽게 열리고, 재조회는 캐시를 사용하며 메모리·UI 정지를 유발하지 않는지 확인한다.
- [ ] `LOG-MAIN` — 메인 실시간 거래 로그가 최근 100줄부터 1초 간격으로 갱신되고 새 XAI 분석·전략·진입·모니터링·청산 로그를 중복 없이 표시하는지 확인한다.
- [ ] `LOG-SOURCE-SIX` — Binance·Upbit·Bithumb·Bybit·OKX·Bitget 각 탭이 자기 거래소의 파일 로그와 현재 세션 로그를 병합해 표시하며 다른 거래소 로그를 섞지 않는지 확인한다.
- [ ] `LOG-FILTERS` — 거래 시그널만·분석 과정만·전체 로그, 초기화/디버그/시스템 로그 숨김, 로그 레벨·거래소·카테고리 필터와 새로고침/지우기가 실제 반환 데이터에 반영되는지 확인한다.
- [ ] `MULTI-EXCHANGE` — 한 거래소 시작 중 UI 전체가 멈추지 않고 다른 거래소를 독립 시작·정지할 수 있으며, 설정 대상 일괄 시작/실행 중 전체 정지가 안전하게 동작하는지 PAPER에서 확인한다.
- [ ] `DASHBOARD-RUNTIME` — 각 워커 시작·정지 뒤 메인 KPI, 포지션/보유자산, 거래 수, 자동 거래 상태, 실시간 운영 알림이 주기 갱신되고 죽은 워커를 실행 중으로 남기지 않는지 확인한다.
- [ ] `SETTINGS-LOG-RUNTIME` — 상세 거래 로그와 로그 레벨 변경을 저장하면 Trader·통합 Trader·Analyzer·connector가 재시작 없이 최신 설정을 사용하고, 실패 시 저장 성공과 런타임 반영 실패를 구분하는지 확인한다.
- [ ] `SAVE-RESTART` — 일반·로그·거래소·AI 설정 저장 후 10초 대기, 닫기·재열기와 앱 재시작 뒤 값·키 등록 상태가 유지되고 자동 백업 복구가 발생하지 않는지 확인한다.
- [ ] `ROLLBACK` — 설치 실패 또는 취소 시 v3.9.1.5 실행 파일과 계정별 `settings.json`, 학습 데이터, 로그를 손상하지 않는지 확인한다.

모든 항목에 비밀값을 제외한 Windows 증거를 첨부해 `[x]`로 바꾸기 전에는 `publish_ready=false`를 유지합니다. 실제 거래 검증은 PAPER를 우선하며 LIVE 주문은 별도 승인 없이 제출하지 않습니다.
