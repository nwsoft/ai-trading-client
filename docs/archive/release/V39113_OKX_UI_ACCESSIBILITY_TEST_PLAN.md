# v3.9.1.13 OKX 안전 종료·가독성·PAPER 검증 안내 검증 계획

상태: **v3.9.1.13 게시 완료 / 게시 뒤 후속 수정은 새 버전 Windows 빌드 전**  
제품 버전: `3.9.1.13` · updater SemVer: `3.9.113`  
원칙: 소스 테스트와 macOS Web 빌드는 Windows 설치본, 실제 거래소, 업데이트 완료의 대체 증거가 아니다.

## 1. 자동 검증

- [x] CCXT 5개 어댑터의 단일 네트워크 요청 제한이 안전 종료 공유 예산보다 짧다.
- [x] 분석 호출 중 들어온 중지 신호가 주문 단계 전에 다시 확인된다.
- [x] API 인증 상태가 거래소 제어 카드 안에 있고 PAPER 이력에 접기/펼치기 상태가 있다.
- [x] 화면 표시 프리셋이 설정 스키마·Gateway·Electron IPC에 연결된다.
- [x] 새 업데이트 알림 이벤트가 설정·dispatcher·Gateway·Web UI에 연결된다.
- [x] AI 커스텀 화면이 LIVE에서 숨은 PAPER 검증을 실행하지 않는다고 안내한다.
- [x] 점수 미산출 폴백을 `0.00`으로 표시하지 않고 거래소별 최신 선정 세션만 조회한다.
- [x] 정상 부분 후보를 고정 목록으로 덮지 않고 `scored_partial`로 유지하며, 점수 없는 후보에 임의 30·50점을 만들지 않는다.
- [x] `fallback_unscored`는 PAPER/LIVE 신규 진입을 차단하고 기존 포지션 보호·청산은 계속한다.
- [x] Binance 거래 가능한 USDT 무기한 선물 전체의 24시간 티커를 거래대금으로 정렬하며 심볼 목록의 앞 100개 절단에 의존하지 않는다.
- [x] 거래소 일괄 ticker 1회, 상세 후보 30개 제한, 최대 8개 병렬, 같은 거래소 single-flight를 결정적 mock 회귀로 확인한다.
- [x] 120초 초과 결과가 이전 정상 후보를 덮지 않고, 국면 전환이 확인 횟수·최소 유지시간을 통과해야 확정되는지 회귀로 확인한다.
- [x] 주식 시장국면이 지원 증권사의 KOSPI 5거래일 이력을 우선하고 동일 증권사 서비스·유니버스를 재사용하는지 회귀로 확인한다.
- [x] 전체 Python 회귀 `1,866 passed, 8 skipped`와 문서 정합성 검사를 최종 수정본에서 다시 통과한다.
- [x] `npm --prefix webui run build`를 최종 수정본에서 다시 통과한다(49 modules).
- [x] Binance 공개 API 읽기 전용 스모크에서 거래 가능 USDT 무기한 선물·24시간 티커 524개 일치와 거래대금 상위 5개 1시간봉 50개 확보를 확인한다(주문 0건).
- [x] 후보 점수 worker가 종목별 캔들·펀딩비·OI 네트워크 호출을 하지 않고 Binance·OKX ticker snapshot으로 제한시간 내 숫자 점수를 계산하는 회귀를 추가한다.
- [x] Binance 네이티브와 Upbit·Bithumb·Bybit·Bitget·OKX 통합 worker에 종료 신호가 먼저 전달되는 전체 소스 회귀를 추가한다.
- [x] 거래 worker 없이 생성된 키움·신한·미래에셋·KIS 어댑터가 모두 수명주기 대상에 포함되고, 장기 Kiwoom RPC 잠금에서도 소유 자식만 정리되는 회귀를 추가한다.

- [ ] `WIN-UPGRADE`: 공개 v3.9.1.12에서 v3.9.1.13 업데이트와 재시작·롤백을 검증한다.
- [ ] Windows 호스트에서 새 `NoahAIEngine.exe`, `NoahAI-3.9.1.13-Setup.exe`, blockmap, `latest.yml`을 같은 소스 fingerprint로 빌드한다.
- [ ] 설치기·blockmap·`latest.yml`·manifest의 버전과 SHA-256을 교차 확인한다.
- [ ] 공개 v3.9.1.12에서 v3.9.1.13 자동 확인 → 다운로드 → 안전 종료 → 설치 → 재시작을 검증한다.
- [ ] 설정, 거래소/AI API 자격증명, 사용자 DB, AI 커스텀 전략과 PAPER 원장이 업데이트 전후 보존된다.
- [ ] 실패한 업데이트가 공개 v3.9.1.12 자산이나 사용자 데이터를 덮어쓰지 않는다.

## 3. OKX·다중 거래소 안전 종료

- [ ] OKX 단독 PAPER/LIVE 권한 상태에서 정상 네트워크 종료와 업데이트를 각각 10회 반복한다.
- [ ] OKX 요청 중 네트워크 단절·고지연·DNS 실패를 재현하고 12초 요청 경계 뒤 worker가 45초 공유 예산 안에 종료되는지 확인한다.
- [ ] 6개 거래소 동시 실행 중 종료 신호가 먼저 모두 전달되고, 종료 요청 이후 신규 주문이 발생하지 않는다.
- [ ] 실제 worker가 종료되지 않았을 때는 업데이트를 계속하지 않고 정확한 거래소·worker 원인을 표시한다.
- [ ] 안전 종료 성공 뒤 설정·PAPER/LIVE 원장·로그 flush와 재시작 복구가 일치한다.
- [ ] 거래를 시작하지 않고 키움 잔고·종목 조회만 수행한 뒤 종료·업데이트를 각각 10회 반복해 `runtime_still_alive`와 잔류 COM 자식이 0인지 확인한다.
- [ ] 신한·미래에셋·KIS도 조회만 수행한 뒤 종료해 연결·세션·worker가 남지 않는지 확인한다.

## 4. 화면·가독성·반응형

- [ ] 1500×980/100%, 1680×1050/112%, 1920×1080/125%에서 상단 메뉴, 거래소 탭, 로그, 메뉴얼, 설정 텍스트가 함께 커진다.
- [ ] 1280×900, 1366×768, 150% Windows DPI와 다중 모니터 이동에서 창이 작업영역 밖으로 나가지 않는다.
- [ ] API 인증 완료·미완료·연결 확인 중의 긴 문구가 제어 카드 밖으로 넘치지 않는다.
- [ ] LIVE에서는 과거 PAPER 이력이 기본 접힘이고 사용자가 펼친 뒤 최근 기록을 읽을 수 있다.
- [ ] PAPER에서는 현재 가상 이력이 기본 펼침이며 카드 접기/펼치기가 포지션·통계·로그 조작을 방해하지 않는다.
- [ ] 창 가장자리를 수동으로 늘이거나 줄여도 고정 px 요소가 겹치거나 잘리지 않는다.

## 5. 알림·AI 커스텀 의미 검증

- [ ] Discord와 Telegram을 각각 켠 계정에서 새 버전 안내가 버전당 한 번만 도착한다.
- [ ] 외부 알림 OFF, 채널 OFF, 전송 실패 상태에서도 업데이트 확인·거래·종료가 지연되거나 실패하지 않는다.
- [ ] 앱 내부 업데이트 화면은 외부 채널 설정과 무관하게 최신/가능/다운로드/준비 상태를 표시한다.
- [ ] LIVE에서 PAPER 검증 등록 후 거래해도 PAPER 거래·관찰 일수가 증가하지 않는다.
- [ ] PAPER로 전환해 해당 전략 버전으로 새 가상 청산이 완료되면 거래 수와 관찰 시간이 증가한다.
- [ ] 다른 전략·버전, 검증 시작 전 기록, LIVE 체결은 PAPER 검증 수치에 합산되지 않는다.

## 6. 누적 거래·증권 외부 게이트

- [ ] `COIN-SELECTION-E2E`: Binance 정상 API에서 숫자 점수와 최신 세션이 표시되고, 후보 부족은 `부분 선정`, 캔들/API 전면 실패는 `미산출·신규 진입 차단`과 원인 로그로 구분되는지 확인한다.
- [ ] 정상 점수 후보가 있어도 후속 신호가 HOLD이면 주문이 없고, 미산출 참조 목록은 AI 커스텀 confirm/independent에서도 신규 주문을 만들지 않는지 PAPER로 확인한다.
- [ ] 6개 거래소를 차례로 재선정해 각 코인 정보 화면에 다른 거래소의 최신 후보가 섞이지 않는지 확인한다.
- [ ] 각 거래소 콜드 20회·웜 캐시 50회를 측정해 캐시 2초, 단일 거래소 콜드 p95 10초 목표를 확인한다.
- [ ] 6개 거래소 동시 콜드 선정을 20회 측정해 전체 p95 15초 목표와 거래소별 API 제한 위반 0건을 확인한다.
- [ ] 자동 재선정 중 포지션 감시·TP/SL·설정·AI 커스텀 API가 대기하지 않고, 완료 전에는 이전 후보·완료 뒤에는 새 후보만 보이는지 확인한다.
- [ ] 네트워크를 120초 이상 지연시켜 완료된 결과가 기존 정상 후보를 덮지 않고 신규 진입도 만들지 않는지 확인한다.
- [ ] 증권사 60초 주기를 30회 실행해 종목 목록·시장국면이 5분 TTL 동안 중복 조회되지 않고 사용자 지정·거래정지 필터가 유지되는지 확인한다.

- [ ] `KIWOOM-E2E`: Windows COM 주 스레드 연결·조회·PAPER와 안전 종료를 재검증한다.
- [ ] `KIS-E2E`: 한국투자 공식 주식·ETF 조회 경로와 오류 분류를 재검증한다.
- [ ] `BITHUMB-E2E`: 현물 LONG/PAPER, 종목별 미체결 조회와 KRW 원장을 재검증한다.
- [ ] `RECONCILE-E2E`: 거래소 체결·NoahAI 관리 청산·수동/외부 포지션 조정을 재검증한다.
- [ ] `SPOT-FUTURES-PAPER`: Upbit·Bithumb 현물과 Binance·Bybit·Bitget·OKX 선물의 방향·통화·PAPER 원장을 분리 검증한다.
- [ ] `REPORT-E2E`: 거래소·통화별 KPI와 AI 리포트, 외부 리포트 발송 정합성을 재검증한다.
