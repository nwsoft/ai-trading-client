# v3.9.0.8 Fix 1 UI 생명주기 장애 분석 및 수정 기준

## 사용자 증상

- 설정 창이 비어 있거나 열리지 않음
- `설정 창 열기 실패: No more menus can be allocated.` 출력
- 블록체인과 주식/증권 왕복 후 거래소·증권사 탭 혼합
- `코인 정보` 또는 `종목 정보`가 source 탭 뒤로 이동
- 포지션 헤더에는 활성 개수가 표시되지만 카드 본문 글자가 비어 있음
- 설정 X 닫기 과정에서 빈 흰색 `NoahAI 설정` 창이 추가로 표시됨

## 근본 원인

1. 설정 화면은 30개가 넘는 `CTkComboBox`를 포함하며 각 항목은 native `tk.Menu`를 소유합니다. 기존 코드는 설정을 저장하거나 취소할 때 전체 창을 파괴하고 다음 열기 때 전부 다시 만들었습니다.
2. CustomTkinter 5.2.x의 ComboBox·OptionMenu 파괴 메서드는 `_dropdown_menu`를 직접 파괴하지 않습니다. 이 메뉴는 일반 `winfo_children()` 순회에도 의존할 수 없어 Windows USER 메뉴 자원이 늦게 회수되거나 누적될 수 있습니다.
3. 한 번의 서비스 전환에서 전체 탭 제거, 이전 탭 제거, 정책 제거가 중복 실행됐고 금융 인텔리전스·source 탭도 반복 재생성됐습니다.
4. 설정 저장 후 현재 화면이 주식이어도 `update_exchange_info()`가 블록체인 탭을 만들고 `show_blockchain_content()`를 호출해 서비스 소유권이 섞였습니다.
5. 탭 순서는 생성 시점에 의존해 삭제 후 다시 만든 정보 탭이 거래소·증권사 뒤로 밀렸습니다.
6. 포지션 한 건마다 라벨 외에 투명 CTkFrame 3개와 Canvas가 추가돼 자원 고갈 상황에서 외곽 카드만 만들어지고 글자 위젯 생성이 실패할 여지가 컸습니다.
7. 2026-08-11 최초 추가 피드백 방어는 AI 관련 네 개 탭만 캐시를 비우는 이름 목록이어서 시장 트렌드·금융 인텔리전스·거래 통계·AI 애널리스트 내부 참조까지 같은 규칙을 강제하지 못했습니다.
8. 통합자산만 레거시 DB를 우회한 뒤 시나리오 점검·보안 경고가 다시 선택 열 `asset_type`·`entry_amount`를 직접 조회하고 있어 동일 스키마 오류가 다른 화면에서 재발할 수 있었습니다.
9. AI 실행 기록은 요청 접수만 추가하고 동일 요청의 완료·오류 상태를 갱신하는 공통 활동 계약이 아니었습니다.

## Fix 1 구현 기준

### 설정 창

- 대시보드 실행 중 `ModernSettingsWindow`는 하나만 생성합니다.
- 저장·취소·X 닫기는 창을 파괴하지 않고 `withdraw()`하며 다음 열기에는 같은 위젯 트리를 `deiconify()`합니다.
- 저장하지 않고 닫으면 저장 정본을 다시 로드한 뒤 숨깁니다.
- 앱 종료 시에만 `dispose()`가 타이머·grab·창을 완전히 정리합니다.
- X 닫기 확인은 새 CTkToplevel을 만들지 않습니다.

### 위젯과 메뉴

- 동적 탭을 파괴할 때 자식 정리 훅을 먼저 실행합니다.
- ComboBox·OptionMenu의 `_dropdown_menu`를 명시적으로 한 번만 파괴합니다.
- Windows 전환 전후 USER/GDI 수를 계속 기록합니다.

### 동적 화면 소유권

- 모든 캐시 위젯은 `WidgetOwnershipRegistry`에 `탭 → 속성/매핑 → 실제 위젯 identity`로 등록합니다.
- 탭 삭제와 탭 본문 재구성은 같은 소유권 무효화 경계를 먼저 통과합니다. 예전 트리의 늦은 정리는 새 위젯 identity를 지우지 않습니다.
- AI 학습·리포트·어시스턴트·AI 커스텀뿐 아니라 시장 트렌드·금융 인텔리전스·AlphaArena·코인/종목 정보·거래 통계·AI 애널리스트 미리보기까지 같은 계약을 사용합니다.
- 대시보드 안의 저수준 `delete_ctk_tab()` 호출은 한 wrapper에만 존재하며 신규 삭제 경로가 캐시 해제를 우회하지 못하게 회귀 테스트로 고정합니다.

### 서비스 탭

- 전환 순서는 `이전 source 탭 제거 → 현재 서비스 본문 → 현재 source 탭 → 정책/순서 적용` 한 경로만 사용합니다.
- 설정 저장 뒤 현재 서비스만 다시 만듭니다.
- 블록체인과 주식의 금융 인텔리전스 위젯은 같은 탭에서 숨김/표시로 재사용합니다.
- 정본 순서는 다음과 같습니다.
  - 블록체인: 실시간 로그 → 코인 정보 → 거래 통계 → 시장 트렌드 → AI 기능 → 금융 인텔리전스 → AlphaArena → 거래소
  - 주식: 실시간 로그 → 종목 정보 → 거래 통계 → 시장 트렌드 → AI 기능 → 금융 인텔리전스 → 증권사

## 완료 판정

- 소스 자동 테스트와 macOS 스모크는 구현 회귀를 확인하는 근거입니다.
- Windows EXE를 새로 빌드한 뒤 동일 프로세스에서 설정 열기/닫기 100회와 블록체인↔주식 100회 왕복을 수행합니다.
- 각 10회마다 USER/GDI 수를 기록해 계속 증가하는지 확인합니다.
- 매 회차 거래소/증권사 혼합 없음, 정보 탭 순서 고정, 포지션 카드 글자 표시, 빈 설정/확인창 없음이 모두 충족돼야 합니다.
- 새 EXE 크기·SHA-256과 설치본 화면을 확인하기 전에는 배포 완료로 표시하지 않습니다.

## 2026-08-11 추가 피드백과 같은 생명주기 기준

- AI 애널리스트 오류의 직접 원인은 서비스 탭이 AI 어시스턴트 입력창을 파괴한 뒤 `ai_assistant_widget` 캐시가 남은 것입니다. 탭 삭제와 위젯 참조 무효화를 하나의 소유권 작업으로 처리하고, 모든 외부 질문 버튼은 살아 있는 입력창을 확인·재생성합니다.
- 하단 실행 기록은 UI 표시용 별도 상태가 아니라 실제 AI 어시스턴트/애널리스트 요청 진입점과 연결합니다. 요청 실패도 기록해 `기록 없음`으로 오인하지 않게 합니다.
- 통합자산 0 표시는 UI 자원 문제가 아니라 DB 스키마 불일치 예외 은폐와 데이터 의미 혼합 문제였습니다. 현재 잔고, 종료 거래 실현손익, 상관 표본을 분리하고 통화가 다르면 환율 없이 합산하지 않습니다.
- 현재 잔고는 스레드 안전 `AssetSnapshotStore` 한 곳에만 저장하고, 통합자산·계좌 패널이 같은 스냅샷을 사용합니다. 종료 거래는 `load_closed_trade_records()`가 구형/신형 열을 정규화해 통합자산·시나리오·보안 경고에 공통 공급합니다.
- AI 활동은 `AIActivityLedger`가 요청 ID 하나를 `running → completed/failed`로 갱신합니다. 하단 요약과 상세 기록은 별도 UI 상태가 아니라 이 원장을 읽습니다.
- 소스 회귀는 재구성 200회 뒤 소유권 바인딩 0개, 구형 DB 공통 읽기, 동시 잔고 갱신, AI 요청 단일 이벤트 완료를 검증합니다. Windows native USER/GDI 상한은 여전히 새 EXE 외부 게이트입니다.
