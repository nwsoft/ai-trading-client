## 구현 계약

- 기존 고객 자료는 읽기 전용 검증 입력으로 취급한다. 새 저장 형식 이관은 원본을 보존하고 재시도 가능해야 한다.
- ai_decisions에 계약 버전·기관·모드·자산/종목 유형·UTC 시각·전략 버전·판단·사유·앱 버전·세션·이벤트 종류·실주문·주문/원장 연결을 추가한다. 과거 근거가 충돌하거나 없으면 unknown으로 유지한다.
- 엔진·어댑터는 달라도 `LEARNING/PAPER/LIVE → 판단 → 차단/주문 → 체결/청산 → 원장 → XAI` 외곽 계약은 하나로 유지한다. 자산별 시장시간·주문 단위·세금·공매도/레버리지·ETF 지표는 같은 값으로 억지 통합하지 않고 XAI 근거와 기관 능력 계약으로 분리한다.
- 같은 시간 구간에서 내용까지 같은 HOLD만 합산한다. 주문·체결·청산·차단·위험·전략 변경은 합산하지 않는다.
- 학습 기록은 SQLite 최근 이벤트, SHA-256 내용 주소형 근거, 검증된 gzip 세그먼트로 보관한다. JSON 전체 주기 재작성을 제거한다.
- 거래소 매니저는 계정 절대경로 및 기관을 기준으로 공유한다. 계정 전환과 동시 생성은 격리한다.
- 일반 로그는 INFO, 상세 로그는 한시적으로 허용한다. 진단 로그 용량과 영구 업무 원장은 별도 정책으로 관리한다.
- 유지관리 상태 조회와 최적화는 계정에 귀속되고, 긴 작업은 백그라운드에서 수행한다.

## 운영·이관 경계

- 과거 `ai_decisions`의 일괄 귀속은 유지관리에서 1,000행 단위로 진행한다. 기존 근거가 충돌하면 unknown이다. 기존 전체 JSON을 판단 주기마다 다시 쓰지 않는다.
- 신규 기관/모드 충돌은 정상 판단 테이블에 unknown으로 넣지 않고 원문·사유를 별도 보존한다. 유지관리에 건수가 표시되며 반복 시 지원 진단이 필요하다. 근거 없는 역사 자료를 버튼 하나로 추측 복구하는 기능은 아니다.
- 기존 기관별 최근 JSON/저널은 최초 1회 스트리밍 이관한다. 과거 `_archive_*.json/jsonl` 및 전역 중복 JSON은 그대로 보존하며 삭제하거나 원장으로 재해석하지 않는다. 신규 과거 기록부터 gzip+해시 카탈로그를 사용한다.
- 512 MiB는 계정 진단 파일의 근사 예산이며 영구 업무 원장·학습 근거를 포함한 전체 디스크 제한이 아니다. 원본 보존 때문에 최초 이관은 용량을 즉시 줄이는 작업이 아니다.
- 닫힌 날짜형 회전 로그는 검증된 gzip으로 대체해 재개 공간을 만든다. 보관 용량은 별도이며 현재 쓰는 파일은 압축하지 않는다. 파일 잠금/디스크 부족/활성 파일만의 초과 시 경고·제한이 남을 수 있다.
- 증권은 기존 ai_decisions 저장 경로를 유지하고 정식 컬럼/기관별 인덱스 조회를 공유한다. `stock_analyze_symbol`뿐 아니라 `stock_auto_trade_symbol`·`stock_auto_exit_symbol`도 같은 화면에서 판단 근거로 조회한다. 암호화폐 JSON 학습 파일 구조로 억지 변환하지 않으며 확인되지 않은 과거 모드·주문은 미확정으로 남긴다.
- 모든 오래된 자유 형식 문장에 새 필드가 소급 복원되는 것은 아니다. 공통 판단 및 주요 log_event/거래 원장 기록부터 계약을 적용한다.
- PnL 대조·위험 한도·거래 시작/재개 조건은 변경하지 않는다. 기존 v43 복구 및 실제 계좌 검증 한계를 이 작업으로 해소했다고 주장하지 않는다.

진단 로그 정리로 거래 원장·주문 영수증·PAPER 성과·XAI 중요 이벤트를 삭제하지 않는다. 저장장치 부족은 숨기지 않고 표시하며, 무제한 영구 보존과 물리 디스크 상한이 동시에 보장된다고 주장하지 않는다.
