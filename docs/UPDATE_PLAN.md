# NoahAI 기술 확장 계획
## AI 자산 의사결정 인프라 로드맵 (v3.9.0+)

### 문서 목적
이 문서는 NoahAI를 "특정 자산용 트레이딩 시스템"이 아닌  
**자산군에 독립적인 AI 의사결정 인프라**로 확장하기 위한  
기술 구조 중심의 업데이트 계획을 정의한다.

본 문서는 다음을 다루지 않는다.
- 수익률 목표
- 자동 투자 또는 자산 운용
- 법적·세무 집행 기능

본 문서는 다음에 집중한다.
- 판단 파이프라인의 확장
- 기록·검증·설명 구조의 일반화
- 자산군/산업 확장 시에도 변하지 않는 기술 기준선

## NoahAI의 정체성 (최상위 전제)

1. NoahAI는 "재테크 플랫폼 / 자산 운용 시스템 / 자동 투자 시스템"이 아니다.
2. NoahAI는 **AI 자산 의사결정 인프라 (AI Asset Decision Infrastructure)** 이다.
3. NoahAI는 판단·설명·기록·검증·환류만 담당한다.
4. 주문·체결·자금 이동·세무 신고·법적 행위는 항상 외부 주체(API·기관·사용자) 책임이다.
5. 본 문서는 "개발 로드맵"이 아니라 **기술 인프라 확장 계획서**로 읽혀야 한다.

### 용어/메뉴 정합성 기준 (2026-04-25 반영)

- 금지 표현: `AI 자산 운용 엔진`, `멀티자산 AI 트레이딩 운영 시스템`
- 권장 표현: `AI 금융 의사결정 엔진`, `멀티자산 AI 금융 판단 인프라`
- UI/문서 메뉴명은 목적 기반으로 유지한다.
  - 예: `글로벌자산` → `자산 통합` 또는 `글로벌 금융 인사이트`
- 거래 지표는 보조 지표로만 사용하고, 최상위 KPI는 판단 품질 중심으로 둔다.
  - 판단 로그 완결률, 재현 가능률, 리스크 경고 적중률, 설명 만족도, 질문 해결률

### 도메인 계층 (문서/메뉴 공통 분류)

1. Asset Decision Domain: 암호화폐/주식/ETF 등 자산군 의사결정
2. Life Finance Domain: 대출·보험·예적금·개인 재무관리
3. Risk Protection Domain: 금융사기·이상거래·고위험 선택 회피
4. Accessibility Domain: 고령층/디지털 약자 접근성, 음성·쉬운 설명
5. Assistant Interface Layer: 대화형 질의응답, 설명·비교·경고 인터페이스

- 상태: 실제 운영 중 (v3.8.9.13 기준)

#### 📋 계획 단계: 차액거래 (Arbitrage)

**차액거래란?**
- 서로 다른 거래소에서 같은 코인의 가격 차이를 이용한 거래
- 예: A 거래소 BTC $46,000 ↔ B 거래소 BTC $46,100
  - B에서 매도, A에서 매수 → 차이 $100 (수수료 제외)

**구현 계획**
1. **실시간 가격 모니터링**: 모든 거래소의 실시간 시세 비교
2. **차액 계산 (수수료 포함)**
   - 거래소별 Maker/Taker 수수료 자동 계산
   - 입출금 수수료 포함
   - 환전 스프레드 고려
3. **수익성 판정**: 차액 > (수수료 합계) 일 때만 실행
4. **자동 실행**: 조건 충족 시 양쪽 거래소에 동시 주문

**기술 과제**
- API 지연 시간 최소화 (양쪽 거래소 동시 주문 필요)
- 규제 이슈 검토 (높은 빈도 거래의 합법성)
- 자본금 요구사항 (양쪽 거래소에 동시 자본 필요)

**현재 구현 여부**: ❌ **미구현** (로드맵 항목)

**단기 목표**: 이번 스프린트에서는 차액거래 자체 구현이 아니라 가격 감시 데이터 구조와 화면/문서 정합성까지만 다룬다.

## Phase G — AI 원버튼 실행/접근성 모드 (2026-05-07 제안 반영)

### 목표
- 대시보드의 `모두시작`을 단순 일괄 실행이 아니라, 사용자 상태를 읽고 필요한 단계만 실행하는 `AI 실행` 버튼으로 전환한다.
- 고령층/디지털 취약계층/초보 사용자를 위해 음성 또는 버튼 1회로 "진단 → 안내 → 확인 → 적용" 흐름을 제공한다.
- 거래소/증권사 OpenAPI 키 발급과 설정을 `AI 상담`에서 단계별로 안내하되, 보안·법무 경계를 침범하지 않는다.

### 핵심 기능
1. AI 실행(원버튼)
  - 시작 전 자동 점검: 네트워크/키 존재/브로커 api 조합/필수 설정 여부
  - 자동 실행: 가능한 태스크만 순서대로 실행하고, 실패 태스크는 원인·대안 제시
  - 실행 리포트: "무엇을 했는지/무엇이 안됐는지/다음 버튼"을 쉬운 언어로 제공

2. 접근성 모드
  - 큰 버튼/고대비/읽기 쉬운 문장/실수 방지 확인 UX
  - 음성 입력(STT) + 음성 안내(TTS) 기반의 단계별 진행
  - "초보 모드"에서 전문 용어 자동 치환(예: API 키=연결 비밀번호)

3. AI 상담 설정 가이드
  - 거래소/증권사별 키 발급 절차를 대화형 체크리스트로 안내
  - 사용자 환경(OS/브로커/계정상태)에 맞는 설정 후보 생성
  - 저장 직전 변경 diff와 영향 범위를 요약 후 최종 확인

### 안전 원칙(필수)
- 고위험 작업(실주문 허용, 브로커 변경, 키 저장)은 `2단계 확인` 없이는 반영하지 않는다.
- AI가 생성한 설정은 즉시 저장하지 않고 "미리보기 + 사용자 승인"을 거친다.
- 키/민감정보는 로그에 마스킹하고, 음성 출력으로 키 원문을 읽지 않는다.

### 맹점/리스크와 대응
1. 과신 리스크: 사용자가 AI를 "자동 투자 실행자"로 오해할 수 있음
  - 대응: 모든 화면에 판단/설명과 실행 책임 경계 문구 고정
2. 음성 인식 오류: 잘못 들은 명령으로 오설정 가능
  - 대응: 숫자/핵심 키 변경은 텍스트 재확인 단계 강제
3. 브로커 정책 편차: 증권사별 절차/필드가 수시 변경
  - 대응: 절차 템플릿 버전 관리 + 실패 시 최신 가이드 링크 제공
4. 접근성 역효과: 단순화가 과도하면 고급 사용자 불편
  - 대응: 초보/고급 모드 분리, 언제든 모드 전환 가능

### 착수 순서 (기존 1·2·3 이후)
1. POC: `AI 실행` 버튼 + 실행 계획 미리보기 + 실패 복구 안내
2. 접근성 UX: 고대비/큰 글자/음성 안내/초보 모드 용어 치환
3. AI 상담 가이드: OpenAPI 발급/연결 대화형 안내 + 설정 diff 승인
4. 회귀테스트: AI 실행 플로우, 음성 fallback, 설정 승인 게이트

### 기술 범위 및 책임 경계
