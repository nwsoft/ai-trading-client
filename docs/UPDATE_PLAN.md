### 2026-07-30 AI 커스텀 제품 계약·거래 파이프라인 정합화

#### 왜 지금 이 작업을 하는가

NoahAI 기본 AI는 실제 사용자 데이터와 거래 결과를 장기간 축적하면서 판단 품질을 높이는 구조다. 그러나 신규 사용자가 수개월의 학습 기간과 초기 손실을 견뎌야만 제품 가치를 확인할 수 있다면 무료 사용자는 학습 표본이 쌓이기 전에 이탈하고 유료 사용자도 비용 때문에 남아 있는 상태가 될 수 있다.

AI 커스텀은 이 문제를 해결하는 핵심 제품 전략이다. 사용자가 이미 이해하거나 시장에서 널리 사용하는 이동평균·추세 추종·눌림목·RSI 평균회귀·거래량 돌파·TradingView/Pine·영상·책·문서 전략을 즉시 실행 가능한 선언형 규칙으로 연결한다. NoahAI는 그 전략을 자신의 기본 전략으로 바꾸지 않고, 적합한 시장국면을 판단하고 국면 전환·계좌 위험·거래소 주문·연결 상태를 감독하며 전략별 결과를 기록한다.

제품 구조는 다음 한 문장으로 고정한다.

> 시중 전략의 실행력 + NoahAI의 시장국면 판단·감독·보호·기록

“TradingView·전략식 자동매매의 상위 전략 운영 계층”이라는 표현은 차트·Pine 생태계 전체를 대체한다는 뜻이 아니다. 외부 전략을 구조화하고, 적합한 국면에서 선택하며, 사용자가 모니터링하지 못하는 동안 국면 변경과 계좌·주문 위험을 감독하는 현재 제공 범위만 가리킨다. 수익·승률 보장 표현은 사용하지 않는다.

#### 불변 역할 계약

AI 커스텀에는 서로 다른 세 축이 있으며 화면·설정·로그에서 섞어 부르지 않는다.

| 축 | 값 | 의미 |
|---|---|---|
| 전략 역할 | 기본 AI 후보 확인(권장) `confirm` | NoahAI LONG/SHORT 후보를 사용자 전략 조건으로 허용·차단 |
| 전략 역할 | 사용자 전략 독립 후보 `independent` | 기본 AI가 HOLD여도 사용자 원형 전략이 LONG/SHORT 후보 생성 |
| 실행 안전등급 | 검증 통과 운용 `standard` | 실행검증을 통과한 전략의 일반 운용 |
| 실행 안전등급 | 1배·1% 제한시험 `limited_live` | 검증 결과를 이해한 사용자가 명시적으로 선택한 최소단위 시험 |
| 주문 환경 | LEARNING/PAPER/LIVE | 판단만 기록할지, 가상 체결할지, 실제 주문 후보로 보낼지 결정 |

`confirm`에서는 기본 AI가 방향을 만들고 커스텀 전략이 진입조건을 재확인한다. 선택된 커스텀 전략에 명시적 청산·TP/SL이 있으면 그 거래의 전략별 청산계획으로 보존한다.

`independent`에서는 사용자 전략이 진입 방향·지표·시간봉·임계값·TP/SL·청산 조건을 결정한다. NoahAI 기본 LONG/SHORT 동의, 기본 신호 임계값, 기본 전략 합의 점수, 전체 NoahAI 거래 성과를 근거로 사용자 전략을 다시 변형하거나 차단하지 않는다. 활성 전 실행검증과 해당 전략 버전·거래소·국면별 성과 검증은 별도로 유지한다.

#### 전략 무결성과 사용자 보호의 분리

NoahAI가 임의로 바꾸면 안 되는 전략 무결성:

- 진입 지표·조건과 LONG/SHORT 방향
- 시간봉·지표 기간·임계값
- 전략에 명시된 TP/SL과 청산·재진입 조건
- 대상 시장국면·전략 우선순위
- 전략 버전과 원문/XAI 근거

항상 유지할 계좌·주문 안전 경계:

- LEARNING/PAPER/LIVE와 실제 주문 실행 권한
- API 연결·시세 신선도·최소 주문액·가격/수량 단위
- 중복 주문·부분 체결·주문 실패·재시작·긴급 정지
- 계좌 전체 최대손실·총 증거금·포지션 수·집중도 상한
- 거래소·증권사 기능 지원 여부와 주문 규격
- 전략 조건 계산에 필요한 데이터가 없을 때의 HOLD

두 경계가 충돌하면 전략값을 몰래 고치지 않는다. 예를 들어 전략 SL 2%가 계좌 위험예산을 초과하면 SL을 1%로 좁히지 않고 수량을 축소한다. 안전한 최소 수량으로도 불가능하면 주문을 차단하고 요청값·허용값·차단 이유를 기록한다. 거래소 가격·수량 단위로 인한 최소 반올림은 요청값과 실제 제출값을 함께 표시한다.

시장국면 이탈 시에도 전략 임계값을 억지로 보정하지 않는다. 사용자가 전략에 저장한 정책에 따라 커스텀 신규 진입을 일시정지하거나 기본 NoahAI로 위임하거나 같은 국면용 승인 전략을 선택한다. 기존 포지션은 진입 당시 전략 버전의 청산 규칙을 우선하고 계좌 긴급보호만 최상위에서 개입한다.

#### 확정 실행 파이프라인

공통 전처리:

1. 거래소·증권사 지원 유니버스 확인

#### SelectionPolicy와 StrategyUniversePolicy

일반과 고급은 같은 전략 목적이 아니므로 종목 선정도 분리한다.

- 일반 `SelectionPolicy`: 사용자 고정 종목을 먼저 포함하고 NoahAI 시장·유동성 자동 후보로 남은 자리를 채운다. 종목 분석과 기본 AI 후보 뒤에 커스텀 `confirm`을 한 번 적용한다.
- 고급 `StrategyUniversePolicy`: 사용자 고정·전략 포함 종목을 우선하고 제외 종목, 최소 거래대금, 최대 스프레드, 최소/최대 변동성, 최대 후보 수를 로컬에서 적용한다. 전략 지표 뒤에 `independent`를 한 번 평가한다.
- 고정·포함 종목은 평가 대상을 보장할 뿐 진입이나 주문을 강제하지 않는다.
- 후보선정 필터는 로컬 시장 데이터만 사용해 종목 수만큼 LLM 비용을 만들지 않는다.

전략의 국면 기준은 `regime_scope=market/symbol/both/none`으로 명시한다. 기본은 `market`이며 `symbol`은 개별 종목, `both`는 둘 다 일치, `none`은 국면 차단을 사용하지 않는다. 선택 범위 데이터가 없으면 다른 범위로 조용히 대체하지 않고 HOLD와 사유를 기록한다.

`exchange:binance`는 Binance 후보에만, `asset:crypto`는 활성 암호화폐 거래소 각각의 독립 후보에, `broker:kiwoom`은 키움 후보에만 적용한다. `asset:all`도 한 거래소의 코인 목록을 다른 거래소나 증권사에 복사한다는 뜻이 아니며, 각 대상의 유니버스와 주문 규격을 독립적으로 유지한다.

#### 동일 기회와 다중 거래소·증권사 실행

동일 BTC·주식 신호가 여러 대상에서 발생하는 것은 중복 오류가 아니다. 실제 주문 대상과 안전검사를 통과하면 기본 `parallel`에서는 각 대상에서 실행한다.

- `parallel`: 각 대상 요청 수량 유지
- `split`: 요청 수량을 실제 주문 대상 수로 분할
- `best`: 저장된 비용표·명시 대상 또는 실제 주문 목록의 첫 번째 대상 한 곳만 허용

세 방식은 자산군·기준 심볼·방향·전략 버전·시간창으로 동일 기회 ID를 만들고 통합 예상 노출·손실과 대상별 결과를 기록한다. 동일 대상·계좌·신호의 재제출만 멱등성 키로 차단한다.

#### ExitPolicy: 청산값 세 계층

모든 자산의 런타임 계산 단위는 `fraction` 하나다. 화면의 주식 5% 같은 퍼센트 포인트 입력은 실행 경계에서 한 번만 `0.05`로 변환한다.

| 계층 | 의미 | 변경 주체 |
|---|---|---|
| 저장된 기본 폴백 | 전략·동적 계산을 만들 수 없을 때의 마지막 안전 기준 | 사용자 설정 |
| 현재 적용 청산값 | 현재 종목·국면·변동성 또는 승인 커스텀 전략이 결정한 TP/SL과 근거 | 기본 AI 동적 정책 또는 선택 전략 |
| 보험 주문 제출값 | 진입가와 거래소 tick/precision을 적용해 실제 제출·확인한 가격과 주문 상태 | 거래소/증권사 어댑터 |

고급 커스텀은 두 번째 계층을 사용자 전략 원형으로 고정한다. 계좌 위험은 그 값을 좁히지 않고 수량을 줄이거나 주문을 차단한다. Binance는 조회로 확인한 보험 가격을, Unified 선물은 어댑터 제출값을 기록한다. 서버 측 보험 주문이 없는 현물·증권 경로는 값을 꾸며내지 않고 `모니터 청산·보험 주문 미제출`로 기록한다.

LEARNING도 1~9의 판단 파이프라인을 실행하고 10번의 주문 제출만 차단한다. “커스텀 전략이었다면 어떤 후보·수량·청산계획·주문 규격을 만들었는지”를 전략 버전·국면별로 기록한다. 학습은 초기 사용의 전제조건이 아니라 전략 선택·국면 감지·비용·체결 품질을 시간이 지나며 개선하는 후행 기능이다.

#### YouTube 전체 맥락 분석·브라우저 연결 고도화 계획 (v3.9.0+)

현재 기준:
- 현재 NoahAI 클라이언트만으로도 `AI 커스텀`에 YouTube URL을 입력해 한국어/영어 자막, 제목·제작자와 대표 장면 최대 9개를 분석할 수 있다.
- 일반 watch, Shorts, youtu.be, embed, live 주소를 동일 ID로 정규화하고 공개/자동 자막 실패 시 yt-dlp 자막과 최대 45분·24MB AI 음성 전사를 순차 사용한다.
- 자막·음성·화면 근거가 모두 없으면 제목만으로 전략·setting을 생성하지 않으며 필수 조건을 누락 상태로 반환한다.
- 현재 방식은 브라우저 화면을 직접 읽는 방식이 아니며, 사용자가 입력한 URL을 `strategy_source_ingestor`가 수집하는 독립형 클라이언트 방식이다.
- 자막 전체 텍스트는 사용하지만 자막 타임스탬프와 차트 장면을 정밀하게 연결하지 않으며, 대표 장면 사이의 짧은 조건은 누락될 수 있다.

목표:
- 브라우저 AI의 간단한 영상 요약 UX를 참고하되, NoahAI는 요약에서 끝내지 않고 `발언/화면 근거 -> 진입·청산·손절·익절 규칙 -> setting -> XAI -> 사용자 승인`까지 추적 가능하게 만든다.
- 클라이언트에 완전한 브라우저를 먼저 내장하지 않는다. 기존 URL 분석을 고도화하고, 필요하면 Chrome/Edge의 현재 탭을 명시적 사용자 동의로 NoahAI에 전달하는 선택형 연결 기능을 우선한다.

단계별 구현 후보:

1. P1 — 클라이언트 URL 분석 고도화(우선)
  - 자막 원문의 시작 시각·지속 시간을 보존하고 긴 영상은 구간별로 나눠 분석한다.
  - 고정 9장만 사용하는 방식에 장면 전환·차트 변화·매매 마커 감지 기반 적응형 프레임 추출을 추가한다.
  - 완료: 사용자가 `AI 분석 및 전략 초안 만들기`를 실행한 URL에 한해 자막 실패 시 비용 안내 범위 내 선택형 AI 음성 전사를 사용한다.
  - 발언, 차트 화면, OCR 결과를 타임코드 근거로 연결하고 각 전략 규칙에 출처 시점을 표시한다.

2. P2 — Chrome/Edge 선택형 브라우저 브리지
  - 브라우저 확장 또는 로컬 헬퍼의 `현재 영상을 NoahAI로 분석` 동작으로 현재 URL·제목·사용자가 선택한 자막/화면 근거를 클라이언트에 전달한다.
  - 사용자가 버튼을 누른 현재 탭만 처리하며 브라우저 기록, 쿠키, 비밀번호, 인증 토큰을 수집하거나 저장하지 않는다.
  - 구독/로그인/보호 콘텐츠의 접근통제를 우회하지 않는다. 사용자가 열람·내보내기 권한을 가진 텍스트·Pine·이미지만 명시적으로 전달한다.
  - 브리지가 없어도 기존 URL 붙여 넣기와 파일/Pine 입력은 계속 동작하도록 선택 기능으로 유지한다.

3. P3 — 선택형 내장 WebView 검토(후순위)
  - 브라우저 확장 설치가 어려운 환경에서만 클라이언트 내부 URL 미리보기와 `현재 장면 캡처/분석` 기능을 검토한다.
  - 로그인 세션, DRM, 사이트 약관, 샌드박스, 자동 업데이트 및 보안 패치 유지 비용을 평가한 뒤 채택 여부를 결정한다.
  - 전체 브라우저 엔진 내장은 필수 구현이 아니며, P1/P2로 동일한 사용자 흐름이 충족되면 도입하지 않는다.

전략 변환·실행 안전 기준:
- 단순 영상 요약과 실행 전략 생성을 분리한다. 요약 성공만으로 전략을 자동 적용하지 않는다.
- 진입·청산·손절·익절·대상 자산·시간봉 중 누락된 조건은 AI가 임의 추정하지 않고 사용자 재확인을 요구한다.
- 추출된 AND/OR 조건과 레버리지·TP/SL·포지션 비율·신호 임계값은 현재 AI 커스텀 승인/실행검증/가드레일 경로만 사용한다.
- 영상 제작자의 주장과 과거 성과 표시는 전략 유효성 또는 수익 보장 근거로 사용하지 않는다.

## NoahAI의 정체성 (최상위 전제)

1. NoahAI는 "재테크 플랫폼 / 자산 운용 시스템 / 자동 투자 시스템"이 아니다.
2. NoahAI는 **AI 자산 의사결정 인프라 (AI Asset Decision Infrastructure)** 이다.
3. NoahAI는 판단·설명·기록·검증·환류만 담당한다.
4. 주문·체결·자금 이동·세무 신고·법적 행위는 항상 외부 주체(API·기관·사용자) 책임이다.
5. 본 문서는 "개발 로드맵"이 아니라 **기술 인프라 확장 계획서**로 읽혀야 한다.

### 용어/메뉴 정합성 기준 (2026-04-25 반영)

- 금지 표현: `AI 자산 운용 엔진`, `멀티자산 AI 트레이딩 운영 시스템`
- 권장 표현: `AI 금융 의사결정 엔진`, `멀티자산 AI 금융 판단 인프라`
- UI/문서 메뉴명은 목적 기반으로 유지한다.
  - 예: `글로벌자산` → `자산 통합` 또는 `글로벌 금융 인사이트`
- 거래 지표는 보조 지표로만 사용하고, 최상위 KPI는 판단 품질 중심으로 둔다.
  - 판단 로그 완결률, 재현 가능률, 리스크 경고 적중률, 설명 만족도, 질문 해결률

### 도메인 계층 (문서/메뉴 공통 분류)

3. Risk Protection Domain: 금융사기·이상거래·고위험 선택 회피
4. Accessibility Domain: 고령층/디지털 약자 접근성, 음성·쉬운 설명
5. Assistant Interface Layer: 대화형 질의응답, 설명·비교·경고 인터페이스

AI 의사결정 인프라를 구축한다.

### 핵심 설계 원칙
1. **판단과 실행의 분리**
   - NoahAI는 판단·설명·기록만 담당한다.
   - 실행은 항상 외부 시스템이 담당한다.

2. **자산군 불변 파이프라인**
   - 암호화폐, ETF, 주식, 선물, 부동산은 모두 동일한 판단 계층을 사용한다.

3. **설명 가능성과 재현성**
   - 모든 판단은 로그로 남고, 사후 검증이 가능해야 한다.

4. **보수적·중단 가능 구조**
   - 언제든 판단을 중단하고, 인간이 개입할 수 있어야 한다.

### 현재 상태 명확화 (2026-04-24)

#### ✅ 완료: 다중 거래소 동시 연결

- 각 거래소에서 **독립적으로** 신호 수신 및 거래 실행
- 통합 잔고 관리, 통계 추적

#### 🚧 진행 중: 거래소별 독립 거래
- 현재: 각 거래소에서 별도로 판단 신호를 받아 거래 실행
- 상태: 실제 운영 중 (v3.8.9.13 기준)

#### 📋 계획 단계: 차액거래 (Arbitrage)

**차액거래란?**
- 서로 다른 거래소에서 같은 코인의 가격 차이를 이용한 거래
- 예: A 거래소 BTC $46,000 ↔ B 거래소 BTC $46,100
  - B에서 매도, A에서 매수 → 차이 $100 (수수료 제외)

**구현 계획**
1. **실시간 가격 모니터링**: 모든 거래소의 실시간 시세 비교
2. **차액 계산 (수수료 포함)**
   - 거래소별 Maker/Taker 수수료 자동 계산
   - 입출금 수수료 포함
   - 환전 스프레드 고려
3. **수익성 판정**: 차액 > (수수료 합계) 일 때만 실행
4. **자동 실행**: 조건 충족 시 양쪽 거래소에 동시 주문

**기술 과제**
- API 지연 시간 최소화 (양쪽 거래소 동시 주문 필요)
- 규제 이슈 검토 (높은 빈도 거래의 합법성)
- 자본금 요구사항 (양쪽 거래소에 동시 자본 필요)

**현재 구현 여부**: ❌ **미구현** (로드맵 항목)

**단기 목표**: 이번 스프린트에서는 차액거래 자체 구현이 아니라 가격 감시 데이터 구조와 화면/문서 정합성까지만 다룬다.

## Phase G — AI 원버튼 실행/접근성 모드 (2026-05-07 제안 반영)

### 목표
- 대시보드의 `모두시작`을 단순 일괄 실행이 아니라, 사용자 상태를 읽고 필요한 단계만 실행하는 `AI 실행` 버튼으로 전환한다.
- 고령층/디지털 취약계층/초보 사용자를 위해 음성 또는 버튼 1회로 "진단 → 안내 → 확인 → 적용" 흐름을 제공한다.
- 거래소/증권사 OpenAPI 키 발급과 설정을 `AI 상담`에서 단계별로 안내하되, 보안·법무 경계를 침범하지 않는다.

### 핵심 기능
1. AI 실행(원버튼)
  - 시작 전 자동 점검: 네트워크/키 존재/브로커 api 조합/필수 설정 여부
  - 자동 실행: 가능한 태스크만 순서대로 실행하고, 실패 태스크는 원인·대안 제시
  - 실행 리포트: "무엇을 했는지/무엇이 안됐는지/다음 버튼"을 쉬운 언어로 제공

2. 접근성 모드
  - 큰 버튼/고대비/읽기 쉬운 문장/실수 방지 확인 UX
  - 음성 입력(STT) + 음성 안내(TTS) 기반의 단계별 진행
  - "초보 모드"에서 전문 용어 자동 치환(예: API 키=연결 비밀번호)

3. AI 상담 설정 가이드
  - 거래소/증권사별 키 발급 절차를 대화형 체크리스트로 안내
  - 사용자 환경(OS/브로커/계정상태)에 맞는 설정 후보 생성
  - 저장 직전 변경 diff와 영향 범위를 요약 후 최종 확인

### 안전 원칙(필수)
- 고위험 작업(실주문 허용, 브로커 변경, 키 저장)은 `2단계 확인` 없이는 반영하지 않는다.
- AI가 생성한 설정은 즉시 저장하지 않고 "미리보기 + 사용자 승인"을 거친다.
- 키/민감정보는 로그에 마스킹하고, 음성 출력으로 키 원문을 읽지 않는다.

### 맹점/리스크와 대응
1. 과신 리스크: 사용자가 AI를 "자동 투자 실행자"로 오해할 수 있음
  - 대응: 모든 화면에 판단/설명과 실행 책임 경계 문구 고정
2. 음성 인식 오류: 잘못 들은 명령으로 오설정 가능
  - 대응: 숫자/핵심 키 변경은 텍스트 재확인 단계 강제
3. 브로커 정책 편차: 증권사별 절차/필드가 수시 변경
  - 대응: 절차 템플릿 버전 관리 + 실패 시 최신 가이드 링크 제공
4. 접근성 역효과: 단순화가 과도하면 고급 사용자 불편
  - 대응: 초보/고급 모드 분리, 언제든 모드 전환 가능

### 착수 순서 (기존 1·2·3 이후)
1. POC: `AI 실행` 버튼 + 실행 계획 미리보기 + 실패 복구 안내
2. 접근성 UX: 고대비/큰 글자/음성 안내/초보 모드 용어 치환
3. AI 상담 가이드: OpenAPI 발급/연결 대화형 안내 + 설정 diff 승인
4. 회귀테스트: AI 실행 플로우, 음성 fallback, 설정 승인 게이트

### 기술 범위 및 책임 경계
- **NoahAI 책임**: 정보 수집·비교·분석·설명·기록·경고
- **외부 책임**: 실행(가입/이체/계약), 법적 행위, 세무 신고
