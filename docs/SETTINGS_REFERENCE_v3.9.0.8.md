# NoahAI 설정·기능 안내 v3.9.0.8

기준일: 2026-08-10  
대상: 처음 사용하는 사용자, 기존 사용자, 테스터, 고객지원 담당자  
상태: 소스 기능 기준. Windows 새 설치본·실계정 장시간 E2E는 별도 검증

## Fix 4 AI 호출비와 LIVE 주문 안전 기준

사용자 제공 DeepSeek 통계와 로컬 `ai_market_call_budget.json`을 대조한 결과, 2026-07-24부터 08-09까지 매일 기존 시장 호출 한도 1,200회를 정확히 소진했습니다. 이는 사용자 착각이 아니라 자동 시장분석이 지속 중인 LONG/SHORT·RSI 극단 상태와 단순 새 캔들을 반복 이벤트로 본 실제 문제입니다. 다만 Provider 화면만으로 `3.9.0.7` 배포가 유일한 원인이라고 단정할 수는 없습니다.

| 설정 | Fix 4 기본값 | 의미 |
|---|---:|---|
| `stable_state_cache_sec` | 1,800초 | 같은 시장상태 AI 결과 재사용 |
| `minimum_event_interval_sec` | 300초 | 미세 가격·RSI 변화의 최소 호출 간격 |
| `exploration_interval_sec` | 1,800초 | 안정 상태의 주기적 재확인 |
| `max_daily_market_calls` | 240회 | 시장분석 전역 일 한도 |
| `max_daily_calls_per_exchange` | 40회 | 거래소별 시장분석 일 한도 |
| `max_monthly_market_calls` | 6,000회 | 시장분석 월 한도 |
| `max_daily_automatic_ai_calls` | 360회 | 모든 자동 AI 역할 합계 일 한도 |
| `max_monthly_automatic_ai_calls` | 9,000회 | 모든 자동 AI 역할 합계 월 한도 |
| `pattern_similarity_cache_sec` | 900초 | 같은 손실패턴 비교 재사용 |

기존 설정 파일에 1,200/300/30,000이 남아 있어도 `allow_high_cost_limits=false`이면 240/40/6,000의 hard ceiling을 적용한다. Fix 4 첫 실행은 이전 누적을 삭제하지 않고 `legacy_snapshot`에 보존한 뒤 새 정책 카운터를 시작하므로, 이미 8월 누적이 6,000회를 넘었다는 이유로 월말까지 전부 차단되지 않는다. 한도 도달은 거래 중지 조건이 아니며 로컬 신호와 국면·계좌·주문 검증은 계속한다. 사용자가 AI 어시스턴트에 직접 보낸 질문은 자동매매 호출예산과 분리한다.

LIVE 암호화폐 주문은 SQLite `crypto_order_commands`에 명령을 먼저 선점하고 Binance `newClientOrderId`, Bybit `orderLinkId`, OKX `clOrdId`, Bitget `clientOid`, Upbit `identifier`로 같은 명령을 연결한다. 현재 Bithumb CCXT 어댑터는 `client_order_id`를 지원하는 새 `/v2/orders`가 아니라 구형 주문 endpoint를 사용하므로 미지원 값을 억지로 보내지 않고 로컬 명령 원장만 적용한다. 인증·잔고·주문규격·포지션 불일치·전송 모호·rate limit을 분류하며, 청산 결과가 모호한 경우 지원 거래소는 client-order ID로 먼저 조회하고 확인되지 않으면 자동 재제출과 해당 거래소 신규 진입을 중단해 이중 청산을 방지한다. Windows 설치본과 거래소별 소액 LIVE 재시작 E2E는 아직 외부 검증 대상이다.

## 처음 설정하는 권장 순서

1. `일반`에서 처음에는 PAPER를 켠다.
2. `거래소 선택`에서 관찰·분석 대상과 실제 주문 허용 대상을 구분한다.
3. `거래소 API`에는 필요한 거래소만 연결한다. 지원 문의에 Key·Secret·Passphrase·UID·IP 값을 보내지 않는다.
4. `AI 엔진/API`는 처음에는 균형형 모델 프리셋과 AI 커스텀 `일반(권장)`을 사용한다.
5. `고급 매매 계층`은 `safe(신규 권장)`를 적용하고 LEARNING/PAPER에서 7~14일 관찰한다.
6. `AlphaArena`는 처음에는 OFF로 둔다.

## AI 엔진/API와 AI 커스텀 사용 난이도

AI 엔진/API에는 서로 다른 목적의 설정이 함께 있다.

| 항목 | 역할 | 신규 사용자 권장 |
|---|---|---|
| AI 애널리스트 | 시장 분석과 기본 신호 후보 | 균형형 |
| AI 어시스턴트 | 대화·설명·설정 안내 | 균형형 |
| 빈번/표준/정밀 역할 | 호출 빈도와 분석 중요도별 Provider·모델 배치 | 원클릭 균형형 |
| AI 커스텀 런타임 | 승인·검증된 사용자 전략을 실제 판단 경로에 포함 | PAPER 준비 전 OFF |
| AI 커스텀 사용 난이도 | 화면 복잡도와 기능 노출의 시작값 | 일반 |

사용 난이도는 서로 다른 전략 엔진이나 위험 등급이 아니다. 같은 전략 ID·버전·IR을 Level 1~3에서 다르게 보여 주는 화면 프로필이다. 개별 고급 기능은 기본으로 접혀 있으며 필요할 때만 펼친다.

- 초보자: Level 1, 원본 근거·누락·PnL/MDD·품질 경고 중심
- 일반: Level 2, 핵심값·월별/연별 표·전략 패키지
- 고급: Level 3, 전체 IR·Expression Graph·제한형 사용자 지표 언어
- 실험실: 고급 기능과 외부 서명 webhook 검증 계약

프로필이나 토글은 사용자 승인, 검증, 시장국면, 계좌 위험, 주문 안전을 끌 수 없다. 분석 전에는 XAI 결과가, 자동검증 전에는 PnL/MDD·기간표가 아직 보이지 않는 것이 정상이다.

## webhook이 필요한 경우와 필요하지 않은 경우

NoahAI가 연결된 지정 거래소의 데이터를 분석하고 앱 안의 전략으로 주문 후보를 만들 때는 webhook이 필요하지 않다. 거래소 API가 시세·잔고·주문 연결이고, webhook은 거래소 연결 방식이 아니다.

webhook은 TradingView 같은 외부 서비스가 만든 알림을 NoahAI로 들여올 때만 사용하는 선택형 입력 통로다. 외부 신호도 저장 전략 버전, 사용자 승인, 실행 권한, 시장국면, 계좌 위험과 주문 가드레일을 다시 통과하는 주문 후보일 뿐이다.

현재 소스에는 HMAC 서명·시간창·nonce·delivery ID 중복 검증 계약이 있다. 운영 서버 endpoint, 재시작 후에도 유지되는 nonce 저장소, 실제 TradingView 재전송 E2E가 완료됐다는 뜻은 아니다. 따라서 실험실 프로필 외에는 강제로 OFF되며, 일반 사용자는 사용하지 않는다.

## AI 멘토 인터뷰와 처음 사용법 AI에게 묻기

- `AI 멘토 인터뷰`: 경험·목표·위험 허용도 등 8문항을 묻고 교육용 전략 후보 2~3개를 만든다. 자동 저장·승인·적용하지 않는다.
- `처음 사용법 AI에게 묻기`: 현재 화면과 프로필을 기준으로 입력 → XAI → 저장 → 승인 → 자동검증 → PAPER 순서를 설명한다. 개인화 전략을 만들지는 않는다.

전략이 전혀 없으면 멘토로 시작하고, Pine·TradingView·문서·영상 또는 이미 가진 규칙이 있으면 사용법 안내를 따라 자료를 입력한다.

## 고급 매매 계층

고급 매매 계층은 새로운 전략을 만드는 기능이 아니라 표준 자동매매의 후보를 뒤에서 검사하는 다섯 개 정책이다. Binance·Bybit·OKX·Bitget·Upbit·Bithumb과 연결된 증권 실행 경로에 적용되며 LEARNING은 주문 계층을 실행하지 않는다. AlphaArena에는 적용되지 않는다.

| 계층 | 역할 |
|---|---|
| 수익성 검증 | 거래수·승률·샤프·MDD·워크포워드와 Hard MDD 검사 |
| 포트폴리오 오케스트레이션 | 자산군 예산·단일 자산 집중·상관관계 제한 |
| 전략 엔진 | 시장국면·다중 신호 합의·심볼 재진입 쿨다운 |
| 실행 최적화 | 재시도·시간 제한·슬리피지·시장가 대체 정책 |
| 운영 자동화 | 거절률·슬리피지·품질 이상 감지·롤백·브리핑 근거 |

`safe`는 신규 사용자 권장이다. 주요 값은 최소 종료 거래 20개, 최소 승률 0.45, 최소 샤프 0.35, 최대 MDD 0.25, 단일 자산 0.25, 합의 임계값 0.70, 쿨다운 120초, 최대 슬리피지 25bps다. 이는 수익을 보장하는 숫자가 아니라 더 보수적으로 통과시키는 시작값이다.

`aggressive`는 통과 기준을 낮추므로 기회와 오탐·손실 가능성이 함께 커진다. `전체 OFF`는 개발·진단용이며 실거래 권장 프리셋이 아니다.

### 고변동장 처리

- `평가 계속` 기본값: 고변동장을 자동 허용하는 것이 아니다. 합의·수익성·국면·계좌·주문 검사를 계속한다.
- `항상 차단`: 고변동장 신규 진입 후보를 모두 막는다.

급등락을 일괄 피하려는 PAPER 초기에는 차단할 수 있다. 거래 기회가 적다는 이유만으로 해제하기 전에 최근 로그에서 실제 차단 원인이 고변동장, 합의, 수익성, 쿨다운 중 무엇인지 확인한다.

## AlphaArena

AlphaArena는 기본 OFF인 숙련자용 독립 실험 모드다. 표준 자동매매의 지정 거래소 전체를 사용하는 기능이 아니라 Binance USDT 선물 전용이며, 현재 설정 화면의 실행 선택은 DeepSeek V4 Flash 하나다. 기존 Qwen 키는 호환 보관되지만 현재 실행 선택으로 노출하지 않는다.

실행 흐름은 `시장 데이터·직전 결과 → LLM 구조화 판단 → 파서 → AlphaArena 주문 게이트 → Binance 선물 주문`이다. 표준 수익성·포트폴리오·전략 합의 계층과 기존 TP/SL 보험·워치독을 공유하지 않는다. 대신 AlphaArena 자체 게이트가 다음을 검사한다.

- 판단 주기 60초, 최소 30초
- 기본 심볼 BTC·ETH·SOL·XRP·DOGE·BNB
- 레버리지 10~20배 제한
- 진입마다 profit target과 stop loss 필수
- 심볼별 쿨다운 30초
- 최대 동시 포지션 6개
- 틱당 모델 제시 위험 합계 상한 1,500 USDT

틱 위험 상한은 계좌 전체 손실 상한이나 수익 보장이 아니다. 소스 단위 테스트 통과는 Windows 설치본, 실제 계정 권한, 부분체결, 재시작 복구, 장시간 운용이 검증됐다는 뜻이 아니다.

## 백테스트와 PAPER

백테스트는 규칙이 과거 데이터에서 올바르게 작동하는지, 비용 후 PnL이 음수인지, MDD가 과도한지, 기간별로 특정 구간에만 맞춰졌는지를 보는 최소 통과조건이다. 미래 수익 예측이나 홍보 수치가 아니다.

현재 시장에서 같은 전략 버전이 어떻게 작동하는지는 PAPER 전진검증이 더 중요하다. 권장 순서는 `과거 최소 필터 → PAPER 7~14일 이상 → 체결·슬리피지·국면 피드백 → 필요한 경우 새 버전 → 소액 LIVE E2E`다.

## 배포와 검증 경계

v3.9.0.8 소스 기능이 완성되고 자동 테스트를 통과해도 새 Windows EXE와 SHA-256이 만들어지고 실제 설치·화면 배율·대표 입력·장시간 PAPER·소액 LIVE를 확인하기 전에는 테스터 배포 완료가 아니다. 테스터는 API 키나 개인정보가 없는 재현 순서와 화면 캡처만 전달한다.
