# 거래소 설정 가이드

이 문서는 API 키 유무와 관계없이 안정적으로 실행할 수 있도록, 빠른 시작부터 멀티거래소 설정과 로그 소음 최소화 팁까지 한 곳에 정리했습니다.

## ⚡ TL;DR 빠른 시작
- API 키 없이도 실행 가능: 기본 페이퍼 모드로 안전하게 구동됩니다.
- 환경설정 핵심 키
    - enabled_exchanges: 사용할 거래소 목록
    - selected_exchange: 기본 선택 거래소(없으면 첫 항목 자동)
    - paper_trading: true 권장(실제 주문 방지)
    - log_level: INFO 권장(소음 최소화)

> ✅ **교차 체크 정책 적용(v3.7.7+)** — UI에서 체크한 거래소만 `enabled_exchanges`에 남으며, 백엔드 전 구간이 이 목록을 기준으로 실제 호출 여부를 결정합니다. 세부 구현은 아래 “활성화 로직” 절을 참고하세요.

예시(settings.json의 일부)
```json
{
    "enabled_exchanges": ["binance", "okx", "bitget"],
    "selected_exchange": "binance",
    "paper_trading": true,
    "log_level": "INFO"
}
```

개발 편의(로그인 우회) 환경변수
```bash
export NOAHAI_SKIP_LOGIN=1
```

고전 UI를 선호하면
```json
{ "classic_view": true }
```

## 🛠️ 설치 및 설정

### 1. 필수 패키지 설치
```bash
pip install ccxt>=4.0.0
```

### 2. 환경설정에서 거래소 설정
1. **환경설정** → **거래소 설정** 탭
2. 사용할 거래소들의 API 키 입력 (여러 거래소 동시 설정 가능)
    - 선택 입력 가능: API 키가 없는 거래소는 비활성 상태로 유지되며, 탭/구독/로그가 생성되지 않습니다.
    - 페이퍼 모드: `paper_trading=true`이면 실제 주문 없이 시뮬레이션으로 동작합니다.
3. 각 거래소별 연결 테스트 수행

### 2-A. 활성화 로직 (2025-09 적용)
- **핵심 동작**: API 키는 그대로 보관해도 되며, 실제 호출 여부는 `enabled_exchanges` 체크 상태와 `selected_exchange` 폴백으로만 결정됩니다.
- **적용 모듈**
  - `trading/api_signal_manager.py`: `_collect_signals()`와 관련 헬퍼가 비활성 거래소를 완전히 건너뜁니다.
  - `trading/exchange_manager.py`: 클라이언트 생성·잔고/가격 조회·일괄 조회가 `enabled_exchanges`를 우선 확인하도록 통합했습니다.
  - `trading/unified_trader.py`: 초기화/코인 선택/설정 갱신 시 활성 거래소만 관리하며, 비활성 거래소 데이터는 정리합니다.
  - `trading/unified_trading_manager.py`: CCXT 초기화/재연결/잔고·포지션 조회 시 동일한 필터를 사용합니다.
- **테스트/검증**
  - `test_multi_exchange_runtime.py` 등 통합 테스트에서 비활성 거래소 호출이 발생하지 않는지 확인했습니다.
  - 수동 테스트: 설정 창 체크 토글 → 로그/대시보드 반응 즉시 확인 (잔고/신호 호출 차단).
- **문서 반영**: 본 문서와 `docs/MASTER_DOCUMENTATION.md`에 갱신 내역을 기록하고, 사용자 가이드에서 “키 제거” 안내를 “체크 해제” 정책으로 교체했습니다.

### 3. 대시보드에서 거래소 선택
1. **대시보드** → **거래소 탭** 선택
2. 원하는 거래소 탭 클릭
3. **"▶️ 거래 시작"** 버튼으로 자동거래 시작
4. 실시간 모니터링 및 로그 확인

### 4. 다중 거래소 사용
- **동시 거래**: 여러 거래소에서 동시에 거래 가능

## 🧩 참고 노트 (v3.7.7)
- 레버리지 상한은 거래소별 `exchange_risk_overrides.{exchange}.max_leverage` 또는 전역 `settings.max_leverage`를 따르며, 명시 없으면 기본 20으로 clamp됩니다.
- CCXT 어댑터 사용 시 심볼은 `BTC/USDT` 형식을 사용하며, 내부에서 `BTCUSDT` 등으로 자동 정규화됩니다.
 - 기본 동작: `default_margin_type`은 ISOLATED로 설정되어 주문 전 자동 적용됩니다.
 - 로그 소음 최소화 팁: API 키 없는 거래소는 비활성 처리되어 구독/검증 로그가 생성되지 않도록 했습니다. 심볼은 내부 캐시로 유효성 검사를 거쳐 무효 심볼 로그를 줄입니다.

#### 3. ⚠️ 계좌 모드 설정 (필수)
OKX는 선물 거래를 위해 계좌 모드를 올바르게 설정해야 합니다.

**설정 방법**:
1. OKX 웹사이트 로그인
2. **거래** → **설정** → **계좌 모드**
3. 다음 중 하나 선택:
   - **Single-currency margin mode** (단일 통화 마진) - **권장**
     - 각 통화별로 독립적인 마진 관리
     - 리스크 관리가 더 용이
   - **Multi-currency margin mode** (다중 통화 마진)
     - 여러 통화를 하나의 마진으로 사용
     - 자금 효율성이 높음

**주의사항**:
- ❌ "Simple mode"에서는 API 거래가 불가능합니다
- ✅ 계좌 모드 설정 후 프로그램을 재시작하세요
- ✅ 계좌 모드 변경 시 기존 포지션이 있으면 먼저 청산해야 할 수 있습니다

**오류 발생 시**:
- 에러 코드 51010이 나타나면 계좌 모드가 잘못 설정된 것입니다
- 상세한 문제 해결은 `docs/TROUBLESHOOTING.md`의 "OKX 거래소 문제 해결" 참고

#### 4. OKX 특수 사항
- **레버리지 설정**: OKX는 마진 타입 변경 시 레버리지 정보를 필수로 요구합니다 (v3.7.8+에서 자동 처리)
- **심볼 형식**: BTC/USDT:USDT (자동 변환됨)
- **Passphrase**: API 키 생성 시 설정한 Passphrase를 반드시 입력해야 합니다

## 📞 문제 해결

### ❌ 일반적인 문제

#### 1. API 키 인증 실패
```
❌ API 키 인증 실패: Invalid API key
```
**해결방법**: 
- API 키와 Secret 키 재확인
- 거래소에서 API 키 상태 확인
- IP 제한 설정 확인

#### 2. 권한 부족 오류
```
❌ 권한 부족: Insufficient permissions
```
**해결방법**:
- 거래소에서 필요한 권한 활성화
- 선물 거래 권한 확인 (바이낸스)

#### 3. 연결 타임아웃
```
❌ 연결 타임아웃: Request timeout
```
**해결방법**:
- 네트워크 연결 상태 확인
- 방화벽 설정 확인
- VPN 사용 시 VPN 연결 상태 확인

## 🔇 로그 소음 최소화 체크리스트
- API 키 미입력 거래소는 비활성: 탭/구독/REST 호출이 발생하지 않습니다.
- BinanceClient 가드: API 키 부재 시 REST 호출을 생략하고 조용히 반환합니다.
- WS 구독 해제: 탭 전환/비활성 시 서버에 UNSUBSCRIBE를 전송해 잔류 메시지를 줄입니다.
- 심볼 정규화/검증: 내부 캐시로 invalid symbol 로그를 억제합니다.
- log_level=INFO 권장, 필요 시 WARNING 이상으로 조정

## ❓FAQ
- Q: 키가 없어도 가격/오더북은 보이나요?
    - A: WS는 시장 데이터만 사용하므로 키 없이도 동작합니다(거래/계정 관련은 생략).
- Q: 왜 잔고/포지션이 비어 나오나요?
    - A: API 키가 없으면 REST 호출을 생략해 빈 결과를 반환합니다(의도된 동작).
- Q: UI가 너무 심플해 보입니다.
    - A: `classic_view=true`를 사용하면 학습/리포트 중심의 고전 탭 배치를 시작 시 자동으로 활성화합니다.
