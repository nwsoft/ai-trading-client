# v3.9.2.11 내 돈 계획 구현·인수

2026-10-11 / renderer `3.9.2.11-ui.20261011.4` / 공개 기반 3.9.2.10. 이 문서는 기존 세무 감사 이후 추가한 내부 가계 계획의 현재 정본이다. 국내 금융회사 대비 성과 우위, 개인별 절세 최적화, Windows 설치·공개 배포·실제 기관 인수 완료를 뜻하지 않는다.

## 사용 흐름

상단 **자산 통합 → 내 돈 계획**에서 시작한다. 금융비서에 “매달 나가는 돈을 줄이고 절세해서 목돈을 모으고 싶어”, “내 돈 계획을 세우고 싶어”라고 질문한 뒤 같은 화면으로 이동할 수도 있다. 질문 문맥을 보존하되 금액·가입 자격을 임의로 추정하지 않는다. 일반 AI 어시스턴트의 기본 보호 경로·일반 안내에서도 같은 로컬 경로를 제공한다.

1. 월 실수령 수입, 생활비, 연간 비정기 지출과 비상금 개월을 직접 입력한다. 생활비에 반복 결제를 포함하고 부채 상환은 제외한다. 없는 금액도 0을 직접 입력한다.
2. 직접 확인한 자산과 원화 부채를 등록한다. 현금·예금·투자·부동산 등을 구분한다. 다른 통화는 합산하지 않는다. 같은 계좌나 자산을 다른 이름으로 중복 등록하지 않는다.
3. 반복 결제의 현재/변경 후 요금, 변경 비용과 보장 손실을 확인한다. 비용 미확인은 0원이 아니며, 예상 절약은 실제 실적이 아니다.
4. 목표별 사용 시점, 초기 현금·월 배분, 수익률·세율·비용·물가 가정을 입력한다. 미확인 가정은 비워 둔다.
5. 필요하면 소득 종류, 올해 총 연금 납입 계획과 남은 공제 가능 세액을 입력한다. ISA 기본 조건과 공식 법령의 확인·재확인일을 함께 검토한다.
6. 계산 결과와 부족액을 검토한 뒤 암호화 보관함을 열고 명시적으로 저장한다. 저장 계획을 불러오면 현재 금액을 확인해 다시 계산해야 한다. 여러 저장 계획은 서로 비교할 대안이며 동시 실행할 합산 배분이 아니다.
7. 월 실제 수입·생활비·상환·저축과 선택적인 목표 잔액을 기록해 계획 대비 현금과 목표 부족을 확인한다. 이번 달은 마감 전 누적일 수 있다. 은행 대조·절약 효과의 인과관계를 증명하는 기록은 아니다.

다른 내부 화면으로 이동해도 작성 입력을 유지한다. 새 계획 만들기·불러오기는 미저장 변경을 확인한다. 앱을 닫거나 보관함이 잠기면 미저장 입력은 사라진다. 기존 보험/금융계획과 같은 암호화 보관함·비밀번호, 고정 15분 잠금, 백업·복원 기반을 재사용한다. 비밀번호를 잊은 경우 자동 복구하는 서비스를 제공하지 않는다.

## 계산과 보호 계약

`trading/wealth_planning.py`의 결정적 계산은 외부 AI·기관·시세 호출·주문 없이 동작한다. 다음 계산을 분리한다.

- 현재 월 잉여금 = 실수령 수입 − 반복 결제를 포함한 생활비 − 부채 월 상환 − 연간 비정기 지출/12.
- 예상 절약액은 별도 표시한다. 확인한 변경 비용·조건이 있는 절약만 가정 잉여금에 표시하며, 실제 월 배분 한도는 현재 잉여금이다.
- 비상금 목표 = (현재 생활비 + 상환액 + 비정기 지출/12) × 입력 개월. 초기 배분 한도 = 확인 현금 − 비상금 목표 − 확인한 변경 비용, 최소 0.
- 31일 이내 직접 확인한 실제 자산만 통화별 등록 소계로 표시한다. 원화 현금만 목표 배분 재원이다. PAPER·미확인·오래된 자산은 제외하고 사유를 표시한다. 예금·투자·외화와 연결 투자계좌를 자동 합산하지 않는다. 원화 부채만 이 화면에서 지원한다.
- 초기·월 목표 배분 합계가 한도를 초과하거나 월 예산이 적자면 저장을 차단한다. 여러 목표에 같은 현금을 재사용하지 않는다.
- 목표 시나리오는 월말 납입·입력 연 유효수익률, 0% 수익, 5%p 낮은 수익률로 계산한다. 수익에만 입력 세율을 적용하고 만기에 입력 총비용을 차감한다. 세율·비용 미확인 시 세후 금액은 null, 물가 미확인 시 현재가치는 null이다. 실제 상품의 중도해지·추가 납입·분배금·인출 과세는 기존 상품 비교에서 별도로 확인한다.
- 세액공제는 소득 종류별 조건과 연금저축 600만원/IRP 합산 900만원 납입 한도, 입력한 공제 가능 잔여 세액 이내 상한이다. 환급액·연금 수령 순이익·월 현금으로 더하지 않는다. `remaining_tax`는 다른 공제 후 남은 지방세 포함 공제 가능 세액을 사용자가 확인한 값이다.
- 세제 규칙은 2026 귀속, 확인 2026-10-11, 재확인 2026-11-10과 공식 출처를 갖는다. 다른 연도·기한 경과 시 개인 계산을 보류한다. ISA 기본 조건 검토는 최종 가입 심사가 아니며 개인별 비과세 한도는 미확정이다. 비과세종합저축·연금 인출세금·전체 세법 예외를 자동 판정하지 않는다.

근거: [ISA 조세특례제한법 제91조의18](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1033166111), [연금계좌 소득세법 제59조의3](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032884269). 일반 계산을 금융기관의 개인별 승인·견적과 혼동하지 않는다.

## 구조·저장·개인정보

`portfolio.plan`을 Web 전용 추가 기능 계약에 등록한다. 상위 5개 서비스·기존 레거시 메뉴 식별자는 유지하고 Web 기능은 36개가 된다. React `WealthWorkspace`는 6단계와 결과·저장을 제공한다. 좁은 화면 보정은 이 화면 활성 상태에만 적용해 기존 거래 화면의 폭 계약을 바꾸지 않는다.

기존 인증·명시적 의도·동일 계정·원본 검사·no-store를 갖는 `POST /api/v1/life-finance/insurance`, `action=wealth_plan`을 재사용한다. `preview`는 보관함 잠금과 무관하게 계산만 하며 개인 저장소를 만들지 않는다. `list/save/delete/actual`은 열린 동일 계정 보관함이 필요하다. 쓰기에는 `confirmed=true`, 기존 계획에는 정확한 정수 revision이 필요하다. 저장소 파일 지문 충돌도 기존 낙관적 잠금으로 차단한다.

계획은 계정별 `vault.enc`의 `wealth_plans`에 암호화 저장한다. 신규 평문 프로필·브라우저 localStorage를 만들지 않는다. 전체 보관함 백업·복원을 재사용하며 `insurance.snapshot()`에는 가계 계획 본문을 추가 노출하지 않는다. 최대 30개 계획·목록별 30행·계획별 120개월·추가 저장 데이터 4MB로 제한한다. 비정상/무한 수치·공란·잘못된 날짜·미래 관측·중복 이름·알 수 없는 필드를 거절한다. 검증 오류에 입력값을 되돌려 보내지 않는다.

계획 수정은 과거 실제 기록을 덮어 계산하지 않는다. 각 월 실제 기록에 당시 계획 revision·잉여금·배분액·목표액을 함께 보존한다. 실제 잔액 미입력은 목표 실적 null이다. 보관함 잠금·만료·계정 전환·저장 요청 이후 입력 변경은 개인 화면과 오래된 응답을 정리한다. 다른 창의 잠금을 15초 조회/창 초점 복귀 때 확인한다. 만료 시각은 서버의 남은 시간으로 표시 상태를 제한하며 목록 조회로 15분을 연장하지 않는다.
