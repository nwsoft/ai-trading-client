# 개인정보/로그 처리 정책 요약 (2026-04-28)

## 1. 수집 목적

- 사용자 인증/세션 관리
- 서비스 운영 안정성 모니터링
- KPI 집계(운영 지표)

## 2. 데이터 구분

- 원문 데이터
  - 상세 로그 본문, 상세 학습 파일, 상세 리포트 파일
  - 기본 원칙: 로컬 보관 또는 최소 보관
- 집계 데이터
  - event_type, category, asset_class, status, metric_value 등 KPI 이벤트
  - 원칙: 관리자 대시보드용 집계/통계 중심

## 3. 최소수집 원칙

- 목적 달성에 필요한 최소 항목만 수집한다.
- 민감정보/고유식별정보 원문은 KPI 적재 대상에서 제외한다.
- metadata에는 원문 개인정보를 저장하지 않는다.

## 4. 보관 및 파기

- 운영 KPI 이벤트는 기간 정책에 따라 보관한다.
- 불필요한 원문 로그는 주기적으로 정리한다.
- 파기 요청 또는 보관 기한 만료 시 지체 없이 삭제한다.

## 5. 접근 통제

- 관리자 권한 계정만 KPI 대시보드에 접근한다.
- 운영 DB 접근은 최소 인원 원칙을 적용한다.
- 운영 변경(배포/마이그레이션)은 감사 가능한 방식으로 기록한다.

## 6. 대외 고지 문구(요약)

- 서비스 품질/보안 향상을 위해 운영 이벤트가 집계될 수 있다.
- 투자 판단 보조 목적 외 사용은 제한한다.
- 개인정보 처리방침 및 관련 법령에 따라 보호한다.
