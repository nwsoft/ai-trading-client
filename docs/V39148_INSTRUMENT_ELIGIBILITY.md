# 3.9.1.48 공통 종목 상태 계약

현행 설계 정본. 구현/회귀 결과는 `TEST_STATUS.md`, Windows 인계는 `DEPLOY_CHECKLIST.md`를 따른다. 46의 잔여 자산 평가 수정과 중복 구현하지 않으며 해당 과거 기록을 현재 전체 종목 보호 완료로 해석하지 않는다.

## 원인과 책임

거래 대상 선정과 계좌 잔여 자산 평가는 다른 책임이다. 46은 미평가 자산을 0원으로 처리하지 않는 평가 경로 및 명시 비활성 후보 필터를 보강했다. 이후 점검에서 오래된 CCXT markets 재사용, Binance 디스크 백업의 TRADING 합성, Coinone ticker 기반 active=None, 증권 사용자 지정 종목의 필터 이후 재유입을 확인했다. 가격 조회 성공은 거래 가능 증거가 아니다.

`trading/instrument_eligibility.py`가 `noahai.instrument-eligibility.v1`의 단일 구현이다. 각 기관의 연결/주문 API와 Strategy IR/승인/위험 검사는 그대로 유지한다. 이 계약은 전략 의미를 변경하거나 새로운 전략 승인 단계를 추가하지 않는다.

## 적용

- 자동 선정, 사용자 지정, 전략/캐시 후보를 최종 검사한다. 지정 종목도 현재 목록에 없거나 제한 상태이면 신규 후보가 될 수 없다. 종목 설정을 삭제하지 않는다.
- Binance Trader·UnifiedTrader·증권 서비스의 PAPER/LIVE 진입 및 실제 주문 어댑터에 적용한다. 오프라인 과거재생에는 현재 목록을 적용하지 않는다. 과거에 상장됐던 종목의 연구 결과를 현재 상장 상태로 지우지 않는다.
- spot/stock SELL, futures reduce_only/close_position은 이 신규 진입 검사에서 제외하고 기존 소유권·수량·보호 검사를 유지한다. 거래소가 실제 청산을 허용한다는 보장은 아니다.
- 기존 포지션·거래 원장·잔여 자산·PnL·전략 버전은 변경/삭제하지 않는다. 잔고에 없는 종목을 이 계약으로 청산됐다고 판단하지 않는다. 손익 보호 우회나 자동 LIVE 시작 없음.
- UnifiedTrader의 기존 포지션 점검은 후보 처리 전에 한 번 실행한다. 후보 없음·현재 거래 불가·점수 미산출로 신규 분석을 생략해도 실행 중인 워커의 체결 대조·보호·청산 점검을 함께 생략하지 않는다.

## 제공사 근거

| 기관 | 종목 상태 근거 |
|---|---|
| Binance | 현재 exchange_info의 TRADING·USDT·PERPETUAL. 오래된 파일/하드코딩 목록은 실행 자격 근거로 사용하지 않음 |
| OKX·Bybit·Bitget | CCXT reload=True 마켓 목록, 명시 상태/활성·상품·결제통화 검사 |
| Upbit | CCXT가 갱신한 공식 market/all 목록. 유의/주의 표시는 상장폐지가 아님 |
| Bithumb | 공식 v1/market/all. 설치된 CCXT의 구형 ticker 기반 목록을 상장 근거로 쓰지 않음 |
| Coinone | 공식 public/v2/markets/KRW의 maintenance_status·trade_status. ticker의 active=None을 TRADING으로 승격하지 않음 |
| 한국투자·미래 공개 마스터 경로 | 공개 종목 마스터와 차단 플래그, 최대 300초 캐시. 한국투자 설정 ETF도 현재 마스터와 교집합 검사 |
| 미래 제휴·신한 | 현재 종목/ETF 목록. 제공된 상태·거래정지 플래그 우선 보존. 상태 필드 자체가 없는 경우 공식 국내 종목 마스터의 현재 코드·상품 유형·차단 플래그로 보완. 그 근거도 없으면 unknown |
| 키움 | 현재 시장별 코드 목록 및 GetMasterStockState의 로컬 OCX 상태. 상태 조회 불가는 unknown |

공식 목록에만 상태가 제공되는 기관은 현재 목록 포함을 증거로 쓰며, 별도 제한 필드가 있으면 제한이 우선한다. 거래소 응답 자체의 지연이나 목록/주문 사이 상태 변경까지 제거할 수는 없다. 확인 불가와 상장폐지를 혼동하지 않는다. 제한의 구체적 이름을 제공사가 주지 않으면 inactive를 상장폐지라고 단정하지 않는다.

Coinone: trade_status 0=양방향 불가, 1=양방향 가능, 2=매수 불가, 3=매도 불가. 새 매수 후 매도 불가 위험이 있으므로 1만 신규 후보 허용. 공식 문서: https://docs.coinone.co.kr/reference/markets . Upbit 주의 표시는 거래 중단과 다르다: https://docs.upbit.com/kr/changelog/market_event .

## 성능·복구·사용자 조치

- 클라이언트 객체·기관별 단일 캐시/잠금. 코인 60초, 증권 300초, 조회 실패 15초 재시도 간격. 후보마다 전체 목록을 다시 다운로드하거나 복제하지 않는다. 재연결로 내부 클라이언트가 바뀌면 근거를 새로 받는다.
- 실패 시 이전 성공 목록을 거래 허가로 재사용하지 않는다. 해당 후보의 신규 진입만 제외하고, 기존 보호·청산은 별도 유지한다. 정상 응답 후 다음 평가에서 자동 복귀하되 정지한 워커를 자동 시작하지 않는다.
- 확인된 invalid/inactive 심볼 주문 거절은 캐시를 무효화한다. 타임아웃을 상장폐지/주문 거절로 단정하거나 이 경로에서 주문을 재전송하지 않는다.
- `instrument_*` 사유·기관·종목·확인 출처/시각을 결과에 남긴다. 반복 경고는 제한한다. 사용자는 상장/거래 상태와 연결을 확인하고, 지속 실패 시 최초 로그·기관·종목·앱 버전을 Q&A/관리자에게 전달한다. API 비밀키는 불필요하다. PnL 초기화/전략 재작성/반복 시작은 해결책이 아니다.

## 새 기관 추가 조건

기관 등록만으로 허용하지 않는다. 공통 등록부 계약, 제공사 목록 수집·상태 정규화, 최종 선정과 주문 경계, 청산 우회가 함께 있어야 한다. 미지원 기관은 명시적 보류다. 11기관 목록과 구현 기관 집합의 일치 시험, 정상/정지/삭제/미확인/실패/복구/동시성/PAPER·LIVE/청산 보존 시험을 추가해야 새 기관을 지원 완료로 판정한다.

## 검증 경계

소스·오프라인 API 모의 시험과 실제 설치본/기관 응답은 분리한다. 키움 OCX 실행 시간, 제공사 제휴 프로필의 실제 상태 필드, 네트워크 지연 및 실제 주문 거절/청산은 Windows 테스터 확인 대상이다. 테스트 수만으로 실계좌 검증 완료·무결점·무조건 거래 가능을 선언하지 않는다.
