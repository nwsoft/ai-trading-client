# NoahAI Client SaaS 비즈니스 플랜 (코드 검증 기반, 2026-06-09)

## 1. 목적

클라이언트 앱의 실제 구현 상태를 기준으로, 가능한 매출화 범위와 단계별 비즈니스 실행안을 정의한다.

## 2. 현재 가능한 수익화

- B2C 구독형
  - 인증/세션/등급 수신 기반 운영 가능
- B2B 운영형(초기)
  - 계정 운영 대행 + 리포트 + 월 운영료
- BYOK 분리형
  - API 호출비를 고객이 직접 부담하고 플랫폼 사용료 과금

## 3. 현재 불가능 또는 제한되는 항목

- 등급별 한도 강제 과금형 SaaS
  - 실행 게이팅 코드 미완
- 완전 자동 초과 과금
  - 사용량 집계/청구 파이프라인 미완

## 4. 90일 상용화 전략

### 0~30일

- 플랜 정책 API/게이팅 1차 적용
- Basic/Starter/Plus 중심 유료화

### 31~60일

- Plus/Pro 초과 과금 이벤트 반영
- BYOK 전환 플로우 상용 반영

### 61~90일

- B2B 운영 리포트 패키지 출시
- Team 계약형 과금(좌석 + 운영료) 고정

## 5. KPI

- Free->Paid 전환율
- 플랜별 ARPU
- 제한 도달 후 업그레이드 전환율
- BYOK 전환율
- 월 이탈률

## 6. 제품-비즈니스 정합 규칙

- 기능 공개보다 운영 안전성이 우선
- 플랜 약속은 코드 게이트가 구현된 기능만 판매
- 법인/기관 계약은 B2B 계약서 기준으로만 판매

## 7. 증권사 SaaS 온보딩 기준 (2026-06-17 추가)

- 증권사 연동 상품은 아래 4개를 모두 충족할 때만 상용 플랜에 편입한다.
  1. 개인 사용 가능
  2. 서버 동작 가능
  3. 다수 고객 계좌 연결 가능
  4. 약관/제휴 정책 허용
- "API 존재"만으로 상용 포함을 결정하지 않는다.
- 키움은 REST 포털 존재 사실과 현재 클라이언트 구현(OpenAPI+ ActiveX 중심)을 분리해 안내한다.

## 8. 2026-06-22 재검증 메모 (코드 교차 확인)

- 유지 가능한 주장
  - 인증/세션 기반 운영 가능
  - user_grade 수신/저장/표시 가능
  - 멀티 거래소 상태 관리/격리 구조 존재

- 수위 조정이 필요한 주장
  - 등급별 강제 게이팅 + 자동 과금형 SaaS는 아직 구현 완료 상태가 아님
  - 판매 문구는 "현재 구현 기능"과 "로드맵 기능"을 분리해 표기해야 함
