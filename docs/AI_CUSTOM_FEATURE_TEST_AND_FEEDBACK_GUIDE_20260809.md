# AI 커스텀 기능 시험·피드백 가이드

기준 소스: NoahAI Client v3.9.0.8 AI Custom Update Fix 4 작업 소스  
기준일: 2026-08-11  
대상: Noah Strategy IR v1·Progressive Strategy UI·P1~P3 클라이언트 기능 사용자 검증  
배포 경계: Windows 재빌드·실계정 장시간 E2E 전

## 0. Fix 4 설치 식별·UI 안정성 선행 시험

AI 커스텀 기능 시험 전에 같은 앱 프로세스에서 다음 두 시험을 먼저 수행한다.

1. 창 제목과 하단 업데이트 카드에 `AI Custom Update Fix 4`가 표시되는지 확인한다. Fix 2이면 이번 소스가 설치된 것이 아니다.
2. 설정 → 업데이트에서 현재 SHA와 배포 SHA 앞 12자리가 같은지 확인한다. 현재 공개 manifest는 Fix 2이므로 Fix 4 EXE·manifest 게시 전에는 이 시험을 시작하지 않는다.
3. `설정 열기 → X → 계속 편집/저장하지 않고 닫기/저장 후 닫기 → 다시 열기`를 섞어 100회 반복한다.
4. 같은 `블록체인` 버튼 재클릭 20회 뒤 `블록체인 → 주식/증권 → 블록체인` 왕복을 100회 반복한다.
5. 각 10회마다 로그의 Windows USER/GDI/TK_MENU 수를 기록한다. 모든 드롭다운을 닫은 상태에서 TK_MENU는 0이어야 하며 하나를 연 동안에도 최대 1이어야 한다.
6. 빈 설정창, 빈 흰색 확인창, `No more menus can be allocated`, 거래소·증권사 혼합, 정보 탭 순서·선택 이동, 제어/잔고/통계가 사라진 부분 화면이 한 번이라도 나오면 실패로 기록한다.
7. 실패 시 반복 횟수, 직전 서비스, 열린 설정 횟수, USER/GDI 수, 설정 → 업데이트의 적용 단계·현재/배포 SHA, 전체 화면 캡처와 해당 시각 로그를 함께 전달한다. API 키·Secret·Passphrase는 전달하지 않는다.
8. 기능 탭 뒤에 `금융 인텔리전스`, 그 뒤에 BINANCE·UPBIT·BITHUMB·BYBIT·OKX·BITGET 순서인지 확인한다.
9. 6개 거래소가 분석 범위이면 상단이 `거래소: 6곳 · 기준 ...`으로 표시되는지, 아무 워커도 시작하지 않았다면 하단이 `자동매매: 정지 (0/6 실행)`인지 확인한다.

### 0.1 Kimi K3 설정 시험

1. `설정 → AI 엔진/API`를 연다. 이 단계에서 `No more menus can be allocated`가 나오면 즉시 실패다.
2. Provider에서 `Kimi (Moonshot AI)`를 선택하고 Kimi Open Platform API 키를 입력한다. 실제 비밀값은 캡처·로그·피드백에 넣지 않는다.
3. `사용 가능 모델 새로고침` 또는 `실제 API 기능 검증`으로 계정이 허용한 모델을 확인한다.
4. 작업별 Provider/모델에서 Kimi와 `kimi-k3`를 선택해 저장하고 설정을 닫았다 다시 열어 값이 유지되는지 확인한다.
5. AI 어시스턴트 질문과 JSON 분석을 각각 1회 실행해 Provider·모델 라우팅과 usage/error 기록을 확인한다. 일반 Kimi 서비스의 멤버십·잔액과 개발자 API 키·잔액·과금은 별도다.

### 0.2 자동업데이트 필수 시험

1. Fix 4를 수동 설치한 뒤 테스트용 새 SHA 자산을 같은 `3.9.0.8` 릴리즈에 게시한다.
2. 업데이트 확인 후 `다운로드 완료`와 설정 → 업데이트의 배포 SHA가 새 자산과 같은지 확인한다.
3. 포지션·미체결이 없는 상태에서 `지금 업데이트 적용(재시작)`을 누른다.
4. 재시작 뒤 적용 단계가 `healthy`, 현재 SHA와 배포 SHA가 동일한지 확인한다. 버전 글자만 같다는 이유로 통과시키지 않는다.
5. 설치 폴더 쓰기 차단 또는 테스트용 교체 실패를 한 번 재현한 뒤 staged 파일과 실패 이유가 남고, 권한 복구 후 다음 실행에서 재시도되는지 확인한다.
6. 유지 포지션 정책 시험은 PAPER 또는 승인된 테스트 환경에서만 수행한다. 실제 API 비밀값과 실계정 포지션 화면은 피드백에 첨부하지 않는다.

이 선행 시험을 통과해야 아래 AI 커스텀 P1~P3 기능 피드백을 같은 설치본의 신뢰 가능한 결과로 취급한다.

### 0.3 공통 원인 필수 시험

1. 블록체인 계좌의 잔고가 표시된 상태에서 `자산 통합`으로 이동합니다. 현재 자산이 같은 USDT 잔고를 표시하고 `0원` 또는 누적 체결액을 표시하지 않는지 확인합니다.
2. 주식/증권 KRW 잔고도 함께 연결했다면 KRW+USDT 합계가 하나의 원화 금액으로 표시되지 않고 통화별로 분리되는지 확인합니다.
3. `AI 애널리스트 → 시나리오 점검 → AI에 시나리오 심층 분석 요청`을 누릅니다. AI 어시스턴트 탭으로 이동하고 `invalid command name ... ctkentry`가 로그에 없어야 합니다.
4. AI 어시스턴트에서 일반 질문도 1회 보낸 뒤 우측 하단 요약이 `AI 실행 기록 없음`에서 최근 요청으로 바뀌는지 확인합니다.
5. 하단 `기록`을 눌러 심층분석/일반 질문의 시각·요약·상태가 보이는지 확인합니다.
6. `시장 트렌드 → 금융 인텔리전스 → AlphaArena(활성 사용자) → 코인/종목 정보 → 거래 통계 → AI 애널리스트`를 서비스 왕복 중 각각 다시 열고 새로고침합니다. 빈 화면·이전 서비스 데이터·`invalid command name`이 없어야 합니다.
7. 종료 거래가 있는 구형 사용자 데이터에서 `시나리오 점검`과 `생활금융 → 보안 경고`도 열어 `asset_type` 또는 `entry_amount` 오류 없이 데이터 있음/없음 상태가 명확히 표시되는지 확인합니다.
8. 하단 기록은 질문 1회당 행 하나이며 `응답 생성 중`에서 `응답 완료` 또는 오류 사유로 바뀌어야 합니다.
9. 실패 시 계정 ID나 API 키를 보내지 말고 전체 화면, 실행 순서, 오류 시각의 로그만 전달합니다.

## 1. 이번에 시험할 기능

AI 커스텀은 자연어를 즉시 주문으로 보내지 않는다. 다음 한 경로를 시험한다.

```text
사용자 원본
→ 실행 규칙과 원문 근거 추출
→ Noah Strategy IR 1.0
→ 지원 / 사용자 확인 필요 / 미지원 판정
→ Level 1·2·3에서 같은 전략 확인
→ 새 버전 저장과 변경점 확인
→ 사용자 승인
→ 자동검증 또는 PAPER 기록
→ 사용자 최종 적용
→ 주문 직전 국면·계좌·주문 가드레일
```

현재 소스에서 확인할 수 있는 핵심은 다음과 같다.

- 현행 안전 DSL과 IR의 canonical rules 무손실 왕복
- 원문 evidence excerpt와 조건·고급 주문 노드 연결
- 필요한 데이터·지표·시간봉·상태·주문·적용 범위 capability 표시
- `supported`, `needs_clarification`, `unsupported` 구분
- 저장·승인·검증·활성화·활성 풀의 IR 무결성 재검사
- 같은 전략을 Level 1 요약, Level 2 핵심값, Level 3 전체 IR/DSL로 표시
- 버전 diff와 승인·검증·최종 적용 상태 분리
- 초보자/일반/고급/실험실 프로필과 개별 기능 ON/OFF
- 총 PnL·총 수익률·MDD·Profit Factor·월별/연별 표와 과최적화/PAPER 분리
- 중첩 Expression Graph·제한형 사용자 지표 언어의 안전 차단
- `.noahstrategy` 로컬 내보내기/가져오기와 비활성 검토 상태
- AI 어시스턴트에 프로필·백테스트/PAPER·XAI 근거·패키지·webhook을 질문했을 때 현재 설정과 운영 경계를 구분하는 답변

## 2. 시험 전 안전 조건

처음 시험은 `LEARNING` 또는 `PAPER`에서 수행한다. API Key, Secret, Passphrase, KYC 정보, UID, 이메일, IP, 인증값은 피드백에 넣지 않는다.

- 전략을 저장해도 실행되지 않아야 한다.
- 사용자 승인 전 자동검증·최종 적용 버튼으로 우회할 수 없어야 한다.
- `unsupported` 또는 IR 무결성 실패 전략은 저장·승인·실행되지 않아야 한다.
- LIVE는 PAPER 결과와 계좌·주문 권한을 확인한 뒤 별도 최종 확인으로만 전환한다.
- 백테스트·PAPER 수익은 실제 수익 보장이 아니다.

## 3. 권장 첫 시험

### 3.1 입력

`AI 커스텀` 화면에서 `텍스트/메모`를 선택하고 다음 문장을 입력한다.

```text
진입 RSI 30 이하 LONG. 청산 RSI 65 이상. 손절 1%. 익절 2%.
포지션 크기 5%. 횡보장에서 사용한다.
```

`AI 분석 및 전략 초안 만들기`를 누른다.

### 3.2 Level 1 — 이해·시험

다음을 확인한다.

- 전략 요약, 진입·종료, 손절·익절, 적용 범위·국면이 이해 가능한가
- `IR 상태: supported`인가
- 근거 연결이 `2/2 노드`로 표시되는가
- 저장만으로 주문하지 않는다는 문구가 보이는가

### 3.3 Level 2 — 핵심값

상단 선택을 `Level 2 핵심값`으로 바꾼다.

- RSI 진입 `lte 30`, 청산 `gte 65`가 조건으로 표시되는가
- 위험예산, 증거금 한도, 레버리지 상한, 시장국면 값이 같은 전략에 연결되는가
- IR 무결성 통과와 해시 앞부분이 표시되는가

핵심값을 변경해 새 버전으로 저장한 뒤 버전 목록의 `변경점`에서 이전·변경 값이 구분되는지 확인한다.

### 3.4 Level 3 — 전체 IR

상단 선택을 `Level 3 전체 IR`로 바꾼다.

- 안전 DSL 편집기가 나타나는가
- 전체 IR에 `format: noah-strategy-ir`, `ir_version: 1.0`이 있는가
- 각 조건 노드에 `node_id`, `path`, `support_status`, `evidence`가 있는가
- capability에 RSI, 비교 연산자, 필요한 주문·상태가 표시되는가
- 버전 목록의 `IR v1.0` 버튼에서도 저장된 전체 계약을 볼 수 있는가

## 4. 차단 시험

### 설정·온보딩 사용성

1. `설정 → AI 엔진/API`에서 AI 커스텀 사용 난이도의 기본값이 `일반`인지 확인한다.
2. 개별 기능 목록이 처음에는 접혀 있고 `개별 고급 기능 펼치기`로만 열리는지 확인한다.
3. 초보자·일반·고급에서는 외부 TradingView webhook 스위치가 비활성이고, 실험실에서만 선택 가능한지 확인한다.
4. webhook 안내에 `지정 거래소 연결 방식이 아님`, `앱 내부 전략에는 불필요`, `운영 endpoint/E2E 전 사용 금지`가 보이는지 확인한다.
5. `설정 → 고급 매매 계층`을 화면 배율 100%·125%·150%에서 열어 모든 설명이 오른쪽에서 잘리지 않고 줄바꿈되는지 확인한다.
6. `safe(신규 권장)` 안내, 5개 계층의 역할, 고변동장·합의 임계값·쿨다운의 기본값과 예시가 한 화면 흐름으로 이해되는지 확인한다.
7. AI 커스텀에서 `AI 멘토 인터뷰`와 `처음 사용법 AI에게 묻기` 차이가 상단에 보이는지 확인한다.
8. `12단계 자세히`를 눌러 준비·전략 만들기·검토/적용·운영의 4구간 모달, 줄바꿈, 스크롤, `AI에게 이 순서 묻기` 버튼을 확인한다.
9. AI 어시스턴트에 아래 질문을 그대로 보내 외부 AI 키가 없어도 현재 설정을 포함한 답이 나오는지 확인한다.

```text
지정 거래소가 있는데 webhook은 왜 필요해?
AI 멘토와 처음 사용법 AI에게 묻기 차이는?
고급 매매 계층 safe 프리셋과 고변동장 처리를 설명해줘.
AlphaArena가 뭐고 일반 자동매매와 무엇이 달라?
```

### AlphaArena 경계

1. `설정 → AlphaArena`가 기본 OFF이고 `숙련자용 Binance USDT 선물 독립 실험 모드`로 설명되는지 확인한다.
2. 현재 실행 엔진 선택과 새 키 입력은 DeepSeek V4 Flash만 노출되고 Qwen 키 입력란은 보이지 않는지 확인한다. 기존 설정의 Qwen 값은 호환 보관 대상이다.
3. 화면과 사용자 메뉴얼에 60초 주기(최소 30초), 기본 6심볼, 10~20배, TP/SL 필수, 쿨다운 30초, 최대 6포지션, 틱 위험 합계 $1,500이 같은 값으로 표시되는지 확인한다.
4. 표준 고급 매매 계층·기존 TP/SL 보험·워치독과 공유되지 않고 AlphaArena 자체 주문 게이트를 쓴다는 경고를 확인한다.
5. 소스 테스트 통과만 보고 실제 계정에서 켜지 않는다. Windows 설치본과 별도 샌드박스/소액 E2E 계획이 승인된 뒤에만 실환경 시험한다.

### 프로필·개별 기능

1. `설정 → AI 엔진/API → AI 커스텀 사용 난이도`에서 초보자, 일반, 고급, 실험실을 차례로 선택한다.
2. 초보자는 Level 1, 일반은 Level 2, 고급/실험실은 Level 3가 초기값인지 확인한다.
3. 프로필을 선택한 뒤 `월별·연별 수익률 표`, `Expression Graph 편집기`, `제한형 사용자 지표 언어`, `.noahstrategy`를 각각 다시 켜고 끈다.
4. 과거 재생을 끄면 월·연도 표와 품질 리포트도 꺼지고, 전략 패키지를 끄면 팀 공유 메타데이터도 꺼져야 한다.
5. 어떤 프로필에서도 유료 마켓이 열리면 안 된다.

### 과거 재생 최소 통과조건

타임스탬프가 있는 과거 데이터를 사용해 `자동 검증 실행`을 누른다.

- 총 PnL·총 수익률·MDD·승률·Profit Factor가 표시되는가
- 월별·연별 표가 실제 거래 종료 시각 기준으로 나뉘는가
- 수수료·슬리피지·스프레드 가정과 미사용 구간·워크포워드·몬테카를로가 함께 보이는가
- 음수 PnL, 표본 부족, 과도한 MDD가 최소 통과 실패 이유로 표시되는가
- 결과가 좋아도 PAPER 미완료이면 승격 준비가 아니며 자동 적용되지 않는가

백테스트는 과거 규칙 동작과 최소 품질을 확인하는 도구이지 미래 수익 예측이 아니다. 홍보용 최적화 수치보다 동일 버전의 PAPER 전진검증을 우선 피드백한다.

### Expression Graph·사용자 지표

고급 또는 실험실 프로필에서 `Level 3 전체 IR → 그래프·지표 예제`를 불러와 안전성 검사를 실행한다. 중첩 `and/or`와 `ema(20, '15m')` 의존성이 IR 노드에 보이는지 확인한다. `__import__`, `open`, 객체 속성 접근, 지나치게 큰 거듭제곱을 넣으면 저장 전에 차단되어야 한다.

### 전략 패키지

1. 일반 이상 프로필에서 저장 버전의 `내보내기`를 눌러 `.noahstrategy`를 만든다.
2. 파일에 API Key, Secret, Passphrase, 계좌번호, 로컬 절대경로, 활성/승인 상태가 없는지 확인한다.
3. 다시 `전략 가져오기`를 눌러 가져온 버전이 `review_only` 성격의 비활성·미승인 버전인지 확인한다.
4. 파일 내용을 임의 수정하면 SHA-256 검증으로 차단되어야 한다.

### 누락 조건

손절·익절·포지션 크기 또는 시장상황을 뺀 원본을 분석한다. 결과가 `조건 재확인 필요`여야 하며 사용자 확인이 끝나기 전 승인되지 않아야 한다.

### 미지원 조건

Level 3 고급 규칙에서 허용되지 않은 지표 또는 연산자를 넣는다. 예: `supertrend`, `predicts_up`. 안전성 검사와 저장/승인 경로가 미지원 이유를 표시하고 차단해야 한다.

### 버전·활성화 경계

1. 전략을 저장한다.
2. 승인 전에 적용을 시도한다.
3. 승인 후 자동검증을 거치지 않고 일반 운용 적용을 시도한다.
4. 자동검증 통과 뒤 최종 적용한다.
5. 적용을 해제하고 이전 검증 버전 롤백을 시험한다.

각 단계의 상태가 `저장`, `승인`, `검증`, `적용`으로 분리되어야 한다. 제한 운용은 자동검증 결과가 존재하고 사용자가 명시적으로 선택한 경우에만 허용되어야 한다.

## 7. 테스터 배포 조건

소스 테스트 담당자는 현재 체크리스트로 바로 검증할 수 있다. 일반 테스터에게 설치 파일을 배포하려면 다음이 모두 필요하다.

1. 전체 자동 회귀와 문서 정합 검사 통과
2. Windows v3.9.0.8 EXE 새 빌드
3. 완성 EXE SHA-256과 release manifest 일치
4. Windows 100%·125%·150% 배율에서 설정·AI 커스텀·12단계 모달 스모크 테스트
5. 설치·업데이트·재실행 후 버전과 메뉴얼 표시 확인

이 다섯 조건 전에는 `소스 후보`이며 `테스터 클라이언트 배포 완료`라고 안내하지 않는다. 첫 외부 배포는 LEARNING/PAPER 전용 권장으로 진행하고 AlphaArena와 webhook은 시험 대상에서 기본 제외한다.

## 8. 현재 확인 범위와 남은 검증

자동 회귀로 IR 컴파일·무손실 왕복·단계 투영·근거·미지원/변조 차단·레거시 승격·대표 RSI 실행 판단·활성 풀 재검증, 기능 프로필, 중첩 그래프, 제한형 수식, PnL/MDD/기간표, 백테스트 단독 적용 차단, 패키지 변조 차단, webhook 중복 차단, 품질 리포트와 새 설정 안내 계약을 확인했다. 전체 회귀는 `1,416 passed, 6 skipped`다. 다음 항목은 자동 테스트 통과와 별개다.

macOS 소스 900×800 설정창에서는 고급 매매 계층의 상단 권장 안내, 고변동장, 합의 임계값, 쿨다운과 AlphaArena 상단 설명이 좌우 잘림 없이 줄바꿈되는 것을 시각 확인했다. Windows 설치본 100%·125%·150% 배율은 아직 아래 외부 검증 대상이다.

- Windows EXE 재빌드와 실제 화면 배율별 Level 전환
- Pine·PDF·영상 대표 코퍼스의 원본 대비 의미 동등성
- TradingView와 NoahAI 재생의 캔들 시점·수수료·슬리피지 차이
- webhook 서버 endpoint·영속 nonce 저장소·TradingView 실제 재전송 E2E
- 회원 초대·철회·서버 다운로드가 포함된 팀 공유와 B2B 인증 API
- 실제 계정 장시간 PAPER와 소액 LIVE의 주문·부분체결·재시작 복구
- 첫 전략 생성 시간, PAPER 전환율, 7일 재방문, 모호함 해결률 KPI

오류 보고에는 전략 원문 중 공개 가능한 부분과 전략/version ID만 포함한다. 계정 자격증명·UID·개인정보·검증값은 포함하지 않는다.
