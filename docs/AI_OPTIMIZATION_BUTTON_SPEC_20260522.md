# AI 최적화 버튼 제품기획 (v0.2)

작성일: 2026-05-22
최신 반영: 2026-06-04
목적: 사용자가 한 번에 이해하고 실행할 수 있는 AI 최적화 경험을 제공하면서, XAI/로그 기반 투명성을 유지한다.

> 2026-07-26 안전 정책: 이 문서의 과거 `ai_auto` 선택안은 폐기됐다. v3.9.0.2부터 거래 관련 설정은
> 적용 버튼과 최종 확인을 모두 요구하며, 위험 확대형 변경은 현재 시장·성과·포지션 데이터가 부족하면 차단한다.

## 1. 왜 필요한가

- 현재 상태: 승률 개선 신호는 있으나 PnL 완전 전환 전 단계.
- 문제: 일반 사용자 입장에서는 어떤 값을 어떻게 조정해야 하는지 어렵다.
- 해결: "AI 최적화" 버튼으로 원클릭 실행 + 변경 근거(XAI) + 7일 추적 자동화.

## 2. 버튼 정의

버튼명: AI 최적화
위치 원칙: 대시보드 Quick Actions를 공식 진입점으로 두고, 설정/어시스턴트 내부 경로를 보조 진입점으로 유지한다.
- 대시보드 Quick Actions → AI 최적화: 어시스턴트 탭 이동 + 최적화 진단 질문 자동 전송 + 설정관리 모달 오픈
- 설정관리 모달 동작: 미리보기만(저장 없음) / 프리셋 바로 적용(최종 확인 후 저장) 분리
- 설정 → AI 엔진/API: 원클릭 프리셋 + 초기 AI 온보딩 시작
- AI 어시스턴트 → 설정관리: 원클릭 프리셋 + 초기 AI 온보딩 시작
고정 정책: 사용자 최종확인 2단계

적용 범위:
- 1차 범위는 "사용자 개인 계정의 최근 7일 데이터" 기반 최적화.
- 커뮤니티/타 사용자 원문 데이터 직접 반영은 제외.
- 외부 공개는 익명화 집계 KPI만 허용.

## 3. 원클릭 사용자 흐름

1. 현재 상태 진단
- 최근 7일 성과 요약: WinRate, RR, Avg Win, Avg Loss, MDD
- 리스크 상태 표시: 일반/주의/고위험

2. 최적화 제안 생성
- AI가 1~3개 조정안 생성
- 각 조정안에 예상 효과와 위험도 표시

3. XAI 카드 표시
- 무엇을 바꾸는지: 대상 파라미터
- 왜 바꾸는지: 최근 데이터 근거
- 얼마나 바꾸는지: 수치 변화량

4. 적용 정책 선택
- 기본: 사용자 승인 후 적용
- 현행: 적용 버튼과 최종 확인 후 반영
- 미리보기 경로: 진단 결과만 확인하고 설정 저장 없이 종료 가능

5. 적용 후 자동 추적 시작
- 7일 추적 티켓 생성
- Day 7 자동 판정 카드 생성

6. 초기 환경설정 AI 가이드 연계
- 초보 사용자는 별도 진입점에서 5문항 온보딩을 먼저 수행할 수 있다.
- 목표/리스크/예산/적용방식/재검증 기준을 수집하고, 이후 최적화 정책에 반영한다.
- 즉, 초기 온보딩은 AI 최적화와 같은 철학을 공유하지만, 첫 진입용 가이드로 분리한다.

## 4. 어떤 항목을 최적화할 것인가 (현재 기능 기반)

자산군 정책:
- 코인/주식/ETF 모두 동일 버튼을 사용하되, 자산군별로 조정 가능한 항목만 노출한다.
- 즉, 버튼은 블록체인 전용이 아니라 자산군 공통 "판단 품질 최적화" 진입점이다.

자산군별 조정 예시:
- 코인: 신호 임계값, 리스크 다운시프트, TP/SL, 포지션 크기, 조기 청산 민감도
- 주식: 진입 임계값, 일일 손실 한도, 포지션 크기, 시장 레짐 필터 민감도
- ETF: 포지션 크기, 분할 진입/청산 강도, 리밸런싱 민감도, 변동성 기반 보호 강도

1. 신호 진입 품질
- 신호 임계값(user_signal_threshold) 조정
- 목적: 과매매 억제 및 저품질 진입 축소

2. 리스크 강도
- 리스크 다운시프트 계열 조정
- 목적: 손실 구간에서 포지션 축소 강화

3. TP/SL 균형
- TP와 SL 비율 조정
- 목적: RR 개선(손익비 개선)

4. 포지션 크기
- 포지션 사이징 상/하향 조정
- 목적: 손실 꼬리 제어 및 기대값 개선

5. 조기 청산 민감도
- 조기 청산 트리거 민감도 조정
- 목적: 이익 보호와 과도한 조기청산 균형화

## 5. 안전 가드레일

- 한 번에 하나만 변경 (single-variable change)
- 1회 조정 폭 제한 (권장 5~10%)
- 고위험 조합은 자동 차단
- 롤백 버튼 제공 (이전 안정값 즉시 복귀)
- 확인 기반 적용에서 변경 로그/사유를 항상 노출

## 6. 사용자에게 보여줄 결과 카드 (필수)

카드 1: 변경 요약
- 변경 전/후 값
- 적용 시각
- 적용 정책(사용자 승인/자동)

카드 2: 기대 효과
- RR 목표
- 과매매 억제 기대
- 손실 꼬리 감소 기대

카드 3: XAI 근거
- 최근 7일 데이터 기반 사유
- 위험 경고 근거
- 권장 관찰 포인트

## 7. 7일 운영 루프 템플릿

Day 1
- 기준선 기록: WinRate, RR, Avg Win, Avg Loss, MDD
- 적용값 스냅샷 저장

Day 2~6
- 일일 요약 기록: 승률, RR, MDD, 특이 이벤트
- 악화 신호 여부 체크

Day 7
- 판정
  - 유지: RR 개선 + MDD 악화 없음
  - 보류: RR 정체
  - 롤백: RR 하락 + MDD 악화

## 8. 릴리즈 기준 (MVP)

MVP 포함
- 버튼 UI
- Quick Actions 진입 플로우(어시스턴트 탭 전환 + 자동 질문 + 설정관리 모달)
- 제안안 1~3개 생성
- 변경 전/후 + XAI 카드
- 7일 추적 티켓 및 Day 7 판정
- 초기 환경설정 AI 가이드(5문항) 및 설정/어시스턴트 진입 버튼

MVP 제외 (후속)
- 다중 자산 동시 최적화
- 완전 무인 자동 최적화 루프
- 개인화 고급 프로파일링

## 9. 커뮤니케이션 원칙

- 투자 수익 보장 표현 금지
- 최적화는 "판단 품질 개선 보조"로 설명
- 공개 페이지는 익명화/집계 지표만 사용
- 내부 상세 분석은 비공개 문서로 분리
- 최종 판단 및 주문 실행 책임은 사용자에게 있음을 명시

## 10. 법적/운영 책임 경계 (필수 문구)

- NoahAI는 사용자의 올바른 선택을 돕는 판단 보조 도구이다.
- NoahAI는 투자 수익을 보장하지 않으며 투자 자문을 제공하지 않는다.
- AI 최적화 결과는 제안이며, 적용 전 사용자 확인을 기본 정책으로 한다.
- 과거 자동적용 모드는 폐기했으며 변경 내역/XAI/롤백 경로와 최종 확인을 항상 제공한다.

## 11. API 비용 최적화 운영 정책 (모델 티어 배치)

목표:
- 동일 품질이 필요하지 않은 반복 업무에는 저비용 모델을 배치하고,
  정밀 진단/중요 의사결정에는 고성능 모델을 배치해 총 API 비용 대비 효율을 높인다.

권장 티어:
- frequent_cheap: 신호분석/패턴 유사성/포지션 사이징 (예: gpt-4o-mini)
- standard: 손익 분석/리포트 (예: gpt-4o)
- premium: 문제 진단/파라미터 최적화 (예: gpt-4o 또는 gpt-5)

운영 원칙:
- 비용은 "호출 빈도 × 토큰량 × 모델 단가"로 관리한다.
- 품질 저하가 없는 범위에서 frequent_cheap을 먼저 낮추고,
  premium은 호출 빈도를 줄여 비용 급증을 방지한다.

### 11-1. 2026-07-24 실사용 점검 정정

- 역할별 모델 배치는 구현되어 2026-05 대비 2026-06 비용이 16.6% 감소했다.
- 그러나 현재 신호 생성 경로는 최종 LONG/SHORT/HOLD 판정 전에 심볼별 LLM을 호출한다.
- 2026-07-21~23에는 거래 48건에 모델 요청 27,879회가 발생했고 OpenAI 비용은 $9.08이었다.
- `frequent_cheap` 단가만 낮추는 것으로는 다중 거래소·다심볼 반복 호출을 막지 못한다.
- 아래 항목은 미완료 P0로 관리한다.
  1. 로컬 선필터 후 상위 후보만 LLM 호출
  2. 심볼별 쿨다운·시장상태 해시 중복 제거
  3. 거래소별·사용자별 일/월 비용 Hard Stop
  4. 다심볼 배치와 짧은 출력 스키마
  5. 호출·토큰·비용과 Fee 차감 PnL 연결

## 12. 사용자 제어 채널 (UI + 대화)

- 환경설정 경로: OpenAI API 탭의 역할별 모델 배치
- 대화형 경로: AI 어시스턴트에 모델/티어 변경 요청 후 확인 게이트 적용
- 적용 정책:
  - user_confirm: 변경 전/후 diff 확인 후 반영
  - ai_auto: 레거시 입력으로만 인식하고 `user_confirm`으로 강제 변환

## 13. 초기 환경설정 AI 가이드(현재 제공 + 다음 확장)

현재 제공:
- 설정 → AI 엔진/API → `AI로 초기 설정하기 (5문항 가이드)`
- AI 어시스턴트 → 설정관리 → `초기 온보딩 시작`
- AI 어시스턴트 채팅 명령: `온보딩`, `초기 설정`, `AI로 초기 설정`

목표:
- 초보 사용자가 많은 설정 항목을 한 번에 이해하지 못해도,
  AI가 질문-응답 방식으로 사용자 성향과 목적을 파악해 초기 설정을 제안한다.

핵심 흐름:
1. 사용자 목표 확인: "비용 우선/균형/품질 우선" 등 운영 목표 수집
2. 운영 제약 확인: 사용 빈도, 예산 범위, 허용 리스크 수준 수집
3. AI 제안 생성: 모델 프리셋 + 역할별 티어 + 적용 이유(XAI) 표시
4. 사용자 확인: 변경 전/후 diff + 예상 비용 레벨 + 위험도 표시 후 확정

필수 원칙:
- 제안의 근거를 항상 문장으로 설명한다(왜 이 설정이 맞는지)
- 모호하면 AI가 반문해 입력을 보강한다(추정 적용 금지)
- 저장 전에는 항상 취소 가능해야 한다

다음 확장:
- 질문 수를 서비스별로 동적 조정(코인/주식/ETF별 분기)
- 온보딩 완료 후 7일 점검 알림 자동화
- 사용자의 과거 선택 패턴을 반영한 질문 순서 최적화

## 14. 고위험 수동 변경 요청 대응(다음 기획)

정책:
- 사용자가 레버리지 급상향, 공격적 모드 고정, 고비용 모델 강제 등 위험 조합을 요청하면
  즉시 적용하지 않고 위험 사유를 설명한 뒤 단계적 대안을 제시한다.

응답 가이드:
- "현재 데이터 기준으로 즉시 변경은 권장하지 않음"을 명시
- 대체안 제공: 소폭 조정(예: 5~10%) + 관찰 기간 제안
- 고위험 변경은 2단계 확인 + 경고 문구 + 롤백 경로를 강제

## 15. 데이터 축적 기반 맞춤형 조절(다음 기획)

운영 제안:
- 사용자 강제 변경 요청이 있어도, 최소 관찰 구간(예: 7일 또는 최소 거래 표본) 이후
  성과 데이터를 기반으로 재조정하도록 유도한다.

판정 기준 예시:
- 유지: RR 개선 + MDD 악화 없음
- 보류: 성과 개선 신호가 불충분
- 재조정/롤백: RR 하락 + MDD 악화 또는 비용 대비 효과 미달

커뮤니케이션:
- "지금 당장 크게 바꾸기"보다 "작게 바꾸고 데이터로 검증" 원칙을 사용자에게 반복 안내
- AI는 최종 결정 주체가 아니라 판단 보조임을 지속 고지

## 16. 실행 작업 분해표 (즉시 착수용)

목표:
- 기획/코드/문서가 같은 기준으로 움직이도록, 다음 개발 사이클의 구현 순서와 완료 기준(DoD)을 고정한다.

### 16.1 우선순위 백로그

| 우선순위 | 작업 항목 | 핵심 내용 | 완료 기준(DoD) |
|---|---|---|---|
| P0 | 온보딩 결과의 7일 점검 알림 연결 | 온보딩 완료 시 재검증 기준(7일/표본)을 저장하고 점검 시점 알림 트리거 연결 | 온보딩 후 설정 저장 + 점검 기준 저장 + 인앱/로그 알림 확인 |
