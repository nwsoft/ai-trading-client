2026-09-26 고객 사본 읽기 재검사: 58버전 중 준비 3/실행식 보완 55, Level 투영 290, 원본 저장소 2개 불변. 55개 원문이 자동으로 실행 가능해진 것은 아니다. 공통 보완 절차는 별도로 원문 질의→사용자 답변→재분석→같은 전략의 새 버전 저장→승인→PAPER→재로드/이전 버전 불변을 검사했다. 정의 없는 원문은 사용자 답변이 필요하며 고객별 수동 DB 수정은 하지 않는다.

마지막 연결 점검에서 추가 수정한 결함: 병행 PAPER가 사용자 전략 불일치 후 기본 AI 후보를 해당 전략의 성과로 기록하던 경로를 전략 key/version 일치 검사로 차단했다. 증권 명시 청산이 진입과 달리 완료 봉·상태 문맥을 받지 않던 경로도 공통화했다. 주식/ETF × 4기관에서 같은 봉 반복과 다음 봉 청산을 검사한다. 상태 저장은 최신 행만 갱신하고 매 호출 후 DB 연결을 닫는다. 학습 저장은 기존 선택 필드·후보 판단 근거를 사용하며 400봉 상태 재생 문맥을 통째로 학습 기록에 추가하지 않는다.

완료 목록이 계속 바뀐 관리 원인: 지원 확대, 고객 자료의 불확정, 미구현, 설치본 검증을 같은 목록에 섞었고 helper 시험을 사용자 경로 완료로 해석했다. 앞으로 버전 범위는 위 세 항목처럼 고정하고 재현된 결함만 추가하며, 시험 방법과 외부 확인을 분리한다.

완료 판정은 **알려진 피드백 → 확정/미확정 원인 → 공통 수정 → 사용자 해결 동선 → 저장/재시작 확인**이다. 고객 한 명의 잔여 숫자 0이나 모든 연구 기능 구현을 대체 기준으로 쓰지 않는다. 현재 개발 미완료 범위를 테스터에게 떠넘기거나 제한 배포를 일반 해결판으로 표현하지 않는다.

2026-09-26 범위 재점검: 기존 주문 계획의 부분익절/추적손절/손익분기 상태와 범용 영속 숫자 변수 실행기는 별개다. 고객 저장 전략 읽기 검사에서 확인한 55건 사유는 `confirm_executable_entry_missing`이며 이 검사는 범용 변수 엔진 부재가 원인임을 증명하지 않는다. 재진입 helper 존재도 모든 런타임 연결/영속성 완료의 증거가 아니다. 반면 원본 `entry_allocations`가 있어도 다른 진입이 중간에 있으면 복구를 거절하던 공통 제한은 합성 자료로 재현하고 수정했다. 각 lot의 진입 선행·수량·시각·비용 검증은 유지하며 아직 진입하지 않은 lot에 대한 청산은 거절한다. 고객 실제 미확정 35건의 원인을 이번 합성 사례로 확정하지 않는다.
