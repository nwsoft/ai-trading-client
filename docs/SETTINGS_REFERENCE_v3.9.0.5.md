# NoahAI 설정 정본 안내 v3.9.0.5

기준일: 2026-07-30  
대상: 다운로드형 NoahAI Client 사용자와 운영·지원 담당자

## 설정 철학

NoahAI의 핵심은 설정 숫자를 많이 노출하는 것이 아니라 `판단 → 설명 → 기록 → 검증 → 환류`를 일관되게 수행하는 것입니다. 사용자가 직접 결정해야 하는 것은 네 가지뿐입니다.

1. 어떤 방식으로 운용할지
2. 어떤 거래소·증권사를 관찰할지
3. 어디까지 실제 주문을 허용할지
4. 어떤 계정과 AI 엔진을 연결할지

지표 기간, 캐시, 재시도, 화면 갱신, 내부 최적화 주기처럼 서비스가 안전하게 관리해야 하는 값은 사용자 설정과 분리합니다.

## 설정 화면 권장 순서

| 순서 | 탭 | 사용자가 결정하는 것 |
|---|---|---|
| 1 | 일반 | LEARNING·PAPER·LIVE 운용 의미, 페이퍼, 포지션 수, 최상단 표시 |
| 2 | 거래소 선택 | 관찰·분석·학습 범위와 신규 실주문 권한 |
| 3 | 거래소 API | 실잔고·포지션·주문에 필요한 거래소·증권사 연결 |
| 4 | AI 엔진/API | 분석·어시스턴트 Provider, 모델, 비용 정책과 키 |
| 5 | 고급 매매 계층 | 근거가 있을 때만 바꾸는 후행 가드레일 |
| 6 | AlphaArena | 일반 자동매매와 분리된 실험 실행 체계 |
| 7 | AI 시스템 상태 | 자동 관리 상태와 시장 국면 진단 |
| 8 | 업데이트 | 현재 설치 버전, 업데이트 상태와 복구 정보 |

## LEARNING·PAPER·LIVE

### LEARNING

- 조건: 페이퍼 OFF, 실제 주문 실행 거래소 0개
- 동작: 시세 수집, 후보 선정, AI/AI 커스텀, 시장국면, 수익성·후행 전략, 계좌 위험, 수량·청산계획·최종 주문 규격 판단과 기록. 유효한 자격증명이 있으면 필요한 읽기 전용 계좌 상태도 확인
- 차단: 거래소·증권사 상태를 바꾸는 레버리지/마진 설정, 신규 진입 주문과 보호주문 제출
- 의미: “작동하지 않음”이 아니라 주문 권한이 없는 관찰·학습 운용

### PAPER

- 조건: 일반의 `페이퍼 트레이딩 활성화` ON
- 동작: 실시간 시세, AI 분석, 전략, 가드레일, 가상 주문·포지션·손익
- 차단: 모든 거래소·증권사 실주문 API, 실제 포지션 복구, 보호주문 제출, 실거래 DB·KPI 기록
- 범위: 지원되는 암호화폐 거래소와 증권 실행 경로에 공통 적용
- 주의: 브로커·시장별 데이터 품질과 기능 차이는 남아 있으며 실제 체결을 보장하는 시뮬레이터는 아님

### LIVE

- 조건: 페이퍼 OFF, 실제 주문 실행 거래소 또는 증권 실주문 권한 ON
- 동작: 선택된 권한 범위에서만 신규 주문 후보를 실제 주문 경로로 전달
- 추가 조건: 유효한 API 키, 회원 권한, 최소 주문액, 손실 한도, 수익성 정책, 시장 시간과 주문 가드레일을 모두 통과해야 함

우선순위는 `PAPER > LIVE > LEARNING`입니다. 페이퍼가 켜져 있으면 실제 주문 범위가 선택되어 있어도 실주문은 최종 차단됩니다.

## 거래소 선택과 실제 주문 실행 거래소

위쪽 `거래소 선택`은 화면·시세·분석·학습 범위입니다. 아래쪽 `실제 주문 실행 거래소`는 그 범위 안에서 신규 실주문을 허용하는 하위 권한입니다.

- 위만 선택: LEARNING
- 위와 아래를 선택하고 페이퍼 OFF: LIVE 후보
- 위를 선택하고 페이퍼 ON: PAPER
- 아래 선택은 반드시 위 선택의 부분집합이어야 하며 v3.9.0.5가 자동 정리
- `활성 거래소를 주문 대상으로 선택`은 체크를 복사할 뿐, 저장 전에는 권한을 확대하지 않음

v3.9.0.5 최초 실행에서는 기존 주문 목록이 사용자의 명시적 선택인지 과도기 자동복사인지 확인할 수 없으므로 기존 값을 호환 보관하고 실제 주문 범위를 0개로 잠급니다. LIVE 사용자는 아래쪽 거래소를 다시 선택하고 저장해야 하며, 이 저장이 사용자 확인 표식이 됩니다.

공개 시세·분석은 지원 거래소에서 API 키 없이 가능할 수 있습니다. 실잔고, 비공개 포지션과 실주문은 거래소가 허용한 유효한 키가 필요합니다.

### 다중 거래소·증권사 실행 방식

`multi_venue_execution.mode`는 같은 투자 기회가 여러 실제 주문 대상에 생겼을 때의 사용자 선택입니다.

- `parallel` 기본값: 선택한 각 거래소·증권사에서 조건과 안전검사를 통과하면 각각 실행
- `split`: 요청 수량을 실제 주문 대상 수로 나누어 총위험 분할
- `best`: 저장된 비용표·`best_target`이 있으면 이를 사용하고, 없으면 실제 주문 목록의 첫 번째 대상 한 곳만 실행

세 방식 모두 자산·방향·전략 버전·시간창으로 동일 기회 ID를 만들고 통합 예상 노출·손실과 대상별 결과를 기록합니다. 동일 종목이라는 이유로 다른 거래소 주문을 막지 않으며, 같은 대상·계좌·신호의 반복 제출만 중복 차단합니다.

### 거래소·증권사 범위와 종목 선택

- AI 커스텀의 대상 범위는 전략을 어디에 적용할지 정하며 다른 거래소의 종목 목록을 복사하지 않습니다.
- 일반 역할은 사용자 고정 종목 뒤에 NoahAI 자동 후보를 채우고 기본 AI 후보를 커스텀 조건으로 확인합니다.
- 고급 역할은 `StrategyUniversePolicy`의 포함/제외 종목, 최소 거래대금, 최대 스프레드, 변동성 범위, 최대 후보 수를 로컬 데이터에 적용한 뒤 사용자 전략을 독립 평가합니다.
- 고정 종목은 평가 대상을 보장하지만 진입이나 주문을 강제하지 않습니다.
- 전략의 `regime_scope`는 `market/symbol/both/none` 중 하나이며 기본은 전체 시장입니다. 선택 범위 데이터가 없으면 암묵적으로 다른 범위를 사용하지 않습니다.

암호화폐 고정 종목 정본은 `crypto_selection.manual_symbols_by_exchange`, 주식/ETF 고정 종목 정본은 `stock_auto_trading.symbols`입니다. v3.9.0.3 이하의 `stock_auto_trading.watchlist`는 자동 호환되며 새 저장에서는 두 값을 동일하게 유지합니다.

### 청산 설정 표시 계약

내부 정본 단위는 자산과 거래소에 관계없이 `fraction`입니다. 설정 화면이 5%처럼 퍼센트 포인트를 받는 경우 실행 경계에서 한 번만 0.05로 변환합니다.

실시간 로그와 판단 기록은 `기본 폴백 / 현재 적용값과 근거 / 실제 보험 제출값과 상태`를 구분합니다. 서버 측 보험 주문을 제공하지 않는 거래소·증권사에서는 제출값을 추정하지 않고 미제출 사유를 표시합니다.

## 일반 설정

### 페이퍼 트레이딩

실시간 데이터와 판단 파이프라인은 유지하고, 주문·포지션 상태만 메모리 안에서 분리한 가상 상태로 처리합니다. 실제 잔고와 실거래 통계는 변경하지 않습니다.

### 대시보드 항상 최상단 표시

대시보드 창에만 적용합니다. 저장 즉시 반영하고 재실행 후 복원되며 기본값은 OFF입니다. 운영체제 또는 다른 앱의 전체 화면·보안 창 정책이 우선할 수 있습니다.

### 포지션 모드

- 집중 모드: 최대 1개
- 다중 포지션: 기본 최대 3개

이 값은 동시 포지션 상한이며 진입을 강제하지 않습니다.

### AI 비용·캐시 자동 정책

사용자가 초 단위 캐시와 재시도 값을 직접 조절하지 않아도 되도록 `ai_cost_control`은 내부 안전 정책으로 관리합니다.

- 시장분석: 먼저 로컬 기술 신호를 계산합니다. 같은 시장상태는 15분 재사용하고 새 캔들·가격·RSI·MACD·국면 변화와 주기적 탐색에서만 새 모델 분석을 요청합니다.
- 호출예산: 기본 전역 1일 1,200회, 거래소별 1일 300회, 월 30,000회입니다. 한도에 닿으면 모델 호출만 로컬 신호로 대체하며 거래 루프 자체는 멈추지 않습니다.
- 포지션 크기: 같은 심볼·방향·상태는 15분 재사용합니다. 방향 변경, 1% 이상 가격 변화, 신뢰도 0.10 이상 변화에서만 갱신하며 실패 후 120초 동안 재시도하지 않습니다.
- 손실패턴 재검사: 같은 신호와 같은 최근 손실 표본은 5분 재사용하고 실패 후 120초 동안 재시도하지 않습니다.
- 성과 임계값 최적화: 최소 10개 완료 거래가 쌓인 뒤 새 거래 5개마다 최대 한 번만 요청합니다. 실패한 같은 표본을 10초 거래 루프마다 다시 요청하지 않습니다.
- 거래 후 손익 복기는 포지션 종료 이벤트에만, 전략 원문 분석·차트 이미지 분석·AI 어시스턴트는 사용자가 요청한 때만 호출합니다.

실제 주문 실행 거래소를 0개로 두어도 LEARNING 범위의 거래소는 분석하므로 AI 호출이 발생할 수 있습니다. 비용을 줄이려면 실제 주문 범위가 아니라 `거래소 선택`의 관찰·학습 범위에서 사용하지 않는 거래소를 끄고, `AI 엔진/API`에서 빈번 호출 역할을 절약형 모델로 둡니다. 모델 호출예산이 지켜지는 것과 Provider 청구액이 일정하다는 것은 같은 의미가 아니며, 단가·토큰·제공사 정책에 따라 실제 비용은 달라집니다.

### 기본 TP/SL과 전략 프리셋

- 설정 정본과 주문 엔진은 fraction을 사용합니다. `0.0018 = 0.18%`, `0.0020 = 0.20%`입니다.
- 화면과 대화형 프리셋은 읽기 쉬운 퍼센트 포인트를 사용할 수 있습니다. 이때 `0.18`에는 `_unit=percent_points`를 함께 두고 주문 엔진 전달 전에 한 번만 `0.0018`로 바꿉니다.
- `0.18%/0.20%`는 과거 균형형 단기매매에서 사용한 시작 폴백이지, 거래소별 검증을 마친 고정 수치나 수익 보장값이 아닙니다. 두 값만 놓고 보면 수수료 전 명목 손익비도 0.9이므로 모든 시장에 그대로 적용할 근거가 없습니다.
- 기본·일반 후보는 분석기 TP/SL과 변동성·RR 정책을 거칠 수 있습니다. 선택된 AI 커스텀 전략에 명시된 TP/SL은 해당 거래의 전략값으로 우선하며, 고급 독립 전략에서는 글로벌 기본값과 혼합하지 않습니다. 거래소 가격 단위 반올림은 요청값과 실제 제출값을 함께 기록합니다.
- 자동 최적화는 승인 전 제안만 만들며 공유 설정을 몰래 바꾸지 않습니다. 런타임 전략 프로파일도 명시적으로 선택한 경우에만 적용하며, 미선택 상태에서는 저장한 TP/SL·레버리지를 유지합니다.
- 같은 `0.18 → 0.0018`, `0.2 → 0.002` 변환이 매 시작마다 반복되는 것은 정상 동작이 아닙니다. 2026-07-30 v3.9.0.5 수정에서 균형 프리셋의 구단위 재주입과 Binance·통합 거래소의 단위 해석 차이를 제거했습니다.

## 고급 매매 계층

고급 계층은 기본 AI와 `기본 AI 후보 재확인(confirm)` 뒤에서 평가하는 선택형 정책입니다.
`사용자 전략 원형 독립 실행(independent)`에는 기본 AI 합의 임계값·패턴 재심사·NoahAI 전체
수익성 정책을 다시 적용하지 않습니다. 독립 전략도 시장국면 적합성·계좌 위험·주문 권한·규격·
데이터/API 상태 같은 공통 안전 경계는 통과합니다.

| 항목 | 의미 | 사용 기준 |
|---|---|---|
| 전략 엔진 | 국면·합의·쿨다운으로 후보 후행 평가 | 시장 근거와 로그가 있을 때 |
| 합의 임계값 | 여러 판단의 최소 합의 점수. 0.60이면 60% 이상 | 낮추면 기회와 오탐이 함께 증가 |
| 심볼 쿨다운 | 같은 심볼 재진입 최소 대기시간 | 과도한 반복 진입 방지 |
| 고변동장 처리 | 평가 계속 또는 항상 차단 | 기본은 평가 계속 |
| 수익성 검증 | 거래수·승률·샤프·MDD·기대값 점검 | 표본 부족과 손실 원인을 구분 |
| 포트폴리오·실행 최적화 | 자본 배분과 주문 품질 평가 | 시장·거래소가 제공하는 데이터 범위 내 |

`safe`가 일반 권장값입니다. `dev`는 개발·테스트용 전체 OFF, `aggressive`는 더 공격적인 임계값이므로 수익을 보장하지 않습니다. 프리셋 적용 전 변경 요약을 읽고 저장해야 합니다.

표준 암호화폐·증권 자동매매는 같은 전역 고급 정책을 사용하되, 거래소·증권사 어댑터가 지원하지 않는 주문 기능은 동일하게 실행되지 않습니다. AlphaArena는 별도 실행 체계입니다.

## AlphaArena

v3.9.0.5부터 `alpha_arena` 하나만 정본입니다. 과거 `alphaarena_*` 이중 설정은 자동 이전됩니다. API 키는 거래소·증권사 키와 같은 사용자별 로컬 설정 정책을 사용하며 Windows 보안 저장소를 요구하지 않습니다.

AlphaArena는 일반 자동매매의 LEARNING/PAPER/LIVE 설명을 그대로 공유하는 기능이 아닙니다. 화면의 실험 모드 설명과 별도 주문 가드레일을 먼저 확인해야 합니다.

## 자동 관리와 더미 설정 정리

v3.9.0.5는 실행 코드가 소비하지 않던 과거 최상위 설정 20개를 신규 템플릿에서 제거했습니다. 기존 사용자 값은 유실 방지를 위해 숨은 `_legacy_settings_v3905` 보관소로 한 번 이동하며 실행에는 사용하지 않습니다.

정리 대상:

`ai_enabled`, `ai_signal_enabled`, `analytics_refresh_interval_minutes`, `api_timeout`, `auto_coin_selection`, `backend_url`, `cache_timeout`, `clear_logs_on_restart`, `db_backup_interval`, `db_backup_retention`, `dynamic_thresholds_hysteresis`, `dynamic_thresholds_hysteresis_enabled`, `entry_order_type`, `learning_period`, `log_file_size_limit`, `log_retention_days`, `ma_period`, `max_concurrent_requests`, `optimization_interval`, `strategy_config`

실제로 소비되는 `slippage_tolerance`, `include_fees`, `tuning`, `trading_strategies`, 거래소별 위험·TP/SL 설정은 유지합니다.

## 설정 정리 상태와 운영 진단

`설정 → 일반` 상단에서 정본 버전, 현재 실행 모드, 호환 보관 수, 모순 수를 확인할 수 있습니다. 모든 설정 탭의 상단 `AI에게 묻기`는 해당 탭 이름과 현재 저장 설정을 AI 어시스턴트에 전달합니다. API 키·비밀값은 전달하지 않으며 설명만 요청하고 설정을 자동 변경하지 않습니다. 질문 후 설정 창은 편집값을 유지한 채 숨겨지고, 대시보드의 `설정`을 다시 누르면 같은 창으로 돌아갑니다.

AI 어시스턴트 오른쪽 `자주 하는 질문`은 별도 스크롤 영역입니다. 질문 항목이 늘어나도 하단 전송·음성입력·설정관리·차트분석 버튼의 위치는 유지됩니다.

개발·지원 담당자는 다음 명령으로 값이나 API 비밀을 출력하지 않고 계약 상태를 검사할 수 있습니다.

```bash
python scripts/audit_settings_contract.py /path/to/settings.json
```

정상 결과는 정본 `3.9.0.5`, 모순 0건입니다.

v3.9.0.5 Update Patch 1 포함 릴리스 소스 검증 결과는 전체 `1,254 passed, 6 skipped`입니다. Windows 설치본 사용자는 `keyring`이나 requirements를 직접 설치하지 않으며 v3.9.0.5는 운영체제 보안 저장소에 의존하지 않습니다. 증권 연결 성공 로그는 계좌번호 대신 설정 여부만 남깁니다. 이 수치는 소스 회귀 증거이며 Windows 설치·실제 계정 연결·실체결 성공을 대신하지 않습니다.

## 거래소·증권사 공통성과 차이

판단·설명·기록·가드레일이라는 상위 철학은 공통입니다. 실제 기능은 시장과 연결 방식에 따라 다릅니다.

- 해외 선물: 레버리지, 마진, 조건부 주문과 선물 포지션
- 국내 현물: KRW 현물 주문과 거래소별 최소 주문액
- 국내 증권: 장 시간, 계좌상품, 브로커 API·ActiveX/REST 차이
- 해외 증권: 현재 앱에서 연결된 어댑터 범위 내 지원

따라서 하나의 고급 설정을 켰다고 모든 거래소·증권사에서 동일한 주문 형식과 데이터가 제공되는 것은 아닙니다. 화면의 연결 진단과 실행 로그가 최종 근거입니다.

## 업데이트 후 확인 순서

1. `설정 → 일반`의 정본과 모드 확인
2. `거래소 선택`에서 위·아래 범위 확인
3. 처음에는 PAPER로 시작해 실주문 미호출과 가상 상태 확인
4. 연결 진단에서 필요한 거래소·증권사만 검증
5. 고급 정책은 기본 safe 유지
6. 실주문 전 PAPER OFF, 실제 주문 범위, API 권한과 손실 한도 재확인

### 업데이트 설정과 검증 정책

- 앱 실행 약 15초 뒤 최초 확인하며 이후에는 `자동 체크 주기` 1~72시간(기본 6시간)을 사용합니다. 필요할 때 `업데이트 확인`으로 즉시 확인할 수 있습니다.
- 인증서나 Authenticode는 요구하지 않습니다. 배포 출처는 GitHub HTTPS로 제한하고 `release-manifest.json`의 필수 SHA-256과 다운로드 EXE가 일치해야 합니다.
- SHA 누락·불일치, GitHub 외 URL, 정상 설치 EXE 경로 미확인, 안전 종료·포지션 사전점검 실패는 적용 차단 사유로 표시합니다.
- 코드서명이 없으므로 Windows SmartScreen/Defender 평판 경고는 나타날 수 있습니다. SHA 검증은 파일 동일성 검증이며 Windows 게시자 평판을 대신하지 않습니다.
- `앱 종료 시 자동 적용`은 안전 점검을 생략한다는 뜻이 아닙니다. 기본은 열린 포지션·주문이 있으면 연기입니다.

### 거래소 체결내역 지원 상태

- Upbit·Bithumb·Bybit·OKX·Bitget의 NoahAI 새 실주문은 주문 응답 즉시 공통 실제 체결 원장에 기록합니다.
- 과거·수동 주문 가져오기는 거래소의 `체결 API`를 먼저 사용하고, 가능하면 `완료 주문 API`로 폴백합니다.
- 두 API가 모두 없으면 `과거·수동 체결 자동 가져오기 미지원`으로 표시합니다. 이 상태는 새 주문 기록 실패나 실제 거래 0건을 뜻하지 않습니다.
- 거래소 실제 체결 원장은 주문·체결 감사용이며, NoahAI 진입부터 청산까지 추적한 완료 거래의 승률·PnL과 분리합니다.

자동검증은 사용자별 거래소 API 키·조회/주문 권한·허용 IP와 실제 체결 성공을 대신하지 않습니다. 연결 실패 시 설정 화면과 거래소 탭의 최종 상태를 기준으로 해당 계정 설정을 확인합니다.
