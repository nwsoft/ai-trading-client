## 1. 문제 정의 (Problem / Slide 2)

## 금융의 본질 문제는 "정보 부족"이 아니라 "판단 구조 부재"

현대 금융은 정보가 과잉이지만, 다음이 구조적으로 남아 있습니다.

1) **판단 과정이 남지 않음**  

- "왜 그 결정을 했는지"가 로그/근거로 남지 않아 사후 검증·감사가 어렵습니다.

1) **책임이 개인에게만 남음**  

- 판단 근거/과정이 분리·기록되지 않으니 결과 책임이 개인에게 집중됩니다.

1) **24시간 시장 + 인간의 감정 개입**  

- 공포/탐욕, 피로, 과잉 확신이 반복적으로 비합리적 판단을 유발합니다.

1) **실행(주문) 중심 솔루션의 부작용**  

- 실행이 자동화될수록 "판단 근거"가 더 보이지 않는 블랙박스가 되기 쉽습니다.

**요약:**  
금융에서 진짜 공백은 "더 많은 정보"가 아니라, **판단을 구조화하고 설명·기록·검증하는 인프라**입니다.

## 2. 기존 솔루션이 실패하는 구조적 이유 (Why existing solutions failed / Slide 3)

## 공통 실패 원인: Decision(판단)과 Execution(실행)을 분리하지 못함

- **자동매매(Execution 중심)**: 실행은 빠르지만, 판단 근거·책임·설명 공백이 생기기 쉽습니다.
- **자산운용/리서치(결과 중심)**: 결과는 남지만 판단 과정이 표준화된 로그로 축적·재현되기 어렵습니다.
- **AI 리포트(일회성 분석)**: 분석은 제공하지만 지속적 환류·재현·감사 체계가 없는 경우가 많습니다.

**핵심:**  
기존 방식은 "판단 과정의 표준 기록/설명/검증/환류"가 제품 구조에 내장되어 있지 않습니다.

## 3. NoahAI의 해법 (Solution / Slide 4)

## "판단 인프라"로 문제를 푸는 방식

NoahAI는 금융기관을 대체하거나, 대신 실행하는 시스템이 아니라  
**판단·설명·기록·검증을 표준화하여 연결하는 중립 계층(Decision Infrastructure Hub)** 입니다.

### NoahAI가 '하지 않는 것'이 핵심인 이유

NoahAI는 의도적으로 다음을 **하지 않습니다**.

- 주문·체결, 자금 이동, 계약/법적 행위(운용/중개 포함)

이 경계를 고정함으로써 다음이 가능해집니다.

- 책임 주체(사용자/외부기관)가 명확해짐
- 판단 과정을 "항상" 로그·설명·재현 가능한 형태로 유지 가능
- 자산군이 바뀌어도 동일한 판단/감사 구조를 재사용 가능

## 4. 핵심 차별성/장점 (Advantages / Slide 5)

IR 제작사가 "왜 모방이 어려운가"를 잡을 수 있도록, 기술적 차별을 '제품 문장'으로 정리합니다.

1) **Decision vs Execution 분리 아키텍처**  
   - 실행을 분리했기 때문에 **판단의 설명/기록/검증 레이어가 제품의 중심이 됨**

2) **Audit & Replay(감사/재현) 기본 탑재**  
   - "로그가 있다"가 아니라, **판단 과정 자체가 재현 가능한 구조로 설계**됨

3) **XAI(설명가능) 중심 UX**  
   - 사용자는 "왜 그렇게 판단했는지"를 **대화/리포트/로그**로 확인할 수 있음

4) **자산군 독립 파이프라인**  
   - 판단 계층은 재사용하고, 실행 브리지만 교체(외부 API)하는 구조 → 확장성이 아키텍처에 내장

5) **실환경 운영 기반 안정화**  
   - 실서비스에서 운영되며 외부 API 변화(거래소 정책 등)에 대응해 온 운영 노하우가 축적됨

## 5. 제품/서비스 형태 (Product / Slide 6)

※ "트레이딩 봇" 오해를 막기 위해 **사용자 경험** 중심으로 정리합니다.

## 5-1. NoahAI (메인) — 판단·설명·기록·검증 UX

사용자가 얻는 것은 **'자동 실행'이 아니라**,

- 시장/자산 상태 요약
- 판단 근거(지표/패턴/리스크) 설명
- 판단 로그/리포트 저장
- 재현 가능한 기록(검증/복기)

### 실행(주문·체결)은 외부 거래소/증권사 API와 사용자 계정에서 수행

## 5-2. Paper Trading 모드 — 집행 없이 판단 검증

- 실제 집행 없이 동일 파이프라인으로 판단/기록/리포트 검증

## 5-3. Alpha Arena — LLM 판단 실험/벤치마크 (연구·검증 전용, 일반 서비스와 분리)

- 여러 LLM 판단을 동일 규칙/가드레일에서 비교·검증하는 실험 환경
- 집행은 외부 API, NoahAI는 판단/기록/검증 구조 제공

## 5-4. Enterprise(기업용) — "판단 인프라"를 외부 시스템에 붙이는 방식

- 내부 시스템/외부 API 위에 **Decision Layer + Audit/Replay Layer**를 얹는 형태
- (실행/계약/책임은 기업/기관에 남는 구조)

## 8. 시장/고객 — 숫자 없이도 "누가 왜 필요한가"가 보이게 (Market / Slide 9)

※ 시장 규모 수치(TAM/SAM/SOM)를 지금 당장 확정할 수 없으면, "타깃/사용 시나리오/구매 동기"를 먼저 명확히 둡니다.

## 8-1. 1차 고객군 (현재 구조와 가장 맞는 곳)

- 24/7 시장에서 **판단 부담이 큰 개인 사용자** (학습/설명/검증 니즈)
- **운영 리스크·감사·리포트**가 필요한 트레이딩/리서치 팀 (기업/기관)
- 디지털 접근성이 낮아도 **"설명/조회"**가 필요한 사용자층 (시니어/비전문가)

## 8-2. 왜 지금 필요한가 (트렌드/환경 요인)

- 시장 복잡도 증가 + 정보 과잉
- AI 도입 확산으로 **"설명가능성/감사/책임"** 요구가 증가
- API 기반 금융/거래 인프라 확산 (연결은 쉬워지지만 판단/검증은 공백)

## 8-3. 차기 고객층 — 생활금융 & 위험보호 도메인 확장 (향후 2026~2027)

암호화폐 판단 인프라를 기반으로, **동일한 판단/설명/기록 구조를 생활금융에 확장 중**이며 실데이터/기관 연동은 후속 고도화 단계입니다.

### 생활금융 의사결정 보조 (Daily Life Finance Decision Support)

#### 대상 사용자

- 금융 상품 선택에 혼란스러운 일반 개인
- 대출/보험/예금 비교에 시간을 낭비하는 직장인
- 금융 이해도가 낮아 사기/약탈적 상품의 피해를 보는 사용자층

#### NoahAI가 제공하는 것

- 대출 상품 비교·위험 평가·상환 능력 분석
- 보험 상품 선택·보장 범위 설명·리스크 평가
- 예금/적금/채권 상품 비교·이율 분석
- **개인 맞춤형 재정 관리**: 수입/지출 분석, 목표 수립, 재무 시뮬레이션

#### 구조적 이점

- 암호화폐와 동일한 **판단·설명·기록·검증 인프라** 재사용 가능
- 외부 금융기관 API만 교체 (가정: 금융사 공개 데이터/API 연동)
- 실행은 사용자/금융기관이 담당

### 위험보호 도메인 (Risk Protection Domain)

#### 금융사기 탐지 & 경고 (Fraud Detection & Prevention)

- 의심 메시지/요청/거래 자동 감지
- 피싱·보이스피싱 패턴 인식
- 약탈적 거래 조건 자동 경고
- 고령층/취약층을 대상으로 한 사기 조기 탐지

#### 거래 이상 감지 (Trade Anomaly Detection)

- 사용자 거래 패턴 대비 비정상 거래 자동 탐지
- 예기치 않은 손실/포지션 변화 경고
- 강제청산·마진콜 위험 사전 예방

#### 타겟 고객

- 고령층·디지털 약자 (금융사기 고위험군)
- 자산 규모가 큰 개인/기관 (리스크 관리 필수)
- 규제·감시 대상 기업 (자동 경고·기록 시스템 필요)
