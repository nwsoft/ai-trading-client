## 제품 원칙과 범위

하나의 금융 비서는 모든 계좌를 자동 수집하거나 대신 투자한다는 뜻이 아니다. 사용자가 제공한 기록의 범위·시각·누락을 유지하면서 **상태 확인 → 비교 → 설명 → 사용자 결정**을 연결한다. 계산은 일반 코드, AI는 설명을 맡는다. 생활비·목표 적립을 투자 가능 잔액이나 PAPER 성과에 더하지 않는다. JEV와 신규 외부 AI 의존성은 추가하지 않는다.

### 이번 구현 범위

1. 생활금융의 이번 달 기록 기반 점검: 수입·지출·내 계좌 이체 구분, 기록 없는 상태, 미래 날짜 제외, 목표 및 다음 확인 항목. 월중 수치를 월말 예측으로 표시하지 않는다.
2. 수입·생활비·상환액·적립액을 직접 입력하는 월간 계획 비교. 대출 원금/이자를 포함한 상환액은 생활비와 중복 입력하지 않도록 안내한다. 계산 결과는 투자 가능액·대출 심사 결과가 아니다.
3. 자산통합에 같은 로컬 재무 점검을 연결하되 실제 계좌 잔액, 가계부 차액, 목표 적립을 합산하지 않는다. 생활금융 조회 실패는 자산 조회를 중단하지 않는다.
4. 폐지된 금투세 계산을 중단하고 제도 안내·필요 자료로 교체. 잘못된 근로소득공제 구간 및 한도 정정. 다른 간이 세무 계산까지 최신 세법 전체 검증 완료로 표시하지 않는다.
5. UI의 ‘순 자산/저축’ 오해를 ‘기록상 수입−지출’로 정정하고, 현재 화면에서 질문 초안을 작성하되 자동 전송하지 않는다.

### 기록 호환성

내부 이체는 `life_finance_transfers.json`에 별도로 보관한다. 기존 수입·지출 파일의 알 수 없는 유형을 지출로 취급하는 구버전에서도 이체가 소비로 잘못 합산되지 않게 하기 위함이다. 새 버전은 두 파일을 함께 읽으며 기존 백업·외부 동기화에 이체 파일을 포함한다. 구버전에서는 이체 목록이 보이지 않으며, 새 버전에서 다시 읽을 수 있다. 이체 파일 손상은 빈 기록으로 덮어쓰지 않고 복구 안내와 함께 로드를 거부한다. 기존 송금·지출은 자동으로 내부 이체로 바꾸지 않는다.

## 별도 단계 — 이번 완료로 표시하지 않을 것

- 마이데이터/오픈뱅킹 자동 수집 및 실제 이체: 정식 연결, 권한, 동의, 중복 대조, 운영·규제 검토 필요.
- 가족 초대·동의·철회·개별 비공개 범위: 별도 소유권 모델 필요. PC 원격 동의를 재사용하지 않는다.
- 실시간 금리·보험 보장 추천: 갱신 출처, 상품 데이터 사용권, 개인 적합성 검토 필요. 현재 기본 카탈로그는 시뮬레이션이다.
- 세무 신고액 확정: 세목·귀속연도·거주성·상품별 과세·예외 사례·공식 자료 검증 필요. 금투세 폐지가 모든 투자소득 비과세를 뜻하지 않는다.
- 은행 수준 FDS·완전한 음성 접근성: 현재 입력 문구 점검/지원 환경 음성과 구분한다.

## 검증 계획

### 공개 설명 정합성

제공받은 소개문의 ‘금투세 계산’은 ‘투자소득 과세 확인·간이 세무 시뮬레이션’으로 변경해야 한다. 이번에 읽은 financial-ai-future 페이지 본문에서는 ‘금투세’라는 정확한 문구는 검색되지 않았으므로, 해당 URL에 그 문구가 현재 게시되어 있다고 단정하지 않는다. 생애 시나리오와 현재 지원 기능을 구별해야 하며, 은행 자동 연결·실제 이체·가족 자동 공유·보험 전체 보장 분석·신고액 확정·은행 수준 사기 차단을 현재 완료 기능으로 광고하지 않는다. 홈페이지 소스/게시 변경은 이번 클라이언트 수정에 포함하지 않았다.

- 빈 기록, 실제 0, 수입만/지출만, 미래 기록, 내부 이체 제외, 잘못된 값, 저장·재로드, 기존 기록 보존.
- 목표와 현금 잔액 중복 합산 금지, PAPER/LIVE·통화 분리 유지, 생활금융 오류 격리.
- 시나리오 입력 누락/음수/비유한값·상환 중복 안내·무저장 확인.
- 금투세 폐지 안내가 API·어시스턴트·화면에 동일하게 전달되고 0원 비과세로 오인되지 않는지 확인.
- 실제 컴포넌트 브라우저 시험, 좁은 화면과 데스크톱 배치, 자동 외부 호출/주문 없음.
- 실행 결과는 TEST_STATUS에 기록한다. Windows 설치본·실계좌·은행 연계·웹사이트 배포는 별도 인수다.
