## 이번에 바꾼 사용자 흐름

1. 처음 알아보기, 받은 견적, 기존 보험, 저장 계획 중에서 시작한다. 목적과 가입 상태를 먼저 정하고 모르는 금액은 건너뛴다.
2. 내부 상품 후보에서 확인된 안내·출처·기한과 개인 견적 미확인을 구분한다. 보험 관심 선택은 같은 화면의 설명, 비교, 저장, 상담 질문으로 이어진다.
3. 견적이 없으면 빈 견적 폼을 강제로 채우지 않는다. 확인 질문과 관심 계획을 암호화 보관함에 저장한다. 견적을 받았을 때 추가하고, 상담 결과도 확인 후 가져온다.
4. AI 모델·키는 설정 → AI 엔진/API에서 관리한다. 빠른 판단은 목적 분류, 어시스턴트는 근거 설명에 사용한다. 로컬 기능은 키 없이 이용하며 외부 AI 요청은 전송 내용과 동의를 확인한다.

- 보험: 요구 보장 체크 선택, 정액/실비·한도·지급 정의·자기부담·면책·감액·갱신 구조화 대조. 보관함에서 사용자가 확인한 유효 KRW 계약을 가져온다. 이름 일치만으로 동일 보장·불필요한 중복·가입 가능성을 확정하지 않는다. 예산/요구 보장 검토 기준을 선택한다.

## 상품 자료를 앱 패치 없이 갱신하는 방법

기존 `finance_product_sources.json`은 이용 권한을 검토한 **정규화 비교용 상품 피드**다. 이번 `finance_reference_source.json`은 **보험 탐색용 편집 자료**의 별도 공급 경로다. 가격/가입 심사와 혼합하지 않는다.

계정 데이터 디렉터리에 다음 구조의 운영 검토 설정을 배치한다. 아래 주소는 형식 예시이며 실제 운영 주소가 아니다. 등록하지 않으면 네트워크 호출 없이 내장/마지막 자료를 사용한다.

```json
{"id":"noah-editorial","api_url":"https://example.org/reviewed-insurance.json","enabled":false,"interval_seconds":3600,"owner":"자료 검토 담당","contact_url":"https://example.org/support","editorial_rights_reference":"자체 작성 요약과 배포 범위 검토 기록 위치","ai_processing_allowed":false}
```

공급 계약은 `schema=noah-insurance-reference-v1`, `source_id`, 증가하는 정수 `sequence`, `published_at`, `products` 배열이다. 상품 필드는 [보험 자료 명세](INSURANCE_REFERENCE_DIRECTORY.md)를 따른다. `products=[]`는 이전 관리 상품 전체 철회다. 빈 응답/JSON 오류/불일치/순번 역행은 철회로 해석하지 않는다. 같은 순번으로 다른 내용을 바꾸면 거절한다. 보관 중인 기한은 실패·롤백·재시도 때문에 연장되지 않는다.

```sh
.venv/bin/python scripts/finance_reference_feed.py --data-dir /operator/account-data export --records /operator/reviewed.json --source-id noah-editorial --sequence 1 --output /operator/release-feed.json
.venv/bin/python scripts/finance_reference_feed.py --data-dir /operator/account-data status
.venv/bin/python scripts/finance_reference_feed.py --data-dir /operator/account-data refresh
.venv/bin/python scripts/finance_reference_feed.py --data-dir /operator/account-data rollback --revision REVIEWED_HASH
.venv/bin/python scripts/finance_reference_feed.py --data-dir /operator/account-data resume
```

생성된 피드를 검토 후 지정 HTTPS 서버에 게시하고 각 고객의 운영 설정에 연결해야 한다. 이 작업 없이 ‘전체 고객 자동 갱신 운영 중’이라고 표시하지 않는다. `resume`은 담당자가 피드와 오류 원인을 확인한 뒤 실행한다. 다른 출처나 가격 데이터의 이용 권한을 부여하는 기능이 아니다. AI 공유는 자체 작성 내장 요약과 운영 설정에서 처리 범위를 확인한 요약만 동의 후 허용하며, 수동 CLI 수입 자료는 기본적으로 AI 공유하지 않는다.

## 상담 API 후속 계약

기존 submit/status 응답의 request_id·receipt_id·status 검증은 그대로다. 선택적으로 `result`를 추가한다.

```json
{"request_id":"기존 접수 요청 ID","receipt_id":"기관 접수 번호","status":"in_consultation","result":{"assigned_advisor":"배정 상담사","expected_reply_at":"2026-10-08T09:00:00+09:00","quotes":[{"id":"기관 견적 ID","provider":"기관 이름","name":"발급 견적 이름","source_url":"https://example.org/quote","valid_until":"2026-10-09T09:00:00+09:00","terms":{"annual_rate":3.5,"fees":0}}]}}
```

예시는 시험용 형식이며 실제 견적이 아니다. 최대 20개, 금액/기한/출처/허용 필드를 검증한다. 수동 회신 파일은 `result` 객체 부분만 저장한다. 화면에서 수신 결과를 확인한 뒤 가져오며 보험 견적의 confirmed는 false로 시작한다. 수정·다른 모델·근거 변경 시 기존 AI 전송 동의를 재사용하지 않는다. 연결 목록은 운영자가 계약·개인정보 처리·보관·접수 경로를 확인한 수신처만 등록한다.
