## 이번 통합 감사에서 확인·수정한 코드 결함 8건

1. 설정 병합·변경 진단이 비밀값 자체를 로그에 출력할 수 있던 문제
2. AI Provider 사전 점검이 읽기 전용이어야 하는데 설정 마이그레이션을 저장하던 문제
3. 거래소·AI 진단 도구가 특정 사용자 설정 경로를 고정 사용하던 문제
4. 인증·IP 오류를 일반 연결 실패로 표시해 사용자가 원인을 알 수 없던 문제
5. 커스텀 전략 저장 파일 권한이 사용자 전용이 아니던 문제
6. 어댑터의 빈 잔고 응답을 성공으로 캐시해 탭이 거짓 정상 또는 영구 로딩처럼 보이던 문제
7. 거래소 준비도 타임아웃 프로세스가 semaphore 정리 경고를 남기던 문제
8. Binance 폴백 어댑터의 포지션·미체결·거래내역·레버리지·마진·펀딩 기능이 빈 구현이던 문제

수정 후 빈 응답은 `empty_response`, 인증·IP 접근 문제는 `invalid_api_keys` 계열 최종 상태로 전달된다. 실패 상태는 성공 캐시에 저장하지 않는다.

## Teayu_02 암호화폐 거래소 실점검

모든 점검은 잔고·계정 정보 읽기 전용이며 주문을 전송하지 않았다.

| 거래소 | 결과 | 사용자 조치 |
|---|---|---|
| Upbit | 인증 실패 | API 키 허용 IP와 조회 권한 확인 |
| Bithumb | 인증 실패 | API 키 Access IP와 조회 권한 확인 |
| Bybit | 인증 실패 | API 키 bound IP 확인 |
| OKX | 인증 실패 | Key·Secret·Passphrase·권한·IP 제한 재확인 |
| Bitget | 인증 실패 | API 키 IP 화이트리스트 확인 |
| Binance | 계정 정보 빈 응답, 자격 검증 실패 | API 키·선물 계정 권한·IP 제한·계정 상태 재확인 |

따라서 Teayu_02에서 거래소 탭 잔고와 포지션이 표시되지 않는 현재 직접 원인은 `keyring` 설치가 아니다. UI가 실패를 영구 `로딩 중`으로 숨기던 코드 결함은 수정했지만, 위 거래소 계정 설정을 사용자가 바로잡기 전에는 실제 잔고가 나타날 수 없다.

## 실행 모드와 실제 주문 의미

- 위쪽 `거래소 선택`: 화면, 공개 시세, 분석, AI 판단, 학습 범위
- 아래쪽 `실제 주문 실행 거래소`: LIVE 신규 주문을 보낼 수 있는 명시적 허용 범위
- LEARNING: 실제 주문 대상 0개여도 분석·학습 루프 시작, 신규 주문 차단
- PAPER: 실시간 시세·분석·전략을 사용해 내부 가상 체결, 거래소·증권사 주문 API 미호출
- LIVE: PAPER가 꺼져 있고 실제 주문 대상이 명시된 거래소만 신규 실주문 허용

두 선택은 모순이 아니라 관찰·학습 범위와 금전 위험 권한을 분리한 것이다. 단, 시작 자체를 막던 과거 동작은 계약 위반이며 v3.9.0.4에서는 실제 주문 목록이 비어 있어도 LEARNING이 시작돼야 한다.

여러 실제 주문 대상을 선택했을 때 기본값은 각 거래소·증권사에서 각각 실행하는 `parallel`이다. 같은 BTC나 주식을 하나의 기회 ID로 연결해 통합 예상 노출·손실과 대상별 결과를 관리하며, 동일 대상·계좌·신호의 재제출만 차단한다. 사용자가 선택한 경우에만 `split` 또는 `best`를 적용한다.

## AI 커스텀·AI 어시스턴트

- 파이프라인 단계: 초안 → 분석 → 저장 → 승인 → 자동검증 → 활성
- 제품 목적: 익숙한 시중 전략의 실행력에 NoahAI의 시장국면 판단·감독·보호·기록을 더하고, 학습은 후행 선택 품질을 개선한다.
- `기본 AI 후보 재확인(confirm)`과 `사용자 전략 원형 독립 실행(independent)`을 구분한다. 독립 역할에는 기본 AI 합의·패턴 재심사·전체 수익성 정책을 다시 적용하지 않는다.
- Binance·통합 거래소·주식/ETF는 공통 `TradeCandidate`/`ExitPlan`을 사용하며 활성 전략 풀은 후보당 한 번 평가한다.
- 일반은 `SelectionPolicy`의 사용자 고정+NoahAI 자동 후보를 기본 AI 뒤에서 재확인한다.
- 고급은 `StrategyUniversePolicy`의 포함/제외·거래대금·스프레드·변동성 로컬 필터와 전략 지표에서 독립 후보를 만든다. 후보선정 때문에 LLM을 추가 호출하지 않는다.
- 국면 범위는 전략별 `market/symbol/both/none`이며 전체 시장이 기본이다. 선택 범위 데이터가 없으면 다른 국면으로 암묵 폴백하지 않는다.
- 공통 `ExitPolicy`가 fraction 단위에서 기본 폴백·현재 적용값과 근거·보험 주문 제출값과 상태를 분리한다. 서버 보험 주문이 없는 경로는 미제출 사유를 기록한다.
- 저장만으로 실거래에 적용되지 않는다. 기본/재확인 역할은 NoahAI 전략 정책과 공통 안전 경계를, 독립 역할은 시장국면·계좌·주문 안전 경계를 따른다.
- LEARNING도 AI 커스텀·수익성·후행 전략·계좌 위험·수량·청산계획·최종 주문 규격까지 평가하고 외부 상태 변경과 신규 주문만 차단한다.
- 주식/ETF도 진입 전략 버전의 명시 청산·TP/SL을 XAI로 영속·복원해 클라이언트 청산에서 사용한다. 증권사 서버 측 보험/브래킷 주문은 어댑터별 지원 범위다.
- Teayu·Teayu_02 활성 전략의 구조, 대상, 버전 참조와 실행 검증 기록은 유효하다.
- adminjung 전략은 승인 상태이며 활성 상태가 아니다.
- 세 전략 파일에서 민감 필드를 찾지 못했고 파일 권한은 `0600`으로 교정했다.
- Teayu_02의 v3.9.0.3 credential reference만 남은 DeepSeek·OpenAI 키는 v3.9.0.4에서 다시 입력해야 한다. 재입력 전 AI 커스텀 Provider 분석과 AI 어시스턴트 실호출은 준비 완료가 아니다.
- 별도 검증 계정의 OpenAI 텍스트·JSON 역할 호출은 통과했지만 전사 프로필은 실제 음원 샘플 검증이 남아 있다.
- 사용자 매뉴얼의 핵심 바로가기·전체 검색·AI 질문 동선과 어시스턴트의 실행모드·AI 커스텀·다중 실행 현재설정 답변을 추가했다.

## 운영자 한정 보안 후속 조치

이 조치는 모든 설치 사용자 대상이 아니다. 단순히 `keyring` 경고를 본 사용자, 설정을 정상 저장한 사용자, 일반 v3.9.0.4 사용자는 키를 교체할 필요가 없다.

이번 통합 진단에 사용한 일부 운영 계정에서는 구버전 설정 로더가 비밀값을 개발 콘솔에 실제로 출력했다. 비밀키가 한 번 화면이나 로그에 평문으로 나타나면 복사·캡처·수집 여부를 완전히 증명할 수 없으므로, 해당 진단에 사용한 키만 폐기하고 새 키로 교체하는 것이 안전하다. 현재 v3.9.0.4 소스는 설정값과 변경 전후 값을 로그에 출력하지 않도록 수정됐다.

교체 방법:

1. AI Provider: 해당 Provider 콘솔에서 노출된 기존 API 키를 revoke/delete하고 새 키를 만든 뒤 `설정 → AI 엔진/API`에 저장
2. 암호화폐 거래소: 기존 API 키를 삭제하고 조회·거래에 필요한 최소 권한으로 재발급, 출금 권한 OFF, 현재 사용 환경의 IP만 허용한 뒤 `설정 → 거래소 API`에 저장
3. 증권사: 개발자 포털에서 노출된 App Secret·토큰을 폐기/재발급하고 해당 증권사 설정에 저장
4. 저장 후 앱을 다시 시작하고 AI 기능 검증 또는 잔고·포지션 읽기 전용 연결 검증 수행

설정 파일과 설정 백업은 지원용 로그 압축에 포함하지 않는다.
