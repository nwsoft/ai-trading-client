# v3.9.1.44 거래 기록 복구 완료 경로 검증

2026-09-21 · 소스 수정 및 오프라인 검증. Client 설치기 빌드·공개 게시 미실행.

## 원인과 수정

기존 복구는 청산 ID가 없는 기록의 이력 검색을 지원했지만, ID가 이미 있고 그 주문이 일부 청산 수량만 포함하면 `partial_or_quantity_mismatch`로 반환해 전체 구간 검색으로 전환하지 않았다. 또한 새로운 점검마다 완료한 조회 구간을 다시 pending으로 바꾸고, 진행률에는 현재 작업 외 이전 조회 구간까지 합산했다. 사용자가 설정 창을 닫으면 UI에 의존하던 다음 배치 실행도 멈출 수 있었다. 이번 시험 중 재시도 대기에서 프로세스 종료 직후 이어하기가 30초 cooldown에 걸리는 경로도 찾아 수정했다.

- 기존 청산 ID의 수량 불일치·체결 미발견에서도 Binance 전체 이력 복구로 전환한다. 하나의 진입 주문이 독립된 포지션 구간을 소유하고 전체 수량·종료 주문·정산이 입증되면 분할 청산을 함께 반영한다.
- 로컬 수량·진입가격의 오류도 같은 증명이 있을 때만 실제 체결 값으로 수정한다. 여러 로컬 거래가 진입 주문을 공유하거나 다른 진입이 섞이면 임의 배분하지 않는다. 원본 백업·행 변경 전후·체결 귀속을 보존한다. 수정 직후 프로세스가 종료돼도 자신의 확정 변경을 알아보고 작업을 이어간다.
- 완료한 구간·v43 분할 페이지 캐시를 재사용하고 현재 작업에 연결된 조회 구간만 진행률에 집계한다. 정산 지연 재점검에서는 필요한 income만 갱신한다.
- 한 번 명시적으로 실행하면 설정 창과 독립적으로 조회량을 제한하며 계속한다. 일시 오류·정산 지연은 5초/15초 간격으로 최대 2회 재시도한다. 앱 종료 시 체크포인트를 보존하고 다음 실행에서 이어간다. 작업 중 계정 잠금과 배치 대기 중 DB lease를 유지한다.
- LIVE 대표 카드는 NoahAI 완료 거래 수를 표시한다. 체결 수는 별도 단위·수집 범위를 표시하고 거래 통계의 기본 접힌 상세에서 최근 체결 ID·주문 ID·수량을 확인한다. `저장 원장`을 무설명 건수 단위로 사용하지 않는다.
